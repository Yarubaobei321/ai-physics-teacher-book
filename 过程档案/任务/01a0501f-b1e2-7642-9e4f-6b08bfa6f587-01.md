结论：SOL 项目的核心要求不是“多放图”，而是“每幅图表都让读者完成一次观察、比较或判断”。这套原则应迁移到新书。新书应强制每章做视觉策划，但不强制每章达到固定图数。

## SOL 项目提出的主要要求

1. 图表必须参与解释和论证

每幅图表都要回答：

- 为什么此处需要看图？
- 读者具体看什么？
- 看完后能够多作出什么判断？
- 这个判断怎样接回正文？

SOL 将其规定为“图表论证门禁”，明确反对装饰、凑数和把正文原样画一遍。[SOL 项目总规则](/Users/yaril/个人文档/3%20写作/人机协同科研%20sol/AGENTS.md:36)

2. 建立“图前—图中—图后”闭环

- 图前：提出本段要解决的问题。
- 图中：给出变量、条件、单位、图例、来源和必要标注。
- 图后：指出差异、趋势、异常、边界，以及它支持什么判断。

“如图所示”不能代替诠释。[图表论证闭环](/Users/yaril/个人文档/3%20写作/人机协同科研%20sol/期刊审美与投稿要求/图表数量类型与论证功能补充研究-2026-08-26.md:155)

3. 不同图表承担不同任务

| 类型 | 适合说明 | 不能单独证明 |
| --- | --- | --- |
| 实物、装置、结构图 | 对象是什么、部件在哪里、怎样连接和测量 | 精度、优越性、教学效果 |
| 原理图、机制图 | 为什么发生、变量怎样联系、模型条件是什么 | 真实装置一定服从理想模型 |
| 流程图、版本序列 | 行动顺序、决策点、失败、退回和修正 | 流程一定成功或更优 |
| 截图 | 某一版本怎样操作、显示什么结果 | 物理正确、长期稳定、学生理解 |
| 数据图 | 变量关系、趋势、异常、理论与数据比较 | 相关即因果、拟合好即真实 |
| 表格 | 精确比较数值、条件、职责、标准 | 用“促进、提升”等空泛词证明价值 |
| 学生作品、课堂照片 | 特定任务中实际出现的作品或行为 | 全班水平和学习效果 |

完整分类见[图表类型及其论证任务](/Users/yaril/个人文档/3%20写作/人机协同科研%20sol/期刊审美与投稿要求/图表数量类型与论证功能补充研究-2026-08-26.md:126)。

4. 采用“最小充分图组”

先建立：

`核心主张 → 读者需要看到什么 → 最合适的表达媒介`

没有解释任务就不补图；同样，一幅图承担太多主张，也应拆开。[最小充分图组规则](/Users/yaril/个人文档/3%20写作/人机协同科研%20sol/期刊审美与投稿要求/图表数量类型与论证功能补充研究-2026-08-26.md:203)

- 表征对象；
- 变量与模型条件；
- 读者的读图动作；
- 由图产生的判断；
- 用公式、数据、反例或第二种表征怎样核验。

书稿还适合增加一种递进表达：

`真实外观 → 结构关系 → 物理模型 → 变量与数据 → 教师判断或读者行动`

不要求每个案例走完整条链，但应判断哪一层仅靠文字最难理解。

## 还应同步采用的版式原则

- 使用克制配色，但信息不能只靠颜色成立。
- 缩小到书页栏宽后仍能辨认文字、线型和符号。
- 流程图必须有真实的决策、输入输出或退回关系，不能只是把小标题装进方框。
- 关系图中的箭头必须表示明确的方向、依赖或回退。
- 避免演示文稿式卡片、渐变、阴影和大面积空背景。
- 图注写“对象＋读图重点”，不只写文件名。
- 来源、作者、版本、隐私和出版授权进入图件台账。
- “能证明／不能证明”主要保留在后台策划单；正文只写真正影响读者判断的条件和边界，避免满篇审核口吻。
