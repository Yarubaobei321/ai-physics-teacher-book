## 总体判断

这套方案的主方向是成立的，而且已经不是普通的“文件索引＋RAG知识库”，而是一套带有**材料边界、证据治理、任务路由和作者裁决**的写作基础设施。

我会给出“**有条件通过**”的评价。

它目前最强的地方有四个：

1. 把“全量发现”和“Agent实际读取”分开，避免全库塞入上下文。
2. 明确记录“能支持什么、不能支持什么”，能抑制AI过度解释。
3. 把排除项当作长期规则，而不是一次性口头说明。
4. B1接收关系和问题，而不是按照旧文件夹、旧书目录重新拼装一本书。

现在最需要优化的不是再增加更多层，而是解决四个结构性风险：

> **B0可能过度建设；材料卡可能迅速过期；六类索引可能多头维护；B0可能提前替B1完成了编辑判断。**

其中，第二和第四项尤其重要。

# 一、最重要的概念修正：区分“稳定材料包”和“动态问题包”

目前方案中有一句：

> 按“能够独立回答一个写作问题”的粒度建立材料包。

这句话容易让B0和B1的边界重新混在一起。

因为“写作问题”本身会随着B1的判断而变化。假如今天的问题是“AI怎样辅助教师开发可视化资源”，明天的问题变成“教师如何验证AI生成的物理模型”，同一批材料可能需要重新组合。

因此建议明确区分三种对象。

### 1. 来源材料包 Source Pack

这是相对稳定的，按照材料本身的来源和实践单元组织，例如：

- “2026特优生评选——学生网页与AI评价项目”
- “ESP32火星车可视化开发项目”
- “高中物理习题实验化论文及其过程材料”
- “旧书某一完整版本及配套资源”

它回答的是：

> 这批材料本身是什么？形成于什么实践？包含哪些证据？

### 2. 任务问题包 Question View

这是动态生成的，例如：

- AI评分为什么不能替代教师评分？
- AI生成的技术资源怎样接受物理真实性检查？
- 一个教学想法怎样从原型发展为可复用资源？

一个问题包可以调用多个来源材料包；一个来源材料包也可以进入多个问题包。

### 3. 价值关系卡 Relation Card

这是B0交给B1的真正中间产物，例如：

> AI能够显著加快物理可视化资源的原型生成，但资源能否进入课堂，仍取决于教师对物理真实性、装置可行性和教学目标的三重验收。

这张关系卡可以由多个来源材料包共同支持。

因此更合适的逻辑是：
```
稳定的来源材料包
    ↓
按任务临时生成的问题视图
    ↓
提炼候选价值关系
    ↓
交给B1进行编辑判断
```

这是我认为整套方案中最值得优先修改的一点。否则，B0早期确定的材料包结构，可能会暗中限制B1能够发现的问题。

---

# 二、增加一个前置层：B0也需要“书的宪法”

目前“书的宪法和作者原则”只出现在B1交接包里，但B0本身已经在进行以下判断：

- 什么是核心材料；
- 什么值得制作人工卡；
- 什么与主线相关；
- 什么具有读者价值；
- 什么应当排除；
- 什么关系值得交给B1。

这些判断不可能完全中立，都需要作者原则作为依据。

建议在B0-0之前，或者作为贯穿B0的控制层，增加：
```
B0-C 作者宪法与材料判断规则
```

它不需要确定书名、目录和章节，但至少应包含：

- 目标读者是谁；
- 本书试图解决什么类型的问题；
- 本书明确不写什么；
- 作者最有资格谈论的实践范围；
- 哪些主张必须有证据；
- 哪些材料只能作为背景，不能作为核心证据；
- AI、物理、可视化三者之间的基本关系；
- 对学生材料、他人材料和商业资源的使用原则。

这样才能避免不同Agent使用不同的隐含评价标准。

更准确地说：

> 书的宪法不负责决定目录，但负责约束B0怎样理解“价值”“核心”“风险”和“偏离”。

---

# 三、六类索引不要成为六套独立文件

六类交叉索引的设计是对的，但实现时最容易发生一个问题：

- 材料卡改了；
- AI主题索引没有同步；
- 证据状态更新了；
- HTML仍显示旧状态；
- B1上下文包又读取了另一套数据。

最后会形成多个互相冲突的“事实来源”。

因此建议建立一个**单一真相源**，六类索引只是同一套数据的六种视图。
```
统一材料登记表／关系库
        ├── AI主题视图
        ├── 物理问题视图
        ├── 可视化媒介视图
        ├── 读者价值视图
        ├── 证据视图
        ├── 风险排除视图
        └── HTML审阅视图
```

不需要一开始就使用复杂的知识图谱数据库。比较稳妥的方式是：

- 机械事实：SQLite、JSONL或结构化YAML；
- 作者判断：可编辑的Markdown或YAML；
- HTML：从前两者自动生成；
- Agent上下文包：从统一数据源临时组装。

还应明确区分两类字段：

### 自动生成字段

例如：

- 路径；
- 文件大小；
- SHA；\
  -修改时间；
- Token估算；
- 文档页数；
- 解析状态；
- 精确重复和近似重复；
- 来源版本。

### 人工判断字段

例如：

- 是否为核心材料；
- 能支持什么；
- 不能支持什么；
- 作者是否认可某种关系；
- 是否允许进入B1；
- 是否属于书的主线；
- 排除原因。

自动扫描程序不应覆盖人工判断字段。

---

# 四、B0不能只是一次性流水线，要增加“失效传播”

现在的结构看起来仍然像一次性加工：
```
登记 → 索引 → 卡片 → 路由 → HTML → 交接
```

但真正的“材料操作系统”必须处理材料变化。

例如：

- 原论文修改；
- 项目代码更新；
- 作者纠正了一个事实；
- 一份精校稿替换了旧转换稿；
- 某张图片获得授权；
- 某个学生案例决定不再使用。

这时不仅原文件变化，所有依赖它的材料卡、事实卡、关系卡和B1交接包都可能失效。

建议为每个派生产物记录：

- `derived_from`：来自哪些文件或材料包；
- 来源文件SHA或版本；
- 生成时间；
- 最后核验时间；
- 生成Agent或处理流程；
- 人工审阅状态；
- 当前是否过期。

状态可以设计为：
```
已发现
→ 已解析
→ 已归包
→ 卡片草稿
→ 作者已审
→ 原件已核
→ 已交接B1
→ 已过期／待复核
```

当底层文件变化时，不要默默重写材料卡，而应把下游产物标记为“可能过期”。

这会比单纯保存SHA更重要。SHA只能告诉你文件变了，依赖关系才能告诉你**哪些判断需要重做**。

---

# 五、把“事实、解释、编辑假设和作者决定”分开

当前材料卡中混合了几种性质不同的信息：

- 内容摘要；
- 可以支持什么；
- 与AI、物理、可视化的关系；
- 可转化的读者工具；
- 与其他材料的关系；
- 推荐读取顺序。

其中一些接近事实，一些已经是编辑判断。

建议每张卡明确分成四层：

### A. 来源事实

材料是什么、由谁形成、什么时候形成、包含什么数据或案例。

### B. 证据判断

材料能够证明什么，不能证明什么，需要怎样核验。

### C. 编辑假设

它可能转化为什么读者价值，可能与哪些材料形成关系。

### D. 作者决定

作者是否接受这一解释，是否进入B1，是否只作为备选。

这样可以避免Agent生成一个“看起来合理”的读者价值后，后续系统把它当成已经确定的事实。

建议在系统中使用明确状态：
```
Agent提出
作者认可
作者否决
待更多证据
仅作备选
```

尤其是“可转化的读者工具”，应标记为**候选转化方向**，而不是材料天然具有的属性。

---

# 六、证据等级不要压缩成一个总分

“证据等级和核验状态”这一设计是必要的，但不建议最终只形成一个A/B/C等级。

一份材料可能同时具有以下特征：

- 是作者亲自实践的；
- 但只进行过一次；
- 数据真实；
- 但尚未形成对照；
- 可以说明过程；
- 但不能说明普遍效果；
- 图片可内部使用；
- 但尚未获得出版授权。

因此建议把证据拆成多个维度：

| 维度可能状态 |                     |
| ------ | ------------------- |
| 来源身份   | 作者实践／同行材料／教材理论／二手信息 |
| 原件核验   | 未核／已定位原件／已逐项核实      |
| 证据作用   | 事实／案例／解释／效果主张／背景    |
| 充分程度   | 单一案例／多案例一致／有对照／仍需补充 |
| 时间状态   | 当前有效／历史材料／可能过时      |
| 权利状态   | 可内部读取／可摘要／可引用／可出版图片 |
| 风险状态   | 无明显风险／需匿名／需授权／禁止输出  |

每一项事实或关系最好还能够指向具体锚点：

- 文件；
- 页码；
- 标题；
- 段落；
- CSV字段；
- 图片编号；
- 代码版本。

“已核验”不能只表示Agent读过全文，而应表示能够回到具体来源位置。

另外，不建议让同一个Agent在同一次处理中既生成卡片，又自行把卡片标记为“已核验”。至少应分成“生成”和“核验”两个处理阶段。

---

# 七、路由应当是“主路由＋全库漏检检查”，而不是完全封闭

当前规定：

> Agent不得从L0直接跳到整本教材、完整项目或完整CSV。

这个原则是对的，但需要区分两件事：

1. 在全库中执行检索；
2. 把全库内容载入上下文。

Agent不应把全库放入上下文，但可以对全库的机械索引、全文索引或语义索引做一次轻量搜索。

否则会形成一个自我强化的问题：

- 早期分类认为某材料属于“智能硬件”；
- 路由到“教师评价”时就不再搜索它；
- 但其中可能恰好存在一个重要的人工验收案例；
- 由于它没有被路由出来，后续永远不会被发现。

建议采用双通道：
```
主通道：按主题、证据和任务类型进行受控路由
影子通道：对全库做一次轻量漏检搜索
```

影子通道不直接载入大量原文，只返回少量“可能被当前分类遗漏的材料”。

这样既节省Token，也防止分类体系把意外发现彻底封死。

同时建议把L3进一步区分为：

- **L3a：带来源锚点的原文片段、数据切片和图片；**
- **L3b：完整原件，仅在结构分析、冲突核验或片段不足时升级读取。**

“1—5份原件”可以保留为默认经验值，但不宜成为硬规则。真正的限制应当是：

- 任务需要的证据是否充分；
- 上下文总Token；
- 来源是否具有足够多样性；
- 是否存在重复材料。

---

# 八、每次上下文包都应生成一份“清单说明”

现在定义了上下文包内容，但还可以增加一个上下文包清单：
```
任务ID：
任务问题：
采用的路由：
纳入哪些材料：
每项材料为何纳入：
哪些高相关材料被排除：
排除原因：
来源版本：
预计Token：
当前证据缺口：
生成时间：
```

这份清单非常重要，因为它能回答作者最关心的问题：

> Agent为什么读了这些，而没有读另外一些？

它还可以用于比较两次任务：

- 上一次为什么遗漏某个项目；
- 新路由增加了什么；
- 某次答案变化是不是因为底层材料发生变化。

这比只展示最终上下文更适合人类审阅。

---

# 九、HTML审阅台需要从“展示界面”升级为“判断闭环”

现在HTML承担的展示职责已经比较完整，但还缺少一个关键对象：

> 作者做出的决定最终写到哪里？

建议增加“作者决策账本”，记录：

- 决策对象；
- 作者选择；
- 决策理由；
- 影响范围；
- 是否允许以后重新提出；
- 什么条件下可以重新讨论；
- 是否替代旧决定。

典型决策包括：

- 确认推荐底本；
- 合并或拆分材料包；
- 否决某个价值关系；
- 将材料降为背景材料；
- 标记为禁止出版；
- 确认某项事实；
- 要求补充证据；
- 接受进入B1。

HTML首页最重要的内容不应是材料总量或关系大图，而应是：

1. 当前最需要作者决定的事项；
2. 新变化和已失效内容；
3. 权限、隐私和证据风险；
4. B1交接是否已经具备条件；
5. 哪些材料长期没有被任何任务召回。

关系图很容易变成“漂亮但无法判断”的毛线团，建议放在次级页面，并只展示：

- 高置信关系；
- 作者认可关系；
- 可按关系类型筛选的关系。

HTML还可以分成两个版本：

- **作者本地版**：允许看到路径、文件级追溯和完整审阅信息；
- **外部评议版**：隐藏姓名、路径、敏感材料和完整文件清单。

---

# 十、B0和B1之间不应只有单向交接

目前整体结构仍然是：
```
B0完成
→ 交给B1
→ B1开始
```

更合理的是循环：
```
B0发现并组织材料
        ↓
B1提出候选方向
        ↓
发现证据不足、关系错误或材料遗漏
        ↓
反馈给B0补充和修正
        ↓
B1再次判断
```

B1应当能够向B0写回以下信息：

- 某张材料卡过于宽泛；
- 某个关键事实缺少原件；
- 某个关系实际没有读者价值；
- 发现了新的跨材料联系；
- 某类材料频繁被调用，应提升为核心材料包；
- 某些材料从未被使用，可能需要降级或重新分类。

因此B0-6不应是最终封存包，而应是：
```
B1交接包 v0.1
B1反馈
B1交接包 v0.2
```

这会让B0真正成为持续工作的操作系统，而不是一次性资料整理工程。

---

# 十一、智能硬件的定位基本正确，但建议增加“抽象测试”

你对智能硬件的定位是合理的。它最大的问题不是能不能进入，而是会不会凭借材料数量和完成度，挤占真正的书籍主线。

可以增加一个简单判断：

> 把ESP32、传感器型号、开发板和具体代码名称删掉以后，这个案例是否仍然能够形成一条教师可迁移的方法？

例如：

- “如何用某款传感器采集数据”可能只是技术内容；
- “怎样让AI生成的数据采集方案接受物理模型与真机数据的双重检验”则具有迁移价值。

还可以把材料角色分为三类：

| 角色判断标准 |                            |
| ------ | -------------------------- |
| 主线关系   | 同时满足AI方法、物理问题、可视化实践、教师迁移价值 |
| 支撑案例   | 主要用于证明或解释一条主线关系            |
| 技术附属   | 代码、接线、器材和实现细节，按需进入附录或配套资源  |

需要注意：

> “必须同时满足四项”适合作为B1主方向的门槛，不适合作为所有材料进入B0的门槛。

否则一些重要的理论材料、评价材料和失败记录可能被过早压低。

---

# 十二、材料卡建议从“固定长度摘要”改为“分级表达”

统一要求300—500字摘要，长期可能产生两个问题：

- 简单材料被迫写得很长；
- 复杂材料又压缩得不够。

建议一张卡同时提供三个层次：
```
一句话定位：快速判断是否相关
短摘要：说明主要内容和来源
结构化字段：支持、限制、证据、风险、关系
```

不是每张卡都必须填满所有字段。系统应允许明确填写：

- 不适用；
- 尚不清楚；
- 未读取；
- 解析失败；
- 需要作者判断。

这比让Agent为了字段完整而虚构“读者工具”或“材料关系”更可靠。

同时，“与AI、物理、可视化的关系”不宜只是有或没有，可以改成：

- 直接关系；
- 间接支撑；
- 背景关系；
- 无明显关系；
- 待判断。

---

# 十三、B1接收的“价值关系”建议使用统一卡片

目前B1接收5—10个可能生长的读者价值关系，但还缺少统一表达格式。

建议每个候选关系至少包含：
```
关系ID：
候选问题或核心张力：
对读者的实际价值：
为什么体现作者独特积累：
主要支持材料：
反例、冲突或限制材料：
当前证据强度：
不能做出的主张：
可形成的可视化表达：
可转化的模板、检查表或工具：
还缺什么证据：
B0判断：
作者状态：未审／认可／否决／暂缓
```

尤其应增加“反例、冲突或限制材料”。

一本有价值的书，往往不是由“材料都在支持同一个观点”产生的，而是来自材料之间的张力，例如：

- AI生成很快，但物理错误很隐蔽；
- 可视化让现象更直观，但也可能掩盖模型边界；
- 自动化提高开发效率，但增加了验收责任；
- 项目资源很多，但不能自然转化为读者方法。

这些关系比简单的主题共现更可能形成书的真正主线。

B1交接包中还应包含少量“已否决方向及理由”，防止后续Agent不断重新提出已经被作者否定的方向。

---

# 十四、验收标准需要从“建设清单”升级为“运行测试”

当前验收标准主要验证“东西是否建了”，还应增加“系统是否真的有效”。

建议增加以下测试。

| 测试检验内容   |                                 |
| -------- | ------------------------------- |
| 已知答案测试   | 选取10个作者熟悉的问题，检查系统是否找回真正关键材料     |
| 跨主题漏检测试  | 检查错误分类的材料能否通过全库影子搜索重新出现         |
| 排除测试     | 明确排除材料是否在搜索、上下文包和HTML中都不会重新进入   |
| 失效测试     | 修改一个推荐底本后，下游卡片和交接包是否被标记为待复核     |
| 卡片准确性抽检  | 随机抽取材料卡，对照原件检查摘要、限制和证据描述        |
| 隐私泄漏测试   | 学生姓名、未授权图片和敏感路径是否进入HTML或交接包     |
| 可追溯测试    | 从B1的一条价值关系能否反向找到具体材料、版本和原文位置    |
| 上下文充分性测试 | Agent只读取轻量包时，能否完成任务；不足时能否合理升级读取 |
| 作者审阅测试   | 作者能否快速知道“需要决定什么”，而不是只看到大量状态信息   |

其中最关键的是“已知答案测试”。

只有当系统在作者熟悉的案例上能够稳定找对材料，才能相信它在未知问题上的路由结果。

---

# 十五、建议增加明确的停止规则，防止B0吞掉整本书

B0最大的现实风险是：

> 它本身越来越完整、越来越漂亮，但B1迟迟没有开始。

建议区分两种完成度：

### 机械盘点完整度

这一层可以追求接近完整：

- 所有候选根目录已登记；
- 文件全部进入机械索引；
- 排除和权限规则已经执行。

### 语义加工完整度

这一层不应追求全库完成：

- 核心材料包优先制作；
- 长尾材料按任务调用后再加工；
- B1实际使用的材料优先人工核验；
- 未使用材料保持机械索引状态即可。

也就是说：

> 全库可以被发现，但不必全库都被精细理解。

建议B0达到以下状态后，就允许B1启动：

- 所有来源范围已经登记；
- 核心作者实践已经形成材料包；
- 排除与权限规则有效；
- 已完成一批典型任务路由测试；
- 能生成第一版关系卡；
- B1能够对候选方向作出初步判断。

后续B0与B1并行迭代，而不是等待B0“彻底完成”。

# 建议调整后的总体结构

在尽量不增加复杂度的前提下，可以调整为：
```
B0-C 作者宪法、边界和材料使用政策
        ↓
B0-0 来源与范围登记
        ↓
B0-1 文件级机械索引与版本家族
        ↓

        ↓

```

贯穿所有层的四个控制面是：
```
来源追溯
版本与失效
权限与隐私
作者决定
```

# 实施优先级

## 实施前必须补上的内容

1. 稳定来源材料包与动态问题包的区分；
2. 单一真相源，六类索引只作为视图；
3. 来源依赖、版本和失效状态；
4. 事实、解释、编辑假设和作者决定分层；
5. 作者决策账本；

## 第一版应当实现

1. 来源登记和排除规则；
2. 文件索引、版本家族和推荐底本；
3. 一批核心来源材料包；
4. 简单的受控词表；
5. 主路由＋全库漏检搜索；
6. 上下文包清单；

## 可以延后

2. 全部材料的事实卡、图片卡和案例卡；
3. 高度交互式HTML后台；
4. 自动生成完整知识图谱；
5. 对所有长尾文件进行人工卡片审核；
6. 复杂的综合评分模型。

## 最终评价

这套方案已经具备很好的骨架。它当前最需要的，不是继续增加“B0-7、B0-8”，而是把现有系统从一条静态加工流水线，变成一套：

> **有单一事实来源、能识别材料失效、能记录作者决定、能接受B1反馈、并且可以用任务测试验证的材料操作系统。**

其中最关键的两项调整是：

> **不要用写作问题定义稳定材料包；不要让六类索引分别维护。**

解决这两点以后，B0既能保持全面性，又不至于过早锁死新书方向，也更不容易在后续维护中失控。

你的补充会明显改变设计判断：**这套方案的方向没有问题，但对“一次性的新书材料整理”来说，已经偏重了。**

它现在更像一套需要长期维护、反复调用、多人协作的知识基础设施，而不是一次性的写书前置工作。继续按当前方案推进，最大的风险不是技术上做不出来，而是：

> B0为了“以后可能有用”加工了大量信息，真正有价值的材料判断反而迟迟不能交给B1。

我建议不再把B0称为“材料操作系统”，而改成：

> **一次性材料清点与价值提炼工作流**

核心原则可以压缩成一句话：

> **材料存在性要全面，材料理解要选择性，具体主张核验要精确。**

也就是：

- 文件层面：全量扫描，避免遗漏；
- 语义层面：只深入核心材料包；
- 证据层面：只核验最终进入B1判断的关系和主张。

# 一、当前方案中最容易过度工程化的部分

## 1. 不需要建立完整的文件治理系统

这些字段没有必要对全库维护：

- 每个文件的SHA；
- 每个文件的所有者；
- 每个文件的默认读取级别；
- 每个文件的敏感等级；
- 每个文件属于原件、转换稿、精校稿、过程文件还是附件；
- 所有重复版本之间的完整关系。

对于一次性工作，建议只保留：

| 必要字段用途  |           |
| ------- | --------- |
| 路径      | 能找到原件     |
| 文件类型    | 判断能否读取    |
| 大小、修改时间 | 粗略识别版本和异常 |
| 所属材料包   | 聚类        |
| 处理状态    | 核心、备选、排除  |
| 推荐底本    | 仅核心材料填写   |

SHA只在**确实存在大量同名、重复或版本混乱文件**时，对疑似重复文件计算，不必全库计算。

---

## 2. 不需要六套独立交叉索引

AI主题、物理问题、可视化媒介、读者价值、证据和风险，逻辑上有价值，但不应该分别建设成六套索引。

它们会造成同一判断被重复写入：

- 材料卡写一次；
- AI索引写一次；
- 物理索引再写一次；
- 可视化索引再写一次；
- 关系图再生成一次；
- B1交接包又写一次。

更简单的做法是只保留一张关系表：

| 材料包AI方法物理问题可视化方式读者价值证据状态处理决定 |
| ---------------------------- |

这张表基本可以代替原来的六类交叉索引。

需要查看某一主题时，直接筛选列即可。

---

## 3. 不需要单独建设Agent任务路由层

当前的B0-4实际上接近一个长期运行的检索系统：
```
任务分类
→ 主题判断
→ 材料检索
→ 上下文组装
→ 原件调用
```

对于一次性任务，不需要把它做成一个独立组件。

只需要给Agent一条稳定规则：

> 先读取范围说明和材料关系表；根据任务选择1—3个材料包；只有当卡片不足以支持判断时，才读取卡片指向的原件。

这是一段工作规范，不需要成为一套“路由系统”。

B1开始后发现缺口，也可以临时回到原材料做一次定向补查，不需要B0提前预测B1的全部需求。

---

## 4. L0—L3不宜成为硬性制度

分层阅读的思路是对的，但建议从“严格层级”改成“默认阅读顺序”。

原来的：

> Agent不得从L0直接跳到整本教材、完整项目或完整CSV。

过于绝对。

有些材料可能没有高质量卡片，或者只有阅读完整上下文才能判断价值。更合适的表述是：

> Agent默认按照“全局说明—材料卡—原件”的顺序阅读；只有在版本冲突、上下文缺失或需要核验具体主张时，才扩大原件阅读范围。

“1—3张卡、1—5份原件”也应当是常规目标，而不是不能突破的限制。

---

## 5. HTML不要做成产品

HTML仍然可以保留，因为它有利于作者审阅，但不应建设成：

- 文件浏览器；
- 全文搜索系统；
- 动态关系图平台；
- 多层筛选后台；
- 可持续更新的Dashboard；
- 带数据库的前后端应用。

只做一个一次性静态页面即可，展示：

1. 材料包总体情况；
2. 核心、备选、排除的数量；
3. 核心材料卡；
4. AI×物理×可视化×读者价值关系表；
5. 5—10个候选价值关系；
6. 缺口、风险和待作者判断事项。

HTML的数据直接来自Markdown或CSV，**HTML本身不作为另一套需要维护的数据源**。

# 二、建议采用的最小B0工作流
```

    ↓
1. 全量机械扫描
    ↓

    ↓

    ↓
4. 作者单页审阅
    ↓
5. B1轻量交接
```

实际上只有三类实质工作：

- 看见全部材料；
- 判断哪些材料值得用；
- 提炼这些材料能生长出什么价值关系。

# 三、每一步具体做什么

## 第一步：全量机械扫描

目的只是回答：

> 工作区里有什么？

扫描全部候选根目录，生成一张简单清单：
```
路径
文件名
文件类型
大小
修改时间
初步材料包
```

这一阶段：

- 不写摘要；
- 不判断写作价值；
- 不读取大量正文；
- 不生成复杂元数据；
- 不为所有文件寻找版权状态；
- 不处理所有版本冲突。

只需要确保重要目录没有漏掉。

---

## 第二步：材料包聚类和三级筛选

按照项目、主题或成果，把文件聚成材料包。

例如：
```
M01 学生AI协作评价项目
M02 物理可视化网站项目
M03 传感器与真实实验项目
M04 旧版专著材料
M05 高中物理习题实验化论文
M06 外部参考教材
```

每个材料包只做三级判断：

### A类：核心材料

很可能直接影响本书方向、案例、方法或核心主张。

需要进一步阅读和制作卡片。

### B类：备用材料

可能在具体章节、案例或核验时有用。

只记录一句话说明和原始路径，暂不深入处理。

### C类：排除材料

明确不进入本书，例如：

- 初高中衔接课程；
- 与主线无关的纯智能硬件教程；
- 版权或隐私风险过高；
- 重复旧版本；
- 无法说明来源的材料。

C类保留排除理由即可。

这一步完成后，B0就已经避免了最严重的“全库深加工”。

---

## 第三步：只为A类制作核心材料卡

每个核心材料包只制作一张卡，而且应尽量控制在一屏内。

建议模板压缩为：
```markdown
## M03 传感器与真实实验项目

- 状态：核心材料
- 原件位置：
- 一句话价值：

### 可以支持
- 本材料能够支持哪些方法、案例或判断。

### 关键证据
- 最有价值的数据、图片、项目、代码或实践记录。
- 对应原件路径或页码。

### 不能支持
- 有哪些证据边界。
- 哪些效果不能直接声称。

### 与本书的关系
- AI方法：
- 物理问题：
- 可视化方式：
- 读者价值：

### 对B1的启发
- 可能生长出的价值关系或研究问题。
```

原方案中的这些字段可以取消或按需填写：

- 统一要求300—500字摘要；
- 预计上下文成本；
- 完整推荐读取顺序；
- 每种可转化读者工具；
- 所有相关材料关系；
- 所有待作者确认事项。

除非某项确实影响B1判断，否则不必填写。

例如：

```markdown
## R02 教师与AI协作的核心不是生成，而是持续验收

- AI方法：Agent、Skills、工作流

- 支撑材料：M01、M02、M03

- 证据缺口：需要统一提炼验收维度
- B1需要判断：是否能够成为全书的中心命题
```

这些关系才是B1真正需要的东西。

# 七、最小版验收标准

原来的验收标准可以压缩为七条：

1. 所有候选根目录已经扫描，没有明显漏项；

# 九、最关键的调整

原方案隐含的逻辑是：

## 三、写好这本书的建议

- **R1｜先冻序言，再冻目录。** 把形态原型里那页序言提到你面前裁决，标准就一条：一个普通物理教师读完，能否说出"这本书能让我独立完成什么"。序言不过，后面全部暂停。
- **R2｜锚点案例限额 4—6 个，其余一律降为变式框。** 静电场、网站、活版电路都是合格的锚点候选，但席位要靠证据完整度竞争，不靠材料多少排队。
- **R3｜文体三层分离，强制执行。** 正文只写对象、行动、判断；证据边界进章末来源说明；档案冲突留在 01\_SOURCE 事实档案。检验方法可以机械化：统计每章"待确认/现有证据/不能据此"出现次数，超标的章节退回重写文体，而不是补内容。
- **R4｜AI 分工降级。** 停止让 AI 交完成稿。正确流水线：你口述或补料 → AI 整理成事实档案 → AI 搭章节骨架＋待填清单 → 你写关键的第一人称段落 → AI 做核查。章 01 证明：有你完整记忆的案例，AI 能写到 80 分；没有你记忆的，永远 60 分封顶。
- **R5｜把"补做实验"接受为写作的一部分。** 静电场章缺的那轮实测（带坐标、重复读数、水条件），补做了不仅补书，还顺便产出新照片、新数据和第一批真实课堂证据。这本书的排期应该容纳一个真实的学期，而不是指望档案里挖出不存在的数据。
- **R6｜尽快上真人试读（决策地图 #5）。** 章 01 现在就可以给 2—3 位目标教师读，只问三个问题：知道这章解决什么吗？能复做吗？知道哪里必须自己判断吗？三章一起试只会稀释反馈。

## 四、资源挖掘与应用的建议
