# S1 失败与修正记录

## 记录格式

| 字段 | 内容 |
| --- | --- |
| 失败 ID | `S1-FAIL-YYYYMMDD-序号` |
| 对象与版本 | 文件、模型、页面或任务 |
| 触发条件 | 输入、操作和环境 |
| 实际现象 | 可观察事实，不先解释原因 |
| 影响 | 物理、教学、视觉、工程或证据 |
| 初步假设 | 可有多项，标明未证实 |
| 定位证据 | 测试、复算、截图、代码位置或教师观察 |
| 修正 | 实际采取的动作 |
| 复验 | 方法、版本和结果 |
| 可复用认识 | 是否转为测试、检查表、课堂提醒或书中方法 |

## S1-FAIL-20260831-01｜本地ES模块可能阻断“双击即用”

| 字段 | 内容 |
| --- | --- |
| 对象与版本 | v0.3预审原型的本地打开路径 |
| 触发条件 | `index.html`以`type="module"`加载`src/app.js`，后者再导入模型；部分浏览器对`file://`本地模块导入有限制 |
| 实际现象 | 代码结构检查和模型测试可以通过，但“双击本地页面即可交互”仍存在浏览器兼容风险 |
| 影响 | 教师可能打开页面却得不到交互；自动测试通过会掩盖真实交付路径未成立 |
| 初步假设 | 问题来自本地模块安全策略，而非碰撞模型或页面控件本身 |
| 定位证据 | HTML原先依赖两级ES模块加载；运行说明同时承诺无需服务器，二者存在交付矛盾 |
| 修正 | 增加无依赖构建脚本，从`src/model.js`和`src/app.js`机械生成经典脚本`dist/app.bundle.js`；HTML只加载生成文件 |
| 复验 | `npm test`每次先重建浏览器包，再执行T1—T7、随机复算和生成文件语法检查；人工双击操作仍列为G4待办 |
| 可复用认识 | “离线”与“双击即用”需要验证最终加载方式；生成包应来自唯一模型源码，不能复制维护第二套公式 |

## S1-FAIL-20260831-02｜冻结证据副本因扁平编号破坏相对路径

| 字段 | 内容 |
| --- | --- |
| 对象与版本 | `S1-PREAUDIT-20260831/artifacts/` |
| 触发条件 | 打包时把`index.html`、`styles.css`、`dist/app.bundle.js`和`RUN.md`改成带序号的扁平文件名 |
| 实际现象 | 证据清单13/13哈希成立，但冻结的HTML仍请求`./styles.css`与`./dist/app.bundle.js`，RUN仍链接`./index.html`，三个相对目标不存在 |
| 影响 | 包能证明文件内容未漂移，却不能按冻结页面的真实加载路径复核；“哈希完整”掩盖了“交付关系损坏” |
| 初步假设 | manifest生成只检查单文件哈希，没有把文件间相对链接当作证据包约束 |
| 定位证据 | 独立完成性审计同时解析`href/src`和Markdown链接，发现3个缺失目标；主原型入口不受影响 |
| 修正 | 不改四个文件内容，把包内路径恢复为`index.html`、`styles.css`、`dist/app.bundle.js`和`RUN.md`，同步更新manifest的`bundle_path` |
| 复验 | 13/13包内副本与源文件的字节数、SHA-256一致；3/3包内本地相对链接存在；S1主原型仍9/9通过 |
| 可复用认识 | 证据包验收要同时检查内容完整性和关系完整性；网页副本应保留原相对目录，不能只做扁平重命名 |
