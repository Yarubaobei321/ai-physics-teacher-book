# S1 项目 Agent 指南

## PROJECT_SUMMARY

- **项目名称**：S1 一维碰撞动量审计台。
- **项目目标**：围绕高中物理一维碰撞，开发一个能同时显示系统边界、正方向、个体动量、总动量和总动能变化的最小教学网页，并完整记录从教学问题、物理建模、开发、审核到入书提炼的过程。
- **当前状态**：2026-08-31 已形成v0.3预审原型，G3自动测试9/9通过并生成13项阶段证据包；G4浏览器人工操作、弹性碰撞通式的物理教师独立复核、G5教学终审与G6作者裁决仍待完成。
- **第一读者**：一线高中物理教师；次级读者为物理教研员，扩展读者包括 AI 教育应用从业者。
- **权威入口**：`README.md` → `00_TASK/项目任务书.md` → `00_TASK/事实源.yaml` → `00_TASK/人机共同审核方案.md` → `03_RECORDS/README.md`。
- **验证入口**：`04_EVIDENCE/` 保存可复核证据包；`review/` 保存面向作者的阶段审阅材料。
- **入书入口**：`05_BOOK/` 只接收已经提炼、标明证据边界并经作者裁决的成果，不直接把开发日志当成正文。

## 工作原则

1. 解析物理模型是唯一状态源；动画、箭头、表格、条形图和结论必须由同一状态生成。
2. 模型输出不得标成真实测量或课堂数据；软件测试通过不等于课堂效果成立。
3. 先记录原始反馈，再分别写澄清、决定、修改和复验；未采纳意见也保留理由。
4. 失败、回退和范围缩小只要能说明物理、教学或工程判断，就作为有价值材料保留。
5. 原始学生信息、未授权图片、访问令牌和外部受版权保护内容不得进入公开证据包。
6. 数智育才网站现有动量页面只作只读参照，未经明确任务不得覆盖或部署。
7. 书稿项目中的 S1 立项材料继续保留；本目录从初始化后承担 S1 的实际研发与过程记录，成熟成果经 `05_BOOK/` 选择性回流。

## 阶段门

`G0任务确认 → G1真值建档 → G2原型实现 → G3自动测试 → G4人工运行 → G5物理与教学终审 → G6作者裁决`

- 未完成 G1，不开始把模型结论写进页面。
- 未完成 G4，不称为“可用网页”。
- 未完成 G5，不称为“可入书案例”。
- 没有真实课堂证据，不描述学习效果。

## 文件职责

- `00_TASK/`：任务边界、事实源和审核门。
- `01_RESEARCH/`：教材问题、来源、推导和研究增量。
- `02_PROTOTYPE/`：v0.3静态网页、唯一模型源、离线构建、测试和运行说明；自动测试已通过，人工运行待完成。
- `03_RECORDS/`：日志、反馈、决定、失败与价值生长记录。
- `04_EVIDENCE/`：最小充分的阶段证据包。
- `05_BOOK/`：供图书主线审读的候选提炼与交接。
- `review/`：面向非程序人员的阶段审阅页。

## 修改与验证

- 每次实质修改先更新 `03_RECORDS/项目日志.md`，并为重要决定分配稳定 ID。
- 公式或边界变化同步更新 `00_TASK/事实源.yaml` 和相关测试。
- 实现后必须运行 T1—T7；测试结果需包含输入、期望、实际和残差。
- 每个阶段证据包使用稳定 `evidence_id`，并标明 `verified`、`partially_verified`、`pending` 或 `not_tested`。
- 不自动提交 Git、不部署、不修改书稿正文。
