# 需求与边界

## 要做的事

选择“机械能守恒的条件判断与解题路径选择”微单元，建立一个足够小、可离线复现、可由教师逐条审查的路径推荐演示。系统从合成学习证据出发，展示可能需要复核的节点，给出2—3个候选下一任务；教师改写理由、采用或否决后，才能记录任务。任务完成结果形成新证据，路径随之更新。

## 不做的事

- 不采集、导入或模拟可回溯到个人的真实学生数据；
- 不从一道错题推断学生真实认知原因；
- 不声称“准确诊断、精准推送、最优路径、因材施教已经实现”；
- 不自动布置任务，不替代教师决策；
- 不连接题库、教材平台、成绩系统或大模型API；
- 不复制教材题目、图片、段落或培训专家的具体页面与算法；
- 不修改新书B1入口、书的宪法、S1文件或主项目台账；
- 不写样章、章节正文或教学效果结论。

## 完成标准

| 标准 | 可验证证据 |
| --- | --- |
| 单一微单元 | 页面和台账只覆盖机械能守恒的条件与解题路径 |
| 8—12项合法微资源 | `app/data.js`与资源台账含10项，均标为本项目自编 |
| 3—5个检查任务 | `app/data.js`与任务台账含4项，均为本项目自编 |
| 合成画像闭环 | 3个画像可完成证据→候选→教师裁决→更新 |
| 推荐理由可见 | 每项候选显示证据、可能卡点、不确定性和行动理由 |
| 教师可改写或否决 | 页面提供理由编辑、采用、否决，且记录决定 |
| 无自动诊断/替代决策 | 文案与验证器检查禁用主张；没有自动推送流程 |
| 最低充分技术有依据 | 三路线比较与ADR可读，规则测试可复现 |
| 可运行 | 直接打开`app/index.html`即可操作 |
| 可回流交接 | `HANDOFF.md`列出可回流、不可回流和作者裁决点 |

## 风险与回滚

主要风险是把有限证据包装成“诊断”，或让漂亮界面掩盖推荐规则的主观性。控制办法是固定弱化措辞、显式展示证据与不确定性、设置教师审核门、使用合成画像并提供规则测试。

所有新增文件位于独立工作树的S4目录。删除该目录即可回滚；主项目原件保持不变。

## 界面构想

- **视觉命题**：像一张教师备课审阅台——暖白纸面、深蓝证据线和少量橙色审核标记，重点是可追溯，不是“AI仪表盘”。
- **内容计划**：上方固定边界提醒；左列为合成画像与原始证据；中列为知识路径和候选任务；右列为教师理由编辑、采用/否决与更新记录；底部可查看全部自编资源。
- **交互命题**：切换画像时路径状态顺次显现；教师编辑/否决即时写入审计记录；新证据进入后节点平滑更新并突出“为什么变了”。
