# 三路线比较与技术决策

## 比较结论

本项目选择“显式知识关系表＋确定性规则引擎”。知识结构用少量可读节点和前置关系表达，但不部署图数据库；大模型不参与证据解释、卡点判断或任务排序。

| 判断项 | 规则引擎 | 知识图谱系统 | 大模型直接推荐 |
| --- | --- | --- | --- |
| 当前规模（10资源、4任务） | 充分 | 明显过重 | 能运行但证据链不稳定 |
| 推荐可解释性 | 规则、阈值、证据可逐项显示 | 关系可见，但路径权重仍需解释 | 需要额外约束，输出可能变化 |
| 教师改写/否决 | 容易，决定可记录 | 容易，但运维成本高 | 可做界面，决策来源仍较黑箱 |
| 离线与隐私 | 完全离线 | 可离线，但需数据库/工具 | 通常依赖模型或本地推理环境 |
| 测试与复现 | 同一输入得到同一结果 | 可复现，测试面更大 | 概率输出难作硬验收 |
| 知识关系表达 | 小规模关系表足够 | 适合更大、多关系网络 | 可辅助草拟，不能替代教师核对 |
| 不确定性处理 | 可把未知与失败分开 | 可以，但需另设推理规则 | 容易用流畅语言掩盖未知 |
| 内容维护 | 教师可直接编辑数据表 | 需要图谱维护能力 | 提示词、模型与版本都会漂移 |
| 当前主要风险 | 人工规则可能漏项或带偏见 | 过度工程化、假精确权重 | 越权诊断、幻觉、不可复现 |

## ADR-001：采用最低充分技术

**决定**：v0.1采用经典前端脚本、可读数据对象和确定性排序规则，不引入框架、数据库、模型、登录、服务器或构建步骤。

**理由**：

1. 10项资源与4项任务不足以证明图数据库带来额外价值；
2. 本轮核心是审查推荐理由与教师决策，不是追求自动化程度；
3. 规则引擎能把“未知证据”“低证据”“矛盾证据”分开，避免把缺数据写成薄弱；
4. 每个候选都可回溯到节点、证据事件、资源和检查任务；
5. 同一输入可重复测试，便于留下失败反例和版本差异。

## “图谱”保留到什么程度

知识结构仍有必要，但这里只使用一张小型有向关系表：

```text
研究对象/系统
├─→ 能量项归属与表达
└─→ 外力做功与守恒条件
      └─→ 初末状态表征
            └─→ 守恒列式/替代规律
                  └─→ 结果与边界复核
```

它叫“知识结构”更准确。只有当节点、资源和多版本教材关系增长到人工表难以维护，且教师确实需要跨单元查询、可视化和关系审计时，再评估图数据库。

## 大模型的后续边界

未来可以让大模型帮助教师草拟一段更自然的推荐说明，但必须：输入只含已审定规则结果；输出不得增加诊断主张；教师逐字确认；核心排序仍由可测试规则完成。v0.1不实现该功能。

## 升级门

满足以下任一条件，才讨论技术升级：

- 超过3个单元、100个节点，关系表已出现真实维护冲突；
- 同一任务需要多种路径权重，教师无法仅凭规则表解释差异；
- 已取得合法、脱敏、连续的学习证据，并有研究设计验证权重；
- 真实教师试用表明规则说明不足以支撑审查，而不是仅觉得页面“不够智能”。
