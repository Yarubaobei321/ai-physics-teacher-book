# 教师审核门与试用脚本

## 审核门

系统每次只提交候选，教师至少检查五类问题：

| 门 | 教师要看什么 | 不通过时怎样做 |
| --- | --- | --- |
| 物理门 | 系统边界、能量归属、守恒条件和替代规律是否准确 | 改写节点/资源/任务；停止采用 |
| 证据门 | 理由是否只引用现有事件；未知是否被写成薄弱 | 改成“证据待补”；安排检查 |
| 路径门 | 是否优先复核更靠前的节点；是否无限重复同类任务 | 换序、选其他候选或暂停自动排序 |
| 权利与数据门 | 是否全部自编/授权；是否含真实学生或外部账号 | 移除材料；不得继续运行真实数据 |
| 使用门 | 任务时长、语言和操作是否适合实际课堂 | 修改或否决；页面可运行不等于可用 |

## 推荐理由审核句式

保留：

- “本次回答尚未显示……”
- “一种可能需要复核的节点是……”
- “也可能受任务表述、情境或偶然因素影响……”
- “建议先完成……再由教师结合其他表现判断。”

退回：

- “系统已确定学生的问题是……”
- “该生已经掌握/完全不会……”
- “这是最适合该生的路径……”
- “无需教师检查即可自动推送……”

## 8分钟人工试用

1. 打开`app/index.html`，确认顶部边界和“无真实数据”声明；
2. 选择合成画像A，核对K3是否显示“本次待加强”；
3. 查看首项候选，确认能看到证据、可能卡点、不确定性和规则轨迹；
4. 改写推荐理由，点击“否决”，确认其他候选出现且裁决记录保留；
5. 采用另一项，确认页面明确“尚未自动发送”；
6. 点击“本次形成支持”，确认K3状态和下一候选更新；
7. 切换合成画像C，确认无证据节点显示“证据待补”而不是能力结论；
8. 展开底部资源与检查，抽查来源说明和任务边界。

## 物理教师待审问题

- K1—K6的前置关系是否遗漏了“功与能量变化”的独立节点；
- K2与K3并列是否符合本校学生的学习顺序；
- 阈值0.6是否应取消，改为完全基于离散规则；
- C01—C04能否在不复制教材题目的情况下，真实观察到目标节点；
- R03“支持力可能不做功”的表述是否需要更严格限定接触点和位移；
- K5替代规律是否只列动能定理，还是应加入功能关系但仍保持微单元足够小；
- 页面中的“本次形成支持”是否容易被误读为稳定掌握。

这些问题由物理教师裁决后，才适合形成v0.2。
