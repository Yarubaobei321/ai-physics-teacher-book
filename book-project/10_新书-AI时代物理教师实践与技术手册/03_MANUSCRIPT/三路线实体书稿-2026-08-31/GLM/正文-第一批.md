# 第一篇　先看清要造什么

## 第1章　想做的东西很多，先选哪一个

### 四个问题，四种可能造出来的东西

把“AI能帮我做什么”写在纸上，答案很快会排成长队：做动画、写教案、改题、分析数据、制作网页、连接传感器、整理资源、评价作品。这样的清单会让人兴奋，也很容易把教师带进一个越来越大的工程。真正动手前，先把工具名称遮住，只留下课堂里的对象和困难，选择往往会清楚很多。

四位物理教师已经留下了四类这样的对象。

王硕面对的是法拉第电磁感应实验。磁铁相对线圈运动，检流计指针发生偏转，学生能够看见电磁感应现象。接下来若要讨论感应电动势与线圈匝数、磁通量变化及变化快慢的关系，困难会突然增加：指针变化太快，手持磁铁的运动不稳定，速度难以控制，交变波形又必须转成可以比较的数值。这里需要造出的，首先是一条定量实验链。装置、变量、传感信号、数据处理和物理论证要接在一起。

丁龙的《超重与失重》教学设计从体重秤切入：在不改装体重秤、也不额外施力的条件下，怎样让示数短暂变大或变小？这个问题会把“体重”这个日常词拆开。秤面给出的读数对应人对秤的压力或秤对人的支持力；人的重力并未随下蹲、起立或电梯启停而改变。课堂需要让现象、预测、受力分析、加速度方向和示数变化连成一条解释链。这里要造出的可以是一组任务，也可以是一套把运动过程与示数变化同步呈现的资源。原教学设计可以支持任务结构，具体实施和学习效果仍需另有课堂证据。

严力耕提供的超失重仪把同一个概念推向真实装置。现有材料能够确认竖直框架和滑台实物，也记录了应变梁压力传感器、HX711、ESP32和标准砝码校准的设计。与此同时，当前可逐行复核的代码主要覆盖网页命令、ESP32接收和串口转发，完整的压力采集、时间同步、实时曲线、滤波和原始数据还没有在同一条证据链上汇合。这里最值得造的是一套能够逐级验收的测量系统。每接上一层，教师都要说清它实际证明到了哪里。

黄灿斌面对的是另一种堆积：课件、实验页面、传感数据、项目任务和评价资源分散在不同位置。单个页面可以解决一时之需，页面增加以后，寻找、更新、核查和发布变成新的负担。数智育才网站留下了页面、源码、测试和版本记录，能够支持从单页到统一入口的开发事实。网站存在本身还不能说明课堂采用、长期效果或每个页面的物理正确性。这里要造出的东西看起来最大，起点仍然可以很小：先让一个页面接住一项真实任务，再看它是否出现了升格的理由。

这四个问题分别指向定量实验、概念任务、测量教具和数字资源系统。它们共同提醒我们：选题时先写“课堂中缺少什么动作或证据”，再写“AI可以承担哪一步”。AI参与代码生成、资料整理、候选方案比较和故障定位时，教师仍要给出物理对象、模型条件、课堂动作和验收标准。

### 先写三个问题，不急着立项

教师手里通常不止一个搁置的问题。第一步可以只写三项，每项控制在五行以内。

| 项目 | 填写内容 |
| --- | --- |
| 具体对象 | 一套装置、一份数据、一个现象、一道题或一项课堂动作 |
| 当前困难 | 哪个环节看不见、测不到、难比较、难解释、难分享或难维护 |
| 希望新增的动作 | 学生或教师完成后能观察、输入、操控、比较、解释或复核什么 |
| 现有材料 | 实物、照片、数据、公式、任务单、源码、论文或已有页面 |
| 当前不做 | 暂时排除的功能、使用者、接口和效果主张 |

“学生不理解机械能守恒”仍然太宽。把它改成“气垫导轨实验中，学生需要把两只光电门测得的速度与同一区间内的重锤下降高度对应起来”，对象、数据和可验收动作便出现了。类似地，“做一个超重失重网页”可以缩成“在一段给定的竖直运动中，让学生先判断加速度方向，再预测支持力与秤的示数变化”。

问题写小以后，低技术方案也应当进入比较。若一张纸质对照表已经能帮助学生完成预测与受力分析，网页的首要价值就需要重新说明。若教师只想在课堂上展示一条理想曲线，一段提前录制的视频可能比实时系统稳定。若数据量很少，手算和电子表格足以完成第一轮核查。低技术方案给复杂开发提供了一条成本基线。

### AI进入判断卡

对三个问题逐项填写下面这张卡。每一栏都要落到当前对象，避免使用“提高效率”“激发兴趣”这类无法直接验收的词。

| 判断项 | 要回答的问题 |
| --- | --- |
| 课堂需要 | 谁在什么场景中遇到了什么具体困难？ |
| 原有卡点 | 人工、现有器材或已有软件在哪一步受阻？ |
| AI新增能力 | AI能够加快生成、分析、修改、编排或排错中的哪一步？ |
| 教师责任 | 哪些物理、教学、证据和发布判断必须由教师作出？ |
| 低技术替代 | 一张表、一次演示、一个现成工具能否已经解决主要问题？ |
| 最小证据 | 首版完成后，用什么数据、样例、实物或学生动作验收？ |
| 错误代价 | 算错、认错对象、改写原始数据或公开越界会造成什么后果？ |
| 维护责任 | 谁保存原件、更新版本、处理反馈，并在什么情况下停用？ |

其中最容易被忽略的是“最小证据”。想做一个实验页面，至少要先准备一组手算样例和一组反预期输入；想做一件测量教具，至少要有原始信号、校准记录和独立参照；想做一个课堂任务，至少要写出学生从打开资源到完成解释的完整路径。没有这些，AI只能生成一个候选外观，教师还无法判断它是否完成了任务。

错误代价会改变首项目的大小。一个只在本地使用的演示页面，发现错误后可以立即撤回；一个连接真实设备、保存学生数据或公开发布的系统，需要增加权限、隐私、回滚和维护检查。首项目宜选择风险边界清楚、能够在短周期内亲自验收的对象。

### 用六项比较选出首项目

把三个问题放在同一张表中，每项按“低、中、高”作相对判断。分数只帮助比较，最后仍由教师决定。

| 比较维度 | 问题A | 问题B | 问题C |
| --- | --- | --- | --- |
| 教学价值：完成后新增的学生或教师动作是否清楚 |  |  |  |
| 材料准备：是否已有可靠原件、数据和物理关系 |  |  |  |
| 首版规模：能否缩成一条完整路径 |  |  |  |
| 验收条件：能否准备外部样例、实物或任务走查 |  |  |  |
| 错误代价：错误是否容易发现、撤回和解释 |  |  |  |
| 维护负担：当前是否有人负责版本和停止 |  |  |  |

适合做首项目的题目通常具备三个特征：对象单一，使用动作明确，正确与否能够由项目外部的依据检查。页面的视觉效果、功能数量和技术新鲜感可以稍后考虑。

例如，法拉第定量探究包含装置控制、波形采集、代理量和拟合算法，材料价值很高，首版工程也较重。丁龙的超重失重任务可以先从一段运动的受力与示数判断做起，低技术版本容易建立。严力耕的装置已经有机械实物和命令桥，完整压力链仍需补齐多项证据。气垫导轨数据页则已有清楚的输入、公式和反预期样例，适合用来演示“一个最小页面怎样接受验收”。这样的比较不会给四个项目排价值高低，它只决定此刻先做哪一个。

### “当前不做”保护首版

首项目选定后，马上写一张“当前不做”清单。它至少回答四类诱惑。

- 暂不增加哪些功能，例如账户、自动结论、联网检索或多页面导航；
- 暂不接入哪些数据，例如真实学生信息、未核接口或来源不明的图片；
- 暂不服务哪些场景，例如先做教师本地走查，不直接承诺整班使用；
- 暂不声称哪些效果，例如页面能运行不等于已经改善理解。

这张清单让第一轮协作有一个可停止的边界。完成以后再决定是否扩展，教师也能清楚说明每次升格新增了什么价值和责任。

## 第2章　一条曲线怎样才有资格支持规律

### 指针偏转以后，定量探究才刚刚开始

线圈、磁铁和检流计放在桌面上，改变磁通量就会产生感应电动势。教材实验能够帮助学生观察“有无”和方向，教师若进一步提出定量问题，实验立刻进入另一种难度：指针变化快，人的读数跟不上；手持磁铁运动的速度与路径难以重复；传感器记录下来的是一段随时间变化的电压信号，规律研究却需要把它转成可以作图的数值。

王硕等教师围绕法拉第电磁感应定律留下的材料，最有价值的地方正在这些转换处。材料中可以辨认出两条实验版本线，装置控制、采集方式、变量规模和数据算法并不相同。为了保留事实，我们分别看它们。

在较早或另一版本中，材料记录了调速、减速、测速和微电压传感等尝试，分别得到匝数6个点、磁铁数量7个点和转速6个点的数据。三组数据在相应装置和区间内呈近似线性趋势。当前材料对交变波形怎样提取单个“感应电动势”数值还没有给出完整算法，图中单位与表头之间也存在毫伏和伏的冲突。因此，这条版本线可以支持“装置与记录值形成近似线性趋势”，还不能把每个数字拼进另一版装置，或把拟合直接写成精确验证。

2021年发表的掌控板实验创新论文由管佩磊、王硕、房继珍共同署名。该版本采用齿轮驱动、掌控板和电压传感器，记录了匝数3点、磁铁数量3点、齿轮齿数5点的数据，并写明50次测量后取5个最大值的平均值。它给出了更明确的单值提取规则，同时带来新的问题：为何取最大值，时间窗怎样确定，齿轮齿数与实际角速度之间有什么对应关系？这些问题决定了数据能够支持多强的结论。

两条版本线都推动实验从“看见偏转”走向“获得曲线”，也分别保留了尚未闭合的证据接口。写书、备课或让AI整理材料时，版本不能靠文件名相似自动合并。装置结构来自哪一版，数据来自哪一版，算法又来自哪一版，需要在同一行里说清楚。

### 一条直线之前发生了四次转换

把实验链展开，可以看见四次关键转换。

第一，快速指针变化被转换为传感器可以连续记录的电压波形。人的观察障碍减小了，采样率、量程、零点和传感器响应成为新的条件。

第二，手持运动被转换为电机、减速机构或齿轮驱动的可控运动。重复性提高了，设定值与真实运动之间必须建立测量关系。

第三，理论量被转换为装置中的操作量。线圈匝数相对直接；磁铁数量通常只是磁通量变化的代理；转速或齿轮齿数也是磁通量变化率的代理。代理量只有在几何、磁路、位置和驱动关系受到控制时，才能承接相应主张。

第四，一段交变波形被转换为一个拟合数值。选择正峰、负峰绝对值、峰峰值、固定时间窗平均值，或者若干最大值的平均，都会改变纵轴的物理身份。

法拉第电磁感应定律可以写成

\[
\mathcal{E}=-N\frac{\mathrm d\Phi}{\mathrm dt}.
\]

公式里的`N`、`Φ`和时间变化率，需要在装置中找到可追溯的对应物。最实用的做法，是为每个进入图表的量登记身份。

**表2-1　理论量进入装置与图表时的身份**

| 理论量或目标量 | 装置中实际操纵、测量或计算的量 | 数据身份 | 解释条件 |
| --- | --- | --- | --- |
| 线圈匝数`N` | 切换不同匝数线圈 | 较直接的操作量 | 线圈几何、位置、内阻和采集条件尽量一致 |
| 磁通量变化`ΔΦ` | 叠加磁铁数量 | 代理量 | 磁铁差异、间距、磁路和线圈距离会改变对应关系 |
| 磁通量变化率`dΦ/dt` | 转速或驱动齿轮齿数 | 代理量 | 固定几何下仍需核对实际角速度和传感器带宽 |
| 感应电动势随时间变化 | 传感器记录的交变波形 | 原始测量信号 | 需要保留零点、采样率、量程和时间轴 |
| 用于拟合的`E` | 从波形中提取的单值 | 派生量 | 必须公开时间窗、取值算法和异常处理 |

这张表比一张漂亮的拟合图更早决定论证质量。AI可以迅速生成图表，也可以帮忙把字段分类为直接量、代理量和派生量；代理关系是否足以承接当前课堂主张，仍要回到装置和物理模型。

### 高`R²`说明了什么

对较早版本的数据作自由截距线性拟合，匝数、磁铁数量和转速三组数据的`R²`分别约为0.99783、0.99120和0.98389。2021年论文版的三组数据复算结果也较高：匝数3点约为0.98770，磁铁数量3点约为0.99787，齿轮齿数5点约为0.98974。

这些数字说明，在各自装置、算法和取值范围内，记录值与相应操作量呈较强的线性趋势。它们没有自动回答四个问题：纵轴究竟取自波形的哪一部分；代理量与理论量之间的关系是否稳定；截距为何不为零；重复测量、不确定度与异常值怎样处理。

点数少时，`R²`尤其容易给人过强的确信。三点可以落在一条很直的线上，仍不足以说明装置精度、线性范围和因果机制。齿轮齿数是驱动条件，不能直接当作实际角速度；磁铁数量也不能直接当作磁通量变化。谨慎的课堂表述应包含装置、范围和条件，例如：“在本装置与当前取值范围内，记录值随线圈匝数呈近似线性趋势。”

还有一个经常被软件隐藏的选择：趋势线是否强制通过原点。理论关系可能给出理想原点，真实测量中的零点偏移、背景噪声和算法偏置也可能产生非零截距。先分别画出自由截距与过原点结果，再检查截距是否具有物理和测量解释，会比直接勾选“设置截距为0”留下更多证据。

### 一个空白单元格怎样造出漂亮原点

王硕的单摆公开课材料提供了另一种更容易遇到的数据问题。2021年9月9日的一次公开课中，学生分组测量摆长和约30次全振动的总时间，数据汇总进Excel。课堂设计比较`T-l`、`T-l²`、`T-l³`和`T-√l`图像，其中一组记录`l=0.64 m`、`t=54 s`、`n=29.5`，得到`T≈1.8305 s`，与相邻数据明显不一致。

工作簿表头预留10次实验，实际只有前9组录入摆长和总时间，第10组为空。四张图的引用范围却覆盖到第10组，并设置“空白按零显示”。这样，图表把一个从未测量的`(0,0)`加入了数据。

对原工作簿中的数值作独立复算，`T`对`√l`的自由截距线性拟合出现了明显变化：

| 处理方式 | `R²` |
| --- | ---: |
| 9组实测数据全部保留 | 0.84743 |
| 9组实测数据加人工原点`(0,0)` | 0.97767 |
| 去掉第5组候选异常点，保留8组实测 | 0.96989 |
| 去掉候选异常点再加人工原点 | 0.99623 |

图像可以在两次设置之后变得接近“完美”：空白位置变成原点，再删去偏离最大的点。实验质量并没有因此自动提高。图表范围、空白处理和异常点裁决已经参与了论证。

进一步用

\[
g=\frac{4\pi^2l}{T^2}
\]

反算，每组非异常数据得到的`g`约分布在`9.04—10.55 m/s²`，第5组约为`7.54 m/s²`。它确实值得回查，现有表格仍不能单独判定根因。`29.5`可能涉及计数方式，也可能来自计时起止、摆长测量、录入错位、摆幅或支点等条件。删点前应回到秒表记录、组别、实验条件或重测证据。

材料显示，当时的处理已经发现突兀点并注意到`29.5`，随后忽略其影响继续讨论关系；课后反思提出时间允许时再次检验。当前没有足够记录证明学生独立定位了异常原因、重测并完成修订。这里最适合带给读者的，是一套下一次可以直接使用的处置链：

```text
发现异常
→ 暂停模型结论
→ 回查原始记录与实验条件
→ 区分录入、测量、装置、模型条件和合理波动
→ 保留、纠正、重测或排除
→ 比较处置前后的模型
→ 记录裁决理由
```

### 数据来路表

每次让AI分析实验数据或生成图表前，先建立一张数据来路表。它能防止“图已经画好”遮住中间的转换。

| 字段 | 要记录的内容 |
| --- | --- |
| 研究问题 | 想判断什么关系，适用范围是什么 |
| 原始量 | 仪器或人工直接记录了什么，单位和时间位置是什么 |
| 操作量 | 实际改变了什么，它与理论量的关系是什么 |
| 代理量 | 哪个量代替了难以直接测量的理论量，需要哪些条件 |
| 派生量 | 由哪些原始量、公式和算法计算得到 |
| 人工处置 | 空白、平滑、补全、换算、删点和异常标记做了什么 |
| 图表口径 | 引用范围、坐标变量、截距、趋势线和误差呈现 |
| 结论强度 | 数据当前能支持到趋势、关系、参数估计还是精确验证 |

AI很适合承担机械检查：查找空白转零、公式断链、单位缺失、引用范围异常，同时并排给出保留或排除候选异常、加入或不加入原点的结果。它不能根据“哪张图更直”替教师删除数据，也不能在缺少原始记录时猜出异常原因。

### 图表口径检查

交付图表前，再做六项检查。

1. 图中的每个点能否回到一行真实记录？
2. 空白单元格在公式和图表中被怎样处理？
3. 派生量是否仍保留公式链，还是已经变成静态粘贴值？
4. 代理量与理论量之间的条件是否写在图旁？
5. 异常点的处置依据来自原始证据，还是来自图形美观？
6. 拟合方式、截距和结论措辞是否与物理模型相称？

这一章建立的标准会贯穿后面的页面、教具和网站：每一条数字都要回答它从哪里来，经过了什么处理，最终允许教师说到哪里。教师有了这双“数据之眼”，才适合把生成速度交给AI。

## 第3章　页面会动，物理是否跟得上

### 公式通过以后，页面仍可能被退回

打开一张物理交互页面，滑块会运动，弹簧会压缩，速度曲线随着时间变化，动量和机械能误差接近零。这样的页面很容易给人“已经正确”的印象。源码中的主体公式确实可能是对的，页面仍要回答另外几类问题：时间轴是否对应当前系统，动画有没有把物体画出边界，图上所谓的“误差”是否来自独立依据，文字有没有改变模型含义。

数智育才网站保存的弹簧—物块动量交互模型提供了一次具体审查。页面研究光滑水平面上的A、B两物体和轻弹簧。B初始静止，A以速度`v₀`沿正方向运动。模型提供“接触后分离”和“始终连接”两种情形。页面、源码和动画都存在，当前证据只覆盖其中一个模型的源码审计与独立复算；浏览器人工复验、修改后的版本和教师终审尚未完成。

先把页面放在一边，只写物理模型。约化质量、相对运动角频率和质心速度分别为

\[
\mu=\frac{m_A m_B}{m_A+m_B},\qquad
\omega=\sqrt{\frac{k}{\mu}},\qquad
v_{\mathrm{cm}}=\frac{m_Av_0}{m_A+m_B}.
\]

在两物体仍由弹簧相互作用的时间内，解析关系为

\[
v_A=v_{\mathrm{cm}}+\frac{m_B}{m_A+m_B}v_0\cos\omega t,
\]

\[
v_B=v_{\mathrm{cm}}-\frac{m_A}{m_A+m_B}v_0\cos\omega t,
\]

\[
x=\frac{v_0}{\omega}\sin\omega t.
\]

由此可以得到三个关键时刻：最大压缩发生在`π/(2ω)`，此时两物体共速；接触模式在弹簧第一次恢复原长的`π/ω`时分离；始终连接模式的物理周期为`2π/ω`。这些关系形成页面之外的真值来源。

“页面之外”很重要。若动画、曲线和守恒显示都调用同一个状态函数，它们彼此吻合只能说明同源数据在重新组合时没有明显冲突。源函数若有错误，三种表征可能一起错。独立复算要从题意和公式重新得到预期值，再与页面实际输出比较。

### 三个样例怎样把问题逼出来

第一个样例取`m_A=m_B=1 kg`、`v₀=3 m/s`、`k=2 N/m`。独立计算得到`μ=0.5 kg`、`ω=2 rad/s`、`v_cm=1.5 m/s`。最大压缩时刻为`0.7854 s`，分离时刻为`1.5708 s`，始终连接模式周期为`3.1416 s`。最大压缩时两物体总动能为`2.25 J`，弹簧能为`2.25 J`；接触模式分离后，A静止、B以`3 m/s`运动。这个样例检查等质量速度交换、共速、能量分配和周期。

第二个样例把B的质量改为`2 kg`，其余条件不变。此时`ω=√3 rad/s`，质心速度为`1 m/s`，分离后`v_A=-1 m/s`、`v_B=2 m/s`。A反向运动能够检查页面的符号、箭头和坐标方向是否一致。

第三个样例取允许范围中的较极端组合：`m_A=4 kg`、`m_B=0.5 kg`、`v₀=5 m/s`、`k=12 N/m`。解析关系没有发散，分离时刻约为`0.6046 s`，两物体分离后的速度分别约为`3.8889 m/s`和`8.8889 m/s`。它检查的重点转向视觉与交互：对象是否仍在画布内，标签是否遮挡，播放是否还能表达当前物理状态。

这三组样例分别承担普通、反预期和参数边界检查。教师可以再加一个故意失败样例，让页面的警告或测试确实触发一次。若所有输入都显示“通过”，检查机制很可能只是常亮的装饰。

### 两个时间被装进了同一个横轴

源码审计发现，页面为方便比较不同劲度系数，使用允许范围中的最小`k`生成固定横轴。固定比较窗口本身有用途：多条曲线可以共享同一尺度。问题发生在页面同时把这个横轴当成当前系统的播放周期。

在等质量样例中，当前物理周期是`3.1416 s`，连接模式的固定横轴却到`4.4429 s`，相当于当前系统的`1.4142`个周期。播放到横轴末端时，物体尚未回到初态；程序随后取模跳回`t=0`，动画就从一个非初态突然回到初态。

这一故障没有改变主体解析公式。它来自时间身份混用：一个时间表示“当前系统经过多久会回到初态”，另一个时间表示“为了比较不同参数，图想展示多长的窗口”。页面需要把二者拆开，播放循环依据当前物理周期，比较图明确标注固定窗口。

接触模式也要区分分离时刻和横轴末端。弹簧恢复原长后，两物体已按末速度继续匀速运动；延长显示可以帮助观察分离后的状态，标题和时间标记必须让读者知道弹簧作用已经结束。

### 数值在屏幕外仍然“正确”

第三个极端样例暴露了另一种边界。按照源码中的画布宽度和位移映射推算，在固定横轴末端，A、B和质心线都会越过`960 px`的画布右边界，B的位置甚至远超画布。公式仍给出有限且一致的数值，读者却看不到对象。

这说明物理页面至少要分三层验收：

| 层次 | 核查对象 | 典型问题 |
| --- | --- | --- |
| 物理数值 | 公式、单位、系统边界、特殊值和守恒关系 | 结果是否与外部真值一致 |
| 视觉状态 | 对象位置、箭头、曲线、标签和可视范围 | 数值正确时，画面是否仍表达得到 |
| 交互状态 | 播放、暂停、跳转、切换参数和重置 | 操作后是否进入同一个物理状态 |

只查`NaN`或程序报错，抓不到对象离开画布、箭头方向误导和循环末端跳变。极端值的意义也在这里：它会同时把数值、视觉和交互推到边界。

### “守恒误差为零”来自哪里

页面的速度、动量、动能和弹簧能都由同一个解析状态函数生成，守恒区再把这些量组合成“动量误差”和“机械能误差”。这种显示能够发现渲染链内的明显不一致，证据身份应写成“同源一致性检查”。

独立真值来自另一路径：手算、单独脚本、教材解析式或经过核对的外部数据。检查者不调用页面自己的状态函数生成期望值。若两条路径相同，程序只是用自己证明自己。

误差的分母也需要说明。当前动量误差使用`max(1,m_Av₀)`作归一化；当初始动量小于`1 kg·m/s`时，显示值便不是严格相对于初始动量的百分误差。页面可以同时给出带单位的绝对残差，再说明相对量以什么特征值归一化。

### 先锁对象身份，再审公式

数字页面还会在公式之前认错对象。网站曾保存同一双头光电门的两张照片：一张已经装上外壳，只能从开口看见探头；另一张没有外壳，两块电路板和两条光路直接露出。AI按外观差异把它们写成单头和双头两种器材。回到实物与设计材料后，才能确认它们是同一装置的两种装配状态。

双头光电门用两条固定间距的光路和两次触发时间差确定速度，数据身份与单头光电门的“有效遮光宽度除以遮光时间”不同。若器材身份写错，后面的测速公式和操作说明会沿着错误对象继续生长。

第一次把真实装置交给AI时，先做五项身份检查：

1. 名称：它在原始程序、实物说明和作者记录中叫什么；
2. 结构状态：裸板、半成品、装壳或课堂布置；
3. 测量量：装置直接记录的是时间、距离、电压、原始计数还是派生速度；
4. 数据来源：实测、解析计算、模拟、默认示例或人工修正；
5. 图片归属：硬件、程序、外壳和课堂使用分别由谁完成。

这五项核查也能限制AI看图描述的权力。它可以提出候选身份，教师要用实物、源码和可靠说明完成锁定。

### 一页物理模型卡

把页面交给AI实现前，先填写一页模型卡。

| 字段 | 本例写法 |
| --- | --- |
| 研究对象 | A、B和轻弹簧组成的系统 |
| 条件 | 光滑水平面、理想轻弹簧、B初静止、A以`v₀`沿正方向运动 |
| 模式 | 接触后分离／始终连接；两种模式的时间边界不同 |
| 输入 | `m_A`、`m_B`、`v₀`、`k`，均注明单位与允许范围 |
| 核心关系 | `μ`、`ω`、`v_cm`、`v_A(t)`、`v_B(t)`、`x(t)` |
| 关键时刻 | 最大压缩、第一次恢复原长、连接模式物理周期 |
| 数据身份 | 页面数值来自解析计算；当前没有实验采集 |
| 外部真值 | 等质量、不等质量、极端参数三组独立样例 |
| 视觉边界 | 对象、质心线、箭头和标签始终可见 |
| 当前状态 | 主体解析关系已复算；页面修改、浏览器复验和教师终审待完成 |

模型卡让“页面看起来正常”变成一组可以复查的判断。它也保留了未完成状态。当前这张弹簧—物块页面最有价值的用法，是呈现一次已经发现具体问题、尚待修改与人工复验的审计现场。把它写成完整成功案例，会抹掉真正能帮助读者的停笔线。

# 第二篇　把第一个东西做出来

## 第4章　把想法写成AI能做、教师能验的任务

### AI收到的第一份材料应当是任务说明

第1章选出的首项目，到这里还只是一项教师愿望。把“做一个机械能守恒实验页面”直接交给AI，它可以迅速补出背景、按钮、图表和结论，也会替教师补许多没有被说明的决定：系统选谁，数据从哪里来，学生输入什么，页面能否修改原始记录，何时算作完成。

任务说明的作用是提前暴露这些决定。它不必写成厚重的技术文档，一页纸已经能建立协作契约。核心字段包括目标、对象、材料、动作、约束、交付和验收；再加上工作区边界与“当前不做”，首版就有了清楚的责任范围。

下面以已经进入机械能守恒公开课的气垫导轨数据页为例。我们根据现有页面、课堂任务和退回记录，倒推一份适合首版开工的任务说明。它用于演示规格写法，不声称当时开发从这份文档原样开始。

### 从课堂过程倒推页面字段

气垫导轨方案研究滑块、钩码与地球组成的系统。小车从第一只光电门运动到第二只光电门时，钩码同时下降。忽略阻力、细绳质量和滑轮转动，细绳保持绷紧且不可伸长，可比较同一区间内的两项变化：

\[
\Delta E_p=mgh,
\]

\[
\Delta E_k=\frac12(M+m)(v_2^2-v_1^2).
\]

`m`是钩码质量，`M`是含遮光条滑块的质量，`h`是小车经过两门期间钩码下降的高度，`v₁`与`v₂`按两只光电门的位置和测量次序命名。页面负责保留原始输入、完成单位换算和计算，再把结果交还给学生判断机械能是否近似守恒。

**表4-1　字段、对象与课堂动作**

| 页面字段 | 对应的真实记录 | 页面动作 | 学生仍要完成的判断 |
| --- | --- | --- | --- |
| `m` | 钩码质量 | 单位换算，参与势能与动能计算 | 质量是否为本次实测或确认值 |
| `M` | 滑块与遮光条质量 | 单位换算，参与系统动能计算 | 系统为何同时包含滑块和钩码 |
| `h` | 两门区间内钩码下降高度 | 参与`mgh`计算 | 是否与两次测速对应同一区间 |
| `v₁`、`v₂` | 小车先后通过两门的速度 | 按原次序计算 | 异常次序是否来自装置、记录、输入或模型条件 |
| 计算结果 | 势能减少量、动能增加量及差异 | 显示和导出 | 当前偏差允许作出什么结论 |

这张映射表会直接约束页面。若只写“输入两个速度”，AI可能按大小排序；若写“按光电门位置与测量次序保存原值”，反预期数据也必须留下来。

### 一份首版Brief

```markdown
任务名称：气垫导轨机械能数据页｜首版任务Brief

【1. 真实问题】
- 使用者：完成气垫导轨分组实验的高中学生及组织汇报的教师。
- 场景：学生操作装置后手动录入本组数据，页面完成计算与呈现。
- 当前困难：多个质量、区间高度和两次速度容易错位，手算与汇报衔接慢。

【2. 首版交付】
- 一个本地可打开的单页。
- 支持录入`m、M、h、v₁、v₂`，字段显示单位。
- 计算`ΔE_p`与`ΔE_k`，保留原始输入顺序。
- 支持清空并重新开始；若已有稳定导出功能，单独验收。

【3. 学生核心路径】
看任务 → 完成真实测量 → 录入原始数据 → 查看计算 → 检查条件与偏差 → 准备汇报。

【4. 物理约束】
- 系统、过程区间、公式与单位按模型卡执行。
- `v₁/v₂`按位置和次序命名，不按数值大小交换。
- 页面计算值明确标为派生量，不与原始测量混写。
- 允许`v₁>v₂`和负的动能增加量出现，并提示检查，不静默修正。

【5. 当前不做】
- 不接入自动采集、蓝牙或串口；
- 不生成模拟实验数据；
- 不自动宣布“机械能守恒”；
- 不增加账号、云端保存、班级管理和公开发布；
- 不修改原始项目目录中的其他页面。

【6. 验收】
- 运行：普通输入、空值、重置和重复输入可完成；
- 物理：至少三组外部手算样例逐项一致；
- 教学：学生核心路径不被模拟数据或自动结论绕过；
- 发布：首版只在独立工作区本地使用，不作课堂效果主张。
```

任务说明中的“当前不做”与“验收”决定了协作质量。AI提出新功能时，先把建议记录在后续清单，不直接扩进首版。页面出现故障时，检查者也能判断故障属于功能、物理、教学还是发布边界。

### 工作区同时限定材料、修改和风险

教师第一次让AI改真实项目，最稳妥的做法是准备一个独立工作区。原件保持只读，首版只写到指定输出目录，其他项目和个人资料不进入本次任务。

工作区边界卡可以写成四栏：

| 权限 | 本例 |
| --- | --- |
| 可读 | 冻结的任务Brief、物理模型卡、必要装置说明、当前页面副本、三组验收样例 |
| 可写 | 首项目独立目录中的页面、说明和验收记录 |
| 禁止 | 原始课堂材料、其他网站页面、受限学生数据、账号密钥、未授权图片 |
| 需批准 | 联网、安装依赖、访问外部账号、部署、删除、改动原件或扩大数据范围 |

材料范围也要分层。任务必须依据的模型卡和实物说明属于输入材料；优秀网页、外部教程和产品案例只能作为参考；学生信息、商业题库正文和未授权图片不应因为“可能有用”就被加入工作区。

独立工作区还提供回滚入口。AI开始修改前记录基线，首版交付后保存一个可恢复节点。教师退回一项功能时，可以比较具体差异，不必依靠聊天记录回忆前一版是什么样。

### 开工前七问

AI复述一遍需求，只能说明它理解了文字。开工前再核对七个对象：

1. 此轮锁定哪一个真实问题和使用者？
2. 可以读取哪些原件，哪些材料只作参考？
3. 允许修改哪个目录，交付写到哪里？
4. 首版只完成哪一条学生或教师路径？
5. 哪些物理关系、单位、数据身份和边界不得改写？
6. 用哪几组外部样例、实物或课堂动作验收？
7. 遇到材料缺失、权限扩大或结论不确定时，在哪里停下来？

七问的答案应当进入文件，不只留在对话窗口。文件可以交给下一位检查者，也能在更换工具或中断会话后继续使用。

### 把“完成”拆成四种结论

页面生成后，AI常会总结“功能已经完成、测试全部通过”。教师要把这句话拆开。

- 运行结论：指定版本能否在指定环境完成输入、计算、重置和导出路径；
- 物理结论：字段、单位、公式、特殊值和数据身份是否与外部依据一致；
- 教学结论：学生是否仍要完成观察、测量、比较和解释，页面有没有绕过关键动作；
- 发布结论：来源、隐私、授权、版本、回滚和维护责任是否允许当前范围的发布。

四种结论具有独立否决权。首版可以在本地通过运行与物理检查，同时保留“未经过课堂走查”“暂不公开”的状态。这样的停点比一句“完成”更容易接手。

### 生成者和检查者分开

实现页面的AI了解自己的思路，也倾向于用设计意图解释结果。独立检查最好开启一个干净任务，只读取冻结Brief、当前交付、模型卡和验收表，不读取生成者的辩护性总结。检查者先复现现象，再给出通过、退回、暂停或停止。

独立AI检查仍然不能替教师签字。物理模型卡由谁确认，课堂关键动作是否被保留，页面能否对学生公开，责任都要落到具体教师。生成速度可以外包，任务的方向与证据上限需要一直留在人手里。

### 本章交付：把自己的起点卡改成Brief

现在取出第1章的八行起点卡，把它扩成一页任务说明。请至少填满这些字段：

```text
目标使用者与场景：
真实问题：
首版最小产物：
一条核心使用路径：
必须使用的原件：
物理与教学约束：
可读／可写／禁止／需批准：
三类外部验收证据：
当前不做：
暂停与恢复方法：
```

任务说明写完，AI才获得开工条件。它也给教师留下一把尺子：后续每一个按钮、图表和自动行为，都要回到这份契约中说明自己为何存在。

## 第5章　第一个页面只做一件事

### 把任务缩成一条可以走完的路径

首版页面的目标很朴素：使用者输入一组有明确身份的数据，程序依据冻结模型完成计算，结果能够由项目外部的样例核对。教师在这一轮不追求网站结构、智能讲解或自动采集，先把“输入—计算—显示—验收—重来”走通。

仍以气垫导轨能量数据页为例。它包含多个相互关联的字段，同时具备三个适合首项目的条件：系统边界可以写清，输入量能够回到装置，反预期结果可以检验页面是否保留原始记录。

纸书不绑定某个AI产品的按钮。不同工具的界面会变，操作次序相对稳定：冻结任务，准备独立工作区，交付最小页面，实际打开目标文件，逐项检查，给出退回或采用决定，保存版本与证据。

### 第一步：先准备答案，再让AI写页面

把模型和至少三组样例写进任务。页面自己的函数不能生成期望值。

取`g=9.8 m/s²`，质量和长度统一换算为国际单位。

**样例A：普通值**

```text
m = 0.050 kg
M = 0.200 kg
h = 0.200 m
v₁ = 0.500 m/s
v₂ = 1.000 m/s
```

手算得到

\[
\Delta E_p=0.050\times9.8\times0.200=0.0980\ \mathrm J,
\]

\[
\Delta E_k=\frac12(0.200+0.050)(1.000^2-0.500^2)=0.09375\ \mathrm J.
\]

页面显示精度可以按教学需要设置，内部计算应保留足够位数。两项能量的差异需要保留给使用者解释，页面不自动宣布实验成功。

**样例B：零变化边界**

将`h=0`且`v₁=v₂`，两项变化都应为零。这是一组程序边界，不代表一项完整的真实实验过程。它用于检查公式、符号和零值显示。

**样例C：反预期次序**

保留样例A的质量和高度，把`v₁`改为`2.0 m/s`、`v₂`改为`1.0 m/s`。页面必须保留输入次序，动能增加量为

\[
\Delta E_k=\frac12(0.250)(1^2-2^2)=-0.375\ \mathrm J.
\]

负值会提示当前记录与预期过程不一致。它可能来自光电门编号、输入错位、导轨状态、细绳条件或其他实验因素。页面可以发出“请检查”的提示，不能交换数值或替使用者选择原因。

还可以补一组显示边界，检查很大或很小的输入是否挤出卡片、截断单位或产生无法阅读的科学记数法。显示测试不改变模型结论，它保证正确数值能够被看见。

### 第二步：规定页面不能替学生做什么

一个数据页很容易在“友好”名义下增加自动行为。首版需要明确三条禁止项。

第一，原始输入不静默排序、平滑、补全或覆盖。发现异常时保留原值，修正要留下理由。

第二，模拟数据与实测数据不混在同一入口。开发测试可以使用样例，学生实验主路径只接收手动录入的真实记录；若将来接入设备，仍要标出原始信号与派生值。

第三，页面不替学生形成物理结论。它可以显示两项能量变化、差值和必要的单位，结论框应引导学生检查系统、条件和误差来源，避免只给“守恒／不守恒”的自动判词。

页面的教学价值由这些保留动作决定。程序做了什么和学生还要做什么，应当在任务说明中并排出现。

### 第三步：先看首版实际对象

AI报告“已经生成页面”以后，检查者先锁定四件事：哪一个文件、哪一个版本、从哪个入口打开、当前看见的是否为刚生成的内容。旧构建、另一个端口或截图不能代替目标对象。

实际走查至少包含：

1. 从空白页开始输入样例A，记录字段与输出；
2. 清空后输入样例B，检查零值、空值和单位；
3. 清空后逐字符输入样例C，观察`v₁/v₂`是否在输入中途被修改；
4. 修改一个字段，检查所有派生量是否同步更新；
5. 重复计算、清空、重新开始，确认状态没有残留；
6. 若有导出，核对导出内容是否保留原始输入、单位、版本和计算口径。

发现问题时，先写可复现现象。例如：“先输入`v₁=2.0`，再向`v₂`逐字符输入`1.0`时，页面把两字段交换。”这比“速度输入有问题”更容易定位，也避免AI用视觉微调掩盖根本冲突。

### 第四步：按门退回，不让一次修补扩大范围

退回单只允许修改与当前冲突有关的范围。

```text
退回门：物理门／教学门
验收对象：指定文件与版本
实际现象：页面按数值大小交换v₁与v₂
预期现象：保留两只光电门对应的原始次序
根本冲突：排序改写了测量时序身份
允许修改：取消自动排序；保留异常提示
禁止扩展：不新增自动修正、模拟数据和结论生成
必须重验：样例A—C、逐字符输入、清空与重复输入
```

AI最初可能提出“等输入完成后再排序”。这个方案能修复逐字符输入造成的程序故障，却仍会改变原始记录。退回理由写到“时序身份”以后，修改目标才会从延后排序转为删除排序。

### 第五步：保存一个能重新开始的项目包

首版通过指定检查后，至少保存五项：

```text
页面文件
任务Brief
物理模型卡
外部验收样例与实际结果
版本、退回和当前状态说明
```

当前状态说明要分开写：运行检查覆盖了哪些路径，物理检查覆盖了哪些样例，教学只做了设计走查还是已有真实课堂，页面能否公开。若尚未进入课堂，直接写“教学门待真实使用证据”；若只允许本地查看，写明发布范围。

首版项目包的意义在于可重现。下一次更换AI工具、增加功能或交给另一位教师时，接手者能够重新得到同一结果，也能知道哪些结论仍未获得证据。

### 从一个页面进入下一章

到这里，读者已经拥有一份可以生成、退回和复验的最小页面包。它在桌面上成立，还没有自动取得课堂位置。下一章回到机械能守恒公开课，看看三种实验怎样共享数字入口，一个输入故障怎样改变教学规则，以及页面为什么会在真实使用后继续长成在线实验室。

## 第6章　一堂课怎样长出在线实验室

### 三种装置要回答同一个问题

2026年4月的一节《实验：验证机械能守恒定律》公开课，把自由落体纸带、圆柱体摆动DIS和气垫导轨系统三种方案放进了同一间教室。全班分成6个小组，每种方案由2组完成。同方案内，一组承担分析或汇报，另一组依据自己的操作经历提问。

这条课例由多位教师共同打磨。现有材料确认黄灿斌、严力耕参与校内公开课的讲授与打磨，成熟成品由王硕承担区级公开课。以下只合并已能确认的共同课堂结构；不同授课与打磨环节的成果仍按各次原始记录分别署名。

把三种装置放在一起，不等于已经完成比较。教师先要给它们一条共同任务：确定研究对象与守恒条件，写出验证关系，由关系式倒推必测量，取得原始记录，比较能量变化，再解释偏差。装置不同，学生形成证据的路径也不同。

**自由落体纸带法**研究重物与地球组成的系统。由位置1运动到位置2时，可以比较

\[
mg\Delta h\quad\text{与}\quad \frac12m(v_2^2-v_1^2).
\]

纸带点迹是直接记录，瞬时速度由相邻点间的平均速度近似得到。学生要保证高度差和两次速度对应同一状态区间。若直接用`v=√(2gh)`计算速度，会把待验证的机械能关系带回测速过程，形成循环。

**圆柱体摆动DIS法**用光电门和数据采集器取得最低点附近的速度。页面采用的简化关系是

\[
mg\Delta h\approx \frac12mv_D^2.
\]

这里的`Δh`应当对应质心高度变化。圆柱体还可能绕自身轴转动，完整动能中可能包含转动动能。若模型暂时只算质心平动，就要把这项遗漏写进边界，不能只把清晰曲线当作守恒证明。

**气垫导轨系统法**研究滑块、钩码与地球组成的系统，比较钩码势能减少与滑块、钩码总动能增加。质量`M`与`m`处在关系式的不同位置，不能像前两种简化关系那样消去。学生还要检查导轨是否水平，细绳是否绷紧，测速结束前钩码是否触地。

| 比较项 | 自由落体纸带 | 圆柱体摆动DIS | 气垫导轨系统 |
| --- | --- | --- | --- |
| 研究对象 | 重物—地球 | 圆柱体—地球 | 滑块、钩码—地球 |
| 速度证据 | 纸带点迹与时间间隔 | 最低点挡光过程 | 两个位置的光电门测速 |
| 关键模型检查 | 状态对应、纸带摩擦 | 质心高度、可能的转动动能 | 系统边界、细绳与滑轮影响 |
| 页面要接住的量 | 高度、两时刻速度 | 高度、最低点速度 | 两质量、区间高度、两位置速度 |
| 学生必须解释 | 速度怎样由点迹得到 | 动能计算包含哪些运动 | 势能和动能分别属于系统中的谁 |

三种页面若只共享颜色、按钮和图表样式，它们还没有形成在线实验室。真正可复用的是“对象—关系式—原始量—派生量—结论”的学习结构；每个实验的模型差异必须保留下来。

### 页面负责处理，学生负责说明来路

课堂中的共同驱动问题可以写成四问：

1. 研究对象在过程中发生了什么能量转化？
2. 用什么关系比较机械能变化？
3. 由关系式可知，必须测量哪些物理量？
4. 装置怎样取得这些量？

学生先完成装置操作并记录真实数据，再手动录入网页。页面承担单位换算、能量计算和图表呈现，小组代表把结果投到大屏并进行讲解。这个使用事实说明网页进入了分组实验和汇报环节。它没有自动给出学习效果，也没有证明串口、蓝牙或自动采集在该课中稳定运行。

课堂中每个数字都可以继续追问三次：“它由哪件仪器、在哪个位置得到？”“页面又用哪些原始量计算出它？”“这组数在当前模型下能支持怎样的结论？”数字工具提高处理与展示速度，这三次追问把证据链留给学生。

### `v₁/v₂`输入故障怎样改变了一条规则

气垫导轨页面早期把较小速度记作`v₁`，较大速度记作`v₂`。AI将这个口径实现为输入过程中的实时比较与交换。实际试填时，先输入`v₁`，再向`v₂`键入小数，第一个字符通常是`0`，程序会在数字尚未写完时提前排序，刚填好的值因而跳到另一个字段。

AI首先建议把排序推迟到输入完成或失去焦点以后。这个修改能消除输入过程的跳动，却保留了“按数值大小重命名”的规则。回到装置以后，教师重新确定了字段身份：`v₁`与`v₂`对应先后两只光电门及其测量次序，异常记录也应当保留。最终处理是取消自动排序。

冻结版本使用`v₁=2.0 m/s`、`v₂=1.0 m/s`这组反预期输入复验。页面保留了原次序，并按当前公式给出负的动能增加量。负值没有被美化，它为后续检查保留了入口：光电门编号是否弄反，输入是否错位，导轨是否水平，细绳是否松弛，模型条件是否满足。

这次退回经历了四个层次：

```text
初始口径：用大小定义v₁/v₂
→ AI实现：输入中实时比较与交换
→ 程序修补：建议延后排序
→ 教学裁决：按位置与时序定义，删除排序
```

最值得沉淀的经验来自最后一步：原始测量记录应保持可追溯；需要修正时，原值、修正值和理由都应可见。它可以迁移到异常点删除、传感器平滑、AI自动补全和模拟数据混入等问题。

### 删掉一个按钮保护了什么

三个实验页面的初期版本都曾设计“AI模拟”入口，点击后可以迅速出现一组数据和图表。开发测试时，这个功能能帮助检查页面。放在学生实验的主路径上，它会改变任务身份：学生可能绕过装置操作与真实记录，也可能分不清哪组数据来自实验、哪组来自程序。

教师因而隐藏了学生可见的模拟入口，保留手动录入。模拟数据仍可在明确标注的开发测试或演示场景中使用。关键是把使用者和证据身份分开：开发者用样例查程序，学生用实测数据完成实验论证。

每次删除功能，都可以写一行保护对象：

| 删除或限制的功能 | 保护的对象 |
| --- | --- |
| 自动排序 | 原始记录的时序身份与异常检查 |
| 学生页模拟入口 | 真实测量主路径与数据来源区分 |
| 自动“守恒”结论 | 学生对系统、条件和偏差的解释 |
| 未核自动采集 | 课堂稳定性与数据真实性 |

功能数量减少后，页面与课堂任务的关系反而更清楚。

### 六组完成了实验，跨方案比较没有自然发生

六组都经历了装置操作和数据处理。同方案的两组拥有相近的器材经验，一组汇报时，另一组能够围绕释放位置、数据取值、公式使用和误差解释提出问题。这样的互评有具体共同对象，课堂组织也较可控。

跨方案的比较却没有自然发生。自由落体、圆柱摆和气垫导轨各有自己的研究对象、测速方式与模型边界；学生完成本组任务以后，还需要一张明确的比较卡，才能把三条证据路径放到同一问题下。现有材料没有记录完整的跨方案比较与复测，后续设计不能写成已经发生的课堂成效。

下一次若继续实施，可以把比较任务收缩为四项：

| 比较问题 | 读者要看到的差异 |
| --- | --- |
| 研究对象怎样选 | 对象决定哪部分势能和动能进入关系式 |
| 速度怎样得到 | 纸带近似、单处光电门、两处光电门具有不同测量模型 |
| 哪些量可消去 | 质量在三条关系中的作用不同 |
| 偏差先查哪里 | 测量、装置条件、非保守力和模型遗漏的顺序不同 |

这张卡属于下一轮任务。只有在真实使用、记录并复核后，才能说明它带来了什么改变。

### 页面什么时候有理由长成在线实验室

三个页面最终进入统一的机械能守恒在线实验室。促成升格的理由可以归为四项：

1. 共同任务：三个页面服务同一规律的实验论证；
2. 可复用结构：任务说明、数据录入、计算、图表和汇报具有稳定骨架；
3. 真实入口：页面进入了分组实验与投屏汇报；
4. 维护责任：字段、公式、图件、版本和后续退回有人继续处理。

升格也新增了责任。统一导航不能抹平三种模型差异；相同字段名要说明是否具有相同身份；页面更新后要知道哪节课、哪份任务和哪组验收样例受到影响；链接失效时要有替代入口。

## 第7章　概念课、传感器和显示怎样接成一条链

### 体重秤上的数字先要认清身份

一个人站在体重秤上，屏幕显示“60 kg”。人没有突然改变质量，秤也没有直接看见重力。它接收人对秤的压力，经机械结构、传感器、电路、标定和显示算法，给出一个按质量单位换算的数值。人下蹲、起立或随电梯加速时，示数会改变；重力`mg`、秤对人的支持力`N`、人对秤的压力、传感器原始计数和屏幕显示量因此必须分开。

丁龙的《超重与失重》教学设计用一个生活问题发动概念学习：不改装体重秤，也不在身体上额外施力，怎样通过动作短暂改变示数？这份材料能够支持教学任务和资源设计，不能据此补写全班反应或学习效果。它给本章提供的是一条清楚的概念路径。

取竖直向上为正，人受到重力和支持力，满足

\[
N-mg=ma,
\]

即

\[
N=m(g+a).
\]

加速度向上时`a>0`，支持力大于重力，秤示数增大；加速度向下时`a<0`，支持力小于重力；自由落体时`a=-g`，支持力为零。运动方向没有直接决定超重或失重。向上运动可以处于失重状态，向下运动也可以处于超重状态，关键在于加速度方向。

丁龙的设计把概念任务排成连续五步：观察现象，先作预测，画受力图，判断加速度，解释示数。体重秤蹲起、自制电梯、纸带重锤、漏水瓶和手机传感器等对象都服务这条路径。它们的价值取决于能否让学生回到受力和运动关系，器材数量本身不构成证据。

| 任务层 | 学生或教师需要说清什么 |
| --- | --- |
| 现象 | 人或装置正在怎样运动，秤的示数怎样变化 |
| 预测 | 下一阶段示数将变大、变小还是不变 |
| 受力 | 研究对象受到哪些力，`N`作用在谁身上 |
| 加速度 | 方向和大小由什么运动阶段决定 |
| 示数 | 屏幕量与支持力怎样对应，适用条件是什么 |

这五步可以先用体重秤和纸笔完成。网页、传感器和自制装置进入时，要给每一步增加可观察证据，不能替学生跳过预测、受力与解释。

### 三组相邻材料，各自负责一段

从概念任务走向动态测量，本书把三组材料放在相邻位置：丁龙负责课堂概念任务；黄灿斌课程材料中的HX711电子秤与测力仪提供静态称重底座；严力耕的超失重仪提供竖直机械实物与运动控制原型。现有证据没有显示三位教师共同开发或在同一班实施，三条线要分别落名。

HX711静态链可以写成

```text
应变片或称重传感器
→ HX711原始计数
→ 去皮
→ 已知砝码多点校准
→ 必要的平均或滤波
→ 质量、力或记录值显示
```

它能帮助读者理解传感器数字如何获得单位。静态校准通过以后，动态测量仍会受到结构振动、传感器带宽、采样率、滤波延迟和接触状态影响。课程中的`±5 g`属于课堂验收示例，其证据范围不能支持计量性能结论。

严力耕的超失重仪材料能够确认竖直框架、轨道和滑台实物，作品文稿描述了应变梁、HX711、ESP32、标准砝码校准、曲线与滤波目标。当前可复核源码主要到“网页写入命令索引—ESP32转发UART字节”。这段距离完整动态测量还很长，恰好适合用来训练证据分层。

### 五种读数身份

| 层次 | 对象 | 容易混淆的说法 | 要追问的证据 |
| --- | --- | --- | --- |
| 1 | 人或物体受到的重力`mg` | 失重时重力消失 | 引力在该情境中是否发生可观变化 |
| 2 | 秤对物体的支持力`N` | 秤直接测重力 | 加速度方向与大小是什么 |
| 3 | 物体对秤的压力 | 与`N`当成同一个受力 | 两个力分别作用在谁身上 |
| 4 | 应变片／HX711原始计数 | 传感器输出天然就是牛顿 | 零点、比例系数、量程、温漂和安装 |
| 5 | 屏幕显示的kg、N或曲线 | 显示成功等于测量正确 | 换算、滤波、时间窗和数据来源 |

给AI一张传感器截图时，它很容易把第五层直接写成第二层。模型卡与数据表应当保留中间三层，让读者看见物理量怎样穿过硬件和算法。

### 按钮成功离物理实验还有多远

当前控制源码中，网页选择命令，ESP32接收索引，再向UART写入对应字节。`uart.write()`返回了正确字节数，只能说明字节进入发送流程。它没有证明驱动器应答、电机转动、滑台位移或平台按设定加速度运动。

现有代码还保留一处参数冲突：UART实际初始化为`115200`，两处启动日志却显示`9600`，网页显示`115200`。究竟使用哪个波特率，需要回到驱动器协议和真实通信测试。把参数改成同一个常量能够消除代码内冲突，串口回环、逻辑分析仪或驱动器应答才能形成外部证据。

完整的动态链可以分成十层：

```text
按钮点击成功
→ BLE写入成功
→ ESP32收到索引
→ UART字节正确
→ 驱动器应答
→ 平台实际位移
→ 实测加速度a(t)
→ HX711原始计数
→ 校准后的N(t)
→ 共同时钟下比较N(t)与m[g+a(t)]
```

每一层都有自己的验收对象。写“发送成功”时，要标明成功到UART；写“平台运动”时，需要视频、编码器或独立位移证据；写“加速度”时，不能使用电机命令值代替实测；写“压力曲线”时，要保留HX711原始计数、标定和时间轴。

### 动态测量为什么必须共时

检验`N(t)=m[g+a(t)]`，至少需要两条真实数据：支持力随时间变化，以及平台加速度随时间变化。两条曲线必须使用同一时钟或清楚的同步事件。若时间轴错位，即使形状相似，峰值和运动阶段也无法对应。

最小测量包应包含：

1. 质量`m`的测量口径；
2. HX711空载、至少三点加载、重复加载、回程和漂移记录；
3. 平台位移—时间数据，用它求速度和加速度；
4. 力与运动量的共同时间轴；
5. 原始曲线与滤波曲线同时保留，公开窗口、阶数或截止参数；
6. 实测`N(t)`与`m[g+a(t)]`之间的残差。

滤波会改变峰值与相位。曲线更平滑，只说明高频变化被削弱；教师还要判断被削弱的是机械振动、传感器噪声还是物理过程中的快速变化。AI可以并排生成不同滤波参数的结果并估计延迟，选择依据仍来自装置响应与教学目的。

### AI适合承担哪些工作

在这条链中，AI适合做四类工作：从代码、网页和文稿中查找参数冲突；为控制链和测量链生成分层测试；对齐时间戳并计算残差；整理“命令—响应—运动—压力—模型”证据表。

以下问题仍须由负责该装置的教师确认：截图中的曲线是否来自这台装置，电机指令是否代表真实运动，滤波是否保留了关键峰值，动态残差能否由摩擦、振动、传感器响应或接触模型解释。缺少原始数据时，AI生成的光滑曲线只能作示意图。

### 从当前原型继续的最小路线

严力耕的装置已经有机械实物和控制桥，下一次开发无需同时补齐所有功能。按证据依赖顺序，可以先做三段。

第一段只验控制：统一波特率，核对命令字节，保存驱动器应答或独立运动证据，记录限位和重复运行。

第二段只验运动：取得位移—时间数据，分辨启动、匀速、制动和换向，由实测位移求速度与加速度。

第三段再接压力：保存原始计数，完成静态多点校准，把运动与压力放到共同时间轴，最后比较模型与测量。

每完成一段，都应保存原件、任务、输入、实际输出、退回和复验。若第一段尚未证明平台运动，后两段不使用“动态超失重测量已经完成”的口吻。

选择一件手边的传感器或教具，依次填写：

概念任务说明“教什么”，传感器链说明“测什么”，分层验收说明“已经做到哪里”。三者接在一起，一件教具才有机会承担课堂中的物理问题。下一章将继续处理升格：页面、数据通道和装置逐渐增多以后，什么时候需要统一网站，什么时候应当保持当前规模。

## 第8章　页面多了以后，什么时候做成网站

三个机械能页面已经有共同入口，浏览器中的数据工具开始连接真实设备，模拟页面、项目任务和智能硬件材料也陆续需要一个可访问的位置。这时很容易产生一个冲动：把所有东西放到首页，网站就建成了。

打开数智育才网站的项目目录，会看到另一幅更具体的图景。每个地址要对应一个稳定对象，导航要告诉使用者自己将进入实验、模拟、编程还是设备连接，公共组件要承担重复结构，物理数据仍要保留各自口径。发布前要检查类型、构建与页面结构；发布后还要处理服务器版本、缓存和回滚。页面越多，教师增加的工作逐渐从“做一个功能”转向“维护一组关系”。

网站升格发生在这些关系已经值得共同维护的时候。

### 三个页面之后，新问题从哪里出现

机械能守恒在线实验室有三个方案入口。它们共享实验目的、器材、步骤、数据表、能量关系、实验回顾和配套习题等结构，也分别处理不同对象与公式。落体法、曲面运动和气垫导轨可以复用页面骨架，气垫导轨中的质量、两只光电门和钩码下降高度仍需保持自己的物理身份。

单页阶段，教师可以在一个文件里同时改标题、公式和布局。页面增多以后，同一种修改会出现三种去向。

- 全部页面都需要的导航、页头或提示，应进入共享组件。
- 同类实验都需要的题目、实验回顾或栏目结构，可以进入结构化数据与通用展示组件。
- 某个实验独有的研究对象、变量关系和边界条件，应留在该实验自己的模型卡、数据文件或页面中。

第三种内容若被过早提成“通用规则”，系统会统一得很整齐，物理对象却可能被统一错。第一章选题时写下的“错误代价”，此时要重新出现：一个共享组件出错，影响的不再是一页；一项通用公式被误用，可能让多页同时产生相同偏差。

数智育才网站当前把路由、组件、数据和文档分开保存。路由回答“这个地址是什么”，组件回答“哪些显示结构可以复用”，数据文件保存习题、实验回顾和站点元信息，文档记录设备协议与维护方法。这套结构的价值在于让一次改动有明确落点，也让检查者知道应当从哪里追踪变化。

### 先判断四种交付形态

教师常把单页、专题、网站和平台都叫作“资源”。它们承担的责任并不相同。

| 交付形态 | 适合的情况 | 新增责任 | 可以暂缓的工作 |
| --- | --- | --- | --- |
| 单页 | 一项输入、计算、演示或记录任务 | 对象、公式、样例和文件入口 | 全站导航、账号和跨页搜索 |
| 专题 | 同一课题下有数个相连页面 | 共同入口、页面身份、相互跳转和同题口径 | 无关学科或无关课程的统一 |
| 网站 | 多类资源需要长期访问和持续更新 | 路由、导航、发布、回滚、隐私、失效链接和维护者 | 复杂设备治理与课程开发平台 |
| 平台 | 多设备、多角色或重复开发需要共享底座 | 协议、权限、版本兼容、测试矩阵、文档和接手 | 尚无真实需求的扩展模块 |

选择形态时，先看真实任务怎样聚合。三个机械能页面围绕同一课堂任务，可以组成专题。在线实验室、模拟实验室、在线编程和网页版DIS面向不同活动，却都需要稳定入口与浏览器访问，网站开始具有组织价值。ESP32Blockly、设备固件和课程教材涉及积木、MicroPython、设备编号、故障板与替代链路，它们只有在重复课程或设备治理需求出现时，才值得承担平台级责任。

页面数量只是一个提示。五个彼此无关且不再维护的页面，放进网站会增加导航与发布负担；两个需要同一入口、共同版本和持续复用的页面，已经可能需要专题结构。

### 系统升格五问

准备扩建前，把现有页面逐项放进下面五问。

1. **共同任务是什么？** 使用者为什么需要从一个页面继续到另一个页面？
2. **哪些结构真的重复？** 重复的是页头和数据表，还是物理对象、公式和操作过程？
3. **身份怎样固定？** 页面地址、实验方案、设备名称、单位和数据格式由谁登记？
4. **谁维护、谁退回？** 修改通过哪些检查，发布失败怎样回到上一版？
5. **何时停止扩建？** 新栏目若没有对象、材料、验收样例和维护者，是否继续进入导航？

机械能专题可以这样填写：共同任务是完成并比较同一守恒问题下的三种实验；复用结构包括实验回顾和习题展示；每个方案拥有固定路由与独立字段；修改需通过构建、结构检查和物理样例复核；尚未发生的跨方案比较不因网站存在而自动补齐。

最后一条很重要。系统能够承接下一项教学设计，不代表下一项教学活动已经发生。网站为任务准备入口，课堂事实仍从课堂记录中来。

### 设备进入网站以后，要有自己的姓名和语法

第7章把一次动态测量拆成十级证据链。多个设备进入同一个浏览器工具后，还要增加协议层身份。数智育才网站的DIS文档为六种模式规定了不同蓝牙名称前缀：力传感器、距离传感器、单头光电门、双头光电门、两只单头光电门和两只双头光电门各有固定前缀。教室里出现多台同类设备时，再用编号区分。

这个命名表解决的是连接前的第一问：浏览器准备连接谁。连接之后，数据格式还要回答三个问题：一次通知中有几个数，每个位置表示什么，单位是什么。力传感器的一组数据可表示力和设备时间；单头光电门发送挡光时间和设备时间，网页再结合遮光物宽度计算速度；双头光电门可以直接发送速度事件。两种“光电门数据”若共用一段没有身份判断的解析逻辑，页面可能正常接收字节，却把时间当成速度。

因此，设备与页面之间应保存一张责任表。

| 层次 | 需要固定的内容 | 最小检查 |
| --- | --- | --- |
| 设备 | 名称前缀、编号、固件版本 | 搜索结果能区分目标设备 |
| 通知 | 浮点数个数、字节序、字段位置 | 用已知数据包检查解析 |
| 物理量 | 名称、单位、正方向、时间来源 | 与模型卡逐项对应 |
| 页面 | 当前模式、输入参数、图表和导出列 | 切换模式后不沿用旧设备 |
| 记录 | 原始包、处理值、设备时间和导出版本 | 能从图表追回数据来路 |

当前网站文档还特别区分了两条力传感器路线：网页版DIS使用的程序是ADS1220差分采集，前章H09材料使用HX711。它们都能被概括为“力传感器”，实际程序、标定和证据不能合并。网站升格后，名称相近的对象更需要保留版本和硬件身份。

浏览器环境也属于接口。Web Bluetooth和Web Serial依赖浏览器支持与安全上下文，网站为不支持的环境准备提示。教师发布设备页面时，应把“浏览器是否提供接口”列为运行门，把“设备数据是否对应真实物理量”留在物理门。两项检查使用不同证据。

### 固定地址背后是一条发布链

把页面放进项目目录，只证明本地存在。数智育才网站当前的项目说明把发布分成若干明确动作：本地类型检查与构建，生成静态文件，上传到新的时间戳目录，切换服务器软链接，检查并重载服务，最后清理边缘缓存。旧版本目录被保留，出现问题时可以把软链接指回上一版，再重新加载并刷新缓存。

这条链为教师提供了三个可迁移原则。

第一，每次发布都应产生一个可指认的版本。若直接覆盖唯一目录，发现错误时很难判断应退回哪些文件。

第二，回滚要在发布前写好。知道“怎样撤下”以后，教师才有能力在物理错误、隐私问题或设备不兼容出现时及时停止。

第三，用户看到的版本可能受缓存影响。服务器已切换，不代表每位访问者立即得到同一页面；回滚以后也要处理缓存，才能避免旧内容继续出现。

本书不要求读者照搬同一种服务器。使用学校平台、静态托管或校内局域网，同样要回答四个问题：发布对象在哪里，当前版本是什么，怎样确认访问者看到的版本，怎样撤回。

### 发布前走完五条路线

网站发布前的检查不能只从首页点到末页。至少要走完五条路线。

**入口路线**：从首页、二维码或课件链接进入目标页，检查标题、返回路径和页面身份。

**任务路线**：以学生或教师的实际动作，从读原理、输入数据到生成图表和表达结论，保存出现阻断的位置。

**物理路线**：用普通值、边界值和极端值核对公式、单位、正方向和异常输入；共享组件改动后，对受影响页面重新复算。

**设备路线**：确认浏览器支持、权限、设备名称、数据字段、断连与重连；没有真实设备时，记录检查停在哪一层。

**撤回路线**：确认上一版、维护入口、发布记录和回滚步骤可找到；涉及公开数据时，同时检查授权与隐私。

项目中的自动构建和结构检查可以发现类型、缺失路由、错误资源引用等问题。高考模拟页面还登记了物理回归样例。这些记录扩大了可重复检查的范围；没有进入测试的物理条件、课堂流程和真实硬件仍需要另行验收。

### 继续扩建还是停在当前规模

网站最容易出现的浪费，是把维护成本藏在“以后也许会用”里。每增加一个栏目，都要回答谁提供材料、谁核物理、谁处理失效链接、谁决定撤回。没有明确对象和维护者的栏目可以留在候选清单，不必立即出现在导航中。

可以用一张升格表做决定：

| 检查项 | 当前证据 | 若升格要新增什么 | 当前决定 |
| --- | --- | --- | --- |
| 共同任务 | 页面之间是否有真实连续动作 | 写出入口与结束条件 | 继续／保持单页 |
| 可复用结构 | 哪些模块已在两个以上页面稳定使用 | 建共享组件和回归样例 | 复用／暂缓抽象 |
| 身份与协议 | 路由、设备、字段、单位是否登记 | 建对象表和版本表 | 可接入／先补身份 |
| 发布与撤回 | 当前版本能否指认、能否回滚 | 建发布记录和撤回步骤 | 可发布／只本地 |
| 维护责任 | 有无维护者与停止条件 | 写维护单和失效处理 | 扩建／停止 |

### 本章交付：系统升格单

把第5章的最小页面、第6章的课堂用途或第7章的传感器链放进下面这张单：

```text
当前交付形态：单页／专题／网站／平台
共同任务：
稳定使用者与入口：
可以复用的结构：
必须独立保留的物理口径：
页面、设备和数据身份：
发布前五条路线：
当前版本与回滚入口：
维护者：
停止扩建条件：
本次检查结论：继续升格／保持当前规模／撤回
```

完成这张单以后，网站不再只是页面的容器。它成为一组能够被定位、检查、发布、撤回和继续维护的关系。下一篇要处理更长的时间尺度：一次调试得到的规则、一次验收形成的样例和一个项目积累的材料，怎样在下一次任务到来时仍然找得到、用得对。

# 第三篇　把一次做法变成工作系统

## 第9章　材料、规则、版本和Skill怎样留下来

一个项目第一次做成时，许多关键信息仍在教师脑中：为什么删掉自动排序，哪一列是原始数据，某个公式只适用于哪段运动，哪一张图还没核过，发布失败时应退回哪里。几周以后再打开项目，文件还在，判断却可能散失。

AI也会遇到同样的问题。新的会话看到一大批文件，并不知道哪份是原件、哪份是旧稿、哪份可以改、哪条结论已经复算。把所有材料一次塞进上下文，会让过期说明和当前事实同时获得注意。一个可持续项目需要给材料分层，给任务安排入口，再把少数稳定规则与可重复方法留下来。

### 原件、知识和产物各有位置

先为项目建立三层。

```text
原件层　raw
  真实数据、原始文档、照片、源码、课堂记录、授权文件
       ↓ 保留路径、来源、日期和身份
知识层　knowledge
  事实卡、模型卡、数据来路表、主张边界、任务路由、待核清单
       ↓ 说明依据与适用条件
产物层　output
  页面、课件、文章、实验单、图表、发布包和交接包
```

原件层尽量保持原貌。更名、转换或脱敏时，保存新文件与原文件的对应关系。知识层承担解释：这一列是什么量，这张图片来自哪里，这条结论能说到哪一步。产物层面向使用者，可以反复修改，但每个关键判断都应当能够回到知识层，再由知识层指向原件。

第2章的数据来路表属于知识层。法拉第实验的原始记录、装置照片和拟合文件属于原件层；书中的图表与读者检查单属于产物层。若把书稿中的概括反过来当作实验原件，下一次修改就会在摘要上继续推断，数据链会越来越短。

三层还可以保护外部材料。商业教辅的原始Word可能依法用于本地整理，产物层不能因此公开复制正文。权限、版权和隐私跟随原件进入知识卡，不能等到发布时才重新猜测。

### 一个资料工程怎样把“成功”分成五级

本地物理资料结构化项目提供了一个适合观察分层的实例。当前登记有616份Word来源，每份来源用SHA-256哈希形成稳定身份；616份完成了转换和结构化运行，生成7,831条候选题记录。自动检查把来源和候选送入待复核队列，同时保守地将457份来源中的5,076个编号区块留在原文，没有强行拆成题。符合既定Schema的正式人工复核记录仍为0。

把这些数字放进同一句“资料已经整理完成”，读者会失去项目的真实位置。更准确的状态阶梯是：

```text
来源已登记
→ 转换已运行
→ 结构候选已生成
→ 已进入人工复核入口
→ 已由真实审阅者审结并决定是否发布
```

当前项目清楚地走到第四级入口之前后的工程状态，尚未走到第五级审结。611份来源被自动标记为需核对，也不等于611份转换失败；4,322条只继承来源提醒的候选，不能写成自身都发现错误；5,076个未拆区块保留了不确定性，不能写成“丢失了5,076道题”。

这套状态设计给造物项目增加了一项重要能力：允许系统说“我做到这里”。第7章的十级测量链也可以采用相同办法。按钮、BLE、UART、运动、加速度、原始计数和校准值分别登记状态，后续人不会从一个绿色“成功”图标误读出整机已经验收。

### 先给资料安排入口，再让AI读取

项目材料增多以后，AI第一步应读入口文件。只有入口不足且当前任务确实需要时，才扩大到目录检索。一个实用入口至少回答四件事：

1. 项目现在要解决什么问题；
2. 主要目录分别保存什么；
3. 当前任务应按什么顺序读哪些材料；
4. 哪些文件禁止修改、哪些结论仍待确认。

在入口之下，可以增加两个索引。

**对象索引**按课例、装置、页面或数据集登记权威入口、作者、状态和证据上限。它解决“我要找谁”。

**任务路由**按实际任务给出短读取路径。例如“检查气垫导轨输入身份”只需进入模型卡、冻结页面、故障记录和三组样例；无需同时读取整个网站、所有课程照片和其他实验源码。它解决“这次读什么”。

每次任务开始时，还可以写一张临时材料单：

```text
本次问题：
必须读取：
需要回查时再读：
只作结构参考：
本次禁止作为事实来源：
预期产物：
```

材料范围越清楚，AI越容易解释自己依据了什么。范围控制也减少了把同名对象混写的风险：H09的HX711力传感器与网站DIS的ADS1220力传感器可以同时存在，只要任务单明确当前核对哪条链。

### 四种东西不要互相代替

一次工作结束时，常见的“保存经验”至少有四种。

| 保存对象 | 适合保存什么 | 不适合保存什么 |
| --- | --- | --- |
| 会话记录 | 当次问题、尝试、输出和未完位置 | 需要长期依赖的唯一事实 |
| 版本记录 | 文件变化、退回理由、复验结果 | 没有来源的经验口号 |
| 项目规则 | 长期稳定且每次都要遵守的禁区与完成定义 | 今天的临时故障、可能很快变化的工具界面 |
| Skill | 已重复成功、输入清楚、结果可验收的程序性方法 | 一次性灵感、未复验建议或特定页面的偶然修补 |

例如，“当前浏览器暂时连不上某台设备”适合进入故障记录；若复查发现原因是设备名称不符合协议，可以把本次原因和处理进入版本记录；“连接前必须核对模式与设备前缀”在多个任务中成立后，可以进入项目规则；一套已反复成功的连接检查与数据身份核对流程，才有资格进一步整理成Skill。

项目规则还应区分慢变量和快变量。学生隐私、成果归属、构建通过不代表物理正确，变化缓慢，应长期保留。某个模型名称、按钮位置、计费方式或在线接口可能频繁变化，使用时现场核对，避免写成永久规则。

### 写一份短而能执行的项目规则

项目规则的作用是告诉AI那些它无法从单个文件推断、又必须每次遵守的事项。规则太长，会把历史说明和当前任务混在一起；规则太空，只剩“认真检查”“保证准确”，无法改变行动。

教师项目可以从六栏开始：

```text
项目对象：服务哪类物理任务与使用者
权威入口：先读哪些索引、模型卡和原件
可改范围：本次允许修改哪些目录或文件
硬性禁区：隐私、归属、版权、物理和发布边界
完成定义：运行、物理、教学、发布分别怎样记录
常见陷阱：本项目已经发生过、需要每次复查的问题
```

气垫导轨项目的“常见陷阱”可以写三条：不得自动交换`v₁/v₂`；`h`只对应两光电门区间内钩码下降高度；模拟数据入口不得在真实实验任务中默认出现。每一条都来自真实退回记录，下一位协作者可以用样例检查它，无需猜测隐含偏好。

项目规则需要定期删旧。删除前先看引用与版本，保留可恢复快照。临时环境故障已经解决，留在故障档案即可；重复规则合并后，仍保留原始决定的出处。规则治理的目标是让当前协作者看到有效约束，同时能够追溯它为何存在。

### 一张检查表何时值得变成Skill

Skill可以理解为一份在适当时机被调用的可执行方法。它需要说明何时使用、怎样操作、交付什么、何时停止以及怎样测试。把一篇说明文改名为Skill，仍然只是说明文。

判断成熟度可以问五个问题。

1. 这套方法是否在两个以上真实任务中重复成功？
2. 输入对象能否被清楚识别，缺少输入时会不会停下？
3. 操作步骤是否足够稳定，不依赖某个人临场猜测？
4. 输出能否由普通、边界和诱饵样例检查？
5. 失败时是否保留原件、说明停点并允许回滚？

第2章的图表口径检查已经在法拉第与单摆材料中呈现出可复用结构，但距离Skill仍差一轮明确的重复测试。可以先写成候选卡：输入为原始表、变量说明和拟合设置；输出为数据来路表、空白与异常检查、拟合口径和主张上限；禁用场景包括缺少原始数据、只有图片或单位不明；失败时保留原表并提出待核问题。

候选Skill还应接受诱饵测试。可准备四种输入：

- 在尾行留下空白单元格，检查是否被静默当成零；
- 提供很高的`R²`，但不给变量换算关系，检查是否越过数据来路；
- 混入一个单位不同的列，检查是否仍直接拟合；
- 只给平滑曲线图片，检查是否虚构原始数据。

方法若在诱饵面前仍能停下、标出问题并保留原件，才开始具备可复用性。成功处理熟悉样例只证明流程能走通；极端、缺项和冲突样例检验它会不会在最需要谨慎时继续生成。

### Skill卡要写五件事

一张最小Skill卡可以这样写：

```text
名称：
触发：什么任务出现时使用
输入：必需材料、格式与权威来源
步骤：按顺序执行的动作与人工确认点
输出：文件、表格、状态和未完成说明
边界与测试：禁用场景、诱饵样例、失败出口与回滚
```

触发条件要具体到任务。“处理资料时使用”范围过大；“收到带原始表格和变量说明的物理拟合结论，需要检查数据身份与图表口径时使用”更容易判断。输出也要可见：生成一份来路表、列出未解释空白与异常、保存拟合设置和主张上限，检查者才知道方法有没有真正执行。

Skill无法替代教师责任。它可以强制查单位、保留空白、复算样例，无法在缺少实验记录时决定某个异常点来自仪器、操作还是物理过程。无法自动判断的节点应写在步骤里，由教师确认后继续。

### 本章交付：把项目整理成可接续结构

完成三项交付。

**第一项：三层资料图**

```text
原件层入口：
知识层已有卡片：
产物层当前版本：
三层之间的来源字段：
版权与隐私限制：
```

**第二项：项目规则**

从对象、入口、可改范围、禁区、四门完成定义和真实陷阱六栏中，各写一到三条。凡是无法用文件、样例或记录解释的口号先删去。

**第三项：Skill成熟度卡**

选择本项目中最常重复的一张检查表，登记已在哪些真实任务中成功、还缺什么边界样例、遇到什么输入必须停止。尚未重复验证时，保留“候选”身份，不急着封装。

项目由此拥有两种连续性：文件让后来的人看见做过什么，规则和Skill让稳定方法在适当条件下再次执行。下一章要继续判断，当一项任务已经超过单个协作者的注意范围，怎样拆成多个角色；当重复流程越来越稳定，哪些部分才可以自动运行。

## 第10章　什么时候需要多个Agent，什么时候可以自动运行

“再增加几个Agent”看起来像提高速度，“设成自动运行”看起来像节省时间。两项决定都会增加新的失败方式。多人可能同时修改同一文件，角色之间可能引用不同版本；自动任务可能在材料未到齐时继续运行，也可能重复发布、持续重试或把待审内容推向公开入口。

第9章留下的三层资料、项目规则和Skill卡，为这两项决定提供了起点。材料入口不清楚时，多个Agent只会更快地产生不同理解；手动流程尚未稳定时，自动化只会重复不稳定动作。

### 先在四种工作方式中选择

面对一项新任务，可以先判断它需要哪一种工作方式。

| 工作方式 | 适合的任务 | 最低条件 | 主要新增风险 |
| --- | --- | --- | --- |
| 单Agent | 范围小、修改集中、需要持续理解同一对象 | 任务Brief、材料入口、验收样例 | 上下文过长、自己检查自己 |
| 多Agent | 子任务能够独立推进，资料或工具不同，结果可以汇合 | 角色契约、独立写入范围、共享产物、总负责人 | 版本冲突、重复劳动、归属漂移 |
| 自动运行 | 同一动作已经稳定重复，输入状态可判断 | 可重复Skill、状态记录、重复执行处理、失败出口 | 空转、重复处理、静默失败、成本失控 |
| 网站或服务 | 多位使用者需要稳定入口和长期访问 | 发布、权限、版本、维护、回滚 | 对外影响扩大、隐私与维护责任增加 |

四种方式可以组合。网站每天检查失效链接属于网站加自动任务；多个Agent共同完成一批页面审查属于多Agent项目；单Agent也可以调用一个稳定Skill。选择时围绕任务结构，不用角色数量或“自动”标签判断成熟度。

一个实用判断顺序是：

```text
一个人能在受控范围内完成吗？
  能 → 保持单Agent
  不能 → 子任务能否独立，产物能否清楚交接？
          能 → 考虑多Agent
          不能 → 先重写任务或缩小范围

同一流程是否已经多次手动成功？
  否 → 继续人工执行并记录失败
  是 → 输入状态、重复触发和失败出口是否可判断？
          是 → 逐级引入自动运行
          否 → 先补状态与停止条件
```

### 以新增传感器页面为例拆任务

假设教师准备把一种新传感器接入第8章的网站。任务至少包含物理模型、设备协议、页面实现和独立复核。四部分存在依赖，不能全部同时开工。

物理模型先确定直接测量量、单位、正方向、时间来源、校准和学生任务。设备协议在此基础上确定名称、数据包和字段。模型与协议冻结到一个可检查版本后，页面实现才能可靠开始。页面首版完成后，浏览器运行检查与独立数值复核可以并行；两份检查最终交给同一位负责人决定采用、退回或停止。

```text
物理模型 ──┐
            ├─→ 冻结的接口表 → 页面实现 ─┬→ 浏览器检查 ─┐
设备协议 ──┘                              └→ 数值复核 ───┤
                                                        ↓
                                              教师合并与发布决定
```

这张图中只有两段适合并行：前端模型与协议可以在共享对象表上协商推进；实现后的运行与数值检查可以使用同一冻结版本独立进行。若物理模型尚未确定，就让页面Agent、测试Agent和文案Agent一起生成，三方很可能各自补一个默认值，最后得到三个内部一致、彼此不相同的对象。

### 角色契约要写到可交接

“你负责物理”“你负责技术”仍然太宽。每个角色需要一份短契约。

```text
角色名称：
负责对象：
权威输入：
允许读取：
独立写入范围：
必须交付：
必须保存的证据：
遇到什么情况停止：
不得作出的结论：
交给谁合并：
```

物理建模角色的交付物应是模型卡、独立真值与三组样例，不能只写“已检查”。实现角色交付页面、变更说明和运行结果，不宣布课堂可用。独立复核角色使用冻结产物，不沿用生成者的计算过程；发现对象不一致时退回到模型卡，不在页面里自行发明新公式。总负责人保留合并、发布和撤回权。

写入范围也要隔离。多个角色同时改正文、数据文件或同一页面，会让版本记录失去因果。可以给每个角色独立目录或分支，只允许总负责人合并共享文件。只读共同原件，分别写各自产物，是最简单的冲突隔离。

### 共享产物比共享聊天更可靠

多Agent协作不能只依赖消息转述。关键结论要落在所有角色能读取的共享产物中。

| 共享产物 | 谁先写 | 后续角色怎样使用 |
| --- | --- | --- |
| 对象与模型卡 | 物理建模 | 协议、实现和复核共同引用变量与边界 |
| 接口表 | 设备／数据角色 | 页面按字段解析，复核按字段造测试包 |
| 冻结样例 | 物理建模＋教师 | 实现作回归，检查者独立复算 |
| 版本与退回记录 | 总负责人 | 所有角色确认当前有效版本和历史决定 |
| 待核清单 | 发现问题的角色 | 教师决定补证、降级或停止 |

共享产物要带版本。实现角色若使用模型卡v2，复核角色却按v1测试，双方都可能“通过”。任务包中应写明模型卡、接口表、页面和样例的对应版本；修改任何一个上游对象后，明确哪些下游检查必须重跑。

### 教师确认点要放在不可逆影响之前

多Agent可以提出方案、生成文件和执行受控检查。以下节点仍应由教师确认：

- 物理模型和简化条件是否符合教学对象；
- 学生数据、姓名、照片和作品是否允许进入处理或公开范围；
- 他人装置、课程和研究成果的归属怎样表达；
- 页面是否进入课堂、公开网站或对外材料；
- 设备动作是否可能带来碰撞、过载、误接或其他安全风险；
- 证据不足时采用降级说法，还是停止发布。

确认点应设置在发布、发送、驱动真实设备或批量改写之前。把人工确认放到任务全部完成以后，往往只剩下接受或整体返工两种选择。

### 自动化从手动流程逐级上升

自动运行可以分四级。

**第一级：人工任务。** 教师发起一次，观察每一步，保存输入、输出与退回。新页面的第一次物理验收属于这一级。

**第二级：稳定Skill或脚本。** 相同输入会经过固定步骤，输出可以用样例检查，仍由人决定何时运行。数智育才网站的类型检查、静态构建和站点结构验证已经具备这类可重复动作；它们检查已登记对象，不替代教师终审。

**第三级：有状态的重复运行。** 系统能判断输入是否就绪、某项任务是否已经处理、上一次停在哪里，并保存每次结果。资料结构化工程的来源哈希、状态字段和待审队列展示了这一级所需的身份基础；正式人工审结仍保持独立。

**第四级：受控的无人值守。** 任务可按时间或事件触发，具备最大重试、预算、告警、降级、人工接管与停用方式。涉及学生数据、物理内容公开或真实设备动作时，这一级需要更严格门槛，许多任务没有必要到达这里。

每上升一级，先问新增责任由谁承担。节省的是重复点击，增加的是状态、日志和失败管理。

### 自动任务至少要认识六种状态

只用“成功／失败”两个状态，很难处理中途缺材料、重复触发和人工等待。教师项目可以先用六种：

| 状态 | 含义 | 允许的下一步 |
| --- | --- | --- |
| `waiting_input` | 权威输入尚未到齐 | 等待或提醒，不生成事实 |
| `ready` | 输入与权限检查通过 | 开始执行 |
| `running` | 正在处理并记录当前步骤 | 继续、超时或人工停止 |
| `needs_review` | 自动部分完成，等待教师判断 | 审核、退回或降级 |
| `blocked` | 出现无法自动解决的冲突 | 保存停点并通知负责人 |
| `completed` | 指定交付和检查均已完成 | 归档，不重复执行 |

状态要和对象身份绑定。以来源哈希、任务ID或版本号判断“这是不是同一项工作”，比看文件名可靠。相同任务再次触发时，系统应读取状态：已经完成则不重复发布，运行中则不启动第二份，待审则提醒责任人，输入发生变化才创建新版本。

这种处理常被称为“幂等”：同一个请求重复到达，不会造成重复副作用。教师无需记住术语，只要能回答一句话——同一份学生文件、同一张页面或同一条发布任务被提交两次，会发生什么？

### 重试、告警和降级要一起设计

自动任务遇到网络中断，可以重试；遇到物理模型冲突，继续重试没有意义。重试前先分类。

- **短暂故障**：网络波动、临时服务不可用，可以有限重试，并逐次延长间隔。
- **输入故障**：缺文件、格式错误、单位空缺，转入等待或人工修正。
- **权限故障**：凭证失效或无权访问，立即告警，不绕过权限。
- **内容冲突**：原件与模型卡不一致，停止生成，交教师判断。
- **安全与隐私问题**：发现姓名、未授权图片或危险设备动作，停止并阻断发布。

每种故障都要有负责人、最大重试次数和最终出口。达到上限以后，可以交付降级结果，例如只生成待核清单、不生成公开页面；只保存本地报告、不发送；只检查文件存在、不宣称内容通过。

告警也要包含可行动信息：任务对象、失败步骤、已尝试次数、最后一条有效产物、需要谁做什么。只发送“任务失败”，会把定位工作全部留给教师。

### 自动检查必须经过真实交付路径

一项外部AI工程复盘提供过一个警示：桥接组件拥有178项单元测试和100%行覆盖率，真实编辑器首次请求仍然崩溃。书稿记录的原因包括测试采用手工挂载，没有经过真实加载器；需要密钥的端到端测试被跳过；本地检查还使用了残留的旧编译结果。

这则材料来自一份整理书稿中的事故复盘，只在这里承担对象身份的对照，不用于判断该工程当前版本，也不能代表所有工程。它能说明一个稳定原则：自动检查要核对自己究竟装载了什么、跳过了什么、最终用户走的是哪条路径。网站构建通过以后，还应从真实路由打开页面；设备解析测试通过以后，还应使用实际通知格式；缓存清理脚本运行以后，还应确认访问者取得的版本。测试数量没有替代验收对象。

自动任务的运行报告至少应列出：实际输入版本、执行环境、已运行检查、被跳过检查、产物位置和人工待办。被跳过的端到端测试必须保持可见，不能被总计中的绿色状态遮住。

### 预算和停用也是教学责任

自动任务会消耗模型额度、存储、网络与教师审阅时间。上线前给它设置三类上限：单次处理量、单日或单周期总量、连续失败上限。任何一项到达上限，任务进入等待或停用，不自行扩大范围。

还要指定一个清楚的停用入口。负责人离岗、课程结束、数据源失效、页面撤回或审阅积压时，可以暂停触发，同时保留已有记录。删除自动任务会失去历史，持续运行又可能制造更多待办；可暂停、可恢复、可查看最后状态更适合长期项目。

教师需要定期抽读自动产物，并亲自复算少量样例。若已经无法解释模型卡、接口、测试和发布链，即使系统仍在运行，也应降低自动化等级，重新走人工任务。专业判断要通过复讲与复验保持，而不能只保留最终批准按钮。

# 第四篇　交付给学生和后来的人

## 第11章　学生和AI共同完成的作品怎样评

学生交来一个能打开、能拖动、带动画和数据表的物理网页，教师面对的已经不只是一份答案。作品背后还有任务要求、学生给AI的多轮指令、AI生成的不同版本、最后提交的文件，以及页面实际运行时产生的数值。

只看对话，容易把学生提出的正确要求当成成品已经实现；只看最后页面，又会把AI生成的机制错误直接算到学生身上。评价需要同时保留两条轨道：过程里学生承担了哪些核验动作，成品能否通过模型、数据和运行检查。两条轨道对齐以后，教师才知道下一次应退回要求表达、页面实现，还是验收动作。

### 先把评价对象分成五份

当前材料来自同一个特优生AI技能测试项目。已有分析范围是25份物理模拟网页；相关目录中的271个文件只表示文件数量，不能当作另一组学生样本。本章从已经整理的个案中选择四份脱敏代号材料，重点展开P06，其余三案只使用当前可定位到的过程与静态成品事实。

每份作品先分成五个对象。

| 对象 | 能回答的问题 | 不能替代什么 |
| --- | --- | --- |
| 任务 | 学生被要求做什么、时间和提交物是什么 | 学生实际怎样理解与执行 |
| 过程对话 | 学生提出过哪些约束、诊断和取舍 | 最终页面有没有实现 |
| 提交成品 | 最后交付的代码和页面机制是什么 | 学生是否亲自写出每一段 |
| 浏览器表现 | 页面打开、操作后实际发生什么 | 未走过的按钮和极端条件 |
| 物理复核 | 关键数值、单位和关系是否经得起独立计算 | 学生的总体能力和学习效果 |

五份对象要有谱系关系。某段对话对应哪一次生成，最后提交页来自哪一版，若无法确认，就把过程和成品分开使用。现有25份材料中，20份能够精确对应，3份属于同一版本族但具体节点不确定，2份对话与网页无法对上号。后两类仍可分别说明过程或成品，不能拼在一起证明“学生说了什么，所以页面怎样”。

### 过程轨看四种可观察动作

过程轨只记录学生在对话中实际留下的动作，不推测没有说出口的思考。

1. **提出约束**：规定对象、公式、单位、参考系、学段或适用条件。
2. **发现异常**：指出表格、图像、术语、动作或数值与预期不一致。
3. **追问依据**：要求AI说明数据来路、公式条件或修改原因。
4. **作出验收决定**：明确采用、拒收、退回或有条件接受某一版。

“把按钮换成蓝色”属于呈现要求；“两球相向运动时不能称作追赶”属于术语核对；“请说明参考平面，否则势能无法判断”属于条件核对。同一条消息可以包含两类动作，评价表应保留具体消息位置与对象，不把整段笼统记作“会提问”。

过程轨还要记录动作有没有闭环。学生发现异常并要求修改，是一次有价值的诊断；AI答应修改以后，学生是否回看新版本，属于另一个验收动作。前者不能自动带出后者。

### 成品轨沿三条路线检查

成品轨至少走三条路线。

**读代码或结构。** 查数据从公式、随机数还是人工输入而来；查单位如何换算；查按钮是否有实际处理；查页面答应的规则有没有进入程序。

**真打开操作。** 走一条预先写好的主路径，检查初始状态、控件、暂停、边界时刻、判分和显示。把页面展示的关键读数保存下来。

**独立复算。** 从页面抄取数值，代回外部公式，核对单位、数量级、守恒量残差和同一状态的多处读数。

三条路线各自有盲区。代码里写着正确公式，页面可能因加载问题显示`NaN`；页面动画流畅，内部可能把像素数直接当作米；屏幕上显示“已验证”，代码可能直接用待验证定律生成数据。检查者要把发现问题的路线一并记录，方便下一次回归。

### P06：对话说破了循环，生成程序仍在循环

P06围绕自由落体与机械能守恒制作页面。过程对话中，学生先发现动能和重力势能数据重复，追问势能是否算错，并要求说明参考平面。随后又明确指出：若直接用`v=gt`得到瞬时速度，再把这个速度代入动能去验证机械能守恒，会形成循环论证。学生还要求把这个问题放入页面问答区。

这些消息能够支持两个判断：学生发现了表图失真，并能点名一种验证逻辑风险。它们不能直接支持“最终页面已经消除风险”。

提交页的表述层确实写出了循环论证说明。打开生成机制，理想数据仍由

\[
s=\frac12gt^2,\qquad v=gt
\]

生成，再计算

\[
E_p=mg(H-s),\qquad E_k=\frac12mv^2.
\]

在页面所用理想条件下，两式相加自然回到`mgH`。页面示例中机械能列保持为98.000 J，数值内部自洽；这组数据由自由落体运动学公式生成，不能承担对同一关系的独立验证。

于是同一份作品出现三个位置：

| 位置 | 可定位事实 | 评价 |
| --- | --- | --- |
| 过程消息 | 学生点名`v=gt`循环风险并要求解释 | 有核验行动 |
| 页面表述 | 问答区能够说明循环问题 | 表述已进入成品 |
| 数据生成 | 理想数据继续使用`v=gt`和位移公式 | 机制未解除循环 |

过程与页面表述对齐，过程与生成机制分离。教师的退回意见应指向这个分离：“问答区已经说明为什么不能循环验证；请修改数据取得方式，或把页面身份改为根据理想运动学关系演示能量转换，不再称作独立验证。”

这样的反馈保护了学生已经完成的判断，也把下一步落到可复核对象。直接给出“物理错误”会抹掉过程中的正确诊断；给出“解释很好、通过”又会放过生成机制。

### 三份个案为什么暂时给出不同结论

**P17**的过程消息反复收紧半径矢量正负、半圆配置、角速度和两物体参数，能够定位为模型约束行动。既有核验材料记录了初始加载时多项读数显示`NaN`、执行重置后恢复的现象。评价表需要同时保存初始状态、操作路径与复核依据；没有这些条件时，不把一句“页面出现`NaN`”扩成整份作品始终无法运行。

**P20**的过程集中增加暂停、分速度、运动时间和画布控制等功能，提交页结构与控件较多，静态代码可定位到线性阻力`F=kv`相关内容。功能密度可能压缩测量逻辑的可检查性，这只构成风险提示；要判断分速度显示是否符合模型，还需把运行条件、读数与公式放在同一条复核记录中。

**P24**在过程里明确要求表格不要预填，设置高度后也不要立即显示全部数据，表现出对“看似探究、结果预写”问题的警惕。提交页能够确认多模块与解锁结构；只凭结构无法判断各模块的能量计算和例题反馈，整体对照仍需运行与复算证据。

三种处理展示了评价中的一个重要动作：证据到哪里，结论停在哪里。清楚的P06可以给出分离判断；只有静态锚点或缺少条件的运行记录，就把运行层留给下一次复核。所有作品无需被压进同一种确定结论。

### 对照只用三个结论

过程与成品对照时，先用三个结论即可。

- **一致**：过程提出的关键约束在提交成品中可以定位，并通过对应检查。
- **分离**：过程能够提出或诊断某项要求，提交成品在同一对象上仍违反要求。
- **无法判断**：版本谱系不清、运行未复现、原始数据缺失或当前检查路线不足。

“无法判断”会产生下一项任务：补版本对应、重跑页面、取得原始数据或扩大测试路径。它不等于学生没有做，也不等于作品通过。

观察表可以写成：

```text
作品代号：
任务要求：
过程消息位置与动作：
对应成品版本：
成品代码／页面锚点：
浏览器检查路线：
独立复算：
对照结论：一致／分离／无法判断
证据上限：
下一次可执行退回：
```

这张表用于任务内观察，当前没有经过评分者一致性与课堂试用检验，不能称作已经验证的量表，也不宜直接换算成学生能力等级。

### 退回理由要落到现象、责任和下一步

一张可执行退回卡包含四栏。

| 栏目 | 要写什么 | P06示例 |
| --- | --- | --- |
| 已完成 | 当前能够确认的有效判断或功能 | 已识别并解释`v=gt`循环风险 |
| 可复核问题 | 文件、页面或数值中的具体位置 | 理想数据仍由`v=gt`生成 |
| 责任位置 | 规格、实现、验收哪一段需要补 | 实现未兑现过程约束，验收未复查 |
| 下一步 | 学生能够执行并再次提交的动作 | 改数据取得方式或降低页面主张，附一组独立验算 |

退回时不从“页面错了”推出“学生不会”。成品错误可能来自AI生成、版本交错、学生未复验或任务时间限制；缺少过程证据时，责任归属保持开放。教师评价的是这次任务中可观察的核验责任与交付质量。

也要保留部分正确。一份页面可能模型条件写得清楚、关键时刻能暂停，但单位换算错误；可以分别记录。一个总分会把这些结构压平，退回卡则告诉学生哪一部分保留、哪一部分重做。

### 把验收写进下一次任务

评价不必等到作品交齐以后才开始。下一次任务说明可以提前加入三项交付。

1. **独立预测**：生成数据前，先写参考系、模型条件、可证伪预期和一组手算结果。
2. **过程留痕**：提交对话或版本记录，标出一次采用、一次退回和一次复验。
3. **成品验收**：从页面抄两个关键数代回公式，查一个单位，走一个边界或错误输入，并保存结果。

AI可以承担代码搜索、单位换算、守恒残差和多处读数比对；报告必须附过程与位置，供学生和教师抽查。浏览器实际操作、课程适切、作品归属与最终接受仍由人完成。

发现问题应被视作任务产物。若学生通过验收发现自己的网页有错，说明验收回路开始工作；让错误保持可见并完成退回，比静默修成一份完美页面更能留下责任证据。

### 本章交付：过程—成品对照与退回卡

从一份脱敏作品开始，不急着给等级。先完成五步：

```text
1. 固定任务与提交版本
2. 标出过程中的约束、诊断、追问和验收决定
3. 读结构、真运行、独立复算
4. 给出一致／分离／无法判断
5. 写明已完成、问题位置、责任环节和下一步
```

这套方法把学生、AI和教师放回各自可观察的责任中。过程记录保护学生真实做过的判断，成品检查保护物理内容，退回卡把评价重新连接到下一次行动。最后一章将处理更远的一次交付：当项目离开当前课堂和当前维护者，后来的人怎样知道它能说什么、怎样发布、从哪里接手，又在什么情况下应当暂停或撤回。

## 第12章　做成以后，证据、发布和接手怎样安排

一个项目“做成”以后，至少会留下几种不同事实：装置真实存在，程序能够运行，物理模型经过样例核对，页面进入过一节课，材料被公开分享，另一位教师使用过，后来的人能够接手维护。它们可能同时成立，也可能只成立其中一两项。

交付的工作，是给每项事实找到匹配证据，让使用者知道当前版本走到了哪里；给发布安排权限、撤回和维护；再给后来的人一条能够亲自复验的入口。

### 静电场描绘仪留下了四种不同记录

静电场描绘仪有真实整机、五组电极与预测线图片、省赛说明文稿、技术交底书、实用新型申请文件和一份2025年12月16日作出的驳回决定。这组材料很厚，恰好能说明“项目存在”与“项目可以主张什么”之间仍有距离。

装置使用浅水中的稳恒电流场模拟相应边界条件下的静电势分布。若介质电导率近似均匀、内部没有源汇，稳恒电流区的电势满足拉普拉斯方程；无自由电荷静电区域的电势也满足同形式方程。几何与边界电势条件相应时，两种电势分布才具有可比性。有限水槽、有限电极和回流边界始终存在，不能把装置称作无限空间理想电场的精确复制。

说明材料设计了两条操作路径。

第一条从测量到图：用探针寻找近似同电势位置，以彩色标记留下测点，再由测点形成等势线。

第二条从图到测量：把数值模型生成的预测图置于透明水槽下，沿预测等势线移动探针，观察电势是否近似不变，并记录偏差集中在哪里。

两条路径中，同一幅图的证据身份不同。第一条把图作为测量结果，第二条把图作为待检验预测。若将预测图直接称作“标准答案”，学生的任务会退化为给图盖章；把偏差位置与水体、电极、边界、探针和供电条件一起记录，装置才形成模型—测量对照。

现有实物与说明能够证明装置结构、两种操作设计和若干误差来源。45°镜面观察框架与顶部摄像位置能够说明设计意图，不能证明全班后排可见或投屏效果。现有材料没有足够原始数据支持某项测量精度，也没有足够课堂记录支持学生理解改善。

权利文件又是另一层。现有正式文件能确认相关申请在2025年12月16日收到驳回决定，理由涉及部件结构、连接关系和效果实现披露不清。该文件不能被改写为“装置不能工作”或“没有教学价值”，也不能被省略后写成“已获授权”。驳回后是否存在复审、重报或其他状态变化，当前材料无法确认，正式出版与对外宣传前应再次查正式记录。

把这组材料分开，会得到四张卡：

| 层次 | 当前可确认 | 仍缺什么 |
| --- | --- | --- |
| 装置存在 | 整机、电极、结构图和说明材料存在 | 版本对应、共同完成者与图片授权细目 |
| 技术与物理 | 模拟条件、两种操作路径和误差来源可说明 | 原始测点、量化误差、复做记录 |
| 权利状态 | 有申请材料与2025-12-16驳回决定 | 之后是否有正式变化 |
| 教学使用 | 有教学应用设想 | 真实课堂实施、学生动作与效果证据 |

四张卡共同进入交付包，谁也不替代谁。

### 四道门各自留下结论

全书反复使用运行、物理、教学和发布四道门。项目结束时，每道门都要形成独立记录。

**运行门**回答：指定文件能否在指定环境中打开、操作、保存或连接；哪些路径已走，哪些设备未测，哪些检查被跳过。

**物理门**回答：对象、系统边界、公式、单位、数据身份和外部真值是否一致；普通、边界和极端样例得到什么结果。

**教学门**回答：资源服务什么任务，学生仍需完成哪些动作，教师如何组织与观察；若没有真实课堂使用，就写设计用途与待试问题，不补反应和效果。

**发布门**回答：来源、作者、授权、隐私、权利状态、稳定入口、版本、维护者和撤回方式是否齐全。

四门记录可以使用同一格式：

```text
门：运行／物理／教学／发布
检查对象与版本：
检查环境或课堂条件：
实际完成的动作：
通过项与证据：
未检查／未通过项：
当前结论：通过／有条件通过／退回／不适用
责任人和日期：
下一次复验入口：
```

项目可以出现“运行通过、物理退回、教学未试、发布暂停”。这比一个总状态更有用，因为每位接手者知道自己应从哪道门继续。

### 给每条主张标出上限

发布说明中常见的越界发生在动词上。“设计了”“制作了”“运行了”“用于课堂”“改善了学习”“被他人采用”需要不同证据。可以为准备公开的句子逐条填写主张卡。

| 准备说什么 | 最低证据 | 缺证时怎样降级 |
| --- | --- | --- |
| 装置或页面已制作 | 实物、文件、版本和作者 | 仍在设计／有结构方案 |
| 功能能够运行 | 指定环境中的操作记录 | 已实现代码／尚未实测 |
| 物理关系通过检查 | 外部真值、样例和复算 | 已写入模型／待独立复核 |
| 已进入课堂 | 日期、对象、任务与使用记录 | 计划用于／可用于 |
| 产生学习效果 | 合适的学习证据与研究设计 | 观察到某次行为／尚未评价效果 |
| 已被他人采用 | 对方实际使用、修改或作品记录 | 已分享／已提供入口 |
| 已成功接手 | 接手者独立完成修改、复验或故障处理 | 已准备交接材料 |

降级不会削弱真实成果。静电场描绘仪的实物、边界比较和操作设计仍然具有价值；准确写出课堂证据缺失和权利文件状态，读者才能分辨可复做部分与待验证部分。

### 发布分成三个范围

同一项目可以有三个发布范围。

**个人或项目内使用**：原始数据、调试日志、未脱敏记录和待核清单可以保留在受控目录，优先保证追溯与复验。

**小范围审阅**：向作者组、教研组或指定测试者提供必要文件，明确只用于核对，标出禁止转发内容与反馈入口。

**公开发布**：只放经过来源、隐私、权利、物理和稳定性检查的版本；公开页说明适用条件、更新日期、维护入口和撤回方式。

范围扩大前重新检查材料。学生对话在项目内可以用于评价，公开页只使用脱敏代号与授权内容；装置照片可以证明实物存在，出版前仍要确认摄影者、共同完成者和使用授权；外部参考图可以用于内部比较，不自动获得出版许可。

一张发布清单至少包括：

```text
公开对象与目的：
文件和版本：
作者、共同完成者与来源：
图片、数据、代码和文字授权：
隐私与脱敏：
物理适用条件和待核项：
权利或法律状态用语：
稳定入口与更新日期：
维护者与反馈入口：
撤回与替代路径：
```

### 分享、采用、接手和维护分开记录

一个链接被发出以后，后续至少有五个层级。

| 层级 | 最低证据 | 当前材料能够支持到哪里 |
| --- | --- | --- |
| 活动发生 | 邀请、计划、课件、现场记录 | 部分分享与活动有材料 |
| 传播 | 明确对象、场合、版本和交付资源 | 若干分享稿、课程材料和公开入口存在 |
| 采用 | 对方真实使用、作品或课堂痕迹 | 尚未找到匹配原件 |
| 接手 | 对方依据交接包完成修改、部署、复核或故障处理 | 网站已准备迁移说明，尚无他人执行结果 |
| 维护 | 问题—处理—复验—版本记录 | 网站可支持当前维护者多轮维护，跨人维护未证 |

邀请函证明活动或邀请，不能证明听众采用；网站可访问，不能证明另一位教师用于课堂；迁移清单写得完整，不能证明接手者已经独立迁移。

传播记录可以增加三栏：对方真正做了什么，对方遇到什么，材料后来怎样改变。只有出现真实操作、卡点、修改与复验，资源才开始越过“发出去”走向采用和接手。

### 最小接手包让后来的人先完成一件小事

一个最小接手包包含八项。

1. 项目解决的真实问题与当前使用者；
2. 当前有效入口、文件位置和版本；
3. 已完成、未完成和明确停止的范围；
4. 关键物理条件、数据身份与三组验收样例；
5. 最小运行、操作、构建或连接步骤；
6. 已经形成的关键决定和退回理由；
7. 常见故障、回滚、暂停与撤回方式；
8. 接手者第一次变更的任务、结果和复验记录。

数智育才网站已有迁移说明，记录项目性质、关键文件、阶段验收和待办，前七项已经具有较好基础。第八项仍缺：尚没有另一位教师或维护者只依靠交接材料完成一次真实修改、复验或故障处理的记录。

第一次接手不宜选择整站迁移或整套硬件平台。可以选一个风险较低的小对象：修改一个页面的说明文字并跑完对应检查，复核一张数据表，或根据设备台账查明一块板的身份。交接者不口头补隐藏步骤，接手者记录卡点；完成后双方共同修改接手包，再请同一人复做。接手是否成立，以后来的人完成了什么为证据。

### 反馈要进入版本，不停留在消息里

收到“打不开”“数值不对”“学生看不懂”时，先把反馈转成可复核问题。

```text
反馈对象和版本：
发生环境与操作路径：
可观察现象：
是否能复现：
归入运行／物理／教学／发布哪一门：
采用、退回或暂不处理的理由：
修改文件与影响范围：
复验样例：
发布或撤回决定：
```

同一句“数值不对”可能对应单位、输入身份、模型条件或页面旧缓存。先复现，再修改。若无法复现，保留环境与版本，不把反馈删除，也不凭猜测大改。

版本记录要写理由。气垫导轨取消速度自动排序，理由是保留原始实验次序；下一位维护者看到这条记录，就不会为了“方便”重新加回相同功能。稳定决定进入项目规则，具体故障留在版本档案，两者共同保护后续修改。

### 什么时候继续、暂停、撤回或归档

项目维护并不要求永远扩建。四种决定各有适用条件。

**继续**：真实任务仍存在，材料和维护者明确，新版本能够通过相应验收。

**暂停**：关键输入、设备、权限、授权或教师确认暂缺；保留当前版本与停点，不继续生成。

**撤回**：发现物理错误、隐私泄露、权利问题、安全风险或公开版本无法及时修复；停止访问并提供替代说明。

**归档**：任务已经结束、技术路线被替代或维护成本超过当前价值；保存原件、最终状态、已知问题和恢复条件。

一张停止单可以写：

```text
项目与当前版本：
触发决定的问题：
影响的使用者和入口：
当前决定：继续／暂停／撤回／归档
立即动作：
保留的原件与记录：
恢复或重新发布的条件：
负责人和复查日期：
```

暂停和撤回是系统能力。缺少停止出口的自动任务、网站或设备项目，会把维护者困在已经不适合继续的承诺里。

### 本章交付：一个可以被接手的最小项目包

回到第1章选出的首项目。现在把十二章形成的产物放在一起：

```text
问题起点卡
+ AI进入判断卡
+ 数据来路表
+ 物理模型卡
+ 项目Brief与工作区边界
+ 一个最小产物
+ 普通、边界和极端样例
+ 课堂使用与版本观察
+ 设备或页面身份链
+ 系统升格决定
+ 三层资料、项目规则和Skill候选
+ 协作／自动化选择与停止条件
+ 过程—成品评价与退回卡
+ 四门记录、发布清单和接手包
```

这个项目包允许结果保持有限。读者可能只完成一个本地页面，运行门和物理门有记录，教学门尚未试，发布门决定暂停；也可能整理出一套课堂专题，完成真实使用，仍不对学习效果作结论。两种结果都比无法追溯的“已经做成”更可靠。

AI让教师更容易把问题变成页面、图表、教具和网站。项目真正获得寿命，要靠教师把对象说清，把数据留下，把错误退回，把证据停在上限，把发布与撤回安排好。后来的人打开接手包，能够找到原件，复算一组样例，理解一个关键决定，并安全完成第一次修改，这件造物才开始离开一次会话，成为可以继续承担物理教学问题的工作系统。
