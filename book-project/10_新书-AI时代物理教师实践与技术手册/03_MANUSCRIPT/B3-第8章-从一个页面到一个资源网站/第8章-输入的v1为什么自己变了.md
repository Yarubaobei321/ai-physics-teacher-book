# 第8章　输入的v₁为什么自己变了

## 从一个实验页面到资源网站

在气垫导轨实验页面里填入第一只光电门测得的速度，再开始输入第二个速度，刚刚填好的`v₁`突然变了，有时看起来像被清空。

公式和浏览器都在正常工作。页面收到每一个字符时，都会立即比较`v₁`和`v₂`的大小。一旦发现前者更大，程序就交换两个数。学生输入小数，先键入的往往是`0`，排序因此在一个数还没有写完时提前发生。

AI很快定位了触发位置，并给出一个看上去合理的修法：把排序推迟到输入完成或失去焦点以后。程序故障可以这样消失，教师面对的问题却没有消失——实验页面有权替学生交换原始记录吗？

我最终退回了这个方案。两只光电门有先后位置，两次测量也有原始次序。即使后一速度小于前一速度，页面也应当保留它，让学生检查装置、测量、输入和模型。后台悄悄把两个数排成“看起来正确”的顺序，会把异常数据变成顺滑答案，也会拿走一次真实的物理判断。

于是，修改要求从“把排序做得更稳定”变成了“取消自动排序，输入什么就保留什么”。这次退回后来成为我审核教学页面的一条基本规则：AI可以计算、提示和呈现，原始观察与测量记录应保持可追溯；需要修正时，让学生和教师看得见修正理由。

一个页面真正开始具有教学价值，常常就在这样的时刻。它能运行，还要经得起真实对象、物理关系和课堂任务的连续追问。

## 页面先接住一项真实任务

这套页面来自2026年4月的一节《实验：验证机械能守恒定律》公开课。全班分成6组，自由落体、圆柱体沿曲线摆动、气垫导轨三种方案各由2组完成。三个装置测量的对象和物理量不同，课堂任务却有一条共同主线：学生先分析系统和守恒条件，再测量数据、比较能量变化、讨论误差，最后用本组证据完成汇报。

气垫导轨方案研究的是重锤与滑块组成的系统。小车从第一只光电门运动到第二只光电门时，重锤同时下降。页面需要记录重锤质量`m`、滑块质量`M`、重锤在两门之间的下降高度`h`，以及小车先后通过两门时的速度`v₁`、`v₂`，再比较同一过程区间内的两项能量变化：

\[
\Delta E_p=mgh
\]

\[
\Delta E_k=\frac{1}{2}(M+m)(v_2^2-v_1^2)
\]

公式放进页面之前，先要把对象和条件说清。气垫导轨保持水平，分析中忽略阻力和滑轮影响；绳长不变、绳保持拉紧时，重锤下降距离与小车通过两门的水平距离相等。这里的`h`对应两只光电门之间的过程区间，不能随意换成从释放点到任意位置的高度。

**表1　页面字段怎样对应同一物理过程**

| 页面字段 | 学生实际记录什么 | 进入哪一项计算 | 教师要检查什么 |
| --- | --- | --- | --- |
| 重锤质量`m` | 悬挂重物的质量 | `mgh`与系统动能 | 单位换算、每次实验是否改变 |
| 滑块质量`M` | 含遮光条滑块的质量 | 系统动能 | 页面默认值是不是示例值，是否允许按实测调整 |
| 下降高度`h` | 重锤在小车通过两门期间的下降距离 | `mgh` | 是否与两门间距对应，绳是否保持拉紧 |
| 速度`v₁`、`v₂` | 小车先后通过两门的速度 | 动能变化 | 编号按位置和记录次序，不按数值大小重排 |
| 能量比较 | 两项能量变化及相对差异 | 实验判断与误差讨论 | 页面只按既定模型计算，不能替代对系统边界的分析 |

这张表比“请做一个气垫导轨实验网页”更接近可执行要求。它把真实对象、物理量、页面字段和课堂动作放在一起，也把AI不能自行决定的部分暴露出来。

页面的最小任务由此确定：学生手动录入本组原始数据，页面完成单位换算、能量计算和图表呈现，学生依据结果检查实验并准备汇报。串口、蓝牙、模拟数据、自动结论和复杂账户系统都可以以后讨论。第一版先保证这条学习链能从头走到尾。

## 一次程序修补为什么变成了教学规则

自动排序故障经历了四步。

第一步，教师提出了一个未经充分推敲的初始口径：把较小速度记作`v₁`，较大速度记作`v₂`。第二步，AI把这个口径实现为输入过程中的实时比较与交换。第三步，实际试填暴露故障，AI建议延后排序。第四步，教师重新检查教学规则，取消了整个自动排序功能。

取消排序以后，我用一组故意违反“后一速度更大”预期的数据复验：`v₁=2.0 m/s`，`v₂=1.0 m/s`。页面保留原顺序，并按公式给出负的动能增加量。这个结果看起来不漂亮，却真实地告诉使用者：当前记录与预期过程不一致，需要继续检查。

异常数据保留下来以后，教师和学生才有机会追问：两只光电门的编号是否弄反，输入是否错位，导轨是否调平，绳是否松弛，重锤是否碰到地面，模型条件是否成立。页面把答案整理得过于顺滑，反而可能切断这条排错路径。

## 两张照片都像光电门，AI却认成了两种器材

另一次退回发生在双头光电门的实物说明上。

网站保存了两张结构图。一张带外壳，只能从开口看到探头；另一张没有安装外壳，两块电路板和两条光路直接露在外面。AI根据外观差异，把其中一张写成单头光电门，另一张写成双头光电门。

对照实物后，我确认它们都是双头光电门，只处于两种装配状态。页面随后改写了标签、替代文本和说明，把读者注意力引向两组探头和两条固定间距的红外光路。

这一类错误很难只靠语言润色解决。照片中的对象身份、装置结构和测量方式来自真实器材，教师必须回到实物、设计资料或可靠说明核对。AI可以描述它看见的形状，却不知道这两张图在同一装置的制造过程中处于什么阶段。

物理页面第一次介绍真实装置时，我会优先检查五件事：对象名称、结构状态、测量量、数据来源、图片归属。对象一旦认错，后面的公式、动画和操作提示都可能沿着错误身份继续展开。

## 一个功能被删掉，课堂任务反而更清楚

三个实验页面的初期版本都设计过“AI模拟”按钮。点击以后，页面可以快速生成一组数据，图表立即出现。开发和演示时，这项功能很方便；放到学生实验页面里，它会改变任务性质。

公开课要求学生操作真实装置、测量物理量、录入本组数据，再对能量变化和误差作出判断。一键生成的数据如果与真实记录并列出现，学生可能绕过测量，也可能无法区分哪一组数据来自实验、哪一组来自程序。于是，我决定隐藏学生可见的模拟入口，保留手动录入作为课堂主路径。

这次删减没有否定模拟数据的全部用途。开发者可以用它检查页面，教师也可以在明确标注的演示场景中展示理想关系。决定取决于使用者、任务和数据身份。页面面向学生实验时，真实测量应当保持清楚；面向开发测试时，模拟数据可以作为工具，但不能伪装成实验记录。

把一个功能删掉，常常比增加一个按钮更需要教学判断。教师要说明删减保护了什么：是原始数据，是学生思考，是课堂时间，还是对证据身份的区分。

## 三道门把“能运行”带到“能上课”

一个页面通过构建和测试，只说明指定条件下的代码可以运行。物理教学资源进入课堂前，我会再过三道门。

### 第一门：物理模型

先检查研究对象、系统边界、变量、公式、单位和适用条件。气垫导轨页面采用重锤—滑块系统，比较两门之间的能量变化；`h`、`v₁`和`v₂`必须来自同一过程区间。页面算出的数值与公式一致，还不能说明公式已经覆盖真实装置的全部能量形式。

### 第二门：真实对象与数据

装置名称、图片身份、字段含义和数据来源要能够回到实物或原始记录。双头光电门误判暴露了对象检查的重要性；速度自动排序则暴露了数据身份检查的重要性。页面可以提示异常，不能在后台悄悄改写实验记录。

### 第三门：教学任务

从学生打开页面开始，完整走一遍“看任务—操作装置—录入数据—读图—判断—汇报”。检查设备、网络、输入方式、课堂时间和展示动作是否匹配。AI模拟按钮最终被隐藏，正是因为它与这节课的真实测量任务发生冲突。

2026年4月的公开课中，实验数据由学生手动录入。小组代表把记录数据所用的平板连接投屏器，将网页结果投到大屏并完成讲解。这个事实能够说明页面进入了分组实验和汇报环节。它还不能说明学生理解发生了多少变化。课堂反思同时留下了两个限制：每组约8人共用1台平板，操作机会不足；对相对差异和模型误差的讨论还可以继续深入。

三道门把“页面完成”拆成三个不同问题：物理关系站得住吗，数据和对象真实吗，学生的任务走得通吗。任何一门没有通过，都应留下具体退回理由；“整体效果不错”不能代替逐项判断。

## 三个页面放在一起，新增的是责任

气垫导轨页面没有单独留在一次性课件里。自由落体、圆柱体摆动和气垫导轨三个页面共享相近的学习结构：原理说明、数据录入、计算、图表和练习。它们随后进入统一的机械能守恒在线实验室，又通过固定入口进入数智育才网站。

这条生长路径容易给人一种印象：页面多了，就应该做网站。真正促成升格的条件更具体。

第一，多个页面服务同一个清楚的读者任务，放在一起能够减少寻找和切换。第二，它们有可以复用的结构，同时保留各自不同的对象、变量和模型。第三，统一入口能够进入真实课堂、课后任务或教师分享。第四，有人愿意承担链接、版本、图件、物理口径和后续修改的责任。

**表2　一个页面升格前新增了哪些责任**

| 形态 | 适合什么情况 | 新增责任 | 暂不升格的信号 |
| --- | --- | --- | --- |
| 单页 | 解决一项明确任务，使用者和场景单一 | 保证对象、公式、输入输出和基本可用 | 任务尚未走通，页面仍频繁改模型 |
| 专题资源 | 几个页面围绕同一概念或课例 | 统一入口、命名、学习顺序和交叉引用 | 页面之间只有主题相同，没有共同任务 |
| 在线实验室 | 页面与装置、数据、任务和汇报形成完整链条 | 设备适配、数据身份、课堂预演、异常处理 | 只有演示页面，没有真实实验动作或数据路径 |
| 资源网站 | 多类资源需要长期查找、发布、更新和复用 | 导航、固定链接、版权、版本、访问角色和维护责任 | 没有人负责更新，栏目主要为了显得完整 |

这张表带来了本章最重要的新认识：页面升格为系统，意味着责任升级。栏目数量、页面数量和技术复杂度只能描述规模，无法单独说明教学价值。

网站也不需要把所有资源做成同一种工具。机械能守恒页面承担学生数据处理和汇报；动量模拟曾用于教师投屏；项目学习页面承接已布置的任务，但学生网页使用情况尚未核实；科创与智能硬件页面主要用于展示。把这些角色分开，网站的边界会更清楚，维护时也知道应当收集哪类证据。

## 发布以后，还要知道什么时候停

AI降低了增加页面和功能的门槛，也让“继续做大”变得很有诱惑力。每增加一个入口，教师都要承担新的物理审核、内容更新、链接检查、版权处理和解释责任。

我会在以下几种情况下保持单页：任务只有一个，使用者清楚，页面不需要和其他资源共享数据或学习顺序；新栏目只能增加外观，不能增加读者动作；维护人和更新时间尚未确定。

我会在以下情况下考虑升格：相邻页面围绕同一真实任务反复出现；通用结构可以复用；读者需要固定入口；课堂或课后任务需要跨页面完成；错误修正和版本变化需要被统一管理。

我也会撤回或停止扩建：物理模型尚未核清，数据身份混乱，第三方图件授权不明，动态工具已经失效，页面长期无人维护，或者继续增加功能正在挤压学生真正要做的观察、测量和推理。

停止并不等于失败。它让资源保持在当前证据和维护能力能够负责的范围内。

## 给教师直接使用的五张表

下面五张表可以单独取用，也可以连成一条开发路径。第一次尝试时，选择其中一张最能解决当前问题的表即可。

### 工具一：三问选题卡

| 问题 | 填写提示 |
| --- | --- |
| 学生或教师正在面对什么具体对象和困难？ | 写一套装置、一份数据、一个现象或一项课堂动作 |
| 现有做法在哪个环节受阻？ | 写清找不到、看不见、算不动、难比较、难分享或难维护 |
| 页面完成后，使用者能多做哪一个动作？ | 只能写可观察、可操作、可检查的动作 |

如果三个问题还只能得到“提高兴趣”“丰富资源”“体现AI”等宽泛回答，先回课堂寻找更小的对象。

### 工具二：轻量任务书

| 项目 | 要写清的内容 |
| --- | --- |
| 对象 | 哪套器材、哪个物理过程、哪类数据 |
| 使用者 | 教师演示、学生分组、课后自学或开发测试 |
| 核心动作 | 打开页面后必须完成的一条主路径 |
| 物理约束 | 系统边界、公式、变量、单位、条件和异常 |
| 输入与输出 | 数据从哪里来，页面产生什么结果 |
| 当前不做 | 明确删去的功能、接口和角色 |
| 通过条件 | 用什么样例、实物或课堂动作验收 |

“当前不做”能够显著减少首版失控。气垫导轨页面如果一开始同时追求自动采集、模拟数据、账户系统、远程管理和智能结论，教师很难判断究竟哪一部分出了问题。

### 工具三：三重验收表

| 验收门 | 最少检查 | 通过证据 | 退回示例 |
| --- | --- | --- | --- |
| 物理模型 | 对象、公式、单位、条件、过程区间 | 手算样例、独立复算、模型说明 | `h`与`v₁/v₂`不在同一区间 |
| 对象与数据 | 器材身份、图片、字段、原始记录 | 实物核对、原始数据、字段映射 | 页面自动交换两次速度 |
| 教学任务 | 学生从打开到汇报的完整动作 | 任务单、角色试用、设备预演 | 一键模拟绕过真实测量 |

### 工具四：版本退回单

| 项目 | 记录内容 |
| --- | --- |
| 我看到了什么 | 写可复现现象，不先下结论 |
| 它影响哪一层 | 物理模型／对象数据／教学任务／发布维护 |
| 当前版本为什么不能通过 | 写清会误导、会丢失或会阻断什么 |
| 希望修改什么 | 给出目标和边界，允许AI提出多个实现方案 |
| 怎样复验 | 使用同一组样例、同一实物或同一任务再走一遍 |
| 最终取舍 | 接受、继续修改、删除功能、暂缓或撤回 |

自动排序案例的核心退回理由是“页面不应替学生修改原始次序”。退回理由写到这一层，下一次开发相邻页面时才可以复用。

### 工具五：维护责任表

| 对象 | 负责人 | 复核触发条件 | 停止条件 |
| --- | --- | --- | --- |
| 物理口径与公式 |  | 装置、教材或任务变化 | 无法确认模型边界 |
| 页面与链接 |  | 发布、域名、依赖或浏览器变化 | 长期无人维护 |
| 数据与隐私 |  | 开始保存学生数据或作品 | 授权和最小收集范围不清 |
| 图片与版权 |  | 对外发布或出版 | 作者、肖像或许可不明 |
| 课堂任务 |  | 换班级、设备或教学目标 | 页面动作挤压真实学习任务 |

这张表决定一个页面能否进入更大的系统。责任留空时，先保持单页或内部试用，会比建立一个无人维护的栏目更稳妥。

## 教师的判断留在每一个版本里

气垫导轨页面从一个数据表开始，经历了字段、公式、默认值、实物说明、输入规则和课堂入口的多轮修改。AI完成了大量实现和故障定位，教师一次次说明什么可以自动完成、什么必须保留给学生、什么需要退回、什么暂时不做，由此确定了页面的教学性质。

后来，三个实验页面进入在线实验室，在线实验室再进入资源网站。固定网址之外，教师还获得了一条可以复用的路径：从真实问题出发，把对象和任务说清，让AI完成最低充分实现，用物理模型、真实对象与数据、教学任务三道门验收，再根据复用和维护责任决定保持单页、进入专题或继续扩展。

下一次面对一个新问题时，教师不必先问“应该做一个多大的平台”。先做一个能够承担责任的小页面，让它在真实对象和真实任务中暴露问题。页面经得起退回、复验和使用以后，网站才有了生长的理由。
