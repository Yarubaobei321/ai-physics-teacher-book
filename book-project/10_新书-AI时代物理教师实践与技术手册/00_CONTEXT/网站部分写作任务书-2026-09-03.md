# 网站部分写作任务书（2026-09-03）

> 当前停点：本任务书交作者审阅；不在本轮直接生成网站部分正文。  
> 上游裁决：[网站部分重启判断与作者裁决](../04_REVIEW/网站部分重启判断与作者裁决-2026-09-03.md)。

## 一、任务目标

把网站部分从“作者项目怎样发展”的回顾性样章，重建为物理教师可以跟做的AI协作建站指南。

第一轮不追求写完整个部分，只完成一条经过作者和目标读者检验的纵向路径：

```text
一个真实教学任务
→ 一份可交给AI的材料包和要求
→ 第一个本地可运行页面
→ 一组物理与操作验收
→ 一次修改或退回
```

这条小路径成立后，再分批展开单页复用、网站结构、课堂试走、发布和维护。

## 二、要做的事

1. 建立网站部分的定向材料包，只读取完成当前读者任务所必需的原件。
2. 从现有会话、源码和版本中提取真实界面、完整提示词、文件变化、运行结果、错误和教师退回，不用项目总结代替操作证据。
3. 建立网站部分的工作结构，覆盖教学层、物理层、功能层、信息结构层、技术层、验收与维护层；结构只服务写作，不提前冻结正式目录。
4. 先写一个纵向操作单元，让零专业编程基础的物理教师从打开AI开发工具开始，完成一个本地可运行页面。
5. 在操作单元中先讲读者怎样做，再嵌入数智育才网站案例；历史决策只在解释当前动作时出现。
6. 为关键操作配置真实彩图或截图任务：界面全景、项目文件树、提示词与修改前后、页面运行、验收和退回。
7. 依次完成事实、物理、技术、图文、表达和目标读者审查；纵向操作单元不过关，不批量扩写网站部分。

## 三、不做的事

- 不覆盖、删除或继续润色现有三样章第二稿；
- 不按2026年4月的日期和提交顺序重写网站史；
- 不把作者当时作过的全部决策都写进读者正文；
- 不让零基础读者一开始就搭建服务器、数据库、账号系统或完整Astro项目；
- 不把当前Codex界面、模型能力、产品价格或部署方式写成长期不变；
- 不为了“完整”一次写出四五章或预设五万字篇幅；
- 不把代码测试、页面运行、公开课使用或访问情况写成学习效果；
- 不修改或部署线上数智育才网站，不接触部署密钥和学生敏感材料；
- 不为现有材料补造提示词、操作截图、学生反馈或作者回忆。

## 四、第一读者与最低起点

- 第一读者是一线高中物理教师；
- 会使用浏览器、文件夹和常用办公软件；
- 可以用自然语言说明教学需要；
- 不假设会HTML、CSS、JavaScript、Git、终端或Astro；
- 第一轮练习默认在本地完成，不要求服务器、域名和公开发布。

正文首次出现文件、代码、项目、预览、构建、版本等术语时，立即用一句日常语言说明对象和作用。

## 五、工作结构候选

下面五个任务单元用于材料分工和样章压力测试，不是正式目录。

### 单元一：先决定网站为谁解决什么问题

- 从教材、学案、课堂困难或现有资源进入；
- 明确教师、学生和其他使用者；
- 写出课前、课中、课后的主要动作；
- 比较网页、表格、演示文稿、仿真和实体教具，判断网站是否是最低充分媒介；
- 形成一页网站任务卡：目的、使用者、核心页面、输入输出、当前不做什么和完成标准。

### 单元二：从打开AI工具到第一个页面运行

- 认识工作区、项目文件夹和对话区；
- 准备可交给AI的材料，处理隐私与版权；
- 写第一条完整需求；
- 让AI先复述理解和列出文件计划，再生成最小页面；
- 在本地打开页面，理解“文件已经生成”和“网页已经运行”的区别；
- 修改一次可见内容，并保留修改前版本。

### 单元三：让教学页面遵守物理与数据规则

- 冻结研究对象、原始量、派生量、公式、单位、参考点和数据身份；
- 区分学生输入、程序计算、演示数据、实测数据和结论；
- 加入表格、图像、异常提醒和导出；
- 使用普通值、边界值、反预期值和独立手算检查页面；
- 用自动排序故障说明：程序忠实执行错误规格时，教师怎样撤销规则。

### 单元四：从一个页面发展为网站

- 区分必须共享的页面能力和必须重新裁决的物理模型；
- 设计首页、栏目、页面和导航；
- 认识公共组件、页面文件、数据文件和静态资源；
- 说明单文件方案何时足够，何时值得进入Astro等项目框架；
- 用数智育才网站解释机械能三页、在线实验室和多功能门户怎样形成关系。

### 单元五：让网站进入课堂并能够继续维护

- 在目标平板、投影、网络和课堂时间中试走；
- 准备手动输入、离线文件和器材故障退路；
- 区分运行、物理、教学和发布四类验收；
- 处理学生隐私、图片与材料授权、演示与实测身份；
- 完成构建、发布、冻结版本、回滚、下线和维护责任；
- 判断什么时候继续扩建，什么时候保留单页或停止。

## 六、当前最小纵向样章

第一轮只写“单元二”的一个完整小节，并调用单元一已经冻结的任务卡：

> 一位物理教师怎样把一份教学任务交给AI，在本地得到第一个可以打开的教学页面，并完成第一次修改和验收。

### 本节必须实际出现

- AI开发工具首次打开后的界面全景与区域说明；
- 新建或选择工作文件夹；
- 教师准备的最小材料包；
- 一段可以完整阅读的真实或明确标为重构模板的提示词；
- AI对任务的理解与文件计划；
- 生成后的最小文件树；
- 打开页面的真实动作和结果；
- 一次教师提出修改、AI修改、教师复验的完整循环；
- 一张本节验收单；
- 一个常见失败及其“现象—原因—检查或修正”路径。

### 本节暂不承担

- 完整机械能公式与数据处理；
- 三个实验方案的页面复用；
- BLE、Web Serial和ESP32接入；
- Astro项目架构；
- 服务器部署和Cloudflare维护。

这些内容只有在第一节的零基础路径被作者和目标教师确认可跟做后，才进入后续单元。

## 七、最小工作流

### 1. 章前价值共识

本任务书与上游裁决共同回答：核心读者问题、核心价值、展开顺序、材料、读者所得、细节处置和跨单元边界。作者确认后进入材料深挖。

### 2. 定向材料与事实包

每次只处理当前操作单元需要的材料。建立：

- 材料与用途清单；
- 真实提示词与界面记录；
- 文件变化与版本锚点；
- 可以写、不能写和待作者补充；
- 截图与彩图任务表。

已有可靠材料卡和开发记录直接复用，不重复生成第二套全库摘要。

### 3. 内容结构与视觉策划

先确定读者操作顺序，再选择案例片段。每幅图说明读者要看什么、看后能完成什么；界面截图必须与正文所讲版本一致。

### 4. 完成一个纵向操作单元

正文按照“指导—操作—原因—案例—验收”推进。关键动作不能全部推给二维码、附件或配套网站。

### 5. 六类审查

1. **事实审查**：操作、日期、提示词和版本能够回到原件；
2. **物理审查**：公式、单位、数据身份和结论边界由独立依据检查；
3. **技术审查**：目标环境中按正文重新操作，读者得到相同类型结果；
4. **图文审查**：实际版面中能看清界面、提示词、文件树和修改差异；
5. **表达审查**：执行[AI Agent文本写作表达门禁](../../../docs/agents/AI-Agent文本写作表达门禁.md)；
6. **目标读者审查**：至少2位未参与项目的一线物理教师按正文操作，记录卡点，不只回答“看懂了”。

### 6. 分批生长

第一个纵向操作单元通过后，每批推进1—2个网站任务单元；每批重新执行章前价值共识、材料核查和表达门禁。实际材料不足时转为补截图、复做、访谈或技术核对，不用概念段落补齐。

## 十一、风险与回滚

| 风险 | 控制方式 | 回滚方式 |
| --- | --- | --- |
| 又写成作者项目史 | 先写读者动作，再选案例；每段执行段落价值门 | 撤回到结构与材料包，保留案例事实，不润色流水账 |
| 变成通用前端教材 | 只解释物理教师完成当前任务所需的最小概念 | 删除不服务教学网站任务的技术扩展 |
| 工具界面快速过时 | 纸书保留稳定动作，动态界面进入配套网站并标复核日期 | B6重截界面，不改核心方法链 |
| 一开始技术门槛过高 | 第一级采用本地单文件，第二级才进入Astro网站 | 保留第一级为独立可完成路线 |
| 案例证据侵入正文 | 版本、授权和证据台账留在后台；正文只保留改变操作的边界 | 从正文移回事实档案或章末来源说明 |
| 现有文件被覆盖 | 新稿建立独立目录；旧样章和网站仓库只读 | 删除或停用新目录即可恢复原状态 |
