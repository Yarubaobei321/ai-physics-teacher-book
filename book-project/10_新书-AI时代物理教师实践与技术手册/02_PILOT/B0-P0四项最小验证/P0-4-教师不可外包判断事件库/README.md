# P0-4 教师不可外包判断事件库

## 目的

从本书已经回查过的一手项目材料中，找出教师必须亲自定义、核对、退回、停止或签字的节点。事件库不是抽象宣言，也不虚构课堂故事；每张卡都要能回到具体材料。

## 当前产物

- `教师判断事件库.csv`：20 个事件，统一记录对象、候选输出、风险、教师动作、证据与最后状态。
- `事件库分析与训练用法.md`：说明这些事件如何归纳成读者工具，以及哪些结论现在仍不能说。
- `tools/validate_events.mjs`：检查事件数量、字段完整性、分类、证据等级和源文件是否存在。

## 证据等级

- **A—已记录历史行动**：材料明确记录了教师当时发现问题、纠正或删除功能的行动。
- **B—本轮审计裁决**：基于已核验的一手项目材料作出的当前判断。它可以进入审核方法和待办，不得改写成过去已经发生的课堂事件。

本轮没有 C 级计划卡进入正式事件库。未来设想、待开发功能和未经核验的课堂效果留在各来源文件的待确认区。

## 五类判断

1. **定义问题**：先决定这项功能要为哪一个教学任务负责。
2. **定义测量**：说明对象、变量、单位、数据身份和处理算法。
3. **审查证据**：判断材料能支持到哪一层，主动拒绝越界主张。
4. **决定干预**：发现错误后，选择退回、修改、复测或改变课堂入口。
5. **决定停止**：在权利、证据、维护或高风险判断不清时暂停发布与扩张。

## 运行检查

在本目录执行：

```bash
node tools/validate_events.mjs
```

通过只表示事件卡结构完整、源文件存在，不表示教学效果或教师共识已经得到验证。
