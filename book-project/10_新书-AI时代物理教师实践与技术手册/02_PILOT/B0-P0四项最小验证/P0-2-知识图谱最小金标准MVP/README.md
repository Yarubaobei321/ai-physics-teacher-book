# P0-2　“动量与碰撞”知识系统最小金标准 MVP

> 状态：B0 本地最小验证，可运行、可审查；尚未经第二位教师审定，也没有真实学生数据。  
> 数据边界：20 道题全部自编，3 名“学生”全部为合成轨迹；未使用培训团队、商业平台或学校的题库、图谱、提示词、算法与数据。  
> 建立日期：2026-08-30

## 这个 MVP 要回答什么

同一个“动量与碰撞”单元，依次增加四层后，教师究竟多看见了什么：

1. **章节标签**：只知道题目属于“动量与碰撞”；
2. **内容图谱**：知道概念之间的前置与依赖关系；
3. **Q-matrix**：知道每道题声称调用哪些知识组件；
4. **简单动态状态**：根据连续作答，生成一组可解释、可更新的诊断假设。

这里的“金标准”指一套可以逐项人工审查的最小事实源，不表示它已经是真实教学中的最终标准，也不表示模型概率就是学生真实掌握度。

## 最快使用

在本目录执行：

```bash
python3 src/build_mvp.py
python3 -m unittest discover -s tests -v
```

然后打开：

- `generated/index.html`：本地审阅页；
- `generated/comparison.md`：四层比较和三组合成诊断；
- `generated/student_state_updates.csv`：每次作答后的状态更新明细。

脚本只使用 Python 标准库，不访问网络，不调用外部 API。

## 事实源

| 文件 | 作用 | 人工仍需裁决什么 |
| --- | --- | --- |
| `data/knowledge_components.csv` | 10 个知识组件的定义与边界 | 粒度是否适合本校教材、备课与评价 |
| `data/graph_edges.csv` | 内容图谱中的前置关系 | 每条边是否必要，是否只是教学顺序偏好 |
| `data/rejected_edges.csv` | 已明确否决的候选边 | 否决理由是否成立，是否需保留为另一种路径 |
| `data/questions.csv` | 20 道自编题及答案要点 | 题干、答案、难度、表征和物理正确性 |
| `data/q_matrix.csv` | 题目与知识组件的多对多映射 | 一题多组件时，错误究竟归因于哪一组件 |
| `data/synthetic_responses.csv` | 3 组合成作答轨迹 | 只用于测试信息层差异，不可解释为真实学习规律 |
| `data/model_parameters.csv` | 演示用状态参数 | 参数未由样本估计，不适合据此分层或评价学生 |

## 当前最重要的发现

- 章节标签能汇总总分，但无法区分“符号方向”“守恒条件”“碰撞分类”等不同缺口。
- 内容图谱能提示应回查哪些前置组件，却没有测量证据，不能定位学生状态。
- Q-matrix 能按组件聚合作答证据，但多组件题会产生归因歧义。
- 动态状态能保留顺序并随新证据更新，但输出只是一组依赖模型和参数的诊断假设。
- LLM 在本 MVP 中没有参与状态估计。它以后最多承担“把已核验状态和规则表述成自然语言”的语言层，不能生成掌握真值。

## 教师不可外包的裁决

1. 节点是否过粗或过细；
2. 前置边是物理依赖，还是某种教学顺序；
3. 每道题实际测到了什么，是否存在替代解法；
4. 错误应归因到哪个组件，还是题意、计算、表达造成；
5. 下一步给复测、追问、讲解还是暂不干预；
6. 什么时候停止使用模型结论并回到原始作答。

详见[教师裁决与证据边界](./教师裁决与证据边界.md)。

## 完成边界

本轮已经完成离线事实源、四层比较、三组合成状态更新和自动检查。尚未完成第二位教师独立标注、真实学生试测、题目难度与区分度估计、参数拟合、延迟复测或教学效果比较。因此只能说“最小结构可运行并暴露了关键归因问题”，不能说“知识图谱提高了学习效果”或“系统准确诊断了学生”。
