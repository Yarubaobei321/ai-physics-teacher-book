# Agent时代教师开发方法：价值增量总案

> 状态：写作准备稿，等待作者裁决；不等于全书目录已调整。  
> 形成日期：2026-08-30。  
> 任务边界：本稿只做价值提炼、章节安放和写作设计，不直接生成章节正文，不改动参考书、课程逐字稿、网站代码及现有十六章价值地图。  
> 主要材料：`B0-REF-AI-001`（AI橙皮书系列）、`B0-REF-AI-002`（WorkBuddy实战蓝皮书）、`B0-CONTED-001`及其v4课程/脚手架、`B0-D2-M4`及数智育才网站仓库。  

## 一、先给结论

这组材料能够为本书增加一条目前仍不够清楚、但非常重要的主线：

> **物理教师使用AI的基本单位，正在从“一次回答”转向“一个可检查、可回退、可积累的真实项目”。教师的核心能力也随之从写提示词，扩展为界定问题、组织材料、配置边界、设计验证、保存版本和沉淀方法。**

这一增量不宜写成“ZCode教程”“Codex教程”或“WorkBuddy教程”。工具界面、套餐、模型和按钮会快速变化；更稳定、也更有出版价值的是一套跨工具的方法：

```text
真实教学问题
→ 可执行任务
→ 受控工作区
→ Agent行动循环
→ 教师专业验收
→ 版本与证据留痕
→ 稳定方法沉淀为Skill
→ 经验证后再复用、协作或自动化
```

本书真正能超出通用Agent指南之处，是把这套方法转译成“教师工程”：Agent可以完成文件读取、页面实现、运行检查和修改；物理教师负责研究对象、模型条件、公式与单位、学生动作、课堂节奏、隐私版权和最终发布。工具能换，责任链不能换。

## 二、为什么这是本书的重要价值增量

### 1. 它补上了“从简单生成到真实开发”之间缺失的一层

当前多数面向教师的AI内容集中在对话、文档、课件和单页生成。这些内容仍有价值，但不足以解释长任务为什么容易跑偏、怎样让AI读取项目资料、怎样限定可修改范围、怎样发现错误、怎样退回上一版，以及怎样让经验在下一次任务中继续生效。

Agent带来的变化不只是一种新界面。通用材料把它概括为：围绕目标观察环境、调用工具、读取结果、修正计划，直到交付或触发停止条件。进入真实项目后，错误不再只是“一句话答错”，还可能变成文件被改、物理模型被悄悄替换、隐私被外发、错误版本被发布。因此，能力升级必须与边界、验证和回退同时讲。

### 2. 它让教师的专业优势有了可操作的落点

继续教育课程已经形成“教师提需求、AI做实现、教师做验收”的教学主线；网站实践进一步证明，教师还要把自研器材、物理模型、课堂动作和发布条件持续写进项目。由此可把教师职责从一句口号细化为四道验收门：

| 验收门 | 主要问题 | 谁承担最终责任 |
| --- | --- | --- |
| 运行门 | 页面能否打开，按钮、数据、构建和链接是否正常 | Agent可执行检查，教师确认使用路径 |
| 物理门 | 对象、系统边界、公式、单位、极限状态和数据身份是否正确 | 物理教师 |
| 教学门 | 是否直指学生难点，学生要做什么，课堂时间与设备是否匹配 | 任课教师 |
| 发布门 | 证据强度、隐私、版权、署名、访问范围和回退方案是否合格 | 作者/教师/项目负责人 |

通用Agent书强调“验证”；本书可以把“验证”具体化为物理教学中的四道门。这是本书可形成原创贡献的地方。

### 3. 它能把现有零散材料连接成一个系统

现有材料中已经分别出现：

- 第3章候选的任务书、输入输出和验收边界；
- 第6章候选的物理成品核查；
- 第8章的公开课网站与资源聚合；
- 第15章的主张和证据上限；
- 第16章的版本、课程、检查表和技能复用；
- 继续教育课程中的PRD、项目规则、Skills、Git与验收清单；
- 网站仓库中的`AGENTS.md`、构建/测试规则、分支、提交、回退和部署边界。

缺少的是一章把这些读者工具连接起来，说明它们为什么共同构成Agent项目，而不是一组零散技巧。

## 三、建议放在哪里

### 推荐方案：用第7章释放章位作为“方法桥梁”

建议候选章名：

> **第7章　从一次对话到一个可验收的项目**

备选：

- AI不只回答问题：物理教师怎样带领Agent完成开发
- 网页做出来以后，怎样让下一次开发不再从零开始
- 给AI一个工作间：规则、技能、验收与版本怎样协同

放在第7章的结构理由：

1. 第3章已经教读者把课堂困惑写成任务，但尚未回答任务怎样在多轮开发中保持方向。
2. 第4—6章分别让读者看见教具、测量和物理核查；读者此时已理解“做出东西”和“判断东西”是两回事。
3. 第7章可以把任务、工作区、规则、Skill、循环、版本和权限组织成一套项目方法。
4. 第8章紧接真实网站案例，展示这种方法怎样承接多页面、共同入口和长期维护。

这能形成自然递进：

```text
第3章：把问题说清
→ 第4—6章：把对象做出并核查
→ 第7章：把多轮开发组织成项目
→ 第8章：让项目进入网站与真实教学
→ 第15章：判断证据能说到哪里
→ 第16章：把稳定经验留下并传播
```

### 备选方案：不占独立章位，分散进入五章

若作者决定保留第7章“作业—诊断—干预”方向，则不要另加一章硬挤十六章。可采用“主线分布＋配套资源”方案：

| 内容 | 放置位置 |
| --- | --- |
| 对话与Agent任务的区别 | 第1章一页认知框 |
| 六要素任务单、PRD、首版边界 | 第3章 |
| 独立验证、能说“不”的检查 | 第6章 |
| Codex＋ZCode网站开发实录的紧凑案例 | 第8章 |
| 工具成功与教学有效的证据差异 | 第15章 |
| Skill、版本、自动化与跨工具迁移 | 第16章 |
| 安装、按钮、命令和最新界面 | 配套数字资源 |

这个方案结构较稳，但读者不容易获得一张完整的Agent项目地图，价值增量会弱于独立第7章。

## 四、第7章候选章节任务书

### 1. 章节承诺

读完本章，零编程基础的物理教师应能：

1. 分辨聊天生成、Agent任务和长期项目的差别；
2. 为一个小型教学网页建立受控工作区；
3. 写出包含目标、材料、动作、约束、交付和验收的任务单；
4. 知道项目规则、Skill、工具、版本与检查点各自解决什么问题；
5. 在功能、物理、教学和发布四道门上保留教师裁决；
6. 判断什么时候只需一次任务，什么时候值得固化为Skill，什么时候暂不自动化。

### 2. 章节不能承诺

- 不承诺读者学完即可独立开发完整网站；
- 不宣称“不会Agent的教师已经落后”；
- 不把某一产品的市场热度、模型排名、免费额度或当前按钮位置写成长期事实；
- 不把Agent自检、测试通过或页面能运行等同于物理正确、课堂有效或学习效果提升；
- 不把课程设计、作业要求和预期作品写成教师培训已经产生的效果；
- 不把Skill描述成安装后必然稳定、跨工具无差异兼容的万能能力。

### 3. 建议开篇场景

不用行业术语开篇。可从一个读者熟悉的反差进入：

> 第一次让AI做网页，教师发一句需求，几分钟后页面出现了。第二次继续修改，它却忘了上一轮的约定；改公式时连配色一起变了；修好动画后习题按钮又坏了；页面能打开，某个极端参数下的物理关系却不成立。问题已经不在“提示词够不够漂亮”，而在整个项目有没有规则、检查和回退。

这段只能作为概括性情境。进入具体错误时必须换用已有真实记录，不编造网站故障。

### 4. 建议正文结构

#### 第一节　对话里做得出来，换个任务为什么又从零开始

- 从教师熟悉的网页对话、文档生成进入。
- 说明聊天输出、Agent任务、项目系统三个层次。
- Agent的关键变化是能够围绕目标读取资料、使用工具、修改文件、检查结果并继续推进。
- 风险同步增加：行动范围、停止点、记录和回退必须可见。

读者工具：**AI任务层级判断卡**。

#### 第二节　先把任务交代清楚，Agent才有机会做对

- 使用“目标—输入—动作—约束—输出—验收”六要素。
- 接入本书第3章的对象、使用时刻、学生动作、物理约束和首版边界。
- 用继续教育课程的PRD模板展示怎样把验收前置。
- “先复述、再执行”只是一种确认点；复杂任务还应确认材料范围、可修改目录和交付位置。

读者工具：**一页任务Brief＋教学难点—功能对照表**。

#### 第三节　项目文件夹会替教师记住规则

- 工作区用于隔离任务、材料和产物，不能默认让Agent访问整台电脑。
- 项目规则文件只写AI无法自行推断、且每次都应遵守的内容：对象、目录、禁区、构建/检查、什么算完成。
- 模板保证交付结构；版本记录保存每个可用节点；检查表防止“看起来完成”。
- 用数智育才网站`AGENTS.md`和教学网页脚手架作实物，不展开代码细节。

读者工具：**教师Agent项目最小工作台**：问题卡、任务单、规则、Skill、验收表、版本、反馈记录。

#### 第四节　做对三次的方法，才值得变成Skill

- Prompt解决这一次；任务卡让同类任务可填写；SOP固定步骤；Skill再把说明、参考、脚本、模板和测试组织成可调用方法。
- 只有重复成功、边界清楚、输出可验收的流程才进入Skill。
- 以“物理交互模拟”和“生成分层习题”两个本地Skill为候选例子，重点审查触发条件、输入、步骤、边界和完成标准。
- Skill是方法封装，不替代学科审核；第三方Skill先查来源、权限和外发范围。

读者工具：**是否值得沉淀为Skill的五问**。

#### 第五节　循环里必须有一个能说“不”的检查

- 把Agent循环翻译为教师语言：读任务和材料—列计划—小步实现—运行与观察—给证据修正—四门验收—保存版本—决定继续、退回或停止。
- 区分AI的自检和教师的独立核验。
- 物理检查优先使用可手算特殊点、极端值、守恒量、单位和模型边界；课堂检查使用学生完整操作路径。
- 自动化程度越高，检查点、日志、告警和停用方法越要明确。

读者工具：**Agent开发循环图＋四道验收门**。

#### 第六节　工具可以更换，教师的责任链不能更换

- Codex＋ZCode路线：适合基于代码仓库持续开发、构建、测试、版本和部署；数智育才网站提供本地证据。
- WorkBuddy路线：本地蓝皮书展示了工作区、任务说明、Skill、工具/连接器、专家团和自动化的桌面路线，也包含网站开发案例。
- 两条路线用同一张映射表呈现，不逐屏教学，不评判哪一款“更先进”。
- 产品的安装、按钮、价格、模型和最新功能放入可更新的配套数字资源。

读者工具：**跨工具迁移表**。

### 5. 章节收束

建议用一张“第一次Agent开发清单”结束：

1. 我解决的是哪个真实教学问题？
2. Agent可以读取哪些材料？
3. 它能改哪里，哪些地方禁止碰？
4. 交付物放在哪里，什么状态算完成？
5. 哪些检查可以自动做，哪些必须由教师做？
6. 哪个节点需要先确认再继续？
7. 如果改坏了，怎样恢复并知道改过什么？

- 第3章结尾：“任务写清以后，还要给Agent一个受控工作间，见第7章。”

- 第8章结尾：“网站上线不等于有效；证据上限见第15章，长期维护见第16章。”

## 六、跨工具共同原理与差异边界

| 共同问题 | Codex＋ZCode开发路线 | WorkBuddy桌面路线 | 本书稳定写法 |
| --- | --- | --- | --- |
| 任务是什么 | 需求、项目文件、构建目标 | 自然语言任务、授权材料、交付物 | 六要素任务Brief |
| 在哪里工作 | 代码仓库/项目目录 | 任务工作区/授权目录 | 每项任务有受控工作区 |
| 怎样记住规则 | 项目规则、文档、Skills | 工作区说明、Skills、专家配置 | 规则写进项目，不依赖长对话 |
| 怎样行动 | 读写文件、运行命令、预览、测试 | 文件、办公工具、连接器、脚本 | 工具和权限决定Agent能做什么 |
| 怎样检查 | 构建、测试、审查、浏览器/人工验收 | 结果预览、检查点、人工验收 | AI自检＋独立验证＋教师四门验收 |
| 怎样回退 | Git提交、分支、差异、部署回滚 | 隔离目录、版本/备份、运行记录 | 重要操作必须留痕且可恢复 |
| 怎样复用 | 规则、模板、Skill、自动化 | Skill、专家团、自动化 | 先重复成功，再固化与自动化 |

此表表达的是方法同构，不证明各工具的具体Skill格式、权限模型或自动化能力完全兼容。出版前仍需按当时版本逐项核验。

## 七、正文与配套数字资源怎样分工

### 进入纸质书的稳定内容

- 对话、任务、项目、系统的层级变化；
- 六要素任务Brief；
- 工作区、规则、工具、权限、检查点、版本的作用；
- Skill的触发、步骤、边界、输出和测试；
- 教师四道验收门；
- 何时用单Agent、多Agent、工作流或自动化的判断原则；
- Codex＋ZCode与WorkBuddy的跨工具概念映射；
- 来自真实网站和课程的本地实物与失败边界。

### 放入配套数字资源的动态内容

- ZCode、Codex、WorkBuddy的安装、登录、价格、额度和模型选择；
- 当前界面位置、快捷键、按钮名称和截图；
- 最新Skill安装方式、插件市场和连接器清单；
- 部署平台、备案网址、云服务价格与操作视频；
- 可下载的项目脚手架、任务卡、Skill样例和验收表。

数字资源应标注核验日期和适用版本，过期后可以更新，不拖累纸质书。

## 八、写作口吻与叙事原则

1. 不使用“还停留在网页对话的人已经落后”作为正文判断。它容易让目标读者在进入方法前先被划分等级。
2. 用任务差异呈现变化：“聊天适合解释和起草；Agent适合在授权范围内推进一个可交付任务。”
3. 不神化“思维链”。正文引导读者查看计划、操作记录、文件差异、运行日志、测试结果和解释；这些才是可审查证据。
4. 不用“AI做不了物理判断”的绝对表述。更准确的写法是：“AI可以参与计算和候选核查，但其自检不能替代教师对模型、课堂和发布的最终判断。”
5. 不把编程术语当作门槛。首次出现工作区、Skill、版本和回退时，用教师熟悉的“备课文件夹、流程卡、教案版本和撤回”类比一次，然后回到准确术语。

## 九、当前最值得形成的三个读者成果

### 成果一：一页“教师Agent项目最小工作台”

包含：三问选题卡、六要素任务Brief、项目规则、一个必要Skill、四门验收表、版本节点和一次课堂反馈记录。读者下载后能直接建立自己的第一个项目。

### 成果二：一个“双工具同题”演示

选择一个材料充分、风险较低的小任务，例如给既有教学页增加一项可验收功能。在Codex＋ZCode路线和WorkBuddy路线中分别执行，比较任务说明、材料授权、工作区、计划、修改、验收和留痕。比较的是方法，不比较生成速度或审美分数。

### 成果三：一个“物理教学Skill”样例

从现有“物理交互模拟”Skill中选一个边界清楚的子任务重做：明确触发条件、输入、分步动作、禁止事项、特殊点测试、输出格式和教师确认点。它既是书中案例，也是第16章“专业经验怎样留下来”的实物。
