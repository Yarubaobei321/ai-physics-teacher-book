## 五、四份可直接交给Agent的检查任务

这些任务只负责产出候选证据，不能替教师签字。为降低自我说服，最好在实现任务结束后开启一个干净检查任务，检查者只读取冻结Brief、当前交付和验收标准，不读取生成者的辩护性总结。

### 1. 运行检查任务

```text
你是独立运行检查者。不要修改文件，先锁定我指定的页面、版本、地址和设备条件。
按项目已有规则运行构建、测试和数据校验；再从普通使用者入口走完核心路径，检查空值、边界值、反复操作、重置、导出和外部依赖。
不得用另一个端口、旧构建、替身服务或“代码看起来正确”代替目标对象。
把每一步的命令、退出状态、预期、实见和证据路径写入运行记录。
结论只能是：通过、退回、暂停待确认、停止。不要自行修复。
```

### 2. 物理检查任务

```text
你是物理审查助手，不是最终裁决者。先从材料中提取研究对象、系统边界、时空区间、假设、变量、单位、公式、方向和数据身份，生成物理模型卡。
准备标准、边界、极端、反预期和独立基准样例，实际运行当前冻结版本并记录输出。
特别检查页面是否排序、平滑、补全、替换或隐藏原始数据；检查图像、字段、导出和说明是否使用同一口径。
不得把自己的代码解释当作独立证据。缺少原件时标记暂停，不得补猜。
```

### 3. 教学走查任务

```text
你是教学路径检查助手。只根据冻结任务和目标学生，逐步写出学生要观察、操作、比较、解释和汇报什么。
从学生入口走完页面，记录页面是否替学生完成了关键判断，是否把模拟或默认数据伪装成实测，是否需要开发者现场提示才能完成。
同时检查课堂设备、分组、时长、投屏、网络和失败替代方案。
把证据分成设计走查、小范围试用、真实课堂、效果证据四级，不能自动升级表述。
```

### 4. 发布检查任务

```text
你是发布前检查助手。不要执行部署。
核对文字、图片、学生作品、代码、字体和数据的来源、授权与署名；扫描学生身份、密钥、本地绝对路径、外发域名和不必要权限；核对本地、冻结版与线上状态的区别。
为每个公开主张写出证据来源，找不到证据就降级或暂停。
最后生成发布版本、公开范围、回滚步骤、维护负责人和下线条件清单。结论只能是通过、退回、暂停待确认、停止。
```

## 六、真实案例演练：`v₁/v₂`自动排序为什么必须被退回

### 1. 已核事实

第一方材料记录了这条开发链：教师最初用数值大小表达`v₁/v₂`，AI把口径实现为输入过程中的实时比较与交换；实际试填暴露输入尚未完成就发生排序，AI首次建议将排序延后；教师重新检查实验含义后取消整个自动排序，因为两次速度由光电门位置和测量次序确定，异常记录应被保留供检查。

2026年8月的冻结副本复验使用`v₁=2.0 m/s、v₂=1.0 m/s`的反预期输入，页面保留原次序，并按当前公式给出负的动能增加量。公开课材料支持学生手动录入、平板投屏和小组讲解；这些事实不能证明学习效果、自动采集、线上当前版本或所有浏览器长期稳定。

来源：

- `03_MANUSCRIPT/B3-第8章-从一个页面到一个资源网站/第8章-输入的v1为什么自己变了.md` 7—13、45—63、83—105行；
- `01_SOURCE/B3/01_样章资料深挖与引用矩阵.md` 30—38、46行。

### 2. 如果只过运行门，会发生什么

早期页面可以启动、接受输入、进行计算；若检查者只看“无报错、结果出现”，很可能给出通过。实际逐字符输入时，排序在数字未写完前触发，运行门应先退回“输入路径错误”。

AI提出“失焦后再排序”后，这个程序故障可能消失，运行门也可能通过，但问题仍未解决：程序只是更稳定地执行了一个不应存在的教学规则。

### 3. 物理门怎样发现根本问题

| 检查 | 发现 |
| --- | --- |
| 字段对应什么 | `v₁/v₂`对应先后两只光电门的测量，不对应较小值／较大值 |
| 数据身份 | 两个输入是原始测量记录，页面无权静默交换 |
| 反预期样例 | `v₁>v₂`应保留，作为装置、测量、输入或模型检查线索 |
| 修正原则 | 删除自动排序；若需要修正，显示原值、修正值和理由 |

因此物理门的退回理由不是“排序时机不对”，而是“数值排序破坏了原始记录的时序身份”。这个理由可以迁移到传感器平滑、异常值删除、AI补全和模拟数据混入等相邻问题。

### 4. 教学门为什么再次支持删除功能

公开课的学习动作包括真实实验、记录数据、录入页面、比较能量并汇报。后台自动把异常数据排成“更合理”的顺序，会拿走学生检查装置、输入和模型的机会。教学门因此提出：

- 原始记录必须保留；
- 页面可以提示异常，不能悄悄修正；
- 模拟数据入口不得与真实测量主路径混淆；
- 负结果可以成为讨论起点，不需要被美化成符合预期。

### 5. 发布门怎样限制结论

截至当前材料，可以写：

> 冻结副本在指定输入下保留`v₁/v₂`原始次序，并完成当前公式下的计算；公开课材料支持学生手动录入与投屏汇报。

不可以写：

- 线上当前版本已经完全一致；
- 自动采集在课堂稳定运行；
- 页面提高了学生理解或降低了错误率；
- 全部浏览器、设备和参数都已验证。

这说明发布门既审查技术发布，也审查书稿中的表述上限。

### 6. 四门最终记录示例

| 门 | 早期排序版 | 取消排序后的2026年8月冻结副本 | 当前证据边界 |
| --- | --- | --- | --- |
| 运行门 | 退回：逐字符输入触发错误交换 | 指定核心路径与输入复验通过 | 不等于线上当前版长期稳定 |
| 物理门 | 停止该规则：破坏测量时序身份 | 指定模型和样例通过 | 真实系统未建模因素仍需说明 |
| 教学门 | 退回：拿走异常检查 | 真实课堂中进入手动录入与汇报环节 | 不证明学习效果 |
| 发布门 | 不允许按“已完成”发布 | 冻结副本可作本地案例证据 | 线上状态、图片授权和出版图件另核 |

## 七、教师培训怎样使用这个案例

建议不先讲四道门定义，而先给教师看同一个结果：“页面能够计算，但`v₁/v₂`被自动调整。”让四组教师分别承担运行、物理、教学、发布检查：

1. 运行组复现输入路径，只回答“程序是否按指定路径工作”；
2. 物理组填写字段—对象—单位表，并设计反预期样例；
3. 教学组写出学生动作，判断自动排序拿走了什么；
4. 发布组判断哪些事实可以写进公开说明，哪些仍缺证据；
5. 四组交换退回单，最后共同决定“修排序”还是“删排序”。

这个活动的关键反转是：程序修得更稳定，可能仍然不应通过。教师由此能亲自体验，四道门不是四遍重复检查，而是四种不同的专业问题。

## 八、模板试用后的反哺规则

每完成一个真实项目，做一次短复盘：

- 哪一项检查真正抓住了问题；
- 哪一项只是重复、应删除；
- 哪一项能机械化为脚本或Hook；
- 哪一项必须保留教师签字；
- 哪个退回理由可迁移到其他项目；
- 哪个结论只是临时环境状态，不应写入永久规则或Skill。

只有在多个项目中重复抓住同类问题的检查，才值得进入稳定模板或教师Skill。
