# 教材主题结构化数据规范

> 版本：1.1  
> 权威关系：三份`02A／02B／02C` Markdown矩阵是内容权威；`data/topics.jsonl`与`data/topics.csv`是机械生成的检索副本，不手工修改。

## 一、用途

结构化目录把111项教材主题转成可检索、可筛选、可接后续项目池的数据。它适合：

- 按教材册次、领域、首选载体、包含载体、AI能力和优先级筛选；
- 建立教材版本适配、项目配置和配套网站索引；
- 检查主题数、字段完整性、标签合法性和来源行号；
- 在Markdown变化后重新生成，防止手工维护两套内容产生漂移。

它不替代原教材、原PDF或人工物理审核，也不增加任何课堂实施与效果证据。

## 二、生成方法

在本目录执行：

```bash
node tools/build_catalog.mjs
```

脚本先完整解析三份主题表，全部验证通过后才写入：

- `data/topics.jsonl`：一行一个JSON对象，适合程序、数据库和流式处理；
- `data/topics.csv`：UTF-8、首行字段名，数组以英文分号连接，适合表格查看。

脚本无第三方依赖，只使用Node.js内置模块。输出内容不写生成时间，因此相同源文件会得到稳定结果。

## 三、字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schema_version` | string | 是 | 当前固定为`1.1` |
| `id` | string | 是 | `TB-领域-哈希`；由领域和完整“主题＋锚点”文本生成，不因行号变化而改变；重复ID会使生成失败 |
| `domain` | enum | 是 | `MEC`、`EM`、`THM` |
| `domain_title` | string | 是 | 领域中文名 |
| `section` | string | 是 | 源文件中的二级分区代码，如`MEC-01` |
| `section_title` | string | 是 | 源文件二级标题原文 |
| `ordinal` | integer | 是 | 该领域内的原始主题顺序，从1开始 |
| `source_file` | string | 是 | 权威Markdown文件名 |
| `source_line` | integer | 是 | 生成时的源行号，用于回查；源文件编辑后可变化 |
| `source_sha256` | string | 是 | 权威Markdown整文件SHA-256；用于判断结构化副本是否对应当前源 |
| `topic` | string | 是 | 括号前的主题原文，保留Markdown行内标记 |
| `textbook_anchor` | string | 是 | 末尾全角括号内的教材定位原文；不擅自补写教材没有提供的定位 |
| `textbook_codes` | string[] | 否 | 从锚点中明确抽取的标准代码，如`RJ-B1`；“两版实验群”等概括锚点可为空 |
| `primary_carrier` | enum | 是 | 源表“主载体”单元格的第一个代码，仅允许`K/S/D/H/V/P` |
| `supporting_carriers` | enum[] | 是 | 同一单元格从第二个开始的其余代码，按源顺序保存；没有支持载体时为空数组 |
| `carriers` | enum[] | 是 | 向后兼容的完整有序组合；必须严格等于`[primary_carrier, ...supporting_carriers]` |
| `learning_object` | string | 是 | “最值得显现的学习对象”原文 |
| `mvp_ai` | string | 是 | “最小开发单元与AI增量”原文 |
| `ai_capabilities` | enum[] | 是 | 从`mvp_ai`明确抽取，仅允许`A1—A8`；不根据语义追加源文未写的标签 |
| `reality_requirement` | string | 是 | “真实／虚实要求”原文 |
| `priority` | enum | 是 | 仅允许`P0—P3` |

## 四、强制验证

生成器失败即不应使用新输出。当前强制门包括：

1. `02A`恰好42项、`02B`恰好40项、`02C`恰好29项，总计111项；
2. 111个ID全部唯一；
3. 每个主题表行恰好6列；
4. 所有必填字段存在；除允许空数组的`supporting_carriers`外，其余必填值非空；
5. 源表第二列表头必须明确为“主载体”；所有载体代码只能属于`K/S/D/H/V/P`；
6. `primary_carrier`必须是源单元格第一个代码，`supporting_carriers`必须是其余代码，`carriers`必须严格重建原顺序；
7. AI能力代码只能属于`A1—A8`，且每个主题至少有一个显式AI能力；
8. 优先级只能属于`P0—P3`；
9. 每个主题必须以全角括号保留教材锚点。

脚本同时报告六类首选载体、六类全部载体、八类AI能力和四档优先级的实际覆盖。覆盖报告不等于强制每个枚举都必须出现：当前Markdown未显式使用`A7`，生成器如实报告`A7:0`，不自行推断标签。这一空缺可作为后续作者审读问题，但不能在结构化副本中改写权威Markdown。

载体角色只读取单元格的原始顺序：第一个代码为首选，后续代码为支持。生成器不根据主题、优先级或其他文字重新排序，也不推断“最低足够载体”。

## 五、离线查看入口

[`viewer/index.html`](./viewer/index.html)把JSONL生成成可直接双击的本地筛选页。它使用同一批111项数据，分开提供“首选载体”和“包含载体”筛选，并展示有序的首选／支持角色、学习对象、最小AI增量与真实／虚实要求。

查看页的生成与验证命令：

```bash
cd viewer
npm test
```

查看页是检索层，不回写Markdown或JSONL，也不把筛选结果升级为项目决定。

## 六、修改规则

1. 修改内容时只改`02A／02B／02C`，不要直接改JSONL或CSV。
2. 修改后运行生成器，并保存完整验证输出。
3. 若主题拆分、合并或改名，内容哈希ID会变化；下游项目应把它当成显式目录变更，而不是静默覆盖。
4. 只调整主题行顺序时，`id`不变，`ordinal`和`source_line`会变化。
5. 正式引用教材公式、数据、题目、图片或原句时，仍须依照来源台账回原PDF核对。
