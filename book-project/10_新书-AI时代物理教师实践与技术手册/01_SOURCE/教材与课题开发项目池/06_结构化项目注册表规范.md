## 一、权威边界

- 不在派生文件中人工改项目名、映射、成熟度、优先级或依赖；
- 权威表发生变化时，先在Markdown中完成作者审定，再重新生成；
- 派生文件不能反向覆盖Markdown，也不能把组合优先级解释成章节立项、课堂效果或研究结论；
- 每条记录保留源文件、源行号和整份源文件SHA-256，用于识别错行、过期导出或未审定改动。

## 三、字段规范

字段顺序在JSONL对象和CSV列中固定如下。

| 字段 | JSONL类型 | 含义与生成规则 |
| --- | --- | --- |
| `rank` | 整数 | 权威表“排名”，固定连续为1—12 |
| `id` | 字符串 | 组合ID；当前精确集合为U01—U05、V01—V05、R01—R02 |
| `layer` | 字符串 | 权威表“层”，当前为共享、课堂或研究 |
| `name` | 字符串 | 权威表“去重后的项目”原义文本，仅清除Markdown行内标记和多余空白 |
| `source_mappings` | 字符串数组 | “主要来源ID映射”按出现顺序提取并去重；CSV中以英文分号连接 |
| `maturity_label` | 字符串 | 完整保留“当前成熟度”文字；例如局部R1、R1-及待复测限制均不得丢失 |
| `primary_maturity` | 字符串 | 从完整标签左到右遇到的第一个R0或R1，仅供筛选；允许值只有R0、R1 |
| `priority_label` | 字符串 | 完整保留“优先级”文字，包括条件升级或不同用途的次级标签 |
| `primary_priority` | 字符串 | 从完整标签左到右遇到的第一个P0或P1，仅供筛选；允许值只有P0、P1 |
| `dependencies` | 字符串 | 完整保留“直接依赖”文字，不把范围写法自动展开成新的关系记录 |
| `source_file` | 字符串 | 相对于本注册表目录的权威Markdown文件名 |
| `source_line` | 整数 | 该项目在当前权威Markdown中的1基行号 |
| `source_sha256` | 字符串 | 生成时整份权威Markdown的SHA-256；12条记录必须相同 |

`primary_maturity`和`primary_priority`只是机械检索键，解释项目状态时必须同时读取完整标签。例：V04的完整优先级是“P1，原件闭合后可升P0”，主优先级仍为P1；R01的完整标签包含研究用途P2，但教师审读的主优先级为P0。

## 四、机械解析规则

脚本只接受如下结构，结构变化会直接报错，不做猜测性补救：

1. 精确定位标题`## 四、前12项目总表`；
2. 核对八列表头及Markdown分隔行；
3. 逐行读取连续数字排名的数据行；
4. 从“主要来源ID映射”提取反引号内的ID，以及当前表中裸写的S1—S4、B2-16；
5. 清理行内代码、粗体标记和重复空白，不改字段原义；
6. 记录原始Markdown行号并计算整份文件哈希；
7. 以固定字段、固定ID顺序、UTF-8和结尾换行生成两个文件。

生成内容不含时间戳、随机值或绝对路径，因此同一权威源与同一脚本会产生字节完全相同的结果。写入模式也只在内容变化时改写文件。

## 五、生成与检查

在`教材与课题开发项目池`目录运行：

```bash
node tools/build_project_register.mjs --write
```

该命令解析、验证并生成JSONL和CSV。再次运行时，若输入未变，两个文件均应显示`unchanged`。

```bash
node tools/build_project_register.mjs --check
```

该命令不写文件；它重新从Markdown计算预期内容，并逐字节比较现有JSONL和CSV。源表已改变但尚未重新生成、派生文件被人工修改或结构不符合约定时，命令以非零状态退出并说明原因。

脚本在写入或检查前执行以下硬验证：

- 正好12项；
- ID精确为`U01,U02,U03,U04,U05,V01,V02,V03,V04,V05,R01,R02`且顺序不变；
- ID唯一，排名连续；
- 13个字段全部非空；
- `primary_maturity`只能是R0或R1；
- `primary_priority`只能是P0或P1；
- 每条来源哈希均为64位小写十六进制；
- 同一进程的二次渲染内容完全一致；
- `--check`时，磁盘输出与当次解析结果完全一致。

## 七、检索示例

查找V01完整记录：

```bash
rg '"id":"V01"' data/projects.jsonl
```

查找所有主优先级P1记录：

```bash
rg '"primary_priority":"P1"' data/projects.jsonl
```

需要按层、成熟度或优先级批量筛选时，优先使用JSONL的结构化字段；需要人工浏览或导入表格软件时使用CSV。无论采用哪一种，涉及项目含义、状态限制或作者裁决时都回到权威Markdown核读完整上下文。
