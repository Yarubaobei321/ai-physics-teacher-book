# 从使用、适配到创造：高中物理教师自研能力的阶段模型

> 女娲 Phase 1｜研究维度 5  
> 研究对象：教师“从用到造”的角色变化、AI 协作开发、验真与维护  
> 本地对象：V1 第6、12章，数智育才网站、ESP32Blockly、继续教育课程设计及项目证据台账  
> 用途：为“物理可视化 × AI 自研”专家技能提供教师发展路径、升级门、回退方案和证据边界  
> 状态：研究底稿；不是已经验证的教师能力等级标准  
> 完成日期：2026-08-12

## 一、研究结论先行

“从用到造”不宜写成“会用工具—学会提示词—成为程序员”的技术升级故事。更准确的变化是：教师逐步扩大自己对教学资源的设计权，同时扩大对学科正确性、课堂适配、证据、发布和维护的责任范围。

[本书综合 I] 本研究据此提出“六种项目角色 + 一条贯穿责任线”：

1. 证据化使用者：选择、理解并有边界地使用现成资源；
2. 情境适配者：修改参数、任务、语言、入口或设备条件，使资源适合本班；
3. 学习任务设计者：从学生难点出发，定义模型、交互、任务、产物和验收；
4. 协作开发与系统集成者：把设计转成可运行网页、教具、程序或硬件链；
5. 验真与改进者：用独立真值、特殊点、实测数据、课堂记录和反例审查资源；
6. 维护与共享贡献者：管理版本、许可、隐私、交接、更新和团队知识。

这六种角色描述的是“某个项目中教师当前承担的主要责任”，不是给教师贴终身等级。一个教师可以在熟悉的力学仿真中处于第5种角色，在陌生的传感器项目中回到第1种；教研组也可以由不同成员共同覆盖六种角色。验真更不能等到第5阶段才开始：来源核对、物理正确、隐私和回退从第1阶段就存在，第5阶段只是把它们变成系统的独立验证。

本模型最重要的两个轴是：

    创造深度：选择 → 适配 → 设计 → 开发
    责任广度：来源/适用 → 验真 → 入课证据 → 维护/共享

“造”发生在两个轴同时扩展时。只生成代码而不定义教学任务，创造深度并未真正建立；只会改页面而不承担验真和维护，责任广度仍然不足；只做严格审查而从不开发，也可以成为团队中关键的专业贡献者。

[本地事实 E2] 数智育才网站、ESP32Blockly 和继续教育课程已经提供了需求、代码、提交、测试、规则、模板与课程结构等过程材料，足以证明作者曾把若干课堂判断转成资源和工装。[P01、P02、P03]

[边界] 这些材料来自一名教师及其项目，继续教育课程目前主要证明“方案与工具包已经形成”。它们不能证明六阶段适用于所有教师，也不能证明 AI 单独导致开发速度、专业成长或学习改善。普遍性需要多教师、跨学科、跨工具和延时任务的后续研究。

## 二、证据标记与写作纪律

本文使用四类标记：

- [外部框架]：原始论文、正式国际框架、政府间组织建议或权威学术出版物；
- [本地事实 E3/E2/E1]：按项目证据台账标记可复核程度；
- [本书综合 I]：本研究把外部框架、本地项目和 V1 方法重新组织后的原创模型；
- [待证]：可进入培训或研究设计，但目前没有本地实施证据。

外部框架与本地案例承担不同功能：

| 问题 | 应由什么回答 | 不能怎样替代 |
|---|---|---|
| 为什么把教师视为设计者 | 教师设计、专业自主与教师能动性文献 | 不能由作者做成一个网站反推普遍理论 |
| 为什么要循环开发与真实情境检验 | 设计型研究／设计研究文献 | 不能把有 Git 提交记录自动命名为 DBR |
| 为什么关注制作、实体反馈与共享 | constructionism、maker、physical computing、OER 文献 | 不能把“做出作品”写成理解与迁移 |
| 教师数字与 AI 能力包含什么 | DigCompEdu、UNESCO AI 教师能力框架 | 不能把本书六阶段冒充其官方等级 |
| 作者实际做过什么 | V1、项目原件、代码、测试、课程材料 | 不能由外部框架替本地效果背书 |
| 这条路径是否改善教师能力 | 多教师实施、表现任务、迁移与延时证据 | 不能用满意度、作品数量或提交数代替 |

项目证据台账把 E3 定义为可逐项复核的原始文件、源码、测试或正式数据，E2 为已汇总但本轮未逐项打开全部原件，E1 为经验、计划或待证推断。本文对网站和 ESP32Blockly 的提交数、系统结构与课程设计主要按 E2 使用；正式入书前若要写精确数量或时间，应回到 Git、源码与课程原件升为 E3。[P00]

## 三、六组外部理论如何进入本书

### 1. Teachers as designers：教师设计的是学习环境，不只是数字成品

[外部框架 F01] OECD 的《Teachers as Designers of Learning Environments》把教师从执行既定目标的技术人员转向教学专业者，强调教学创新是植根于专业判断的问题解决。该报告能够支持“教师具有设计学习环境的专业角色”，不能证明每位教师都需要独立写代码。

[外部框架 F02] Koehler 与 Mishra（2005）研究教师与研究生共同设计在线课程的情境，把真实设计活动作为技术—教学—内容知识发展的场域。该研究支持“学习于设计”的可能路径，但样本、任务与组织条件均特定，不能写成任何自研项目都会带来 TPACK 增长。

[外部框架 F03] Laurillard（2018）讨论用技术支持教师成为技术增强学习的设计者，并关注设计知识产品的分享、复用、检验和共同改进。本书可以借其“设计—实施—分享—改进”的方向，不能在未完成本地教师共同体研究时声称已经建立知识建构共同体。

对本书最有用的转译是：教师设计的首要产物不是 HTML、传感器或动画，而是一个带有对象、难点、活动、反馈和证据的学习环境。技术成品只是该环境的一个构件。由此，第三阶段“学习任务设计者”必须先于第四阶段“协作开发者”。

### 2. 设计型研究 DBR：反复修改还不等于研究

[外部框架 F04] Design-Based Research Collective（2003）把设计型研究描述为理论驱动的学习环境设计与经验研究的结合，用来理解创新在真实复杂情境中何时、如何、为何工作。其关键不只是循环，而是设计主张、真实实施、过程与结果数据、分析、再设计和可分享知识之间的联系。

本书可借鉴三点：

1. 原型应进入真实条件，而不只在作者电脑上演示；
2. 每次修订要说明“哪条设计判断因什么证据而改变”；
3. 多轮项目最终应产出带条件的设计原则，而不只留下成功故事。

本书暂不能把网站和 ESP32Blockly 的持续迭代直接称为 DBR。提交记录能证明版本演进；若没有预先明确的理论主张、系统实施数据、分析方法和多轮再设计，它仍是有证据的开发实践，不是完整的设计型研究。继续教育课程若以后开展多轮试点，可以把“六阶段模型是否帮助教师完成更高责任的项目角色”作为设计假设，再采集表现任务、访谈、修复记录和迁移作品。

### 3. Maker、physical computing 与 constructionism：作品必须连回意义、反馈和社区

[外部框架 F05] Papert 与 Harel（1991）的 constructionism 强调通过制作对自己或他人有意义、可被共同观看和讨论的外部作品来建构知识。它为“造物、编程、调试和分享”提供理论入口，但不允许把“做出东西”直接写成概念理解或稳定迁移。

[外部框架 F06] Martin（2015）把 maker movement 的教育潜力分解为三组条件：低成本数字制作／微控制器工具、线上线下社区基础设施，以及 maker 的实践取向与习惯。该文同时把这些视为仍需研究的教育潜力。本书据此不能把购买开发板等同于 maker 教育；至少还要有真实问题、迭代制作、共享对象、反馈与可修改性。

[本地事实 E2] ESP32Blockly 形成“积木—MicroPython—教师服务器—ESP32—传感器／执行器反馈”的 physical computing 链。这里的“物理计算”指代码读取真实环境并通过装置产生可观察反馈；它要求同时处理电路、传感、程序、设备身份、网络和课堂组织。[P02]

这条传统对本书的作用不是为“硬件一定促进学习”背书，而是提醒：

- 软件输出必须回到真实设备与物理量；
- 调试失败本身可以成为可观察的设计证据；
- 作品应有源文件、结构、说明和复现条件；
- 社区共享的前提是别人有权且有能力修改。

### 4. Open source 与 OER：可看见源码不等于开放

[外部框架 F07] UNESCO 2019《开放教育资源建议书》把 OER 定义为公有领域材料，或在开放许可下允许无偿访问、再使用、改作、适配和再分发的教育材料；并把能力建设、支持性政策、质量与包容、可持续模式和国际合作列为行动方向。

本书应严格区分：

- “用了开源组件”：某个依赖具有经核验的开源许可证；
- “源码可见”：读者能看到代码，但未必有修改和再分发权；
- “本项目开源”：项目整体已有明确许可证、第三方许可清单、可构建源文件和贡献规则；
- “开放教育资源”：教育材料满足开放许可、可访问与可适配条件。

目前项目总览没有足够证据证明数智育才网站或 ESP32Blockly 整体已经以开放许可证发布，因此只能写“使用了某些开源技术”或“具备可共享潜力”，不能直接称项目为开源或 OER。第6阶段的升级门必须包含许可证、第三方素材、隐私与复现检查。

### 5. 专业自主与教师能动性：自主是负责任的情境行动

[外部框架 F08] ILO—UNESCO 1966《关于教师地位的建议书》第61—63条确认教师在既定课程框架内对教学材料、教材和教学方法的选择与适配应发挥关键作用，同时把自由、主动性和责任联系起来。这为“教师有权适配和创造教学资源”提供规范性依据，也提醒自主从来不是脱离课程、学校制度、法律和学生权益的任意行动。

[外部框架 F09] Priestley、Biesta 与 Robinson（2015）的生态取向把教师能动性理解为个体能力、学校文化、关系和结构条件共同作用的结果。它直接修正“有 AI 就人人能造”的叙事：设备权限、网络、时间、同伴、领导支持、数据政策、维护岗位和学校技术环境都会决定教师能否行动。

[本书综合 I] 本书把专业自主操作化为四项可观察责任：

1. 能说明为什么选择或拒绝某项技术；
2. 能把学科与教学判断写入需求和验收；
3. 能在证据不足时停止发布、降级使用或回退；
4. 能留下他人可以复核、接手和继续修改的资源包。

专业自主的标志不是“凡事独立完成”，而是教师在必要处主动求助、分工和拒绝不可靠自动化，并对最终教学决定负责。

### 6. DigCompEdu 与 UNESCO AI CFT：外部能力框架是坐标，不是本书阶段的别名

[外部框架 F10] DigCompEdu 包含六个领域、22项能力：专业参与、数字资源、教学与学习、评价、赋能学习者、促进学习者数字能力。其“数字资源”领域明确区分选择、创建／修改、管理／保护／共享；官方还提供 A1 Newcomer 至 C2 Pioneer 的六级熟练度描述。

[外部框架 F11] UNESCO 2024《AI Competency Framework for Teachers》提出五个维度、15项能力：以人为本的观念、AI伦理、AI基础与应用、AI教学法、AI促进专业学习；每个维度按 Acquire—Deepen—Create 三层推进。框架强调教师权利、人的能动性、问责和可持续性。

本书六角色与两套框架的关系如下：

| 本书角色 | DigCompEdu 的主要对话点 | UNESCO AI CFT 的主要对话点 | 不能等同 |
|---|---|---|---|
| 1 证据化使用者 | 选择数字资源、基本教学使用 | Acquire：理解能力、风险与基本使用 | 不是 A1/A2 测评等级 |
| 2 情境适配者 | 修改资源、管理与保护 | Acquire→Deepen：安全适配具体实践 | 不是仅因改了资源就达到 Deepen |
| 3 学习任务设计者 | 教学编排、评价、赋能学习者 | Deepen：把 AI 与教学设计、伦理整合 | 不是任何 PRD 都证明 AI 教学能力 |
| 4 协作开发者 | 创建复杂资源、创新教学格式 | Deepen→Create：用 AI 创造、反思工具 | 不等于 UNESCO Create 全维度达成 |
| 5 验真改进者 | 分析证据、反思与改进 | 人的问责、伦理、专业判断贯穿 | 不是框架中的独立官方层级 |
| 6 维护共享者 | 专业协作、发布、许可、同行支持 | 专业学习与负责任创新 | 不等于 DigCompEdu C1/C2 |

[本书综合 I] 六角色是“项目责任模型”，DigCompEdu 与 UNESCO AI CFT 是“能力领域与进阶参照”。一个教师可以在开发角色上很强，却在数据隐私、可访问性或评价效度上仍需 Acquire；反之，不写代码的教师也可能在资源选择、学科验真和团队治理上承担高责任。正式成书必须保留这一区分。

## 四、模型 C／F 下的第12章项目责任画像与治理子卡：六角色—八道门

### 1. 模型的原创成分

| 成分 | 来源性质 | 说明 |
|---|---|---|
| 教师是学习环境设计者 | 外部框架 | 来自 teachers as designers、TPACK 设计活动与 OECD 教师专业者视角 |
| 真实情境中的循环设计与证据 | 外部框架 | 来自 DBR；本书只迁移方法纪律，不宣称项目已构成 DBR |
| 造物、物理计算、共享作品 | 外部框架 + 本地事实 | constructionism、maker/OER 提供方向，ESP32Blockly 提供本地对象 |
| 专业自主受文化与结构条件影响 | 外部框架 | ILO—UNESCO 规范与教师能动性的生态视角 |
| 数字／AI能力维度 | 外部框架 | DigCompEdu、UNESCO AI CFT |
| 六种项目角色 | 本书综合 I | 由 V1“选题—定义—开发—验真—入课—维护—共享”重组而来 |
| 创造深度 × 责任广度双轴 | 本书综合 I | 防止把写代码当作唯一进步 |
| 八道升级门、每阶段 AI 分工和回退方案 | 本书综合 I | 来自三个项目的实际工作对象与 V1 发布门 |
| 角色证据包 | 本书综合 I | 把培训评价从自我感受转为可审查产物 |

### 2. 八道门

六种角色之间不是自动晋级。每一次扩大范围之前至少检查八道门：

| 门 | 核心问题 | 最低产物 | 未通过时 |
|---|---|---|---|
| U0 问题门 | 学生或教师的真实困难是什么 | 一条具体问题、现有证据、使用场景 | 继续观察，不立项 |
| U1 来源与权利门 | 资源从哪里来，能否使用、修改、发布 | 来源、版本、许可、个人信息清单 | 只在许可范围内使用或换资源 |
| U2 适配门 | 现成资源究竟哪里不适合 | 差距表、最小改动方案 | 保留原资源，增加纸质任务或教师说明 |
| U3 设计门 | 学生要做什么，留下什么可观察产物 | 任务流、模型卡、PRD、验收条件 | 先做纸面原型，不开发 |
| U4 实现门 | 技术链能否在目标设备与课堂条件运行 | 最小可行版本、源码、运行记录、回退点 | 降级为静态图、视频、本地单文件或人工演示 |
| U5 验真门 | 物理、测量、功能和生成内容是否独立核验 | 特殊点、真值表、原始数据、回归与异常记录 | 停止公开或课堂使用，回到模型／实现 |
| U6 入课证据门 | 资源怎样改变课堂任务，实际发生了什么 | 对象、时间、设备、任务、学生产物、问题记录 | 只写设计／工程价值，不写学习效果 |
| U7 维护共享门 | 谁负责更新，别人能否接手，公开是否合规 | 版本、说明、许可、维护人、交接包、停用条件 | 冻结稳定版、限本地／校内使用或归档 |

### 3. 三条非线性规则

第一，允许跳过开发。若现成资源已能支持目标任务，教师在第1阶段做好选择、任务编排和证据收集，可能比新造一个网页更专业。

第二，允许回退。设备、网络、时间或权限变化时，从 H5 回退到本地单文件、从传感器回退到纸带、从自动评价回退到教师抽样复核，是风险管理，不是能力下降。

第三，允许团队分工。物理教师负责模型与任务，信息教师负责系统实现，同伴负责真值检查，学校负责账号与发布。六种责任都有人承担，比“一个人包办全部技术”更可持续。

## 五、阶段 1：证据化使用者

### 角色定义

证据化使用者不只是“会打开资源”。他能说明资源表达什么、从哪里来、在哪些条件下有效、学生要完成什么任务，以及出错时怎样退出。使用他人资源本身是一种设计决定。

| 要素 | 要求 |
|---|---|
| 进入条件 | 已识别一个具体教学困难；有一个可访问的候选资源；知道目标班级、课时、设备与网络条件 |
| 核心决策 | 该资源让什么对象可见；与本节目标是否匹配；由教师演示还是学生操作；必须补什么任务；何时不用 |
| 主要产物 | 资源选择卡、来源与版本、适用条件、课堂任务、替代方案、退出条件 |
| 可观察证据 | 能指出至少一个有效功能和一个误导风险；能用独立课本／公式核对关键结论；实际使用记录包含对象、时间和问题 |
| AI 分工 | AI可检索候选、比较功能、整理说明、提出风险清单；教师核对来源、课程适配、物理内容、学生数据与最终选择 |
| 失败模式 | 以画面精美或热门程度代替适用性；把厂商说明当效果证据；不知道数据／模型来源；课堂依赖网络却无备用 |
| 升级门槛 | 明确记录现成资源与本班任务之间持续存在的差距，并确认修改权、修改成本和预期收益 |
| 回退方案 | 教师演示、截图／视频、纸面图表、传统实验、口头问题链；保留原始资源，不带病改造 |

[本书综合 I] 本阶段最小证据包为“一卡一案”：一张资源选择卡和一个故障／退出方案。若教师只能说“很好用、很直观”，尚未达到证据化使用。

[与外部框架的关系] DigCompEdu 的资源选择不仅看吸引力，还逐步加入作者、可靠性、许可、学习目标和学习者群体。本书把这些标准落到物理对象、模型条件与课堂设备。

## 六、阶段 2：情境适配者

### 角色定义

适配者保留资源的核心模型或技术链，修改使其进入本班情境的部分。适配可以是语言、参数、数据、任务顺序、字号、设备入口、离线方式、题目或提示；若改动已经改变模型和学习逻辑，就应进入第3阶段重新设计。

| 要素 | 要求 |
|---|---|
| 进入条件 | 原资源经过基本核验；差距明确；拥有或取得修改许可；保存可回退原版 |
| 核心决策 | 改哪些、不改哪些；修改会不会改变物理含义；不同学生与设备需要何种替代；怎样保留来源与许可 |
| 主要产物 | 修改前后差异表、适配理由、参数／文本／任务变更、兼容性记录、新版本号 |
| 可观察证据 | 每项修改都能对应一个学情或环境证据；改动后原有关键状态仍通过；能一键或按说明回退 |
| AI 分工 | AI可改写语言、调整界面、生成本地化数据、批量替换与做差异报告；教师决定物理语义、学段难度、可访问性和版权边界 |
| 失败模式 | 只换颜色和校名却称“校本化”；改参数范围导致模型失效；删掉警告与来源；AI大改后无法说清变化 |
| 升级门槛 | 适配需要新增学生行动、反馈逻辑、测量模型或新交互，已经超出原资源局部修改 |
| 回退方案 | 恢复原版；用外接任务单补充；限制参数；只在教师端演示；把复杂分支移到课后 |

[本书综合 I] 适配的核心证据是“差距—改动—复核”三联表：

| 现有差距 | 所作改动 | 独立复核 |
|---|---|---|
| 本班只使用双光电门，原页混入单头公式 | 分开两个测量入口并标注 L 与 d | 用已知间距、触发时间和手算速度核对 |

这一阶段把“改得更像自己的课”转成可追溯设计，而不只留下最终成品。

## 七、阶段 3：学习任务设计者

### 角色定义

学习任务设计者从真实困难反向定义资源。他先写学生对象、误区、物理模型、交互、证据和验收，再选择网页、教具、仿真、传感器或低技术方案。V1 第12章把 PRD 解释为“开发前的教学决策表”，与 teachers as designers 的核心一致。[P04]

| 要素 | 要求 |
|---|---|
| 进入条件 | U0问题门通过；已有学生错误、课堂观察、作业或器材限制；能说明现成资源为何不足 |
| 核心决策 | 保留哪些物理关系；学生预测、操作、测量、比较、解释什么；哪些参数开放；哪项产物支持哪种判断；技术是否值得 |
| 主要产物 | 三问选题卡、模型卡、任务流、纸面原型、PRD、验收清单、证据计划 |
| 可观察证据 | 学生动作和产物具体；公式、单位、边界与特殊点明确；每个功能能追溯到教学难点；可用纸面方式预演 |
| AI 分工 | AI可把口述整理为PRD、生成多种任务流程、查找遗漏、画线框、提出测试；教师决定目标、模型、认知要求、证据上限和停止条件 |
| 失败模式 | 从“想做一个炫酷网页”出发；先选技术后找问题；功能清单没有学生动作；验收只写“美观、流畅、好用” |
| 升级门槛 | 纸面原型和验收条件稳定；现成资源无法满足；开发收益超过使用、适配或低技术替代成本 |
| 回退方案 | 保留任务设计，使用纸笔、实物、演示视频或现有平台实现；缩小为一个最小关键交互 |

### 本阶段的六层 PRD

V1 已给出六层：对象与场景、难点与误区、内容与交互、技术边界、验收标准、交付物。阶段模型在此基础上增加两个强制字段：

- 不开发理由：哪些条件下现成方案更好；
- 证据上限：完成该资源最多能证明“设计完成、可运行、入课使用、表现变化”中的哪一级。

[本书综合 I] “不开发理由”保护教师时间与专业自主。能清楚拒绝无效开发，是设计能力的组成部分。

## 八、阶段 4：协作开发与系统集成者

### 角色定义

开发者把设计变成可运行对象，并把内容、代码、传感、设备、数据和发布环境连成技术链。生成式 AI 降低了代码表达门槛，却没有替代系统边界、物理模型与验收责任。

| 要素 | 要求 |
|---|---|
| 进入条件 | PRD、模型卡和最小验收已形成；项目目录、版本与回退点准备好；目标设备可获得 |
| 核心决策 | 自研、组合还是外包；最小可行版本是什么；数据从哪里来；哪些依赖可接受；代码与物理对象怎样对应；怎样分步集成 |
| 主要产物 | 源文件、最小可行版本、依赖与版本、提交记录、数据字典、设备／接口图、运行说明、已知问题 |
| 可观察证据 | 从需求到实现可追溯；每次改动范围清楚；目标设备能运行；失败可定位到内容、模型、代码、设备、网络或数据层 |
| AI 分工 | AI可生成代码、页面、图件、测试和文档，执行机械修改与排错；教师提供真值、限定改动、审查依赖、决定是否合并和发布 |
| 失败模式 | 一次性生成全站；代码能跑但变量物理含义不清；提示词成为唯一记录；供应商或接口改变即失效；真机链被模拟数据替代 |
| 升级门槛 | 候选版本可稳定运行；模型与数据来源明示；测试环境固定；已知问题足以进入独立验真 |
| 回退方案 | 冻结最近稳定版；砍掉非核心功能；退回本地单文件；用手工数据／人工操作替代不稳定接口；分离硬件与网页 |

### physical computing 的专门要求

网页仿真只需在模型与屏幕状态间建立可检查关系；physical computing 还要经历：

    真实量 → 传感器 → 电信号/协议 → 程序变量
    → 换算/判断 → 执行器或图形 → 现实反馈

ESP32Blockly 的三端结构、WiFi／USB／BLE 三种传输、只生成 MicroPython、不开放学生 WiFi 块、不落盘学生代码正文等取舍，说明开发不是“把积木画出来”，而是同时处理课堂并发、设备控制与隐私。[本地事实 E2：P02]

### AI 工装的作用边界

V1 把规则、技能、模板、验收和版本列为五类工装。它们分别稳定长期约定、复用流程、说明单次任务、检查质量和保留回退点。[P04]

这些工装能够证明开发过程更可追溯，不能在无工时比较时写成“显著提高效率”。提交数证明过程规模，不证明质量，更不能把速度全部归因于 AI。

## 九、阶段 5：验真与改进者

### 角色定义

验真者不以“AI说正确”“页面无报错”或“学生喜欢”为结论。他把主张拆开：工程可行、物理正确、测量可信、课堂可用、学习表现、迁移与长期维护分别需要不同证据。

| 要素 | 要求 |
|---|---|
| 进入条件 | 可运行候选版本；模型、代码、数据与版本可定位；至少有一条独立真值来源 |
| 核心决策 | 验证什么主张；独立真值来自手算、课本、真实仪器、另一实现还是专家；哪些错误必须停用；修复后回归哪些功能 |
| 主要产物 | 真值表、特殊点测试、测量／校准记录、功能回归、异常与修复日志、课堂试用记录、主张边界 |
| 可观察证据 | 输入—预期—实际—差异可复算；同源循环被标记；修复前后版本可比；未通过项不会被总体印象掩盖 |
| AI 分工 | AI可生成候选测试、运行批量检查、比较版本、发现冲突；教师选择独立真值、审查测试覆盖、解释误差并决定停用／发布 |
| 失败模式 | 用同一代码生成预期和实际；只测正常路径；把拟合优度当物理真值；把稳定运行写成课堂有效；用AI自评AI |
| 升级门槛 | 关键风险通过；已知限制公开；至少一次目标情境试用；维护责任、发布层级和交付物已明确 |
| 回退方案 | 停止发布；降为教师演示；限制参数；恢复稳定版；切换独立数据／人工复核；保留失败记录供再设计 |

### 五层验证必须分开

| 层 | 可写结论 | 最低证据 | 仍不能写 |
|---|---|---|---|
| 工程可行 | 在某设备／版本运行 | 构建、启动、关键功能、失败路径 | 测量准确、课堂有效 |
| 物理／测量可信 | 在给定模型与校准下符合预期 | 特殊点、原始量、标定、重复、独立对照 | 学生理解改善 |
| 课堂可用 | 在某对象、时间、设备下完成任务 | 实施记录、中断、学生产物 | 因技术导致学习变化 |
| 学习表现 | 给定任务表现发生差异 | 基线、可比任务、评分、替代解释 | 稳定能力、迁移 |
| 迁移／保持 | 新情境或延时仍表现 | 未见任务、延时、多场景 | 对所有教师／学生普遍有效 |

[本地事实 E2] V1 记录数智育才全站审查曾发现姓名暴露、角色错位、作品定级、宣传与功能不一致及资源路径问题。这类记录最能说明“能运行只是最外层条件”，但一次审查也不能证明永久正确。[P04]

## 十、阶段 6：维护与共享贡献者

### 角色定义

维护者让资源离开作者仍能使用、复核、更新和停用；共享贡献者把个人经验转成带条件、可修改的团队知识。阶段6并不要求公网发布，最小共享也可以是教研组内一个有版本、有说明、有许可的资源包。

| 要素 | 要求 |
|---|---|
| 进入条件 | 已有稳定且通过相应验证的版本；确认持续需要；有人承担更新；素材、数据和依赖权利清楚 |
| 核心决策 | 本地、校内还是公网；谁维护什么；更新频率和停用条件；是否开放许可；怎样收集问题而不侵犯隐私 |
| 主要产物 | 版本与发布说明、README、源文件／物料表、测试、许可证、第三方清单、维护矩阵、问题入口、交接包、归档策略 |
| 可观察证据 | 新成员按说明能运行；旧版和新版本可区分；重大更新重过风险门；问题有负责人和处理状态；停用可执行 |
| AI 分工 | AI可整理变更日志、扫描断链、生成文档、分类问题和提醒测试；教师／组织决定授权、公开范围、个人信息、维护优先级与退役 |
| 失败模式 | 只有成品没有源文件；公开但无许可证；接口失效无人管；个人英雄式维护；把访问量当质量；学生材料长期暴露 |
| 升级门槛 | 本阶段没有强制“更高等级”；可转入共同设计、培训或正式研究，但必须另设证据 |
| 回退方案 | 冻结稳定版；转本地或校内；关闭数据收集；撤下高风险页面；导出静态归档；明确宣布停止维护 |

### 维护也是设计

V1 提出本地、校内、公网三级发布；分享范围扩大，访问、合规和维护责任同步增加。物理错误、身份暴露与数据角色错位应优先停用，外观和低频说明可排期处理。[P04]

维护阶段产生三类专业知识：

- 条件知识：在什么设备、版本和课堂条件下工作；
- 故障知识：常见错误怎样出现、怎样诊断和回退；
- 设计知识：哪些判断可复用，哪些只适用于当前情境。

只有当这些知识被写入说明、测试、版本和任务包，个体经验才可能变成教研组资产。把源码上传到仓库但不写许可、模型条件和使用任务，仍不足以构成可持续共享。

## 十一、三个本地项目在模型中的位置

### 1. 数智育才网站：支持“完整过程存在”，不支持普遍成长

| 角色 | 当前本地证据 | 证据等级与边界 |
|---|---|---|
| 使用／适配 | 网站把在线编程、网页版 DIS、在线实验室和仿真资源组织为统一入口，并针对本地课堂器材设计三套机械能方案 | E2；能证明系统与资源结构，不能证明每个页面已入课 |
| 设计 | 三套实验、分层习题、硬件入口、学生作品档案反映了特定教学问题与任务选择 | E2／I；“教学闭环”是项目归纳，效果需另证 |
| 开发 | 项目总览记录 Astro、TypeScript、Git 和 2026-04-18 至 07-02 的64次提交 | E2，正式入稿前回 Git 升 E3；提交数不等于质量或 AI 效率 |
| 验真 | 全站审查、学生作品复核、浏览器兼容和数据角色问题进入 V1 | 部分 E2/E3；证明做过审查，不证明所有功能通过 |
| 维护 | 有版本迁移、备案、去机构化、资源路径和诚实声明 | E2；可说明维护对象，尚不能称完整开放资源或长期可持续 |

网站最适合支持的结论是：“一名高中物理教师借助 AI 协作，把课堂问题、网页、硬件入口、数据与版本组织成持续迭代项目。”它不能支持：“零基础教师都能在相同时间独立建站”“AI显著降低成本”“网站普遍改善学习”。

### 2. ESP32Blockly：从页面开发进入 physical computing 与系统责任

| 角色 | 当前本地证据 | 证据等级与边界 |
|---|---|---|
| 设计 | 学生端积木、教师端按设备编号下发、设备端运行；不开放学生 WiFi 块、不落盘代码正文 | E2；可支持课堂约束进入系统设计 |
| 开发 | 三端架构、三种传输、30余积木、42个例程、43次提交 | E2；数量证明规模，不证明课程成效 |
| 验真 | 总览记录核心管线真机与无头测试，并列出硬件测试、板子台账等材料 | E2；正式写精度、稳定性和并发前须回原始测试 |
| 维护 | 文档、台账、设备身份和集成计划已经存在 | E2；安卓源码未入库，部分实现为推断，构成交接缺口 |
| 入课 | 总览有36名学生／8组口径 | E1/E2；须核对课堂原始材料，不能据此写学习效果 |

该项目展示“开发者”并不等于网页作者：教师还要承担协议、硬件差异、设备健康、隐私、并发和故障回退。它也提醒第6阶段的门槛：构建产物存在但源码缺失时，功能可以使用，维护与共享能力仍不完整。

### 3. 继续教育课程：已经形成路径，尚未形成成效证据

[本地事实 E2] 继续教育课程设计采用 WHY—WHAT—HOW—DO 四课时结构，包含三问选题卡、PRD、规则、技能、验收、版本和发布任务；课程详细设计还给出结业网页及过程材料的量规。[P03]

课程可以作为六角色模型的初步教学载体：

| 课时功能 | 可承接角色 | 建议补强 |
|---|---|---|
| WHY：发现真实问题 | 1 使用者、2 适配者 | 加入“何时不开发”和现成资源选择证据 |
| WHAT：规则、需求、版本 | 2 适配者、3 设计者 | 先做差距表和纸面原型，再进入工具 |
| HOW：完整开发与修复 | 3 设计者、4 开发者、5 验真者 | 把特殊点、独立真值、失败版本设为必交 |
| DO：发布、反馈、迁移 | 5 验真者、6 维护者 | 加许可证、隐私、停用与交接；发布不强制公网 |

[边界] “课程已设计”与“课程已实施”必须分开。当前材料没有足够的学员人数、完成率、作品质量、迁移任务或延时维护记录，因此不能写“教师实现了角色转变”。可写“课程拟通过这些任务支持角色变化，并为后续评价提供可观察产物”。

## 十二、贯穿六阶段的人—AI分工

AI 的能力随模型与产品变化，本书应固定判断权，而非固定产品名。

| 工作 | AI适合承担 | 教师必须承担 | 独立复核 |
|---|---|---|---|
| 资源发现 | 扩展候选、归纳功能、初筛格式 | 确定教学问题、来源可信与适用性 | 原始页面、教材、许可 |
| 情境适配 | 改写语言、界面、参数、数据格式 | 决定是否改变物理语义和任务难度 | 原版与修改版差异 |
| 教学设计 | 整理PRD、列方案、画任务流 | 确定目标、学生行动、模型与证据上限 | 同行、纸面原型、试教 |
| 实现 | 生成代码、图件、文档、机械测试 | 决定架构、数据源、依赖、合并与回退 | 目标设备、源码、版本 |
| 物理验真 | 提议边界、批量算例、查冲突 | 选择真值、解释差异、决定停用 | 手算、真实仪器、另一实现或专家 |
| 课堂解释 | 汇总日志、辅助编码、生成图表 | 判断观察代表什么、处理替代解释 | 原始任务、学生产物、评分规则 |
| 发布维护 | 写变更日志、查断链、整理问题 | 授权、隐私、许可、公开范围、退役 | 人工抽查、组织制度、恢复演练 |

三条硬边界：

1. 需求的学科与教学目标不能由 AI 代签；
2. 生成内容不能由同一模型自证正确；
3. 发布、个人信息、许可和高风险停用由人承担最终责任。

[本书综合 I] 可以把 AI 看作跨阶段的“候选生成器、执行器和记录助手”，把教师看作“问题所有者、模型责任人、证据解释者和发布责任人”。这个分工比“AI是助教”更精确，也更容易验收。

## 十三、升级决策与回退路线

### 1. 何时继续、何时停止

    现成资源能支持目标任务吗？
    ├─ 能 → 阶段1：有边界使用，收集问题
    └─ 不能
       ├─ 局部修改即可且许可允许吗？
       │  ├─ 是 → 阶段2：适配并做差异复核
       │  └─ 否
       ├─ 问题、任务、模型和验收清楚吗？
       │  ├─ 否 → 阶段3前：观察、纸面原型，不开发
       │  └─ 是
       ├─ 自研收益高于低技术／现成替代吗？
       │  ├─ 否 → 使用替代方案
       │  └─ 是 → 阶段4：最小实现
       ├─ 有独立真值和目标设备测试吗？
       │  ├─ 否 → 不发布，回设计／实现
       │  └─ 是 → 阶段5：验真与入课
       └─ 有维护人、许可、交接和停用条件吗？
          ├─ 否 → 限本地／校内或冻结归档
          └─ 是 → 阶段6：维护与共享

### 2. 回退是显式设计

每个资源在 PRD 中预先写一个回退层：

| 原方案 | 第一回退 | 第二回退 | 停止条件 |
|---|---|---|---|
| 浏览器连接 ESP32 实时采集 | 本地保存数据导入网页 | 纸面数据表和手算 | 数据源不明、连接不稳影响课堂 |
| AI生成交互仿真 | 冻结已验真版本 | 静态关键帧和图表 | 特殊点不通过或模型条件缺失 |
| 公网学生作品展示 | 校内限权访问 | 脱敏截图／摘要 | 身份、授权或角色归属不清 |
| 自动AI评价 | AI初筛＋教师复核 | 教师量规抽样或全评 | 同源循环、误判或不可解释 |

专业自主包含“选择最低足够技术”和“在证据不足时降级”的权利。升级不是越复杂越好，回退也不是失败。

## 十四、常见失败模式与修复

| 失败模式 | 表现 | 为什么危险 | 修复动作 |
|---|---|---|---|
| 把六角色当教师身份等级 | “维护者比使用者高级” | 忽略学科差异、团队分工和情境条件 | 改为项目角色画像，按任务重新定位 |
| 工具中心主义 | 先教模型、IDE、Git，再找课堂问题 | 技术学习与教学决策脱节 | 用U0问题门和“不开发理由”开场 |
| 表面校本化 | 换校名、颜色、题目数字 | 没有改变学习任务或适用条件 | 提交差距—改动—复核三联表 |
| 提示词依赖 | 成果只存在某次长对话 | 无法复现、更新或交接 | 把稳定知识迁入规则、PRD、测试和版本 |
| AI权威化 | 模型既写公式又判正确 | 形成同源循环 | 强制独立真值和人工发布责任 |
| 过早平台化 | 一个小任务先做账号、云端和后台 | 维护成本吞噬教学价值 | 先做本地最小版本，按需升级发布 |
| physical computing 黑箱 | 曲线出现但不知传感、采样和换算 | 视觉结果可能掩盖测量错误 | 数据字典、标定、原始值、故障树 |
| 假开放 | 源码可见就称开源 | 侵犯许可，别人不能合法改作 | 核对许可证、第三方材料和贡献规则 |
| 维护债 | 发布后无人负责 | 浏览器、依赖、内容和隐私逐渐失效 | 维护人、复检周期、冻结与停用机制 |
| 个体英雄叙事 | 强调单人、速度、零基础 | 遮蔽时间、支持、基础设施和失败成本 | 报告环境、已有能力、协作者、缺证与回退 |
| 把设计当成效 | 页面完成即宣称能力提升 | 主张超过证据 | 分开工程、课堂、学习、迁移五层 |
| 强制人人“造” | 培训只认可完整成品 | 浪费时间并制造不安全资源 | 允许高质量选择、适配、验真或团队角色作为结业成果 |

## 十五、怎样验证这套教师发展模型

### 1. 评价对象不是“会不会AI”，而是项目责任

建议为六角色各设计一个表现任务：

| 角色 | 表现任务 | 关键评分证据 |
|---|---|---|
| 1 使用者 | 从三个候选资源中选一个用于具体课例 | 来源、模型、任务、风险和退出理由 |
| 2 适配者 | 针对给定班级与设备修改一个现成资源 | 差距证据、修改边界、前后复核 |
| 3 设计者 | 为一个真实难点完成纸面原型与PRD | 学生行动、物理模型、特殊点、证据上限 |
| 4 开发者 | 形成可运行最小版本并处理一次失败 | 需求追溯、版本、运行、故障定位 |
| 5 验真者 | 审查一个含隐藏物理错误的AI页面 | 独立真值、反例、修复、回归与停用决定 |
| 6 维护者 | 把陌生项目整理为可移交资源包 | 许可、隐私、版本、复现、维护与退役 |

### 2. 至少保留五类数据

1. 入门画像：既有学科、技术、设备和组织条件；
2. 过程产物：选择卡、差距表、PRD、提示与规则、提交和修复；
3. 成品表现：功能、物理、可访问、许可和目标设备测试；
4. 迁移任务：换一个学科主题、资源类型或AI工具后是否仍能完成相同责任；
5. 延时维护：数周或一学期后能否找到、运行、解释、修复和交接。

满意度只能回答参与者感受，不能替代表现任务。作品数量只能回答产出规模，不能替代质量与归属。提交数只能显示过程痕迹，不能自动表示深度。若要研究“专业自主”，还应访谈教师为什么选择、拒绝、回退和求助，并记录学校时间、权限、设备和同伴支持。

### 3. 可形成的研究问题

- 六角色是否能被不同教师稳定区分，双人编码一致性如何？
- 哪些升级门最能预测项目停滞或返工？
- AI协作后，教师是在扩大设计判断，还是把判断外包给模型？
- 纸面原型、特殊点和版本回退是否减少高风险错误？
- 从网页迁移到教具／传感器时，哪些责任能够保持，哪些必须重学？
- 维护与交接任务能否区分“一次成品”和“可持续能力”？

### 4. 何时可以称为 DBR

若继续教育课程开展试点，至少满足下列条件后再考虑“设计型研究”表述：

1. 明确六角色与升级门的理论主张；
2. 在真实培训与项目情境实施；
3. 预先定义过程、成品、迁移和维护证据；
4. 连接实施过程与结果，而非只做前后满意度；
5. 依据证据完成两轮以上有说明的再设计；
6. 形成带条件、可被他人检验的设计原则。

只有“课程改了三版”或“网站提交很多次”仍不足以满足这些条件。

## 十七、安全动词与主张边界

| 当前证据 | 建议动词 | 避免动词 |
|---|---|---|
| 项目文件／总览 | 形成、实现、记录、包含、显示 | 证明教师普遍成长、显著增效 |
| 版本与测试 | 经某项检查、在某环境运行、发现并修复 | 完全正确、稳定可靠、永久可用 |
| 课程方案 | 设计、拟支持、要求、提供可观察产物 | 已培养、已提升、实现转型 |
| 单人案例 | 展示一种可能路径、提供设计对象 | 可复制、普适、适合所有教师 |
| 外部框架映射 | 借鉴、对话、转译、与某维度相呼应 | 等同、认证为、达到官方等级 |
| 共享准备 | 具备交接材料、可在给定条件复用 | 开源、OER（无明确许可时） |
| 课堂实施 | 在某班／某课使用、观察到 | 导致学习改善（无比较设计时） |

建议总论句：

“本书基于一名高中物理教师的三个项目，归纳出六种项目角色和八道升级门，用来组织选择、适配、设计、开发、验真与维护责任。它是一套待通过多教师任务验证的实践模型，不是教师数字能力的通用等级，也不替代 DigCompEdu 或 UNESCO AI 教师能力框架。”

## 十九、最终边界

这份研究可以支持：

1. 把“从用到造”改写为教师设计权与责任范围扩展，而非编程技能神话；
2. 为六种项目角色提供进入条件、决策、产物、证据、AI分工、失败、升级和回退；
3. 把 teachers as designers、DBR、maker／physical computing／OER、专业自主、DigCompEdu 与 UNESCO AI CFT 接到本书真实项目；
4. 为继续教育课程设计可观察的表现任务、迁移任务和延时维护证据。

它目前不能支持：

- 六角色是教师能力的普遍发展顺序；
- 一名教师的建站与硬件项目能代表所有教师；
- 课程设计已经带来教师角色转变；
- AI单独造成效率、能力或专业自主提升；
- 本地项目已经构成完整 DBR、开源项目或 OER；
- 会开发复杂系统的教师在伦理、评价、可访问与维护方面必然处于高水平。

现阶段最稳妥的称谓是：**“本书在核心模型 C／F 下，基于三个本地项目与外部教师能力框架归纳的第12章项目责任画像与治理子卡”**。它不与 A—F 六个核心模型并列。下一步应通过多教师的角色编码、表现任务、跨主题迁移、延时维护和团队交接检验其可用性。
