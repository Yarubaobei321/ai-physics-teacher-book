# 《从用到造》候选模型三重验证

> 女娲 Phase 2｜独立候选筛选  
> 输入范围：Phase 1 研究 01—05 与 `phase1-preaudit-01-03.md`  
> 输出目的：从来源理论、项目归纳和操作方法中筛出 3—7 个能够统摄全书、生成新章节动作且具有本书辨识度的核心模型  
> 边界：本文件是本书综合层的候选竞争记录，不把学习科学框架升级为全书核心模型，不把本书归纳写成学界既有定论，也不改写 V1。

## 一、验证口径

本轮沿用女娲 Phase 2 的三重验证，并针对“主题型 Skill”作如下操作化处理：

1. **跨章节／跨项目复现**：同一判断结构必须在至少两个不同场景中成立。两个页面、两张由同一模型生成的图，不算两个独立场景；优先要求跨章节、跨资源形态或跨“数智育才网站—ESP32Blockly—继续教育课程”项目复现。
2. **生成力**：不能只概括已经写过的内容。给它一个尚未扩写的章节或新资源，它应能推出具体动作、产物、检查点或停止条件。
3. **排他性**：不能只是“以学生为中心”“加强实践”“重视评价”“教师要审核”等泛泛常识。它应包含本书特有的对象划分、责任转移、证据门槛或组合关系；删掉本书主题后仍能原样用于任何教育书的，原则上不通过。

计分规则：每项只记 `1` 或 `0`，不以“部分通过”抬高结果。总分 3 为候选核心模型；总分 1—2 降为启发式、方法卡或检索标签；总分 0 淘汰。三项验证回答不同问题，不用“来源权威”替代“跨项目复现”，也不用“本地反复出现”替代“排他性”。

### 2.2 本书综合层：竞争核心模型的对象

综合层必须同时接住三种材料：十二章中的反复判断、三个本地项目中的真实责任、外部来源给出的边界。它最终要能回答五个连续问题：

```text
当前看不见、不可比或不可审查的对象是什么？
→ 现成资源是否已足够？
→ 若需改造或自研，怎样把判断变成可运行对象？
→ 用什么独立证据允许它失败？
→ 当前证据只允许把结论写到哪里，谁维护与叫停？
```

下列 24 个候选只在这一层竞争。

## 四、推荐的六个核心模型

六个模型不是六套平行分类。它们分别占据“定义对象—组织结构—作出选择—验真—控制结论—维持生命周期”的不同位置，可以首尾连接而不互相抢位。

### 核心模型 A：可追溯共同工作对象闭环

**一句话**：可视化资源只有同时说清“显出什么、从哪里来、怎样编码、谁做什么、留下什么、不能说明什么”，才从视觉材料变成可共同操作和审查的教学对象。

```text
对象 → 来源 → 视觉／实体／程序编码 → 学生或教师行动
  ↑                                      ↓
边界与反证 ← 可保存产物 ← 比较、解释、修改或检验
```

**跨场景证据**：静电场描绘仪连接测量、采样和等势线；机械能实验连接读数、派生量、图表和解释；AI网页连接模型、控件、代码与测试。[研究01：操作性定义](</Users/yaril/个人文档/3 写作/图书出版/从用到造：高中物理可视化教学的自研之路 V2-理论增强/00_SKILL/physics-visualization-ai-researcher/references/research/01-visualization-theory-landscape.md:12>)

**章节生成动作**：每一章至少补一张“对象—来源—编码—行动—产物—边界”小表；若资源只剩展示，没有行动与产物，就把它明确降为教师呈现；若提出课堂或学习主张，再增加学生产物。

**失效条件**：闭环完整不能证明编码最佳或学习发生；编码质量交给方法卡，学习主张交给模型 E。

### 核心模型 B：四层正交架构

**一句话**：先按要显出的对象分类，再按技术载体实现；人工或 AI 只是生产方式；来源、测试、课堂和维护属于证据责任。

| 层 | 回答的问题 | 可选项示例 |
|---|---|---|
| 可见对象 | 原先看不见、不可比或不可审查的是什么 | 过程、结构、关系、数据、模型、推理 |
| 技术载体 | 用什么最低足够技术把它变成共同对象 | 真实增强、教具、传感、图示、仿真、物理计算、H5／平台 |
| 生产方式 | 谁怎样把载体做出来 | 直接使用、模板、人工制作、AI固定链、智能体协作 |
| 证据责任 | 它凭什么可信、可入课、可公开、可维护 | 来源身份、独立测试、课堂产物、主张级别、版本与责任人 |

**消解分类混放**：研究01的六类只进入“可见对象”；研究02的前六类主要进入“技术载体”，H5／平台明确为载体容器，生成式 AI 移到“生产方式”，学生作品移到“证据责任”；研究03的图像、网页、仿真、代码、平台和测试是交付物，不再新增可视化类型。这正面落实预审 P1 和 P8。[预审：四层矩阵要求](</Users/yaril/个人文档/3 写作/图书出版/从用到造：高中物理可视化教学的自研之路 V2-理论增强/03_REVIEW/phase1-preaudit-01-03.md:49>)

**章节生成动作**：每个案例只给一个主要对象、一个主要载体；AI参与另列生产记录，学生作品另列证据用途。“AI生成的H5仿真”即拆为：模型／过程对象 + H5仿真载体 + AI工作流 + 独立测试与课堂证据。

**失效条件**：它是组织架构，不是效果理论；是否值得开发由模型 C 决定。

### 核心模型 C：最低足够的“用—改—造”责任梯度

**一句话**：从使用走向创造，增加的不是身份等级，而是对需求、模型、测试、版本、公开和维护的责任；现成资源足够时，停在“用”是更专业的决定。

```text
直接使用 → 参数配置 → 局部适配 → 组合编排 → AI协作自研
来源/适用   差异复核    回归与许可    系统边界     独立验真、版本、发布、维护
```

**跨项目证据**：网站承担资源编排与维护，ESP32Blockly承担代码—设备—数据责任，继续教育课程组织选题、PRD、验收和发布。[研究05：六角色与双轴](</Users/yaril/个人文档/3 写作/图书出版/从用到造：高中物理可视化教学的自研之路 V2-理论增强/00_SKILL/physics-visualization-ai-researcher/references/research/05-from-use-to-create.md:10>)

**章节生成动作**：每个自研案例先补“现成工具差距”和“不开发理由”；每次升级写新增责任与回退方案。若没有独立真值、目标设备或维护人，就停在纸面原型、本地开发或限定试用，不把复杂度当进步。

**失效条件**：梯度不是能力等级，也不要求单人走完全程；团队可分担并允许回退。

### 核心模型 D：独立真值—可失败验真

**一句话**：生成结果与检查结果不能共享唯一生成机制；真正的验真必须提前写出独立预期，并允许资源在特殊点、趋势、不变量和否决边界上失败。

**最小结构**：

1. 画出结果与证据的依赖图；
2. 找出共同祖先：同一公式、代码、模型、仪器或 AI 回答；
3. 在生成路径之外选择手算、实测、另一算法、另一软件、解析解或专家原始来源；
4. 预写输入、预期、容差与否决条件；
5. 失败后冻结样例、修复并回归；无法解除同源循环时，只称“内部一致”。

**跨场景证据**：P06 同源生成位移、速度和能量；AI同时写实现与预期也会自证；动画、读数和图表共享状态只能说明一致。[研究04：循环检验](</Users/yaril/个人文档/3 写作/图书出版/从用到造：高中物理可视化教学的自研之路 V2-理论增强/00_SKILL/physics-visualization-ai-researcher/references/research/04-verification-governance.md:200>)

**章节生成动作**：教具补反向翻译，仿真补物理测试与外部对照，实验补校准与独立数据，AI资源补对抗输入、真机和人工叫停。

**失效条件**：独立证据也可能有误差，一次外部对照不等于普遍有效；结论强度交给模型 E。

### 核心模型 E：主张权限 × 本地可复核强度双轴

**一句话**：先判断一句话想声称的是设计、功能、内部一致、指定用途、活动表现、学习变化还是迁移，再判断本地锚点是原件、台账还是经验；两个轴互不替代。

| 主张轴 | C0设计意图 | C1作品／功能 | C2内部一致 | C3指定用途 | C4活动／本任务表现 | C5学习变化 | C6迁移／保持 |
|---|---|---|---|---|---|---|---|
| 本地复核轴 | E1经验／待证 | E2台账汇总 | E3原件可复核 | 三档贯穿所有 C 级，不能因 E3 源码而越级到 C5 |  |  |  |

**跨场景证据**：源码可以 E3 证明某公式存在，却仍只到 C1／C2；一次课堂活动有完整原件，也只到 C4；提交数与页面数甚至不能证明 C2；要写学习变化和迁移，必须增加基线、比较、未见或延时任务。[研究04：主张—证据等级](</Users/yaril/个人文档/3 写作/图书出版/从用到造：高中物理可视化教学的自研之路 V2-理论增强/00_SKILL/physics-visualization-ai-researcher/references/research/04-verification-governance.md:401>)

**章节生成动作**：每个强动词先定 C×E 坐标；证据不足时缩小范围、换安全动词或生成补证任务。来源性质仍单独记录，不与 C×E 合成总分。

**失效条件**：双轴不是质量量表；C6 只表示回答了更强问题，不表示比 C1 更优秀。

### 核心模型 F：门控式资源生命周期

**一句话**：教学资源不是交付即结束的成品，而是带用途、状态、责任人、复验触发器和回退路径的长期对象。

```text
立项 → 使用/适配/设计 → 最小实现 → 独立验真 → 入课
  → 本地/校内/公开发布 → 监测维护 → 复验、回退或停用
```

每一段只保留一个主门：问题与来源、设计、实现、验真、入课证据、权利公开、版本维护。四种状态为“已发布、限定试用、本地开发、隔离停用”；状态不是荣誉等级，而是当前允许用途。[研究04：四种资源状态](</Users/yaril/个人文档/3 写作/图书出版/从用到造：高中物理可视化教学的自研之路 V2-理论增强/00_SKILL/physics-visualization-ai-researcher/references/research/04-verification-governance.md:45>)

**跨项目证据**：网站处理数据、学生材料与更新；ESP32Blockly处理设备、源码和故障恢复；继续教育课程要求需求、测试、许可与交接。[研究05：八道门](</Users/yaril/个人文档/3 写作/图书出版/从用到造：高中物理可视化教学的自研之路 V2-理论增强/00_SKILL/physics-visualization-ai-researcher/references/research/05-from-use-to-create.md:203>)

**章节生成动作**：核心资源标状态、责任人、核验日、限制、复验触发器和回退层。物理硬错、身份泄露或权利不清触发停用；无维护人则冻结稳定版。

**失效条件**：门越多不等于治理越好。正文只保留一条生命周期和七类问题，特殊点测试、许可清单、学生证据等作为门内子卡，避免再次堆出多套数字清单。

## 五、六个核心模型怎样共同运行

```text
A 可追溯共同工作对象闭环
        ↓ 定义一个案例必须具备什么
B 四层正交架构
        ↓ 分开对象、载体、生产、证据
C “用—改—造”责任梯度
        ↓ 决定做到哪一步，并允许不开发/回退
D 独立真值—可失败验真
        ↓ 决定资源凭什么可信
E C×E 主张双轴
        ↓ 决定文字和结论能走多远
F 门控式生命周期
        └── 决定谁在何种状态下发布、维护、复验和停用
```

这条运行顺序同时消解预审指出的四种混放：

1. **分类混放**：由核心模型 B 把对象、载体、生产和证据拆开；九类谱系只作检索，不再与六类对象并列竞争。
2. **方法重复**：模型卡、特殊点、来源身份、发布门分别收进 D 或 F 的子卡；不再保留“五层、六门、七门、八门”多套并排清单。
3. **发展路径混放**：核心模型 C 表达责任增量，六角色只是项目画像；不把角色、自动化层级或技术复杂度写成教师等级。
4. **证据标签混放**：来源性质、C0—C6 主张权限、E1—E3 本地可复核强度三者各守一轴，不折算成单一“证据分”。

## 六、降级候选的安置位置

16 个两分候选不删除：六类对象、多表征与过程—成品—解释进入课堂任务卡；五层术语、九类标签、来源身份、PRD、五类工装、智能体梯度和原型循环进入技术开发卡；四方责任、三级检验和六角色—八道门进入 D、F 的治理子卡。它们不再形成平行分类或成熟度等级。

候选23、24进入反模式：不以动态数量、技术复杂度、AI生成量、提交数、作品数或访问量替代物理、课堂和学习证据。

## 七、最终建议与诚实边界

推荐把以下六个模型进入下一阶段 Skill 构建：

1. 可追溯共同工作对象闭环；
2. 四层正交架构；
3. 最低足够的“用—改—造”责任梯度；
4. 独立真值—可失败验真；
5. 主张权限 × 本地可复核强度双轴；
6. 门控式资源生命周期。

它们的组合能够对新章节产生完整动作：定位对象、选技术、决定是否自研、形成工程产物、设计独立测试、限定主张、安排发布与维护。它们也保留了本书最有辨识度的张力：**AI扩大实现候选，教师扩大判断责任；可视化扩大可见性，证据纪律限制结论；从“用”走向“造”可以前进，也必须能够停下和回退。**

当前仍需保留四条诚实边界：

- 六个核心模型来自单本书、三个主要本地项目与现有研究的综合，尚未经过跨作者、跨学校的独立效度研究；
- 四层架构和 C×E 双轴需要在后续章节编码中检查互斥性、可用性与双人一致性；
- 六个模型能生成设计与验收动作，不能自动证明这些动作改善学生学习或教师能力；
- 动态可视化、多表征、认知负荷等学习科学内容继续作为条件性解释和章节方法卡，不承担 AI 自研与教师发展的核心论证。

因此，最稳妥的命名是：**“《从用到造》基于物理可视化、AI协作项目与证据治理归纳的六模型实践框架”**。正式写作使用“本书提出／本书归纳／在本地项目中复现”，不用“统一理论”“普遍规律”或“成熟度标准”。
