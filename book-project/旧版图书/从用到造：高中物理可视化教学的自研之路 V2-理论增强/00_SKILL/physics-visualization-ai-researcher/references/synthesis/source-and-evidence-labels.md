# 统一来源与证据标签

> 版本：v1.0（2026-08-12）  
> 用途：统一六维研究中曾并存的多套标签。技能输出、章节插入卡和试点只使用本文件定义的标签。

## 1. 两条正交轴

### 轴 A：来源性质

| 标签 | 名称 | 定义 | 典型用途 |
|---|---|---|---|
| R | 原始研究 | 同行评议论文、原始报告、作者正式学术出版物 | 理论定义、特定样本中的观察、方法与局限 |
| F | 正式框架 | 政府、国际组织、标准机构发布的框架或指南 | 规范、能力维度、风险管理原则 |
| E | 官方工程 | 产品方或研究机构关于功能、系统和工程模式的正式资料 | 工作流、接口、工具能力、工程取舍 |
| L | 本地材料 | V1、项目资源、源码、测试、文献卡片、课堂材料 | 本书事实、案例、项目过程、本土学科对照 |
| B | 参考书导航 | 《聪明教物理》等二手材料 | 定位表达结构和待回查来源 |
| S | 本书综合 | 由多源材料归纳出的本书模型、方法或编辑判断 | 原创框架、操作卡、阶段模型、章节路由 |

### 轴 B：本地事实可复核度

只在来源为 L 时使用。

| 标签 | 定义 | 允许语气 |
|---|---|---|
| E3 | 已打开原始文件、源码、正式数据、测试或现场材料，可逐项复核 | “原始记录显示”“在文件中可核验” |
| E2 | 经过项目台账或文献卡汇总，本轮未逐项打开全部原件 | “据项目台账”“现有汇总记录为” |
| E1 | 作者经验、计划、推断或待补材料 | “可作为假设”“尚需核验” |

旧研究卡中的 `L1/L2/L3` 只作为历史标记保留；新输出统一转写为 `来源=L + E1/E2/E3`，避免把来源类别和可复核度混在同一标签中。

## 2. 不能合并的“高低”

- 来源质量高，不代表证据可以支持强因果结论。
- 原始源码可复核，只能证明代码写了什么，不能证明模型代表现实或学生发生学习。
- 正式框架说明“应关注什么”，不能证明某产品安全、合法或有效。
- 官方工程文档说明系统怎样工作，不能证明教师普遍提效。
- 单课例可以说明怎样设计和实施，未提供比较数据时不能证明稳定学习效果。

## 3. 引用卡必填字段

每条引用候选必须写：

```text
来源标签：R / F / E / L / B / S
本地可复核度：E1 / E2 / E3（非本地来源写 N/A）
完整来源：作者、年份、题名、出版物或机构
定位：DOI/URL/本地绝对路径 + 页码或行号
核验状态：已回原文 / 只读官方页面 / 只读卡片 / 待回原件
直接支持：一句话
不能支持：一句话
本章用途：定义 / 机制 / 方法 / 案例 / 边界 / 对照
```

## 4. S（本书综合）的发布纪律

本书综合模型可直接作为作者的方法主张，但必须满足：

1. 标为“本书提出、归纳或采用”；
2. 给出至少两个不同章节或项目的复现锚点；
3. 给出一个能推导新设计动作的示例；
4. 给出失效条件或不适用场景；
5. 不把外部框架的名称移作自己的模型名称；
6. 未经多教师或多案例研究，不称“能力等级”“普遍规律”或“成熟标准”。
