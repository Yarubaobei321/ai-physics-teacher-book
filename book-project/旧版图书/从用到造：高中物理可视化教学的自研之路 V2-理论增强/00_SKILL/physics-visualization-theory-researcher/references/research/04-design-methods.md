# 调研维度 4：教学设计方法与教师动作

## 0. 用途与核心结论

本文件为“高中物理可视化理论研究专家”提供一套可执行的方法库。它把 V1 已有案例、本地物理教育文献卡片和源理论补充包连接起来，统一转写为：

> **理论或研究线索 → 设计原则 → 教师动作 → 学生任务 → 可观察产物 → 修订触发**

三个结论贯穿全文：

1. **技术选择由物理学习任务决定。** 教师先定位学生需要完成的物理动作，再决定使用实物、图、动画、仿真、网页、传感器、编程或 AI。
2. **学习任务必须产生可检查的外部痕迹。** 预测、模型、原始数据、代码、解释、版本和答辩记录，分别承担不同证据功能。
3. **一次设计的终点是下一次可解释的修改。** 评价信息需要返回表征、任务、支架、仪器、反馈或资源版本中的具体变量。

本方法库综合了多类来源。文献中的案例能够说明某种设计怎样实施，不能替本书证明学习效果；经典理论提供概念和机制，仍需完成页码定位；V1 能够证明项目已经写明、做成或记录了什么，不能自证理论普遍性。

## 1. 证据标签与写作纪律

### 1.1 四类标签

| 标签 | 含义 | 允许的写法 | 禁止的跨越 |
|---|---|---|---|
| **[F-V1]** | V1 正文、事实档案或项目原件可回查的已有事实 | “第 6 章设置了三套实验方案”“项目保留了 25 份作品及过程材料” | 从设计存在直接推出学习提升 |
| **[L-A/B/C]** | 本地文献卡片归纳的研究结论；字母表示语料索引中的证据等级 | “该研究在特定装置下报告……”“该课例展示了……” | 超出样本、任务、设备与研究设计外推 |
| **[T]** | 源理论、权威综合或源方法提供的概念与机制 | “TPACK 用于分析技术、教学法与内容知识的协调” | 未定位原文时写成可直接引用的精确原句或效应结论 |
| **[I]** | 本调研根据理论、文献和 V1 情境形成的设计推演 | “据此，本章可把……设计为……” | 写成已经实施或已经有效 |

其中，[T-待定位] 表示书目和官方入口已经核验，正式书稿引用前仍需补页码或稳定段落；[T-全文入口已核验] 表示已找到全文入口，仍需在真正引用的段落上做定位。

### 1.2 组装顺序

每个设计判断按以下顺序组装：

1. 用 [F-V1] 说明本项目已经出现的对象、问题或做法；
2. 用 [L] 或 [T] 说明相关研究提供的机制、先例或限制；
3. 用 [I] 明确下一步设计原则和动作；
4. 写出拟观察的学生产物及修订触发；
5. 保留尚不能判断的部分。

推荐句式：

> [F-V1] 第 8 章已经把光电门时间换算为速度的中间关系放在屏幕上。[L-B] 张传兵的装置研究表明，有效挡光宽度可能受具体光电门和计时模式影响。[I] 因此，下一版任务可要求学生先做本机标定，再用独立方法复核速度；标定曲线、设备编号和修正前后结果共同进入实验记录。

## 2. 三层设计循环

方法库可嵌入三个相互包含的循环。

### 2.1 课堂任务循环

> 发现问题 → 作出预测 → 操作或测量 → 组织证据 → 解释差异 → 修正模型或方案

它关注学生在一节课或一个项目阶段中做什么、留下什么。

### 2.2 资源设计循环

> 定位难点 → 写需求与边界 → 做原型 → 学科验真 → 进入任务 → 收集使用问题 → 发布新版本

它关注教师如何把教学判断变成装置、网页、仿真、数据工具或学习材料。

### 2.3 教师学习循环

> 设计 → 实施 → 分析 → 解释取舍 → 分享可复用材料 → 在新情境中再设计

它关注教师怎样从单次作品积累情境化的技术—教学—内容知识。设计活动可以成为教师学习的场域；只有保留问题、决策、证据和版本，经验才可能被同事理解和迁移。

## 4. M01 隐藏任务定位法

### 4.1 适用问题

当问题被描述为“电磁感应很抽象”“机械能守恒不会做”“动画看不懂”时，教师还无法据此选择表征、任务或工具。该方法把宽泛困难拆成学生需要完成、同时可以观察的物理动作。

### 4.2 理论与语料依据

- **[T-待定位] TPACK。** 技术整合涉及内容、教学法、技术及其交叉关系的情境化协调。它提醒教师从内容和学习任务出发选择技术，避免先有工具再寻找用途。
- **[T-待定位] 教师作为设计者。** Koehler 与 Mishra 的设计活动研究可作为“教师在具体设计中协调多类知识”的入口；Laurillard 可作为教师设计学习环境的理论评论入口。
- **[F-V1]** 第 2 章先问“学生看不见什么”，第 12 章用“学生困难—资源缺口—实际使用”三问筛选开发问题。
- **[L-B]** LIT-0063 把器材选择放入电容知识建构和定量化任务中；证据是单元案例与实验输出，无学生学习样本。

### 4.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 技术、教学法和物理内容需要在具体情境中协调 |
| 设计原则 | 难点必须落到对象、关系、条件和动作 |
| 教师动作 | 收集真实错答或操作问题；圈出学生卡住的转换；写成“学生需要用〈对象/证据〉完成〈动作〉” |
| 学生任务 | 辨认对象、比较状态、改变参数、画关系、选择模型、解释冲突或复核结果 |
| 可观察产物 | 错误样例、任务句、预测、草图、关系表、模型选择理由 |
| 修订触发 | 任务产物无法区分学生是否完成目标动作；工具功能与任务没有一一对应 |

### 4.4 教师动作清单

1. 从作业、课堂、装置或平台日志中选一条真实困难。
2. 分辨困难位于物理对象、变量关系、表征转换、测量、证据解释还是模型边界。
3. 写出学生在没有工具时无法完成的关键动作。
4. 说明现有资源具体缺少什么。
5. 指定资源进入课堂的时机、使用者、设备和产物。
6. 选择最低足够媒介；一张图能解决的问题不增加复杂交互。

### 4.5 不适用与常见滥用

- **不适用：** 事实性信息查找、一次口头说明即可解决的小问题；没有真实困难证据时，应先观察而非开发。
- **滥用：** 把“提高兴趣”“培养核心素养”直接写成开发目标；把 TPACK 三个圆当作作品的质量认证标志；用工具名称替代学习任务。

## 5. M02 表征分工与转换法

### 5.1 适用问题

一个页面同时放置实物图、动画、曲线、数值和公式，学生仍可能只看“运动得很像”。该方法先为每种表征分配功能，再要求学生在表征之间完成可观察的翻译。

### 5.2 理论与语料依据

- **[T-待定位] DeFT 多重表征框架。** 多表征效果取决于表征的教学功能、设计与任务匹配；同时出现多种表征不能自动推出理解提高。
- **[T-待定位] 多媒体学习。** 语言和图像信息需要在有限容量条件下被选择、组织和整合；具体原则需结合学段、内容和学习者。
- **[T-待定位] ICAP 与自我解释。** 学生能否产生超越给定信息的新表达，可用于区分观看、操作、建构和互动；小样本自我解释研究不能直接替本书证明效果。
- **[L-C]** LIT-0002 展示“视频—模型—频闪—传感数据—函数拟合—迁移”的课例结构，未提供学生思维变化的独立证据。
- **[L-C]** LIT-0004 提供“具体材料经过选择、比较、简化和提炼后成为抽象支架”的解释框架，缺少学习效果测量。
- **[F-V1]** 第 2 章强调表征转换，第 3 章把实物、模型和测量放在同一视野，第 4 章要求多表征共享状态且各有分工，第 9 章要求每种图解决一种主要困难。

### 5.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 多表征需要功能匹配和学习者主动整合 |
| 设计原则 | 一种表征承担一种主要解释任务；关键状态在表征间同步 |
| 教师动作 | 列出每种表征显示什么、隐藏什么；设置预测；要求指出对应量和转换规则；制造可解释的不一致 |
| 学生任务 | 从实物指向模型，从模型指向公式，从数据指向图像，再用另一表征复述或检验 |
| 可观察产物 | 对应表、带注释草图、预测—观察表、表征翻译说明、冲突解释 |
| 修订触发 | 学生能操作却说不出对应关系；多表征状态不同步；某一表征只增加装饰信息 |

### 5.4 教师动作清单

1. 定义学生当前看不见的关系。
2. 为实物、图、动画、曲线、数据和符号分别写一个功能句。
3. 删除不能服务该功能的信息。
4. 在显示结果前让学生画图、选方向或预测曲线。
5. 要求学生用指认、连线、标注或文字说明表征间对应。
6. 在表征冲突处暂停，追问数据、模型和画面哪一项需要修正。
7. 后续任务逐渐撤去教师提供的图，让学生自己生成表征。

### 5.5 不适用与常见滥用

- **不适用：** 学生已能直接观察并准确表达关系；新增表征会分散注意或需要大量无关操作。
- **滥用：** 把媒介数量当成“可视化程度”；让动画、数值和图线由不同状态生成；只要求学生观看；用漂亮场景掩盖比例、方向或时间尺度错误。

## 6. M03 可反驳模型工作台

### 6.1 适用问题

仿真、网页或代码可以稳定运行，也可能只是把预设关系画出来。该方法要求模型公开假设、接受边界测试，并由独立证据挑战。

### 6.2 理论与语料依据

- **[T-待定位] 模型本位探究。** Windschitl 等提出可围绕可检验、可修正且具有解释力的模型组织校内科学探究。
- **[T-待定位] 概念转变。** Posner 等的框架可用于分析原有解释、异常与新解释的关系；一次冲突不能证明稳定概念转变。
- **[T-已核验官方页] 科学论证。** Osborne 等的研究展示专门课程材料与教师支持改善论证质量的可能性，不能替本书未收集的数据背书。
- **[L-B]** LIT-0058 通过非理想 RC 等效模型、U-t 与 I-t 同步数据、积分和参数扫描建立定量链，缺少课堂学习数据。
- **[L-B]** LIT-0085 在机械能实验中根据残差重新审视系统边界并加入弹簧能量项，仍有校准和不确定度局限。
- **[F-V1]** 第 4 章把动画升级为有假设、计算、输出、检验和警告的模型工作台；第 11 章 P06 显示同一公式生成与验证会制造循环论证。

### 6.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 科学模型通过解释、预测、检验和修正发挥作用 |
| 设计原则 | 公开假设；安排可能失败的测试；验证数据不与生成机制同源 |
| 教师动作 | 写模型卡；选择边界点、临界点和反事实条件；准备独立数据链；展示残差和警告 |
| 学生任务 | 预测、调参、解释输出、寻找反例、比较独立证据、修改模型 |
| 可观察产物 | 模型卡、参数表、预测、残差图、反例记录、修订前后模型 |
| 修订触发 | 输出与独立数据冲突；残差有系统方向；模型在边界点出现不合理结果；警告条件被频繁触发 |

### 6.4 模型卡最小字段

- 研究对象与系统边界；
- 保留和忽略的因素；
- 输入量、状态量与输出量；
- 关系式及单位；
- 初始条件和参数范围；
- 可独立计算的特殊点；
- 可能失效的条件；
- 验证数据的来源；
- 当前版本与修订理由。

### 6.5 不适用与常见滥用

- **不适用：** 纯展示性历史资料或无法形成可检验预测的内容；数据来源不足时只能写设计假设。
- **滥用：** 把调参观看称为模型探究；用同一段代码生成数据并验证结论；只挑吻合点；把随机噪声当成真实误差；仿真结果与真实现象冲突时默认实物“做错了”。

## 7. M04 概念建构与迁移链

### 7.1 适用问题

学生可以复述定义和公式，却无法辨认物理对象、变量关系和适用条件。该方法用“对象—模型—变量—证据—迁移”组织概念课。

### 7.2 理论与语料依据

- **[T-待定位] 概念转变。** 原有概念、解释困难和新解释的关系可用于设计诊断与修订任务。
- **[T-待定位] 自我解释与建构性活动。** 学生需要产生自己的关系表达，而非只接收教师完成的解释。
- **[L-B]** LIT-0063 用实物、PhET 和传感器组织电容知识建构与定量拟合；证据主要是实验和仿真输出，无学生样本。
- **[F-V1]** 第 7 章以莱顿瓶和静电计把电容概念组织为辨认对象、建立模型、分离变量、连接证据、检验迁移五个动作。

### 7.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 新概念需要处理已有解释，并通过学习者主动组织形成关系 |
| 设计原则 | 定义放在对象、条件和证据之后；迁移任务更换外形但保留结构 |
| 教师动作 | 暴露原有解释；提供可操作对象；要求写出保留与忽略；一次改变一个变量；追问证据链 |
| 学生任务 | 辨认对象、画模型、预测变量方向、操作测量、用完整关系解释、处理新外形或反例 |
| 可观察产物 | 初始解释、模型图、变量控制表、证据链、修订定义、迁移判断 |
| 修订触发 | 学生依赖表面外形；定义缺少条件；操作结果与解释断开；迁移时重新套用记忆句 |

### 7.4 教师动作清单

1. 用一个真实对象或异常现象引出概念。
2. 先请学生说出当前解释并留下记录。
3. 要求明确系统、变量和模型删减。
4. 让学生在操作前预测变量变化方向。
5. 让实物、测量、曲线和公式互相指认。
6. 用结构相同、外形不同的新情境检验迁移。
7. 让学生用新证据修改原解释和定义。

### 7.5 不适用与常见滥用

- **不适用：** 已经稳定掌握、只需熟练化的程序性内容；没有足够证据支撑“概念转变”研究主张时，应只描述任务表现。
- **滥用：** 为制造“认知冲突”选择物理条件含混的奇观；教师过早揭示答案；把一次正确回答当成概念已经稳定改变。

## 8. M05 测量—换算—校准链

### 8.1 适用问题

数字传感器能快速给出读数，但读数还需经过仪器响应、几何条件、换算模型和误差判断，才能成为支持物理结论的证据。

### 8.2 理论与语料依据

- **[L-B]** LIT-0033 通过恒速装置和不同挡光宽度拟合光电门的固定修正量；修正量依赖设备、模式和环境。
- **[L-B]** LIT-0064 展示“视频采集—定时—标尺读数—表格计算—图像拟合”的数据链，也暴露透视、标定和释放误差未量化的问题。
- **[L-B]** LIT-0059 展示一个低成本传感器跨多个电学实验复用的可能性，同时只有有限校准描述。
- **[L-B]** LIT-0082 提醒开发前先理解传感器敏感方向和动态误差；多数证据仍是定性吻合。
- **[F-V1]** 第 5 章区分原始读数、校准和物理判断；第 8 章把光电门时间追溯到有效挡光宽度和速度模型，并保留单摆异常点。

### 8.3 方法链

| 环节 | 内容 |
|---|---|
| 研究线索 | 仪器读数受响应阈值、敏感方向、量程、几何和环境影响 |
| 设计原则 | 直接读数、派生量、模型和结论分层显示；关键设备按使用条件校准 |
| 教师动作 | 标出传感链；设计零点、多点和重复校准；保存原始数据和元数据；安排独立复核 |
| 学生任务 | 记录直接量、完成单位与换算、绘校准曲线、比较修正前后、解释异常 |
| 可观察产物 | 原始表、设备编号、校准曲线、换算式、误差表、复测记录 |
| 修订触发 | 不同设备结果系统偏移；残差随量程或方向变化；异常无法由现有模型解释；元数据不足以复现 |

### 8.4 “传感链”字段

1. 被测物理量；
2. 传感器实际响应的量；
3. 直接输出；
4. 几何或时间换算；
5. 标定标准与范围；
6. 采样率、分辨率和单位；
7. 环境与设备编号；
8. 派生量算法；
9. 独立复核方法；
10. 当前不确定因素。

### 8.5 不适用与常见滥用

- **不适用：** 目标只是观察现象方向，精确测量会挤占主要学习任务；设备不稳定且无法校准时，不宜生成定量结论。
- **滥用：** 把传感器输出直接写成真实值；单点对齐代替校准；跨设备套用修正量；只报告相对误差最小的一次；删除异常数据以使曲线整齐。

## 9. M06 同一问题多路径比较

### 9.1 适用问题

多个实验、仿真或数据工具可以回答同一物理问题。并列展示只能说明“方法很多”，共同问题和统一比较字段才能让学生学习如何选择证据。

### 9.2 理论与语料依据

- **[L-B]** LIT-0045 比较三种 DIS 测重力加速度路径，展示运动学与动力学多角度测量；三种方法的重复次数和仪器条件不等价，不能普遍排序。
- **[L-C]** LIT-0032 组织共同任务、四条技术路径、统一报告和组间质询，未提供学生作品评分和效果数据。
- **[L-B]** LIT-0063 比较实物、Phyphox、PhET 与商用 DIS 的不同功能，提示虚实互补和器材择优。
- **[F-V1]** 第 6 章围绕机械能守恒准备三套实验方案；第 8 章把三套装置写成三种“从直接读数到目标量”的证据翻译。

### 9.3 方法链

| 环节 | 内容 |
|---|---|
| 研究线索 | 不同技术路径对变量、误差、操作和表征有不同可见性 |
| 设计原则 | 固定共同问题和报告字段，再比较路径；比较解释力与限制，不只比较谁最接近标准值 |
| 教师动作 | 确定共同目标；统一重复与记录要求；分配或开放路径；组织交叉质询 |
| 学生任务 | 选择方案、说明原理、测量、处理数据、比较边界、回应质询 |
| 可观察产物 | 方法卡、原始数据、模型式、误差来源、比较矩阵、选择理由 |
| 修订触发 | 路径不可比；某条路径只承担展示；比较结论受不同重复次数或仪器精度支配 |

### 9.4 统一比较字段

- 直接测量量与目标量；
- 物理模型及近似；
- 仪器、量程和校准；
- 数据处理与重复设计；
- 随机与系统误差；
- 安全、时间与设备条件；
- 对学生可见的物理关系；
- 适合的课堂阶段；
- 本次数据支持的结论；
- 仍待复核的问题。

### 9.5 不适用与常见滥用

- **不适用：** 课时不足，学生连一条路径的测量链都无法完成；各方案测量对象或条件差异过大。
- **滥用：** 按一次相对误差给方法永久排名；不同方法使用不同重复次数却直接比较；教师预先宣布“最好方案”，学生只执行；虚拟结果被用来覆盖实物误差。

## 10. M07 作品建构与支架渐退

### 10.1 适用问题

学生可以加载例程、照图接线或修改一个参数，却未必能够独立提出方案。该方法把可运行样例当作起点，再逐步撤去结构、提示和答案，让学生通过制作、调试和说明形成外部作品。

### 10.2 理论与语料依据

- **[T-待定位] 造物取向的建构主义。** Papert 与 Harel 的 constructionism 关注学习者制作对自己和他人有意义的外部作品；作品完成本身不能证明概念理解或迁移。
- **[T-待定位] ICAP。** 学生是否产生新的表达，可用于检查活动是否停留在操作层。
- **[F-V1]** 第 5 章把积木编程安排为基础动作、数据关系、校准和判断，并设计支架撤除；第 10 章以完整工程解决进入问题，再从修改走向独立创造。
- **[L-B]** LIT-0059 展示一个开源传感器跨实验复用的开发路径，教学成效没有学生数据。

### 10.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 有意义的外部作品可成为建构、讨论和调试的共同对象 |
| 设计原则 | 样例先降低进入成本，随后逐步转移决策权；作品、过程和解释共同验收 |
| 教师动作 | 提供最小可运行样例；标注可修改点；按阶段撤去提示；用诊断问题代替直接修复 |
| 学生任务 | 运行、拆解、修改、重组、独立设计、测试、解释、分享和再修改 |
| 可观察产物 | 实物或网页、代码/积木、需求说明、测试记录、版本差异、口头解释 |
| 修订触发 | 学生离开样例无法开始；作品功能正常但说不清物理关系；不同版本没有修改理由 |

### 10.4 支架渐退的四级

1. **运行完整样例：** 打通连接、下发和读数。
2. **修改限定变量：** 改引脚、阈值、时间或显示，解释行为变化。
3. **重组模块：** 从功能要求选择积木、传感器和数据处理。
4. **独立设计与验收：** 自写需求、方案和测试，并接受质询。

每一级都要留下产物。进入下一级的条件是学生能解释当前级别的输入、过程、输出和限制。

### 10.5 不适用与常见滥用

- **不适用：** 安全风险高、设备昂贵或基础操作尚未稳定时，开放程度需降低；学习目标是理解现象而非制作时，作品不必复杂。
- **滥用：** 把“做出东西”等同于理解；支架永久保留；只评外观和功能；教师替学生完成关键修复；让 AI 生成作品后只要求学生展示。

## 11. M08 项目证据契约

### 11.1 适用问题

项目学习需要开放方案，也需要收紧物理主线、证据、安全和阶段责任。该方法在项目启动时建立“证据契约”，提前规定每一阶段要回答什么、交什么和怎样复核。

### 11.2 理论与语料依据

- **[T-待定位] PBL。** Blumenfeld 等强调驱动问题、作品、持续探究、动机与教师支持之间的关系；跨课时制作活动不能自动归类为高质量项目学习。
- **[T-待定位] 造物取向的建构主义。** 可分享作品为思考和交流提供共同对象，仍需学生解释和检验。
- **[L-C]** LIT-0123 提供项目准备、方案论证、制作实验、展示评价四阶段及五维量规；全文属于教学方案，没有真实学生数据。
- **[L-C]** LIT-0032 展示共同问题、多技术路径、统一报告和组间质询的流程，无效果测量。
- **[F-V1]** 第 10 章把项目写成问题定义、物理主线、最低标准、版本失败、AI过程证据、答辩、真实观众和安全公开。

### 11.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 项目学习需要驱动问题、持续探究、作品与支持共同维持“做”和“学” |
| 设计原则 | 开放方案，固定证据底线；项目阶段由可检查产物连接 |
| 教师动作 | 写驱动问题与物理主线；设最低标准和安全门；安排阶段审查、同伴质询和公开答辩 |
| 学生任务 | 定义问题、建模、提出方案、制作、测量、诊断失败、修订、答辩 |
| 可观察产物 | 项目说明、模型、原始数据、作品、版本日志、失败记录、答辩与同伴反馈 |
| 修订触发 | 作品与物理解释不一致；失败没有记录；证据只来自同一生成链；安全或公开边界不清 |

### 11.4 证据契约字段

- 驱动问题及服务对象；
- 核心物理量、关系和模型边界；
- 允许开放的设计变量；
- 不可放松的安全、伦理和数据条件；
- 各阶段最低可交付产物；
- 数据和测试要求；
- AI、教师与学生的责任；
- 同伴质询和答辩问题；
- 失败记录与版本规则；
- 最终公开范围。

### 11.5 不适用与常见滥用

- **不适用：** 一课时内即可完成的封闭概念任务；没有持续探究、作品修订或真实选择空间；存在不可控安全风险。
- **滥用：** 给普通制作活动加上“项目式”名称；用热闹展示代替数据；虚构真实情境；评价只看成品；开放所有条件导致物理目标消失；把合作分工表当成协作质量证据。

## 12. M09 TPACK 约束下的人机共设计

### 12.1 适用问题

生成式 AI 能快速产生教案、代码和页面，也可能生成学科错误、无效交互或脱离课堂条件的“完整成品”。该方法把 AI 放在教师定义的设计与验收结构中。

### 12.2 理论与语料依据

- **[T-待定位] TPACK。** 教师需要协调物理内容、教学法与技术及其交叉关系；一张框架图不能替实践贴上“深度融合”标签。
- **[T-待定位] 教师作为设计者。** 设计活动可能成为综合知识发展的情境，不能推出所有自研都会促进专业发展。
- **[L-B]** LIT-0116 的 22 名职前数学教师研究显示，参与者较容易发现教学法问题，却常漏掉模型生成的数学错误；样本、任务和学科限制外推。
- **[L-B]** LIT-0118 的 29 名职前小学科学教师作品研究中，教学策略得分高于 AI 功能选择，且准确性与依赖是常见顾虑；该文为预印本且无课堂实施。
- **[L-B]** LIT-0119 的小样本艺术 STEAM 教案研究显示 AI 辅助作品盲评分数提高，但没有课堂与学生结果，不能迁移为物理教学效果。
- **[L-B]** LIT-0087 的物理任务测试暴露复杂情境、图像和真实性风险，模型时效性和研究设计限制明显。
- **[F-V1]** 第 12 章已经形成问题筛选、规则、技能、模板、验收、版本、PRD、五道门和特殊点核验；第 10—11 章保留学生—AI过程与成品分离的实例。

### 12.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 技术整合需要内容、教学法与技术的情境化协调；生成结果需要学科鉴别 |
| 设计原则 | 教师先独立定义问题和验收判据，AI提出候选，最终通过学科、功能、使用、合规与留档检查 |
| 教师动作 | 写 PRD；提供物理依据和边界；比较多版本；准备独立特殊点；在真实设备上测试；保存取舍 |
| 学生任务 | 使用资源时完成预测、操作、记录和解释；参与 AI 项目时核对模型、来源和输出 |
| 可观察产物 | 需求文档、提示与输入材料、候选版本、测试用例、验收表、变更说明、课堂任务单 |
| 修订触发 | 物理输出与独立预期不符；功能与学习目标错配；真实设备或课堂条件失败；来源、隐私或责任不清 |

### 12.4 八步人机共设计

1. **教师独立定义问题。** 先写学生困难、使用场景和完成标准。
2. **建立物理基准。** 用教材、原始文献、手算或独立仪器给出特殊点。
3. **写内容—教学—技术约束。** 指定模型、学生动作、设备和证据产物。
4. **让 AI 生成候选。** 候选可以是结构、代码、图、题目或测试清单。
5. **逐项比较。** 把候选与原需求、物理基准和课堂条件对照。
6. **学科与功能验真。** 分开检查文字、公式、动画、数据和交互。
7. **微型实施。** 先用小范围、真实设备和边界情境测试。
8. **版本化发布。** 记录改动、依据、验证和公开责任。

### 12.5 不适用与常见滥用

- **不适用：** 涉及未脱敏学生数据、无授权材料或高风险实验且缺少专业审查；教师无法建立独立学科基准时，不宜直接发布。
- **滥用：** 只优化提示词，不定义教学任务；用 AI 自己生成的答案验收 AI；只检查教案结构和页面美观；把生成速度等同于教师发展；让 TPACK 成为“用了三种知识”的标签。

## 13. M10 小步设计迭代

### 13.1 适用问题

教师常会反复修改装置、网页和任务，但若没有明确问题、证据和版本，修改很难积累为可复用的设计知识。

### 13.2 理论与语料依据

- **[T-全文入口已核验] 设计型研究。** Design-Based Research Collective 把真实情境中的干预改进与情境化理论发展联系起来；个人反复修改作品的经历不足以构成完整设计型研究。
- **[T-待定位] 教师作为设计者。** 设计、实施、分享和知识积累可作为教师专业工作的分析入口。
- **[L-B]** LIT-0085 通过实验残差重新划定系统边界，是“证据触发模型修订”的应用先例。
- **[F-V1]** 第 11 章将评价返回下一次教学；第 12 章要求一次只改一个功能、立即验证、保留回退点并记录理由。

### 13.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 设计知识来自真实情境中的系统干预、证据分析与多轮修订 |
| 设计原则 | 每轮只改变可定位变量；同时记录情境、证据、决定和结果 |
| 教师动作 | 写设计猜想；冻结版本；实施；收集多源证据；解释问题；修改一个变量；复验 |
| 学生任务 | 在一致任务中产生过程、成品和解释；对修改版完成相同或等值复验 |
| 可观察产物 | 版本包、实施条件、课堂记录、作品、问题清单、修改说明、复验结果 |
| 修订触发 | 预期动作没有出现；证据相互冲突；技术问题中断任务；新版本带来新的误导 |

### 13.4 最小迭代记录

| 字段 | 内容 |
|---|---|
| 情境 | 学生、课时、设备、分组、教师支持 |
| 原设计猜想 | 预计哪项设计改变哪种学生动作 |
| 当前版本 | 工具、任务、量规和数据口径 |
| 观察证据 | 过程、成品、解释及技术日志 |
| 问题解释 | 主要解释与替代解释 |
| 修改变量 | 表征、顺序、支架、测量、反馈或技术中的一项 |
| 复验任务 | 如何判断修改后的表现 |
| 可迁移原则 | 在什么条件下可供其他章节或教师参考 |

### 13.5 何时可以称为设计型研究

至少需要：

- 明确的实践问题与理论驱动的设计猜想；
- 在真实情境中实施；
- 系统收集和分析证据；
- 多轮迭代及版本可追溯；
- 同时报告有效、无效和情境限制；
- 产出可供检验的设计原则，而非只讲个人成长故事。

达不到这些条件时，可称“设计迭代”“教学改进”或“原型修订”。

### 13.6 不适用与常见滥用

- **不适用：** 尚未进入真实使用情境；只有成品变化而无实施证据；研究目标只需完成单次技术验收。
- **滥用：** 所有反复修改都称设计型研究；多处同时改变后把结果归因于一项修改；只保留成功版本；用版本数量代替研究质量。

## 14. M11 共同对象与可移交设计

### 14.1 适用问题

教师经验常停在个人电脑、一次培训或一段聊天记录中。该方法把资源、规则、证据和版本组织成共同对象，让同事能够理解、复用、质疑和继续修改。

### 14.2 理论与语料依据

- **[T-待定位] 实践共同体。** Wenger 以实践参与分析学习、意义和身份；群聊、培训班或松散交流群不能自动称为实践共同体。
- **[T-待定位] 教师作为设计者。** Laurillard 可作为设计、实施、分享与专业知识积累的文献入口，未阅读全文前不归纳具体效果。
- **[F-V1]** 第 12 章写明可移交资源包、版本、协作、发布和维护；书稿与网站项目已使用集中资产、需求文档、验收和版本记录。

### 14.3 方法链

| 环节 | 内容 |
|---|---|
| 理论线索 | 共同实践需要共同问题、可共享工具、话语和历史 |
| 设计原则 | 分享可继续工作的资源包，同时保留设计理由、证据和责任 |
| 教师动作 | 统一入口；写 README 与设计说明；提供源文件、测试、授权和版本；组织复用者反馈 |
| 学生任务 | 若资源进入课堂，继续留下任务产物和使用问题；教师发展场景中，学习者完成复用与改造 |
| 可观察产物 | 资源包、复用记录、问题单、改版、共同量规、案例说明、授权与署名 |
| 修订触发 | 资源离开作者无法运行；同事无法判断适用条件；重复出现同类错误；来源和维护责任不清 |

### 14.4 可移交资源包

- 本体与源文件；
- 集中资产与数据；
- 教学问题、对象和使用场景；
- 物理模型、边界和特殊点；
- 任务单与可观察产物；
- 校准、测试和验收记录；
- 已知问题和故障排查；
- 版本与变更说明；
- 素材来源、许可、隐私与公开范围；
- 维护者和反馈入口。

### 14.5 不适用与常见滥用

- **不适用：** 涉及学生隐私、未清版权或高风险装置时，先完成脱敏、授权和安全说明；资源仍处于不可复现的个人实验阶段时，应限定分享范围。
- **滥用：** 把参加群聊等同于共同体学习；只发成品链接；用下载量证明专业发展；抹去原作者和贡献记录；没有维护责任却公开长期服务承诺。

## 15. 教师动作词典

下表把抽象教学原则转换为可观察的教师动作。

| 设计阶段 | 教师动作 | 需要指向的对象 |
|---|---|---|
| 定位 | 收集、圈出、拆分、命名、排序 | 错误、难点、转换、条件 |
| 约束 | 限定、保留、隐藏、分段、设界 | 信息、变量、参数、角色、风险 |
| 引出 | 展示、提问、延迟、制造差异、要求预测 | 对象、现象、模型、结果 |
| 支持 | 示范、提示、给样例、搭支架、同屏对应 | 操作、表征、测量、解释 |
| 取证 | 编号、记录、保存、抽样、复测、交叉核验 | 对话、数据、作品、设备、版本 |
| 反馈 | 指认、追问、比较、描述差距、给复验任务 | 证据、条件、反例、下一步 |
| 修订 | 调序、删减、替换、拆分、合并、撤架、回退 | 任务、表征、仪器、提示、版本 |
| 分享 | 打包、署名、说明、授权、交接、维护 | 资源、来源、责任、适用条件 |

动作必须带对象。例如“加强引导”要改写为“在学生看到曲线前，要求先画出方向预测”；“及时反馈”要改写为“指出模型条件没有进入代码，并安排一个独立特殊点复验”。

## 24. 可直接用于技能蒸馏的方法 DNA

### 24.1 必须做

- 先从 V1 的真实对象、困难和证据状态出发；
- 只选能改变设计变量的理论；
- 将每条理论转成教师动作与学生产物；
- 给每个方法写不适用条件和常见滥用；
- 把文献结论限制在原研究对象、任务和情境；
- 将跨情境设计明确标为 [I]；
- 为理论、文献、V1 和推演分别保留锚点；
- 让异常、冲突和失败进入下一版设计。

### 24.2 禁止做

- 用 V1 案例自证理论；
- 用文献中的设计案例证明本书成效；
- 把 TPACK、建构主义、PBL 或 DBR 当作标签；
- 把“教师动作”写成“加强引导、促进思考”等无对象口号；
- 把页面运行、项目完成或作品精美当作学习证据；
- 把 AI 输出交给 AI 自己验收；
- 在缺少实施证据时写“学生已经……”；
- 为增加理论感复制分类、流程图或参考案例。

### 24.3 最小输出

> **问题签名｜来源与证据等级｜设计变量｜教师动作｜学生任务｜可观察产物｜修订触发｜不适用条件｜常见滥用｜本地锚点**

这十项齐全，理论才真正进入教学设计。
