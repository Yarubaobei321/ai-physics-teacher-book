# 蓝牙模式使用说明

蓝牙模式用于单机或在家测试：学生端 PWA 通过 Web Bluetooth 直接连接 ESP32，不经过教师 Mac 服务器，也不需要设备编号绑定。

课堂主路径仍然是 WiFi 模式。蓝牙模式适合这些情况：

- 没有教室 WiFi 或教师服务器时，临时把一块 ESP32 当作离线练习板。
- WiFi 不可用但 BLE 正常的 B 类板。
- 单台真机验证 Blockly 生成的 MicroPython 是否能运行。

## 浏览器要求

- 推荐 Chrome / Edge。
- 页面必须是 HTTPS，或在本机 `localhost` 打开。局域网普通 `http://192.168...` 通常不能使用 Web Bluetooth。
- iOS Safari 不支持 Web Bluetooth。

## ESP32 固件要求

设备上需要有这些文件：

- `boot.py`
- `main.py`
- `ble_transport.py`
- `config.json`

`config.json` 里把 `transport` 设为 `ble`：

```json
{
  "id": "B01",
  "label": "蓝牙练习板",
  "transport": "ble",
  "ble_name": "ESP32Blockly-B01",
  "wifi": { "ssid": "", "password": "" },
  "server": ""
}
```

说明：

- `id` 用于蓝牙连接成功后的提示，不参与权限校验。
- `ble_name` 是浏览器蓝牙选择窗口里看到的名字。
- 蓝牙模式不需要 WiFi；保留 `wifi` 和 `server` 字段只是为了兼容现有配置结构。

如果 `transport` 缺省或写成 `wifi`，设备仍按原来的课堂 WiFi 模式启动。

## 学生端使用

1. 打开 ESP32Blockly 学生端。
2. 顶栏连接方式切到“蓝牙”。
3. 点击“连接蓝牙”。
4. 在浏览器弹窗中选择 `ESP32Blockly-...` 设备。
5. 拼好积木后点“上传”。

运行输出会回到页面底部串口窗口。短程序执行结束后会显示“程序结束”。

## 停止与重传限制

BLE 模式尽量在不中断蓝牙连接的情况下直接启动学生代码；但 MicroPython 不能可靠杀掉一个正在 `while True` 中运行的线程。

因此：

- 如果设备空闲，上传会直接运行，不需要重连。
- 如果旧程序还在运行，再次上传或停止时，设备会 `soft_reset()` 来清掉旧线程，蓝牙会断开，需要重新点“连接蓝牙”。
- 教学代码里建议保留 `time.sleep_ms(...)` 或 `time.sleep(...)`，避免纯忙等循环饿死通信主循环。

## 验证建议

先用最小程序验证：

```python
print("hello ble")
```

再测试循环输出：

```python
import time
while True:
    print("tick")
    time.sleep(1)
```

预期结果：

- 页面能发现并连接 `ESP32Blockly-...`。
- 上传后串口窗口显示输出。
- 对正在运行的循环程序点“停止”后，设备重启并断开，重新连接后应回到空闲。
