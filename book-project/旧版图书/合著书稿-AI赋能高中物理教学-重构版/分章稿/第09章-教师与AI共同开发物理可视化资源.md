# 第9章 教师怎样与AI共同开发物理可视化资源

> 主笔：黄灿斌
> 本稿性质：重构版第一轮初稿。建站版本、页面截图、公开课数据和课程实施数据仍需核验；文中不把功能验证写成学习效果。

## 从“我想做一个网页”回到学生的具体难点

教师想开发一个教学网页，最容易从工具开始：选一个能生成代码的平台，输入“请帮我做一个机械能守恒实验网页”，然后等待一个看起来完整的页面。页面也许很快就能显示公式、按钮和动画，但它很难自动回答最重要的问题：这个页面究竟要帮助哪一类学生跨过哪一道物理学习障碍？

资源开发的起点不应是“AI能生成什么”，而应是“学生现在为什么看不见、测不出、说不清或无法迁移”。如果学生不理解重力势能和动能怎样对应，页面需要的可能是能改变参数、对照模型条件的交互演示；如果学生有原始数据却不会判断误差，页面需要的可能是保留原始量、显示差异方向并要求写出归因链的数据表；如果学生课上做过实验，课后练习却完全换了装置和符号，页面需要的可能是课堂—课后同源，而不是再增加一个动画。

这也是第8章与本章的分工。第8章从真实装置出发，讨论证据如何进入机械能守恒模型；本章从教师的开发决策出发，讨论怎样把这种学科判断转化为一个可用、可检查、可维护的资源。第8章问“学生凭什么相信这个模型”，本章问“教师怎样造出能让学生检查模型的工具”。

### 三个不匹配

教师自研可视化资源，通常源于三个不匹配。

第一个是学情不匹配。通用课件把知识按统一进度呈现，却不一定处理本班学生反复出现的误区。比如，学生把向上运动等同于向上加速，或者把曲面下滑中平动动能的不足简单写成“实验误差”，一个通用动画可能只能展示理想过程，不能让学生追问模型边界。

第二个是器材和场景不匹配。商用数字化实验系统有稳定的功能，但它的接口、传感器、实验方案和数据字段未必适合一所学校现有的设备。教师想同时比较纸带、双头光电门和气垫导轨，或者希望浏览器直接接收学校自制的ESP32光电门，现成系统不一定允许这种改造。

第三个是能力不匹配。教师最了解学生难点，却往往不具备完整的前端开发能力；程序员能够实现页面，却未必知道为什么一个起算点、一个平均速度或一个符号约定会改变学生的物理解释。生成式AI降低了实现门槛，却没有消除这三个不匹配，只是把“不会写代码”的问题部分转移成“不会提出可验收需求、不会检查科学性”的问题。

### 三问选题卡

在动手开发之前，可以先填写一张三问选题卡：

| 问题 | 需要写清什么 | 机械能守恒案例中的回答 |
|---|---|---|
| 学生难点是什么 | 是概念、测量、模型、迁移还是评价障碍 | 手算占用时间，学生难以比较三方案的模型差异；“差不多相等”缺少判据 |
| 现有资源差在哪里 | 现成课件或实验系统为什么不能解决 | 不能同时承载三种方案、真实数据、误差解释和课后同源练习 |
| 使用场景在哪里 | 谁在什么时候用，输入和输出是什么 | 教师备课、学生分组实验、课后手机复盘和下一节课的错题反馈 |

三问卡的作用不是筛选“有创意”的题目，而是阻止教师把一个模糊愿望直接交给AI。如果第二问只能回答“希望页面更漂亮”，第三问只能回答“课堂上用一下”，说明开发目标还没有进入物理学习过程。

### 从一个误区确定一个资源任务

开发对象越大，越容易让AI替教师做选择。更稳妥的起点，是把一个具体误区写成一个可观察任务。例如：学生看到曲面下滑的数据后，把平动动能偏小直接写成“仪器有误差”，却没有考虑滚动圆柱体的转动动能。

这个误区可以转化为一个最小任务：学生输入释放高度、质量和光电门速度，比较重力势能减少量与平动动能增加量；页面显示差异方向，要求学生选择“操作误差”“测速模型近似”“遗漏转动动能”三个解释，并写出其中一个解释会带来的新预测。

这样，AI接到的不是“做一个机械能守恒网页”，而是一个能够明确验收的学习任务：

| 任务元素 | 具体内容 |
|---|---|
| 学生动作 | 输入原始量、查看差异、选择解释、写出新预测 |
| 物理模型 | 重力势能、平动动能、转动动能及其适用条件 |
| 页面输出 | 能量比较、差异方向、解释选项、预测记录 |
| 教师验收 | 公式正确、异常数据保留、解释不能直接给出、预测可复核 |

一个小任务完成后，再决定是否扩展到三套方案、课后习题和教师后台。资源开发因此呈现“误区—任务—页面—证据”的顺序，而不是“功能—页面—再找用途”。

## 六要素不是功能清单，而是一条学习支架

机械能守恒在线实验室采用六个要素：原理讲解、交互演示、数据表、误差分析、分层习题和实验回顾。它们不是为了让页面显得丰富，也不是把课件、计算器、题库和说明书拼在一起。六要素的意义，在于它们分别接住了学习过程中不同的责任。

### 原理讲解：先让公式中的量有来源

原理区不能只放一段“机械能守恒定律是指……”，再配一个公式。学生需要知道研究对象、系统边界、势能零点、直接测量量和处理后的物理量分别是什么。第8章中，纸带方案从点位和时间间隔估计速度，曲面方案从挡光时间得到区间平均速度，气垫导轨需要把滑块与重锤纳入同一系统。原理区应把这些关系逐项说明，不能把最终能量公式当作黑箱。

一个可验收的原理区至少回答四个问题：

1. 我们研究哪个系统？
2. 直接测量什么量？
3. 怎样从直接测量量得到速度和能量？
4. 公式在哪些条件下成立？

如果页面只展示最终公式，学生可能把网页输出当成事实；如果原理区把所有推导写成大段文字，学生又很难在实验中找到需要使用的字段。适合教师资源的原理说明，应该把公式拆成“量—关系—条件”的短链条，让学生在输入数据时能回看它。

### 交互演示：让学生改变条件，而不是播放答案

交互演示的价值不在于动画流畅，而在于它是否让学生看到改变一个条件会发生什么。对于机械能守恒，可以让学生改变释放高度、质量、摩擦条件或系统边界，观察能量柱状图、速度和运动轨迹怎样变化；也可以给出两套看似相同的装置，让学生判断哪套满足“只有重力做功”的近似。

交互演示应保留一个“模型出口”：学生改变参数后，需要写下观察到的变化和自己的解释。若动画只播放一条理想曲线，学生只能获得视觉印象，不能形成可检查的模型。

演示还要告诉学生它没有模拟什么。真实轨道的振动、纸带摩擦、传感器噪声、浏览器连接失败，不一定都能在一个简化模型中呈现。仿真可以帮助放大某个关系，却不能替代真实测量中的限制。页面应在“模型条件”或“使用边界”中明确这一点。

### 数据表：把计算负荷接走，把证据责任留下

数据表是六要素中最容易被误解的部分。自动完成乘方、单位换算和能量差值，可以释放课堂时间，但如果页面只显示处理结果，学生会失去对数据链的掌握。

一个合格的数据表应把字段分为三类：

| 字段类型 | 示例 | 页面要求 |
|---|---|---|
| 原始量 | 点位、时间间隔、挡光时间、质量、高度 | 学生或传感器直接输入，保留原始值和单位 |
| 处理量 | 速度、动能变化、势能变化、相对差异 | 显示公式、参数和计算过程 |
| 解释量 | 主要误差来源、模型条件、证据强度 | 不能只自动生成，须保留学生选择和说明 |

数据表至少要提供一个人工复算入口。学生任选一个数据点，按页面公式手算，再与自动结果比较；如果结果不同，页面不应直接标红“错误”，而应提示检查时间间隔、单位、起算点、质量和公式版本。这样，网页成为证据检查器，而不是答案发放器。

### 误差分析：让“差一点”拥有方向和原因

“请分析实验误差”是很多实验报告中最空泛的一项要求。学生通常列出摩擦、空气阻力、读数误差和仪器误差，却没有说明这些因素会让哪个量变大、哪个量变小，也没有判断它们是否与实际数据方向一致。

误差分析区可以先显示能量差的大小和符号，再给出候选原因，要求学生排序并写出因果链。例如：

`曲面下滑中平动动能偏小 → 可能遗漏转动动能 → 若补测角速度，应观察到……`

这种页面不会自动替学生确定“真正原因”，而是提供组织证据的结构。若页面只有一个“误差来源”下拉菜单，学生可能机械选择；若页面要求学生写出数据预期，工具才真正进入模型推理。

### 分层习题：分的是思维责任，不只是难度

三套实验的习题可以按基础、提高和挑战分层，但分层不能只按数字大小和计算步数排列。

- 基础层：认识装置、单位、起算点、系统和基本物理量；
- 提高层：从原始量计算处理量，比较数据，解释差异方向；
- 挑战层：比较方案、修改模型、设计新的测量或审查一个错误解释。

题目还应与页面同源。学生刚在落体页面填写过实际计数点间隔，习题就可以追问隔点取样时`T`应如何变化；学生刚在曲面页面看到转动动能缺口，习题就可以要求区分“模型遗漏”和“操作误差”；学生刚在气垫导轨中选择研究系统，习题就可以给出一个连接体新情境，检查系统观是否迁移。

自动判分适合判断单位、计算和明确选项；涉及模型边界和证据解释的题，应保留简答、量规或教师复核入口。自动生成的解析也必须经过物理教师校验。

### 实验回顾：把操作记忆接回模型

实验回顾不是把器材和步骤再抄一遍，而是帮助学生把“我做了什么”连接到“为什么这样做”。一份回顾应包括：实验目的、研究系统、原始量、关键操作、公式和条件、最可能的失败点、数据解释和可迁移问题。

缺席学生可以通过回顾区了解操作链，已完成实验的学生则可以用它检查自己的记录。回顾区也能成为教师维护资源的入口：如果多个班级在同一个步骤出错，就说明页面、器材说明或课堂提示需要修订。

### 六要素的最低版本

并非每个课题一开始都要做出六要素齐全的标准页面。最低版本可以只包括原理说明、一个可操作演示和原始数据记录；先验证学生是否真的需要这个资源，再逐步增加数据处理、误差、习题和回顾。

最低版本不是降低科学性，而是降低无效开发的成本。教师应先用一个真实难点检验页面是否改变了学生的观察或解释，再决定是否扩大功能。资源的复杂度必须由学习任务推动，而不是由AI可以生成的按钮数量推动。

### 六要素怎样互相咬合

六要素真正成为“体系”，需要它们之间有数据和问题的往返，而不是六个互不相连的页面。

原理讲解提出研究对象和模型条件，交互演示让学生改变一个条件；数据表接收实验中的原始量，输出处理结果；误差分析把结果中的差异变成需要解释的问题；分层习题把课堂中的装置和符号带入个体迁移；实验回顾再把操作、公式和边界重新组织，供下一次课和教师备课使用。

可以把这种关系写成一条资源链：

`原理条件 → 交互预测 → 原始数据 → 处理结果 → 误差论证 → 分层迁移 → 回顾与再设计`

如果数据表默认填入一组理想数据，误差区显示的只是程序预设；如果习题情境换成学生完全没有见过的装置，课堂—课后同源就被切断；如果回顾区只重复器材清单，教师也无法知道哪个步骤导致了错误。资源结构的好坏，不在于每个模块单独看起来是否完整，而在于前一个模块提出的责任能否被后一个模块接住。

对于设备有限的学校，可以先做纸带数据输入和离线习题；对于设备较齐全的学校，可以接入光电门和实时图表。但无论版本如何变化，原始量、模型条件、解释入口和迁移任务这四个核心接口不能被省略。

## 先写需求，再让AI生成

### 一页式需求模板

与AI协作时，最有价值的文件往往不是最长的提示词，而是一页能够反复复用的需求模板。模板至少包括：

| 字段 | 写法示例 |
|---|---|
| 目标用户 | 高中物理教师和完成验证实验的学生 |
| 学习难点 | 学生只看两个结果是否接近，不会追问系统和模型条件 |
| 使用场景 | 课堂分组、课后复盘、教师备课 |
| 输入量 | 点位、时间间隔、质量、挡光时间、高度 |
| 输出量 | 速度、能量变化、差异、图表、解释入口 |
| 公式与单位 | 写出公式、符号、单位和默认参数 |
| 不能做什么 | 不自动删除异常数据，不把设计意图写成效果结论 |
| 完成标准 | 原始量可追溯、公式可复算、移动端可操作、缺失数据有提示 |

需求模板迫使教师在开发前完成一次学科建模。若“输入量”写不清，AI很可能自作主张生成一组默认数据；若“不能做什么”没有写，AI可能自动平滑曲线、删除异常点或把“误差”改成“错误”。

### 把一个页面拆成任务块

不要一次要求AI生成完整网站。可以把一个实验页拆成若干独立任务块：

1. 建立页面信息结构和术语表；
2. 完成原理说明和公式注释；
3. 完成一个交互演示；
4. 完成原始数据表和处理公式；
5. 添加误差分析与学生解释入口；
6. 添加分层习题和解析；
7. 做移动端、数据边界和科学性验收；
8. 保存版本并记录未完成事项。

每个任务块都应有输入、输出和验收条件。AI可以承担代码、表格、文本初稿和测试数据的生成，但任务完成与否由验收条件决定，而不是由AI说“已完成”决定。

### 提示词的四个部件

一条可复用的开发提示，至少包含四类信息：

- **角色与范围**：你是协助物理教师实现一个页面，不负责判断教学效果；
- **已有材料**：术语、公式、页面结构、数据字段和参考文件；
- **约束条件**：单位、浏览器、移动端、隐私、不能删除原始数据；
- **验收标准**：哪些按钮、字段、公式、错误提示和页面状态必须可检查。

提示词不一定越长越好。长篇背景如果没有任务边界，反而容易让模型抓不住重点。更可靠的方式是把稳定规则放在规则文件，把本次任务放在需求模板，把测试结果和修改要求写入版本记录。

### 一个任务块的协作示例

以“数据表和误差分析区”为例，教师可以按四轮与AI协作。

第一轮只要求AI根据已确认的物理量和公式搭建字段，不生成默认实验结论。教师检查字段名称、单位、输入类型和空值处理。

第二轮要求AI添加处理公式和一个可复算的测试输入。教师用纸笔复算速度、动能变化和相对差异，检查公式和数量级。

第三轮要求AI添加图表、候选误差来源和学生解释入口。教师检查图表是否保留原始数据，候选原因是否与该实验模型相匹配，系统是否避免直接告诉学生正确答案。

第四轮才要求AI处理移动端布局、数据导出和异常提示。教师用空数据、极端值、单位错误和断网情况测试页面，并把发现的问题写入版本记录。

每一轮都只改变一类内容。即使页面出现问题，也能知道是字段、公式、交互还是工程兼容导致的。协作过程不追求模型一次生成最终版本，而追求每一步都能被人理解和验收。

## AI生成之后，教师必须做四层校验

### 第一层：物理校验

教师先检查公式与模型，而不是先检查颜色和动画。重点包括：研究对象、系统边界、正方向、单位、有效数字、势能零点、平均量与瞬时量的关系、适用条件和异常状态。

机械能页面中，一个单位写错就足以改变学生判断。例如速度平方的单位应为`m²/s²`，不能写成`m/s`；相对差异的分母和符号必须前后一致；曲面下滑中只显示平动动能时，要明确转动动能是否被忽略。AI生成代码时，工程上可运行不代表物理上正确。

教师应建立“公式三查”：

1. 量的定义是否与页面字段一致；
2. 单位和数量级是否一致；
3. 公式是否写明了模型条件。

### 第二层：教学校验

页面完成后，要重新问：学生在这个页面中实际做了什么？是只点击按钮、看一条动画和抄一个结论，还是必须提出预测、输入原始数据、比较结果并解释差异？

教学校验至少检查五点：

- 任务是否有明确起点和终点；
- 学生是否能看见自己的数据；
- 系统是否给学生留下解释和反驳空间；
- 分层任务是否体现认知台阶；
- 页面输出能否回到下一次教学决策。

如果网页让学生快速完成了所有计算，却没有留下任何解释证据，它可能提高了操作效率，却没有改变学习过程。相反，一个功能较少但要求学生说明模型条件的页面，更可能成为有价值的教学资源。

### 第三层：工程校验

工程校验关注“页面能否稳定地被不同的人使用”。要检查：

- 空数据、负值、单位错误和极端值是否有提示；
- 页面在手机、平板和教师电脑上是否可用；
- 公式、图表和按钮是否在不同屏幕尺寸下保持可读；
- 浏览器权限、蓝牙连接、断线重连和数据导出是否有明确状态；
- 外部字体、公式库和网络资源失效时，核心内容是否仍可阅读。

开发者电脑上一切正常，不等于学生设备上也正常。高分屏画布模糊、移动端布局挤压、外部公式资源加载失败、浏览器接口权限变化，都可能在真正使用时暴露。工程验收必须换设备、换网络、换输入，而不是只在作者电脑上点一次“运行”。

### 第四层：版权与隐私校验

网页中的图片、装置照片、课件截图、学生作品、对话记录和第三方库都需要来源和使用边界。学生页面和AI对话即使已经匿名，也要检查文件名、账号、头像、班级和独特文字是否能够反查身份。第三方截图、字体、图标和模型生成的素材也要记录来源和授权状态。

教师可以把版权与隐私校验写成上线前的停止条件：只要来源不明、授权未确认或个人信息未脱敏，页面可以在内部测试，但不能进入公开课材料或出版稿。

## 一个资源从原型到课堂的四个版本

把“开发完成”当成一个单一时刻，会掩盖资源质量的变化。更适合教师协作的是把资源分成四个版本。

### V0：问题原型

V0只证明学习问题存在。它可以是一张纸、一份表格或一个静态页面，包含学生难点、研究对象、原始量和一个任务。V0不追求漂亮，也不接传感器。教师先问学生是否能够理解问题、提出预测和指出需要什么证据。

### V1：可计算原型

V1加入原始量输入、公式和结果显示。此时重点是复算和边界：页面不会自动替学生生成原始数据，不会把空值当作零，也不会在输入错误时输出看似合理的结论。

### V2：可教学版本

V2加入交互演示、误差分析、分层任务和回顾。页面开始承担完整的课堂—课后学习链，但仍应先进行小范围试用。试用记录包括学生在哪个字段停顿、哪条提示被误解、哪种解释无法由数据支持。

### V3：可维护版本

V3才考虑真实设备接入、移动端适配、版本冻结、导出、授权和替代方案。一个页面能在作者电脑上运行，最多说明它接近V1；只有经过多设备、异常输入、断线和版本记录检查，才有资格进入V3。

这种版本分层可以防止“先做大系统再寻找学习用途”。如果V0无法让学生提出有效问题，继续增加功能只会让问题更昂贵地失败。

## 从单次提示词到教学开发支架

论文中的“harness engineering”可以转译成教师能够掌握的五项习惯。这里不把产业术语当作本章核心概念，而是关注它如何改变教师与AI的协作结构。

### 规则文件：让长期约定不靠记忆

规则文件记录设计系统、术语、目录约定、数据边界、隐私要求和科学性原则。例如本项目明确：统一使用“网页DIS”“ESP32Blockly”“证据—模型—进阶”，不把所有动画都称为网页DIS；AI提议，人来验证并拍板；原始数据不覆盖，处理数据另存；没有真实证据时使用待办标记。

规则文件的价值不是让AI变得更聪明，而是让每一次协作都能回到同一组约束。规则变化时应保存版本，不能在聊天中临时改口径。

### 技能文档：把重复任务变成操作卡

如果教师每次新建实验页都要重新解释字段、公式、图表和验收标准，协作成本会不断重复。可以为“新建实验页”“添加分层习题”“接入传感器数据”“生成来源表”等任务建立操作卡。

操作卡不应只是“请AI完成某功能”的提示词，而应包含：输入文件、先读什么、允许修改什么、验收什么、失败时回退到哪里。技能文档越接近真实任务，越能减少模型随意扩展范围。

### 需求模板：让学科判断进入工程输入

需求模板把学生难点、原始量、模型条件和完成标准写成工程可以使用的字段。它是教师专业判断进入软件的入口，也是避免“页面功能越来越多、学习问题越来越模糊”的边界。

### 验收清单：把“看起来不错”拆成可检查动作

建议把验收分为科学性三查、教学性三查、工程性三查和合规性三查：

| 类别 | 检查项 |
|---|---|
| 科学性三查 | 公式与单位、模型条件、异常与边界 |
| 教学性三查 | 学生任务、证据产物、迁移出口 |
| 工程性三查 | 多设备、错误输入、断网或接口失败 |
| 合规性三查 | 来源、授权、个人信息 |

清单的作用是让教师在上线前停下来。任何一项没有证据，不应因为页面已经“能运行”就跳过。

### 版本管理：允许失败被看见

AI协作最危险的状态，是一边修改一边失去“上一个可用版本”。每个可用版本应记录日期、任务、变更内容、测试结果和已知问题。若使用Git，应保持小步提交；如果教师暂时不使用Git，也可以先按日期保存文件夹，但要保证版本之间可以比较和回退。

版本记录还保存了开发过程中的失败证据。某次“顺手优化”让数据表失效，或某次添加动画破坏了移动端布局，这些失败不是应该删除的污点，而是帮助下一次协作理解约束的材料。资源工程化的成熟，不是从不出错，而是出错后可以定位、回退和解释。

版本记录建议至少包含六列：日期、版本号、任务块、修改内容、验收结果、已知问题。若一次改动同时影响公式、样式和数据接口，应拆成多个小提交或在记录中明确影响范围。教师不需要掌握复杂的分支策略，但需要能够回答：“本次修改之前哪个版本是可用的？本次改动改变了哪一个学习任务？如果失败，如何回到上一个版本？”

这套记录还可以成为第18章讨论教师专业自主权的材料。教师与AI协作时，真正需要留痕的不是每一句聊天，而是关键判断：为什么采用这个模型、为什么删除某个功能、为什么保留某个异常点、为什么暂缓上线。版本管理因此不只是软件工程习惯，也是教学责任的档案。

## 一个资源的失败、回退与修订

### 物理内容错误

生成式AI可能写出看似合理的公式、单位和解析。教师不能只靠语言流畅判断正确性。应从一个最小输入开始复算：输入一个已知质量、时间和高度，手算结果并与页面输出比较；再输入边界值和异常值，检查页面是否遵守物理条件。

物理内容错误一旦发现，应记录在版本中，包括错误位置、错误性质、影响范围、修复方式和重新验收结果。修复一个单位时，也要检查图表坐标、习题解析和导出表格是否同步更新。

### 工程兼容问题

网页资源的工程问题往往不是在第一次打开时出现。移动端画布变形、公式库加载失败、蓝牙权限被拒绝、设备断线后数据状态不明确，都需要通过有意设计的失败测试发现。

排查顺序应从低成本证据开始：先看页面是否有日志和明确状态，再检查输入字段和网络，随后单独测试接口和传感器，最后才修改系统结构。一次只改一个变量，才能知道修复究竟改变了什么。

### 资源结构问题

有时页面运行没有技术错误，但学生仍然只是在点击。此时不能继续增加动画和按钮，而要回到需求模板检查：学生难点是否写得足够具体？页面是否要求学生输入原始量？误差分析是否真正要求解释？有没有一个迁移或反驳任务？

如果答案是否定的，最合理的修订可能是删除功能、重排信息或增加一个记录和解释入口，而不是继续生成代码。

## 课堂—课后同源与资源维护

### 同一资源的三个使用时刻

机械能守恒在线实验室的设计，试图把三个时刻连接起来：课堂中学生输入真实实验数据，课后用同一页面完成分层习题，下一节课教师根据错题和解释记录重新安排开场任务。

这种“同源”并不意味着所有活动完全相同。课堂需要合作测量和证据会议，课后需要个体复盘和迁移，教师需要查看错误分布。但三者使用同一套符号、装置情境和模型边界，学生不必每次重新学习一个陌生的题面。

### 三种证据层级

资源开发中必须区分三种证据：

| 层级 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 功能验证 | 页面、公式、交互、接口按预设运行 | 不能说明学生学会了 |
| 课堂试用 | 教师和学生在某次课堂中能够使用，发现具体问题 | 不能直接推广到所有班级 |
| 学习效果证据 | 学生作品、前后测、访谈、过程档案等显示某种变化 | 仍需说明样本、方法和替代解释 |

论文中的调试数据可以证明功能验证，公开课使用可以支持课堂试用；只有在采集并核对学生作品、任务完成情况或其他合适证据后，才可以讨论学习效果。当前项目中，机械能页面的调试数据和公开课材料仍应分别标记，不能混写。

### 维护和退出机制

教师自研资源上线后，维护责任才真正开始。浏览器接口会变化，设备固件会更新，第三方库会失效，学校器材会更换，学生难点也会变化。因此，每个资源应有版本号、更新时间、已知问题、适用设备、替代方案和停止使用条件。

如果蓝牙接口暂时不可用，课程应能退回手工录入；如果网页无法加载，教师应保留纸质任务单和离线数据表；如果一张图片授权失效，页面应能替换为原理图或文字说明。可维护性不是工程团队的额外要求，而是教学连续性的组成部分。

### 维护不是“继续加功能”

资源上线后，教师容易把维护理解成增加页面、动画和题目。更重要的维护通常是减法：删除已经不符合课程口径的参数，修正一个学生反复误解的提示，替换失效的外部链接，隐藏尚未完成的实验接口，保留一个稳定的离线版本。

每次维护都应先判断它属于哪一类：

| 维护类型 | 例子 | 是否需要重新做物理验收 |
|---|---|---|
| 内容维护 | 术语、公式、题目和解析修订 | 需要 |
| 设备维护 | 浏览器、蓝牙、传感器或固件变化 | 需要 |
| 体验维护 | 布局、字体、按钮和移动端适配 | 需要做教学与工程验收 |
| 合规维护 | 图片授权、学生脱敏、第三方库许可 | 必须 |
| 功能扩展 | 增加新方案、新传感器或新评价 | 需要重新建立需求和证据包 |

如果一个功能无法说明它改变了证据产生、模型建构、任务进阶或评价过程，就不应因为AI可以快速生成而自动加入。资源的长期质量依赖于一套可以拒绝功能的机制。

## 小规模试用：先观察学习任务，再统计页面点击

资源开发不宜一上线就追求大规模使用。小规模试用的目标，是检查设计中的学习任务有没有真正发生。教师可以邀请一组学生或一位同事完成一个最小任务，观察四类证据：学生先看了什么、在哪一步停顿、提出了什么问题、最后留下了什么解释或修改记录。

页面访问次数、按钮点击数和停留时长可以帮助发现工程问题，却不能直接证明学生完成了建模或科学论证。比如，学生反复点击“下一步”可能是认真比较，也可能是没有看懂提示；学生很快完成页面可能是熟练，也可能是跳过原始数据和解释。使用记录只有和任务产物、课堂观察或访谈结合，才有教学解释价值。

试用记录可以采用下面的简表：

| 观察环节 | 记录内容 | 后续决策 |
|---|---|---|
| 进入页面 | 学生是否知道要解决什么问题 | 修改开篇情境或任务说明 |
| 输入原始量 | 是否知道每个字段来自哪里 | 增加实物图、单位和字段解释 |
| 查看结果 | 是否把图表当成答案 | 增加预测、异常点和解释入口 |
| 分析差异 | 是否能提出与数据方向一致的原因 | 调整候选原因和提示层级 |
| 完成迁移 | 是否能在新情境调用模型 | 增加变式或降低前置概念负担 |

这份记录不要求教师把每位学生的表现都量化成分数。它首先帮助教师判断页面哪一段在支持学习、哪一段在制造额外负担。如果后续要讨论学习效果，再根据研究问题设计合适的样本、工具和统计方法，并明确哪些变化可能由其他因素解释。

试用阶段还应允许教师主动撤下页面。若学生连续误解同一公式、页面输出与实物测量不一致，或设备状态无法确认，暂停使用比继续收集点击数据更负责。暂停本身也是一条有效的维护记录：它说明教师把证据可靠性放在资源上线率之前。

## 从试用观察到资源修订

小规模试用的记录需要能够回到页面决策，而不是只停在“学生觉得好不好用”。教师可以把观察分成三个层次：任务理解、证据操作和模型解释。若学生不知道要解决什么问题，先修改开篇情境；若学生知道问题却不会输入原始量，先补字段、单位和实物来源；若学生能够输入和作图却把曲线当作答案，增加预测、异常和反例入口。

一轮试用结束后，可使用“保留—删减—重写—暂缓”四种动作：

| 观察到的现象 | 资源动作 | 说明 |
|---|---|---|
| 学生能用数据支持主张 | 保留并记录证据 | 不因页面简洁而盲目增加功能 |
| 学生反复跳过原始量 | 重写字段和任务顺序 | 先把数据来源变得可见 |
| 学生被动画吸引但不解释 | 删减装饰，增加模型出口 | 让按钮服务于物理判断 |
| 页面与实测不一致 | 暂缓上线，回到物理验收 | 不用提示语掩盖公式或接口问题 |

AI可以根据试用记录提出修订列表，但每项修订都应由教师决定优先级，并在版本记录中写清它改变了哪一个学习任务。这样，试用数据才真正进入下一版资源，而不是成为“使用人数”的宣传材料。

## 开发台账：把四类判断放在同一张表上

教师与AI协作时，建议为每个资源维护一张开发台账，避免物理、教学、工程和合规信息分散在不同聊天记录中。

| 任务块 | 学科主张 | 学生证据 | AI承担的工作 | 人工验收 | 当前状态 |
|---|---|---|---|---|---|
| 原理区 | 说明系统和守恒条件 | 能指出研究对象与条件 | 组织文字和公式排版 | 物理教师复算、审符号 |  |
| 数据表 | 由原始量得到处理量 | 能输入并解释原始数据 | 生成字段和计算逻辑 | 手算、边界值和空值测试 |  |
| 误差区 | 差异方向可以支持模型解释 | 能写出主张—证据—推理 | 生成候选原因和提示 | 检查原因与数据是否对应 |  |
| 习题区 | 任务能够迁移模型 | 留下简答或版本选择 | 生成题面初稿 | 教师逐题审解析和难度 |  |
| 发布层 | 页面可用且可维护 | 能在指定设备完成任务 | 处理布局、导出和状态 | 多设备、授权、离线方案 |  |

台账中的“当前状态”必须允许写“待核实”“内部试用”“暂不发布”。这种状态词让协作过程拥有中间状态，避免在页面尚未经过人工验收时被AI或教师口头宣布为完成。台账也能为四位作者的共同写作提供贡献线索：谁提出了学科要求，谁提供了装置和数据，谁完成了代码或页面，谁进行了审校，都可以在进入正文前记录清楚。

## 教师的边界：AI提议，人来验证并拍板

生成式AI确实改变了教师开发资源的可能性。过去需要程序员才能完成的页面结构、表格和交互，现在教师可以直接参与实现。但这并不意味着教师的专业责任变小了。恰恰相反，当教师可以直接把学科理解写进软件，科学性判断、教学任务设计和最终发布责任更集中地回到教师身上。

本章可以用一张开发验收表收束：

| 问题 | 已有证据 | 当前状态 |
|---|---|---|
| 学生难点是否具体 | 学情记录、错例、任务表现 | 【待作者补充】 |
| 页面是否保留原始数据 | 字段、导出和版本记录 | 【待核实】 |
| 公式和模型是否正确 | 人工复算、边界测试、物理审校 | 【待核实】 |
| 页面是否改变了学生任务 | 预测、解释、迁移和作品记录 | 【待数据支持】 |
| 图片和材料是否可公开 | 来源、权利人、授权状态 | 【待授权确认】 |
| 资源失效时能否继续教学 | 离线方案、替代器材、退出条件 | 【待作者补充】 |

这张表中的“待”不是失败标签，而是把不确定性公开放在资源进入课堂和出版之前。AI可以帮助填写、比较和提醒，但不能替教师把空白改成“已完成”。

网页自动计算、规则判分和普通程序功能不应全部称作AI；AI生成的代码、文字和图表也不应自动成为可信证据。统一原则仍然是：**AI提议，人来验证并拍板。**

## 一个资源团队的分工

教师与AI共同开发资源时，团队可以把工作分成四种角色：学科负责人确认物理量、模型和边界；学习设计者确认学生任务、支架和迁移；工程协作者确认页面、接口、设备和版本；合规负责人确认图片、学生作品、数据和发布渠道。一个人可以兼任多种角色，但四类检查不能因为人员少而消失。

每次迭代只指定一个主责人和一个验收人。AI不作为发布责任人，生成的代码和文字必须由人接手。若资源涉及真实学生数据，合规负责人拥有暂停公开的权利；若页面和实物测量不一致，学科负责人拥有退回原型的权利。分工表让“AI协作”不再是一个模糊的集体动作，而是可以追踪的责任链。

## 资源开发的退出标准

教师也要为资源写退出标准：当公式或接口无法核验、连续试用仍产生相同误解、第三方授权失效、维护人无法交接或离线版本不存在时，资源回退到内部原型或停止使用。退出不意味着开发失败，而是承认当前版本不能承担更大范围的教学责任。

## 本章的限制与来源说明

本章把机械能守恒在线实验室和“数智育才”网站作为开发路径案例，重点讨论资源结构和协作方法。当前材料可以支持六要素设计、需求拆解、教师校验、版本管理和维护边界；不能据此推出生成式AI普遍提高教师效率或学生学习效果的结论。

后续需要补充或核对：建站版本记录、具体页面截图、公开课真实数据、课后习题完成率、学生书面论证、课题编号、第三方工具信息和图片授权。若课程仍处于申报或录制阶段，应保持“课程设计”口径，不写成已经完成的学员效果。

## 结语：让教师的教学理解成为资源的第一生产力

一个网页的价值，不由按钮数量、动画速度和生成时间决定，而由它是否帮助学生更清楚地看见现象、获得证据、建立模型、迁移方法和评价结论决定。生成式AI让教师有机会把自己的学科理解直接转化为资源，但只有经过需求约束、科学校验、课堂试用、版本回退和持续维护，这种可能性才会变成可承担的教学实践。

教师不需要成为专业程序员，仍然需要成为资源的第一责任人：知道为什么开发，知道输入什么，知道如何验收，也知道什么时候不能继续下结论。AI可以缩短从想法到原型的距离，却不能替教师走完从原型到可信资源的路。

## 本章小结

本章把生成式AI放回教师的学科判断中：先由教师提出问题、字段和物理边界，再让AI生成原型、整理界面或协助调试，最后经过公式复算、边界测试、课堂试用和版本回退。资源开发的核心不是生成速度，而是学生是否因此更容易看见证据、表达模型、迁移方法并接受复核。

一个可交付的资源还必须能够被接手、被维护和被质疑。若页面没有数据契约、离线方案、维护人和停止条件，就不能仅凭界面完整宣称资源成熟；若没有学生产物或过程档案，也不能把公开课试用写成学习效果证据。
