# 附录D 多作者协作与出版交付手册

本附录面向《智启格物》四位作者、编辑、设计和出版工程人员。它解决三个问题：多人如何共同写而不互相覆盖，研究材料如何在正文和来源表之间保持一致，书稿如何从纯文本进入可交付版本。

## D.1 文件分层

建议把项目分成五层，不同层级的文件有不同的修改权限：

1. **总纲层**：全书命题、篇章结构、章节功能和作者分工；
2. **素材层**：论文、课例、数据、照片、网页、代码和访谈原始材料；
3. **工作层**：章节蓝图、写作包、审稿记录、作者补充问题和决策日志；
4. **成稿层**：逐章正文、插图建议、表格和来源说明；
5. **交付层**：目录、版权页、参考文献、图片、Word/PDF、校样和发布记录。

原始素材层默认只读，工作层和成稿层可以由负责作者修改，交付层由统稿和出版负责人验收。不能把修改后的正文直接覆盖论文初稿、原始数据或未处理图片。

## D.2 多作者任务卡

每项写作或补证任务建立一张任务卡：

| 字段 | 内容 |
|---|---|
| 任务名称 | 例如“补充第8章曲面方案证据包” |
| 主责人 | 负责推进和首次交付的人 |
| 供材人 | 提供数据、照片、代码或课堂事实的人 |
| 审校人 | 检查物理、结构、语言或授权的人 |
| 输入 | 文件、数据、访问方式和版本 |
| 输出 | 章节段落、表格、图、来源卡或待补清单 |
| 截止状态 | 草稿、待核、试用、确认、公开 |
| 不做什么 | 避免越界、重复和擅自推断 |

任务卡中的“主责人”不等于全部贡献者。正文可以由一个人整理，但材料、实验、装置和审校应按实际贡献记录。作者暂时无法确认的归属，统一使用【待确认贡献归属】。

## D.3 决策日志

全书会出现许多不宜埋在聊天记录里的决定：章节是否合并、同一案例放在哪一章、一个术语采用哪个译法、某张图片是否公开、某个结论降格到什么语气。建议使用以下格式：

| 日期 | 决策 | 选项 | 依据 | 影响章节 | 是否可撤回 |
|---|---|---|---|---|---|
|  | 第8章与第9章分工 | 方案A/方案B | 避免机械能案例重复 | 8、9 | 是 |
|  | 统一“网页DIS”口径 | 词语1/词语2 | 术语表和项目版本 | 7、8、9 | 是 |
|  | 某照片暂不公开 | 公开/内部 | 授权或隐私缺口 | 4、15、16 | 是 |

决策日志只记录结论、理由和影响，不把所有讨论复制进来。若新证据推翻旧决定，建立一条新记录并链接旧记录，不删除历史。

## D.4 术语与口径表

### 物理口径

- 直接测量量：仪器或观察直接获得的量；
- 处理量：经过公式、图像或算法处理的量；
- 证据：支持或反驳明确主张的数据、现象、图像或过程记录；
- 模型：对研究对象、变量和关系的选择性解释；
- 边界：模型成立的对象、条件、范围和近似；
- 迁移：改变情境或表征后调用、修正或否定模型。

### AI口径

- AI生成：由模型生成的文字、代码、图、数据示例或建议；
- AI整理：对已有材料做分类、格式化或摘要，不新增事实；
- 人工验收：教师或学生根据物理、教学、工程和合规证据作出的检查；
- 过程证据：问题、提示、测试、版本和反思等能够说明责任的材料；
- 成品证据：最终网页、装置、报告或图表的运行与质量。

### 结果口径

优先使用“本次测量中”“在当前装置和范围内”“材料显示”“设计建议”“尚待核验”，谨慎使用“显著”“普遍”“有效提高”“证明了”“可推广”。效果结论必须有样本、方法、时间范围和替代解释。

## D.5 来源与引用台账

每条引用至少记录：作者/机构、题名、出版物或网页、日期、页码或链接、访问日期、正文使用章节、引用类型、核验状态和版权限制。来源分为：

- A：原始文件、正式出版物或可验证官方资料；
- B：内部论文初稿、课例、项目文档或作者提供材料；
- C：线索、二手摘要、未核验网页或暂时无法访问的材料。

C级材料可以帮助设计问题，但不应单独支撑高风险结论。正文引用内部材料时，说明其性质，不把项目计划写成实施结果。

## D.6 图片、表格和代码台账

### 图片

记录编号、标题、来源文件、作者/摄影者、人物是否可识别、授权范围、是否脱敏、是否重绘、分辨率和发布渠道。课堂照片默认内部使用，出版前逐项确认；学生作品和第三方截图不能仅因出现在项目文件夹就视为可公开。

### 表格

记录数据来源、字段解释、单位、处理规则、制表人、复核人和版本。表格如果由AI生成，必须与原始数据逐项对照。示例数据和实测数据在标题或注释中明确区分。

### 代码与网页

记录仓库或文件来源、许可证、版本、依赖、运行环境、生成或修改者、测试结果和已知限制。公开代码前核对第三方库和字体许可；学生代码需确认学校、学生和教师贡献边界。

## D.7 版本和交接

每次重要修改至少记录：版本、日期、负责人、修改摘要、受影响章节、验证动作、已知问题和回退版本。交接文件说明：已读材料、已确认事实、未确认事实、不能重复做的工作、下一步和推荐技能。

交接不要求新成员相信旧结论。新成员应先读交接，再抽查原始文件；若发现冲突，保留旧判断和新证据，更新决策日志。交接文件的价值是节省重复探索，不是替代核验。

## D.8 Word/PDF交付检查

### 文字层

- 章节顺序与总纲一致；
- 标题层级、编号、术语和标点统一；
- 公式、变量和单位无明显错位；
- 占位符集中形成待办，不残留内部评论；
- 作者贡献和来源说明与台账一致。

### 图表层

- 图表编号与正文引用一致；
- 图片清晰、比例和颜色适合印刷；
- 图题、表题、来源和授权状态齐全；
- 学生、教师和设备信息已脱敏；
- 代码截图、网页截图和第三方元素可公开。

### 构建层

- 从清洁目录重新构建，记录工具和版本；
- 目录、页码、交叉引用和链接没有断裂；
- 图片路径、字体、公式和特殊字符在目标环境正常；
- Word、PDF和纯文本内容一致；
- 生成文件与源文件分离保存。

构建成功不等于出版完成。最终仍需人工通读目录、扉页、章节开头、图表、公式、参考文献和高风险安全段落。

## D.9 交付状态

| 状态 | 含义 |
|---|---|
| 结构稿 | 总纲和章节骨架基本稳定，正文可大幅调整 |
| 初稿 | 每章有连续正文和实践清单，证据缺口已标记 |
| 内审稿 | 四位作者完成结构、物理和贡献审校 |
| 出版审校稿 | 引用、图片、授权、术语和版式基本核对 |
| 样书稿 | 已构建Word/PDF并完成校样，仍可有排版修订 |
| 交付稿 | 作者、出版社和版权材料确认，源文件和交付文件归档 |

不要因为生成了一个Word文件就把项目标为交付稿。状态必须由结构、证据、作者、版权、构建和人工校样共同决定。

## D.10 全书最终审查会议

最终审查会议按四个环节进行：

1. 统稿人说明全书主线和章节依赖；
2. 各主笔只报告本章仍未解决的事实、贡献、授权和效果缺口；
3. 物理审校人抽查公式、系统边界、测量模型和高风险实验；
4. 出版负责人根据台账决定哪些内容进入交付稿，哪些保留为后续补证。

会议结束后生成三份清单：必须在交付前解决、可以在再版解决、明确不进入本书。后两类不能被混写成“以后再说”，要有责任人和状态。书稿的可信度不只来自已经写出的内容，也来自明确知道哪些内容尚未完成。
