# 附录F 教师与AI协作提示卡

以下提示卡用于本书讨论的典型任务。每张卡都把AI限定在一个可检查的子任务中，要求教师先提供物理约束，再进行人工验收。提示卡不是“复制后保证正确”的魔法指令，正式使用前仍需根据班级、器材、数据和安全条件改写。

## F.1 设计一节概念课

```text
你是高中物理教研助手。请先不要写完整教案。

本节要解释的真实现象是：……
学生已有的直觉或常见错误是：……
可获得的证据是：……
不能使用的器材或条件是：……

请输出：
1. 三个可观察的起点问题；
2. 一项证据冲突任务；
3. 一个最小模型卡模板；
4. 两个改变边界的迁移情境；
5. 每一项任务的学生产物；
6. 需要教师人工核验的物理点。

不要替学生写出标准结论，不要虚构课堂效果，不要把AI生成内容写成真实实验。
```

验收：检查现象是否真实可观察、任务是否需要学生作出判断、模型是否写明对象和条件、迁移是否改变结构而非只换数字。

## F.2 处理实验原始数据

```text
下面是实验原始数据和字段说明。请只做数据整理，不改变原始值。

实验问题：……
直接测量量：……
单位：……
重复次数：……
希望比较的模型：……

请输出：
1. 字段和单位检查；
2. 缺失值、重复值和异常记录清单；
3. 处理量计算公式；
4. 一张处理前后对照表；
5. 不能仅凭当前数据下结论的地方。

请不要自动删除异常点、补造数据或把处理结果写成实测值。
```

验收：逐项与原始表核对，手算至少一个数据点，确认处理参数和异常点都保留。

## F.3 生成候选图表

```text
请根据已确认的物理问题和原始数据，提出不超过三种可能的图表表达。

请对每种图表说明：横纵坐标、单位、它能检验的关系、需要的模型条件、可能误读、适合的学生任务。

不要根据哪张图“最直”直接宣布模型成立，也不要删除偏离点。
```

验收：检查每张图是否有理论理由、数据范围是否足够、单位和时间/空间基准是否一致。

## F.4 生成错误解和反例

```text
请围绕以下已确认模型，生成两个看似合理但分别违反不同条件的错误解释。

模型：……
适用条件：……
学生先修知识：……

每个错误解释请附：错误位置、可能误导点、学生需要观察的证据、一个能够反驳它的测试。
不要生成涉及危险实验的操作步骤，不要把错误解释冒充真实学生答案。
```

验收：教师先独立复核错误是否确实错误，再检查反例是否能够在现有器材和安全范围内完成。

## F.5 生成网页原型需求

```text
请把以下物理学习难点转成一个最小网页原型需求，不要直接写完整代码。

学习难点：……
用户：……
直接测量量：……
处理量：……
模型和条件：……
数据来源：真实/仿真/示例
不能做什么：……

请输出页面信息结构、输入字段、状态、学生任务、验收测试和离线替代方案。
```

验收：若需求中出现“提升兴趣”“提高能力”等无法直接验收的词，改写成学生动作和证据产物。

## F.6 解释代码但不替学生调试

```text
请解释下面这段代码中与物理模型直接相关的变量和计算链。
不要重写代码，不要假设未给出的传感器参数，不要直接宣布程序正确。

请输出：
1. 输入、状态变量、输出；
2. 每个物理量的单位和来源；
3. 公式或更新规则；
4. 两个可能的边界测试；
5. 需要学生或教师现场确认的事项。
```

验收：用手算、模拟输入和真实设备分别检查。解释清楚不等于代码正确。

## F.7 设计校本项目

```text
请把以下教具或传感器转成三个层级的项目：可靠使用、局部改造、开放创造。

教具：……
可测物理量：……
固定条件和安全边界：……
已有数据或版本：……

每个层级请说明目标、输入、学生决策、必交证据、失败判据、维护要求和下一阶段接口。
不要虚构学生完成情况，不要把设备功能等同于学习效果。
```

验收：项目是否有真实问题，开放程度是否与先修能力匹配，是否保留原版作为对照和回退。

## F.8 生成高三复习变式

```text
请围绕已确认的模型生成三道迁移任务。

核心结构：……
每题只改变一个关键条件：系统边界/测量方式/初始条件/表征/摩擦等。
请列出保留的结构、改变的条件、可能错误路径、需要学生说明的边界。
不要只替换数字和故事，不要生成条件不完整或物理不成立的题目。
```

验收：教师逐题核对答案路径、信息充分性、难度变化来源和错误解释。

## F.9 整理学生AI过程证据

```text
下面是学生提交的对话、版本和网页文件。请先只做证据索引，不评分。

请逐项标记：材料来源、角色（学生/AI/教师/同伴/不确定）、时间、可确认主张、缺失信息、隐私风险和授权状态。
不能根据AI的主动语气推断是学生发言；不能根据网页成品倒推学生过程能力。
```

验收：人工抽查角色标记，确认AI回复没有被计入学生首问、诊断和模型表达。

## F.10 生成章节审稿清单

```text
请根据以下章节正文和术语表，输出审稿清单，不要直接重写。

检查结构：开篇问题、章节功能、证据链、模型链、迁移和结尾回收。
检查事实：实测/仿真/设计建议区分，数据来源、单位、贡献和授权。
检查表达：是否有过度宣传、论文腔、技术黑箱和未解释术语。
检查边界：安全、隐私、维护、浏览器、设备和离线替代。

每条问题注明位置、风险级别和建议动作。
```

## F.11 AI使用记录表

每次重要协作可以记录：日期、任务卡、输入材料、AI承担的工作、人工修改、物理验收、教学验收、工程验收、是否采用、版本和未解决问题。不要保存与任务无关的完整学生隐私或聊天内容。

## F.12 何时不应调用AI

以下情况优先回到原始材料或人工判断：数据来源不明、装置安全未确认、贡献归属有争议、学生隐私未脱敏、模型对象未定义、页面已经出现不可解释的异常、需要决定是否公开或是否给出效果结论。AI可以帮助列出问题，但不能替代这些决定。
