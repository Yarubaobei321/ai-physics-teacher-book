# 《智启格物》章节蓝图与审稿模板

> 形成依据：第2章理论短章、第4章样章及其第一轮审稿记录。
> 用途：正式写某章前先建立章节蓝图；初稿完成后按同一结构审查。
> 边界：本模板负责组织内容，不把【待作者补充】自动变成正文事实，也不要求每章机械套用同样的小标题。

## 一、先定义章节承诺

每章动笔前先填写以下六项。任何一项说不清，暂不进入正文扩写。

| 字段 | 要回答的问题 | 合格标准 |
|---|---|---|
| 章节功能 | 本章在十八章中承担什么不可替代的任务 | 删除本章后，全书会缺少一个明确环节，而不只是少一个案例 |
| 核心矛盾 | 读者在课堂、实验、开发或评价中遇到什么真实困难 | 能用一个具体问题表达，不使用“如何更好地赋能”等空泛措辞 |
| 读者起点 | 默认读者已经知道什么、尚不会什么 | 不把编程、传感器或研究方法知识当作默认常识 |
| 进阶终点 | 读完后读者能够判断、设计或复现什么 | 使用可观察动词，避免只写“理解”“认识” |
| 证据产物 | 本章凭什么支持其主张 | 至少有材料、数据、作品、代码、课堂记录或规范文献中的一种 |
| 相邻章边界 | 哪些内容必须留给前章或后章 | 写出“不在本章展开”的具体内容 |

## 二、通用章节蓝图

### 1. 真实问题

- 用课堂困境、实验矛盾、开发失败或评价难题开篇。
- 开篇应让读者知道“为什么原有办法不够”，不要先介绍工具功能。
- 可用一段真实情境或一组相互冲突的数据；没有原始记录时，只写设计问题，不补造课堂对白。

### 2. 进阶目标

- 写清学生或教师从什么状态走向什么状态。
- 至少设置两个中间台阶，体现能力叠加，而不是活动顺序。
- 说明本章与六级学习过程的主要落点；不强求覆盖现象、证据、模型、迁移、创造、评价全部六级。

### 3. 证据设计

- 列出本章需要出现的现象、原始量、处理后数据、图像、作品或过程档案。
- 区分证据来源与理论绘图，区分功能验证、课堂实施和学习效果。
- 关键主张必须登记为“主张—证据—边界”三联项。

### 4. 教学或开发过程

- 不是流水账，而是呈现关键选择：为什么这样设计、放弃了什么、失败后如何修改。
- 实验章至少说明器材、变量、校准、操作、数据处理和安全边界。
- 开发章至少说明需求、科学性约束、原型、验收、版本和维护边界。
- 评价章至少说明评价对象、证据来源、规则、复核和熔断条件。

### 5. 模型与解释

- 先界定研究对象、物理量、符号和适用条件，再给公式或框架。
- 把“数据呈现什么”与“为什么可以这样解释”分开。
- 主动处理一个反例、误差来源或模型失效条件。

### 6. 迁移工具包

根据章节类型选择任务单、器材表、量规、检查表、需求模板、排障表或复用框架。工具包必须让一线教师知道：

1. 最低条件下如何开始；
2. 标准条件下如何完成；
3. 有更多设备时如何升级；
4. 出现失败时先检查什么；
5. 哪些条件不足时应停止下结论。

### 7. 限制、待补证与来源表

- 将作者补证与当前可写内容分开，补证可以后置，但不能删除。
- 每章末附证据来源表：材料、作者/权利人、日期、等级、授权状态、正文落点。
- 涉及学生材料时使用匿名编号并写明授权门槛。

## 三、不同章节类型的变体

| 类型 | 开篇优先 | 正文重心 | 必备工具包 | 主要风险 |
|---|---|---|---|---|
| 理论框架型 | 一个无法由工具直接解决的学科矛盾 | 概念定义、框架关系、微型案例、边界 | 框架使用检查表 | 写成概念综述或口号 |
| 实验进阶型 | 真实数据与理想结论之间的差异 | 测量链、模型链、误差链、方案比较 | 器材表、数据表、误差审查表 | 把漂亮曲线当成准确证据 |
| 单课案例型 | 学生的典型误判或教师备课难题 | 目标、评价证据、活动、课堂生成 | 任务单、表现量规 | 设计稿冒充实施实录 |
| AI资源开发型 | 通用资源无法适应真实学情 | 需求拆解、学科约束、原型、验收、迭代 | 需求模板、科学性验收表 | 写成软件说明书 |
| 平台与课程型 | 规模化课堂中的组织约束 | 技术选择如何服从课程和课堂 | 课程梯度、器材与并发方案 | 用平台功能替代学习证据 |
| 学生项目型 | 成品漂亮但过程和能力不可见 | 问题定义、迭代、作品、过程档案 | 项目量规、停止条件 | 把AI产物算作学生能力 |
| 评价与边界型 | 证据不可信或评价对象混淆 | 规则、证据惩罚、复核、教师裁定 | 双轨量规、对抗审查清单 | 评分精细但证据失真 |

## 四、从第4章提炼出的写作检查点

1. 不把多位作者的材料并排陈列，要用一个认识问题重组材料。
2. 不按“传统—数字—智能”暗示设备等级，而按证据功能解释各自不可替代性。
3. 每出现一条曲线，都追问来源、坐标、单位、校准、采样和处理方法。
4. 每出现一个装置，都区分“设计目标”“归档代码已实现”“实测已验证”。
5. 每出现一个效果判断，都检查是否有原始课堂或统计证据；没有则降格为设计意图。
6. 图表必须承担比较、解释或复现任务；缺少原图时保留图题与验收要求，不生成假证据图。
7. 实践工具包与主论证对应，不能成为正文末尾临时堆放的附件。

## 五、初稿审稿模板

### 1. 审稿结论

从以下四项中选择，并用一段话说明最主要依据：

- 可进入作者事实确认；
- 修改后可进入作者事实确认；
- 需要补齐核心材料后重写；
- 章节定位需要重新讨论。

### 2. 十项审查

| 审查项 | 核心问题 |
|---|---|
| 章节承诺 | 是否完成了总纲规定的不可替代任务 |
| 物理科学性 | 研究对象、物理量、公式、条件和边界是否准确 |
| 证据真实性 | 事实能否回到原始材料，是否把设计或功能验证写成课堂效果 |
| 进阶逻辑 | 读者能否看见从起点到终点的认知台阶 |
| 案例组织 | 案例是否服务同一问题，是否与相邻章节重复 |
| AI角色 | AI是否承担支架任务，人是否保留科学判断和责任 |
| 可操作性 | 首次使用者能否据此实施、检查和排障 |
| 图表与数据 | 图表是否有来源、单位、图注、授权和论证功能 |
| 语言与多作者口径 | 是否摆脱论文腔、宣传腔和材料拼盘感 |
| 引用与授权 | 文献、课题、合作者和学生材料是否按边界使用 |

### 3. 修改意见格式

每条意见统一记录：位置、原文信号、问题归因、修改策略、改后示例、是否已处理、仍需谁确认。

### 4. 完成门槛

- 结构完成不等于事实完成；作者补证可后置，但正式定稿前必须清零高风险占位。
- 章节达到目标字数不等于完成；章节承诺、证据链、工具包和来源表必须同时成立。
- Word或PDF生成不等于完成；仍需抽查公式、图表、分页、图片和引用。
