# 附录A 章节工作包与教研模板

本附录把正文中的方法压缩成可以直接复制的工作表。它不替代各章的物理内容，而是帮助教师、作者和审校者在同一套格式下记录问题、证据、模型、任务、AI参与和下一步。使用时可以删减字段，但不要删掉“证据来源、条件边界和责任归属”三类信息。

## A.1 一页式章节蓝图

正式写作前，先为每一章填写一页蓝图。蓝图不是目录扩写，而是章节对读者的承诺。

| 字段 | 要回答的问题 | 写作提醒 |
|---|---|---|
| 章节功能 | 本章在全书中解决什么问题？ | 不写成“介绍某工具”，要写认知或实践功能 |
| 目标读者 | 读者已有何种基础？ | 区分教师、学生、管理者和研究者 |
| 开篇情境 | 读者首先看到什么真实矛盾？ | 优先使用可观察现象、失败或决策 |
| 核心主张 | 本章最重要的一句话是什么？ | 必须能被证据或方法支撑 |
| 直接证据 | 哪些原始材料支持主张？ | 写出文件、数据、课堂或版本位置 |
| 模型 | 哪个物理或教学模型组织材料？ | 说明对象、变量、条件和边界 |
| 任务 | 读者或学生要做什么？ | 任务必须留下可检查产物 |
| 迁移 | 换什么条件后仍要调用模型？ | 不只替换故事和数字 |
| AI角色 | AI生成、整理、比较还是反馈？ | 写清人工验收点 |
| 失败与边界 | 哪些情况会使方案失效？ | 不用“注意误差”一笔带过 |
| 贡献与授权 | 谁提供材料，谁拥有权利？ | 区分主笔、实施者和素材权利人 |
| 完成标准 | 何时可以称为初稿完成？ | 结构、证据、插图、来源和待补项分开验收 |

章节蓝图完成后，先由另一位作者做“承诺审查”：本章是否承诺了材料目前无法支持的效果？如果承诺过大，先改标题和主张，再进入正文。

## A.2 章节写作包

每一章正式起草前，建立一份写作包，内容按以下顺序排列。

### 1. 事实包

- 已核验事实：可以直接写入正文；
- 待核实事实：需要回到原文件、作者或实物确认；
- 设计建议：作者提出的可执行方案；
- 推论：根据材料作出的暂时判断；
- 不宜下结论：证据不足或存在竞争性解释的内容。

### 2. 证据包

每一项重要主张都建立“主张—证据—推理”三联表：

| 主张 | 证据位置 | 推理是否完整 | 缺口 |
|---|---|---|---|
| 学生能在新情境中迁移模型 | 任务、作品或答辩记录 | 是否说明改变了什么条件 | 【待数据支持】 |
| 工具减少了某类机械负担 | 操作记录、版本或课堂观察 | 是否与学习责任区分 | 需补时间或任务证据 |
| 某装置提高了测量可重复性 | 重复测量、校准和元数据 | 是否说明量程和误差 | 【待核实】 |

### 3. 任务包

每项课堂或项目任务至少说明：起点、限制、学生动作、原始产物、处理产物、模型产物、迁移产物和评价方式。AI生成的任务也必须经过物理、难度、安全和隐私四项检查。

### 4. 版本包

保留初始材料、第一次结构稿、一次被否决的版本、当前版本和未处理清单。版本说明不需要长，但要写“为什么改、改了什么、依据是什么、怎样验收”。

## A.3 作者访谈模板

当章节需要作者补充真实课堂或装置事实时，不要只发“请补充案例”。使用以下问题按对象访谈。

### 课堂事实

1. 哪一届、哪个年级、什么课型？
2. 学生首先观察到什么？有没有原始预测或错误解释？
3. 教师在什么地方改变了任务或装置？为什么？
4. 学生留下了哪些原始材料：数据、照片、图像、版本或答辩？
5. 哪个结果是课堂事实，哪个只是教师判断？
6. 是否有未解决的问题或失败记录？

### 装置与资源

1. 装置的实际型号、尺寸、供电和版本是什么？
2. 直接测量量是什么，处理后显示什么？
3. 校准、采样、滤波、单位和边界如何记录？
4. 发生故障时先查什么，何时停止使用？
5. 图片、代码、网页和学生作品的权利人是谁？

### AI协作

1. AI具体承担了哪一项工作？
2. 学生或教师在哪一步提供约束？
3. AI是否给出过错误建议？怎样发现和处理？
4. 哪个版本被采用，哪个版本被回退？为什么？
5. 最终结论由谁复核、谁负责？

访谈记录需标注日期、访谈者、受访者和是否允许引用。作者口述可以成为来源，但不能因为“作者亲自说过”就跳过数据、照片或授权检查。

## A.4 章节审稿卡

第一轮审稿关注结构和事实，第二轮关注读者体验和语言，第三轮关注出版合规。每轮都要留下具体位置和修改理由。

### 结构审稿

- 开篇矛盾是否在正文中得到推进？
- 每节是否完成不可替代的功能？
- 章节之间是否重复同一案例或理论？
- 证据、模型、任务和迁移是否形成链条？
- 结尾是否回收开篇问题并交给下一章？

### 事实审稿

- 所有数据是否有来源、单位和时间口径？
- “效果”“提高”“显著”“普遍”等词是否有足够证据？
- 设计建议是否被误写成已实施结果？
- 作者贡献、学生身份和图片来源是否准确？
- 未核验内容是否保留统一标记？

### 读者审稿

- 教师能否据此设计一个最小任务？
- 学生能否看出自己要观察、测量和解释什么？
- 技术描述是否解释了物理意义和课堂边界？
- 表格和图是否减少理解负担，而不是增加装饰？
- 读者是否知道方案失败时如何回退？

### 出版审稿

- 标题层级、术语和公式是否统一？
- 图片、表格、代码和网页是否有编号与来源？
- 学生作品是否匿名，授权是否可追溯？
- 外部链接、软件版本和政策题录是否需更新？
- 占位符是否集中形成待办台账？

## A.5 全书交叉阅读表

完成三章以上后，使用下表做跨章节审查：

| 项目 | 第一次出现 | 后续使用 | 是否需要统一 |
|---|---|---|---|
| 现象—证据—模型—迁移—创造—评价 | 第2章 | 全书 | 六个词的含义不漂移 |
| 直接测量量/处理量 | 第5章 | 第6—10章 | 不把处理结果写成仪器直接读数 |
| 证据包/版本记录 | 第7章 | 第10、14、17章 | 同一责任语言 |
| 低风险替代 | 第4、16章 | 第15、18章 | 安全要求不降低 |
| 双轨评价 | 第10章 | 第17章 | 成品和过程不混分 |

交叉阅读不是把每章改成同一套模板，而是检查同一术语是否在不同章节承担了相同的最低责任。发现冲突时，优先修订术语表和章节边界，再改正文。

## A.6 章节发布前的暂停条件

出现以下任一情况，章节可以作为内部初稿保存，但暂不进入出版稿：

1. 关键事实只有文件名，没有原始内容；
2. 重要数据没有单位、来源或处理方法；
3. 学生作品只有成品，没有授权或匿名记录；
4. 装置功能依赖未核验的代码、网页或硬件版本；
5. 课堂效果被写成普遍因果结论；
6. 图片、截图或第三方材料来源不明；
7. 贡献归属无法确认；
8. 章节承诺超出当前证据范围。

暂停不是退稿。编辑应在章节状态中写清缺口、责任人、所需材料和下一次核验时间。只有这样，书稿才能在扩写过程中保持诚实，而不是因为赶进度把不确定性隐藏在流畅文字后面。
