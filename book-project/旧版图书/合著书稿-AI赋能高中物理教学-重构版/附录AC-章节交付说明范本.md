# 附录AC 章节交付说明范本

章节交付说明是主笔把一章交给统稿、审校和出版人员时附带的短文。它不重复正文，而是说明本章可以相信什么、还缺什么、下一步怎么处理。

## AC.1 主笔交付说明

```text
章节：
主笔：
本章功能：
当前版本：
正文新增内容：
已核验事实：
主要素材来源：
仍未核验：
作者需要补充：
贡献归属待确认：
图片/数据/代码授权状态：
物理审校重点：
读者试读重点：
下一步建议：
```

## AC.2 物理审校说明

```text
抽查范围：
公式与符号：
研究对象/系统：
直接量与处理量：
边界和近似：
数据来源：
高风险实验：
需要作者回答：
是否允许进入内审稿：
```

物理审校人不负责确认所有版权和学生隐私，但应指出哪些图表、设备和数据必须回到原始材料。

## AC.3 结构审校说明

```text
开篇问题是否成立：
章节功能是否兑现：
段落/案例重复：
与前章接口：
与后章接口：
理论—案例—任务比例：
结尾是否回收：
建议删除/合并/拆分：
```

## AC.4 证据审校说明

```text
本章最强主张：
对应证据位置：
证据等级：
最弱主张：
是否存在设计/实施/效果混写：
是否存在AI生成冒充事实：
是否需要降格语气：
需要补充的最小材料：
```

## AC.5 出版审校说明

```text
标题层级：
术语和公式：
图表编号：
图片来源与授权：
学生/教师隐私：
参考文献题录：
内部标记清理：
Word/PDF构建：
校样页码：
```

## AC.6 章节状态说明

### 结构稿

主线和章节功能已经确认，正文可大幅修改。适合内部讨论，不用于对外引用。

### 初稿

正文连续，核心案例和方法已写出，事实、数据、图片和贡献仍有待补。可以供作者审阅和读者试读。

### 内审稿

四位作者完成结构、物理、贡献和关键事实审校，未解决项集中在补证台账。可以进入统一术语和图片规划。

### 出版审校稿

来源、授权、隐私、术语、图表和构建基本完成，仍需校样和最终作者确认。

### 交付稿

作者、编辑、版权、构建和交接都已确认。交付稿仍需保留源文件和版本归档，不等于未来无需勘误。

## AC.7 章节退回说明

章节可以被退回，而不是被简单判定“不合格”。退回说明要写清：哪个主张超过证据，哪个模型条件缺失，哪个案例重复，哪个授权未确认，哪项任务无法实施，以及下一次只需改什么。退回后保留旧版本，避免作者丢失原始材料。

## AC.8 统稿人的最终意见

统稿人用一段话说明：本章如何推进全书主线，最值得保留的现场或模型是什么，最需要作者补证的地方是什么，读者可以先拿走哪项方法，哪些结论暂时不能拿走。这样，章节进入全书时不只带着文字，也带着证据和边界。
