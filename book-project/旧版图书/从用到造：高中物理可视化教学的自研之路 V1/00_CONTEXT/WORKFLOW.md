# 图书生产工作流

## 总览

```text
章节任务书
   ↓ G0
素材考古与来源登记
   ↓ G1
事实档案与证据边界
   ↓ G2
内容结构与视觉策划
   ↓ G3
图文正文
   ↓ G4
事实、物理、版权、可读性审查
   ↓ G5
作者确认
   ↓ G6
进入统稿
```

## G0：章节任务书

输入：全书定位、章节地图、蓝图、作者要求。

输出：`01_SOURCE/第XX章/章节任务书.md`。

必须写清：

- 本章解决的读者问题；
- 本章在全书中的功能；
- 主案例与不纳入内容；
- 负责作者与待采访作者；
- 可验证的完成标准；
- 与前后章节的边界。

通过条件：作者或总编确认章节承诺和案例范围。

## G1：素材考古

输入：章节任务书、全书资源地图、章节资源索引。

输出：`01_SOURCE/第XX章/素材考古表.md`，必要时创建 `facts/`。

工作顺序：

1. 从入口层定位项目总览、摘要或目录说明；
2. 只打开与章节问题直接有关的原件；
3. 登记文字、图片、数据、视频、学生作品和版本差异；
4. 区分已发生事实、设计设想和待确认主张；
5. 列出作者需要补充的问题。

通过条件：主案例至少有一项原始事实来源；没有原始来源的案例不得进入正式正文。

资料挖掘采用两层前置：全书级索引现在建立并持续维护，用来回答“材料在哪里、可能服务哪章”；章节级深挖必须在该章写作前完成，用来回答“这句话由什么支撑、原件在哪里、能写到哪一步、哪幅图承担解释”。不能先写正文，再为既有结论寻找佐证。

单文件或整本Markdown教材优先调用项目级`book-material-mining`。Office文档用anydoc转写；整本教材用目录模式生成合并全文、逐章哈希清单、图片调用索引和教材总卡。中央台账通过绝对路径与SHA-256防止重复劳动。

批量资料考古可以交给 5.6 Terra：适合做来源定位、同类材料归并、图件候选、版本冲突和观点—证据初步对应。物理正确性、证据强度、作者归属、正文口吻和最终取舍仍由主 Agent 与作者裁决。

## G2：事实档案

输入：原始材料与素材考古表。

输出：`01_SOURCE/第XX章/facts/<事实ID>.yaml`。

一份事实档案记录一个装置、课程、网站模块、课堂事件或数据集，包括：

- 稳定事实；
- 来源路径；
- 作者与所有权；
- 版本冲突；
- 可写主张；
- 禁止越界的主张；
- 待作者确认问题；
- 可用视觉证据。

通过条件：每个强主张能回到原件；冲突没有被隐去。

## G3：内容与视觉策划

输入：章节任务书、素材考古表、事实档案。

输出：

- `01_SOURCE/第XX章/章节结构.md`
- `01_SOURCE/第XX章/视觉策划单.md`

每一节先确定读者理解任务，再选择文字、照片、图表、公式或二维码。图片与正文在此阶段共同排布。

通过条件：每幅拟用图都有解释任务、原始路径、证据边界和图注要点；缺图处明确标注“待补”。

可按 `SKILL_ROUTER.md` 调用图解或插图技能。真实装置、课堂、学生作品和实验数据不使用生成式技能补造；解释性图解必须建立在G2已核验事实之上。

## G4：图文写作

输入：G0—G3全部交付物。

输出：`02_MANUSCRIPT/第XX章 …… .md` 与 `02_MANUSCRIPT/assets/chXX/`。

要求：

- 正文不出现编务过程；
- 图片第一次出现的位置符合读者理解顺序；
- 技术内容回到教学问题；
- 待核实内容不进入确定叙述；
- 每个案例写出适用条件和证据边界。
- 所有进入正文的照片、截图、图解和表格图片都复制到本书的`02_MANUSCRIPT/assets/chXX/`，不让正式书稿依赖外部资料路径；原始出处和授权仍保留在章节视觉台账。
- 正文统一使用相对于`02_MANUSCRIPT/`的路径，如`assets/ch05/example.png`。不使用含空格的本机绝对路径，保证VS Code预览、跨电脑协作和PDF导出都能读取。

通过条件：正文图片已复制到对应章节资源目录，使用相对路径且链接有效；图号连续；所有事实可追溯。

## G5：四类审查

输出放入 `03_REVIEW/第XX章/`：

1. 事实审查：事实、数据、人物、时间、奖项、专利和课堂状态；
2. 物理审查：概念、公式、单位、边界条件和误差分析；
3. 版权与隐私审查：图片来源、署名、学生信息和第三方材料；
4. 可读性审查：结构、重复、图文对应、术语和教师读者负担。

通过条件：问题被明确标为“已解决、待作者确认、不通过”，不得使用“应该没问题”。

文字审校技能只能作为问题发现器，不能以“AI检测率”代替出版审校，也不能自动补写个人经历或把设计方案改成课堂事实。内部PDF可用于检查图文节奏和断页，不代表出版社最终排版。

## G6：作者确认

作者只需要裁决 Agent 无法替代的事项：

- 课堂是否真实发生、时间与对象；
- 个人经历与贡献归属；
- 图片、学生作品和数据是否授权；
- 不同版本哪个进入正文；
- 图量、公式深度和章节节奏是否合适；
- 章节是否达到出版表达要求。

确认结果写入 `03_REVIEW/第XX章/作者确认.md`，不要只保留在聊天中。

## 章节完成标准

一章只有同时满足以下条件才可标为“可统稿”：

- 章节任务书已确认；
- 主案例有事实档案；
- 视觉策划已执行或明确删图理由；
- 正文与图片路径有效；
- 事实和物理审查通过；
- 版权、隐私和作者归属无未处理红线；
- 待作者确认项已经裁决；
- 与相邻章节的重复有明确主落点。

## 索引维护

- 新发现材料先进入章节素材考古表，再决定是否提升到全书资源索引。
- 只对高复用、跨章节资源更新全书级索引。
- 机械文件清单用 `tools/build_resource_index.py` 更新，不手工维护数千条路径。
- 外部资源被移动后，先更新根目录或原始索引，再运行校验。

## 网页审阅

- 审阅页生成后交由作者人工查看，不调用 Playwright 或其他浏览器自动化工具生成截图。
- 不生成桌面端或移动端审阅截图，不把截图纳入完成标准。
- Agent 只检查 HTML 文件存在、内部链接路径和必要资源是否有效，并提供可直接打开的入口。
