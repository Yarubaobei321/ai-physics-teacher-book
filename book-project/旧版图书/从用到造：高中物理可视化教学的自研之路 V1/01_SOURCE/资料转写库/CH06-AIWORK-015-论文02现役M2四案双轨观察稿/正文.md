# 对话里会核验，页面上仍可能“假守恒”——高中生与生成式AI共制物理网页的双轨观察

**摘要：** 学生借助生成式人工智能制作可交互物理网页时，对话中的物理判断与成品页面的模型—证据—运行机制可能并不一致。本文以一次约 50 分钟、使用 DeepSeek、要求提交单文件 HTML 与对话记录的高中物理活动为材料，对四份个案做过程行动与成品机制的对照阅读。最清晰的个案显示：学生能够点名“用 $v=gt$ 默认机械能守恒”的循环风险，提交页的问答区也能陈述该循环，理想数据却仍由自由落体运动学公式生成并呈现“守恒”表象。据此提出过程核验行动与成品一致性的双轨观察表，并给出任务设计上的三条原则：真值约束先于功能堆叠、预测—验收分离、过程与成品对照记录。主张限于个案定位与评价工具提案；不报告样本比例，不证明能力提升或量表效度。

**关键词：** 生成式人工智能；物理核验；学生作品评价；探究诚实；交互式网页

---

## 1 问题提出

高中物理课程标准强调科学探究与科学思维，要求学生能基于证据提出问题、形成猜想、分析论证并交流反思[^1]。生成式人工智能进入课堂后，学生可以在短时间内做出带控件、图表和动画的物理网页。页面“能运行、看起来像实验”，并不自动等于探究过程诚实，也不自动等于模型—数据—显示三者一致。

已有研究分别触及相邻问题：PhET 一类仿真对学习成效的元分析提示，交互仿真的教育价值依赖使用方式而非工具本身[^2]；作业与评价研究强调生成式 AI 环境下应把过程证据纳入评价设计[^3]；物理教学中也出现了教师主导的 Python 仿真与可视化网页、课堂交互页、学生造可运行实验工具、以及带验收标准的跨学科成品等实践[^4][^5][^6][^7][^8][^9]。这些工作为“AI + 物理页面/仿真”提供了丰富近邻；在已检索的近邻中，少见把**同一学生**的对话核验行动与提交成品的机制缺陷放在同一评价对象上对照的同构写法。

本文关心的问题是：学生在与生成式 AI 协作制作可交互物理网页时，如何提出物理约束、诊断失真、维护探究诚实并决定验收；教师如何用对话中的核验行动与成品的模型—证据—运行一致性对照，作出有限、可反驳的任务内评价？材料来自一次真实活动中的四份个案（编号 P06、P17、P20、P24）。结论停留在个案层的双轨分离定位、观察表协议与任务设计原则；不把四案推广为全体模式，也不以页面总分替代核验责任。

## 2 双轨对象：过程核验行动与成品一致性

评价对象拆成两条可独立取证、再对照的轨道。

**过程轨**只看学生在对话中可定位的用户消息（排除系统水印、角色不明段落与整页 HTML 回贴），记录四类核验行动：

| 代码 | 行动 | 操作定义 |
|---|---|---|
| A1 约束提出 | 给出必须满足的物理量、公式、单位、参考系或边界条件 |
| A2 失真诊断 | 指出输出与物理预期不符，并给出可检查理由 |
| A3 探究诚实 | 质疑循环验证、假数据、预填结论、用结果反推测量等 |
| A4 验收决策 | 明确接受、拒收或有条件接受某一版成品 |

**成品轨**看提交 HTML 的静态机制，并在有条件时补浏览器运行。缺陷类型包括：模型与页面表述不一致（B1）、表图数据来源不明或与声称测量程序不符（B2）、控件无响应或读数异常（B3）、用已假定定律的运动学反“验证”该定律（B4）、交互堆叠使测量逻辑不可检查（B5）。

**对照**只允许三种判定：一致、分离、无法判断。过程会说破循环而成品仍用循环机制制造表象，记为分离；运行未复现则保持无法判断或标注待核，不升格为确定缺陷率。

双轨对象的教学含义是：教师可以分别看见“学生是否在对话里承担核验责任”和“页面是否经得起模型—证据—运行检查”，再判断二者是否对齐。总分或完成度指标可以辅助管理，但不宜作为评价核验责任的唯一主对象。图1给出对象关系示意（非已验证量表结构图）。

![图1　双轨评价对象示意：过程核验行动与成品一致性对照](figures/fig1_dual_track.png)

**图1　双轨评价对象示意。** 左为过程轨行动类型，右为成品轨缺陷类型；中间仅允许“一致 / 分离 / 无法判断”三种对照结论。

## 3 任务条件与材料范围

活动要求学生在约 50 分钟内使用 DeepSeek，持续修正并提交单文件可交互 HTML，同时提交对话分享记录。上述任务条件来自本次教学活动的现场说明（内部材料，不作正式参考文献）。主样本目录中 P01—P25 均有过程对话与提交 HTML 文件对；本文只做其中四案的厚描述，不做 25 份统一编码或比例统计。

证据优先级为：教学现场说明与可追溯的用户消息、提交网页源码为原始事实；历史浏览器复核笔记仅作运行现象的稳健性参考，并标明 partial；既有评分文件、汇总表与量表结果不进入本文主张。

## 4 焦点个案：机械能守恒网页中的循环生成（P06）

### 4.1 过程：诊断失真并点名循环风险

学生围绕自由落体情境下的机械能关系迭代页面。一条用户消息指出动能与重力势能数据重复，质疑势能算法，要求先声明参考平面，并描述期望趋势：机械能大致不变、重力势能减小、动能增大（消息锚点 s01-m003）。这对应 A2（失真诊断），并带有 A1 成分（参考平面与趋势约束）。

随后一条用户消息明确写出：用 $v=gt$ 等于默认机械能守恒，会陷入理论循环；同条又要求删掉“参考平面说明”、加大质量以放大曲线，并把注意事项改为问答（消息锚点 s01-m005）。探究诚实意识（A3）与呈现策略取舍出现在同一条指令里：学生能说出循环风险，同时推动页面更“好看、好讲”。两条消息原文见图2。

![图2　P06 过程轨用户消息摘录（s01-m003 / s01-m005）](figures/fig2_p06_dialogue.png)

**图2　P06 过程轨用户消息。** 上条诊断表图失真并要求声明参考平面；下条点名 $v=gt$ 循环风险，并要求改成问答详解。来源：`过程对话.json`（role=user，已确认）。

### 4.2 成品：理想数据仍由 $s=\tfrac12gt^2$、$v=gt$ 生成

提交网页以“验证机械能守恒”为题，参数取 $m=2\,\mathrm{kg}$、$g=9.8\,\mathrm{m/s^2}$、$H_0=5\,\mathrm{m}$，并声明 $E_{p0}=mgH_0=98.0\,\mathrm{J}$（页面首屏见同目录 `figures/fig3_p06_page.png`）。理想数据表中机械能各点均为 98.000 J，曲线呈守恒表象（图3）。

![图3　P06 成品数据表与能量曲线：机械能恒为 98.000 J](figures/fig3_p06_data_panel.png)

**图3　P06 成品数据与曲线。** “重置为理想实验数据”状态下，$E$ 列恒为 98.000 J，呈现守恒表象；数据生成机制见下文源码锚点。

手算与源码一致：

$$
E_{\mathrm{total,ideal}}=mgH_0=2\times9.8\times5=98.0\,\mathrm{J}.
$$

数值自洽成立，不等于探究逻辑无循环。成品问答区已写明：用 $v=gt$ 计算速度再代入动能去“验证”守恒，属于循环论证（图4）；页脚与脚本却写明理想数据基于 $s=\tfrac12gt^2$、$v=gt$ 生成（图5）。表述层能够陈述风险，生成程序仍依赖 $v=gt$——二者未对齐。历史浏览器复核笔记也记录了 $E_{p0}=98$ 与守恒显示；该笔记仅作定性对照，其分数字段本文不采用。

![图4　P06 成品问答区（展开）：页面自陈“循环论证”](figures/fig4b_p06_qa_live.png)

**图4　P06 成品表述层。** 问题“为什么不能用公式 $v=gt$ 计算瞬时速度”的展开解答明确使用“循环论证”表述。

![图5　P06 提交作品源码锚点：理想数据仍由 v=gt 生成](figures/fig5_p06_code.png)

**图5　P06 成品生成层。** 页脚说明与脚本中的 `const v = g * t`、`s = 0.5 * g * t * t` 表明理想/随机数据依附自由落体运动学生成；与图4自陈未对齐。

### 4.3 对照：过程与成品分离

| 轨道 | 可观察内容 | 标签 |
|---|---|---|
| 过程 | s01-m003 诊断表图与参考平面；s01-m005 点名 $v=gt$ 循环并要求改成问答详解 | A2、A3 |
| 成品表述层 | 问答区解释“用 $v=gt$ 再验守恒属循环论证” | （自陈风险） |
| 成品生成层 | 理想数据仍由 $v=gt$ 等公式生成；随机误差依附同一机制 | B4、B2 |
| 对照 | 过程与成品表述层都能说破循环，生成程序仍制造守恒表象 | **分离** |

P06 说明：双轨分离可以在单案内定位到消息锚点、页面自陈与源码生成机制；它支持“评价应对照过程与成品（含表述层与生成层）”，不支持“该生能力高低”或“此类任务普遍失败”的推广。

**P20（抛体与阻力相关交互）。** 过程消息大量指向暂停、分速度显示、设定运动时间、调节画布等功能规格，功能轨突出（图6）。成品静态层体量大、控件多（图7中），并含与 $F=kv$ 相关的脚本痕迹，可定位功能堆叠压过测量可检查性的风险（B5 候选）。历史笔记称飞行中 $v_y$ 显示未按阻力预期衰减等问题（partial）。过程/静态可定位；运行对照待核。

**P24（分层进阶式能量相关页面）。** 过程要求表格勿预填、设置高度后勿立刻显示全部数据，并要求模块闯关解锁，体现对“假探究交互”的警惕（A3，图6）。成品结构呈课程编排式多模块解锁（图7右，静态可定位）。历史笔记称能量损失约 13%、部分例题无解等，本轮未复现，运行对照待核，整体对照记为待定。

在所读四案中可见：对话里会出现核验行动，成品仍可能保留循环生成、预填数据风险、运行异常或功能掩盖。它们共同支撑观察表与任务设计讨论，不支撑样本比例或能力增益判断。

## 6 双轨观察表与任务设计原则

### 6.1 观察表用法（试编）

教师可按“过程消息 ID → 过程标签 → 成品锚点 → 成品标签 → 运行是否已核 → 对照”记录一行。一条消息可多标签；成品可多缺陷。禁止把观察表得分直接写成能力等级，也禁止在未完成统一编码前报告比例。

最小记录示例（P06）：

```text
案号：P06
过程消息：s01-m005 / 点名 v=gt 循环并要求改成问答详解
过程标签：A3（兼有呈现策略取舍）
成品锚点：问答区「循环论证」说明 + 理想数据生成段（v = g * t）
成品标签：B4（生成层）；表述层已自陈风险
运行核验：历史笔记 partial；本轮未现场复现
对照：分离（表述层与生成程序未对齐）
```

### 6.2 三条任务设计原则

**原则一：真值约束先于功能堆叠。** 任务说明可要求学生先声明参考系、守恒条件、测量程序与可证伪预期，再叠加动画与控件。P20 显示功能请求易于淹没可检查的测量逻辑。

**原则二：预测—验收分离。** 要求学生在生成“理想数据”之前写下独立预测，或禁止用待验证定律直接生成验证用数据。P06 的循环机制正是预测与生成程序未分离的结果。

**原则三：过程与成品对照记录。** 提交物同时包含对话分享与 HTML；评价模板预留对照栏（一致/分离/无法判断）。这与“只看页面完成度”或“只看提示词文采”的单一对象不同，也与仅强调作业过程证据的一般 AI 评价主张相衔接，但把物理学科的模型—证据—运行检查写进成品轨[^3]。

## 7 与既有研究的边界

在已执行的检索范围内，未见与本文完全同构的“过程核验行动 × 成品模型—证据—运行一致性”双轨评价专文；近邻工作分别覆盖仿真成效[^2]、GenAI 作业评价[^3]、教师/学生造可视化或可运行工具[^4][^5][^6][^7][^8][^9]。本文增量是对象候选与个案协议，不是领域空白宣告。PhET 元分析提醒交互工具的效果依赖使用方式[^2]；本文把这一提醒落到学生自制页面的核验责任上，材料与主张尺度均小于成效研究。

## 8 局限与结论

**局限。** （1）仅四案厚描述，未做 25 份统一双轨编码。（2）P17/P20/P24 的关键运行现象依赖历史浏览器笔记，本轮未隔离复现，正文已标 partial；图7仅提供静态首屏，不替代运行复现。（3）观察表未经评分者一致性或教学现场试用检验，不能称为已验证量表。（4）英文库未系统补检；文献定位限于当前检索边界。（5）配图为原件截取与排版呈现，便于审稿核验锚点；投稿时需按目标期刊调整图幅与分辨率。

**结论。** 在所读四案中，学生与生成式 AI 共制物理网页时，对话中的核验行动与成品机制可以分离；P06 提供了消息锚点、页面自陈与生成程序对照的清晰例证——表述层说破循环，不等于生成层已解除循环。双轨观察表把这种分离变成可记录、可反驳的任务内评价动作；任务设计宜把真值约束、预测—验收分离和过程—成品对照写进活动规则。后续若补齐统一编码与运行复现，主张强度才可能上移；在此之前，评价应守住个案证据与工具提案的上限。
