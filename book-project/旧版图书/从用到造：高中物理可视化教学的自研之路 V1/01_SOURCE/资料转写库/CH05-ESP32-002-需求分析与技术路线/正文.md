# ESP32 图形化编程教学工具 —— 需求分析与技术路线书

> 立项纲领。读者：项目作者本人 + 后续协作的 AI。
> 定稿日期：2026-06-23。决策已锁定：**Web 优先 + MicroPython**。

---

## 1. 背景与目标

高中科创选修课，需要让学生在课堂上做 **ESP32 / ESP32-S3 的图形化编程 + 烧录测试**。

课堂实情：
- 24 套 ESP32 / ESP32-S3，36 名学生，8 组；**每组 1 台安卓平板 + 2 套 ESP32**；教室有 WiFi。
- 学生**无 PC**，主力终端是**安卓平板**。

诉求：参考 aily-blockly 但**它太重**，要做一个**只服务 ESP32/S3** 的精简工具，能在 PC、**最好安卓平板**上用，有线或无线烧录，**后期并入门户网站 shuzhiyucai.cn**，并与 `Natural-Language-Hardware-Development` 教程配套。

## 3. 关键架构判断（为什么这样选）

两条硬技术事实，决定了路线：

1. **aily-blockly 是 Electron 桌面应用，物理上跑不了安卓平板。** Android 无 Electron 运行时。砍得再小也只能跑 PC。能搬到平板的只有它的 **Blockly 编辑器那一层（纯 Web 技术）**，不是整壳。
2. **安卓 Chrome 不支持 Web Serial（`navigator.serial`）。** 网站现有 `esp32-serial.ts` 有线烧录只在**桌面 Chrome/Edge** 可用，平板用不了——这正是当年做 ESP32Blockly **无线下发**的根本原因。

因此"精简 aily-blockly + 上平板"互斥。**选 Web，就只能搬 aily 的编辑器层，烧录另接管线。**

## 4.1 决策深探：MicroPython 库生态是不是短板？

**结论：是，生态确实比 Arduino 小一个数量级；但对本项目不构成短板，且有可逆退路。**

**生态差距是真实的（不美化）：** Arduino 官方库索引是数千量级（~7000+），加 GitHub 不计其数；厂商买来的模块例程**几乎都是 Arduino C++**。MicroPython 官方 `micropython-lib` 是精选的，几十到一两百个模块，社区驱动散落、质量参差。差距在**长尾**和**前沿**两头最明显。

**但对本项目，约束不是"库多少"，是"积木多少"：** 学生能用的边界，是**你做了积木的那一撮**，不是 GitHub 上有没有驱动。aily 那 7000 个库里没做成积木的，对学生一样不存在。你的硬件是**固定一套**（Grove + 常见 I2C/模拟量），只需覆盖**自己的器材箱**（约 20~40 件），而这批**绝大多数 MicroPython 覆盖良好**：

| 课堂会用 | MicroPython 现状 |
|---|---|
| GPIO/PWM/ADC/I2C/SPI/UART/DAC/触摸/定时器 | `machine` 内置，一等公民 |
| WS2812 / DHT11-22 / DS18B20 / 超声波 HC-SR04 | `neopixel`/`dht`/`onewire` 内置或一行搞定 |
| OLED(SSD1306)/BME280/MPU6050/TM1637/舵机 | 成熟社区驱动；舵机即 PWM |
| WiFi/HTTP/BLE/ESP-NOW | `network`/`aioble`/`espnow` 全有，比 Arduino 还短 |

**短板真实存在，但被框死在这几个角落**（高中科创 80% 碰不到）：① 性能/时序敏感（解释执行慢 10~100×）；② 摄像头 / 重 GUI(LVGL) / 端侧 AI(TF-Lite)；③ 全新或冷门厂商芯片（无 `.py` 驱动，需照手册移植，几小时的活、不是墙）；④ 内存开销更大。

**退路可逆、可增量（关键）：** Blockly 块层与目标语言**解耦**（aily 同一套块挂着 arduino/js/micropython 三个生成器）。所以"MicroPython 优先"≠永远锁死——真撞到非 C 不可的高级项目（如摄像头），可**给那一类单独接一条 Arduino C++ 生成 + 编译服务器**，而不推翻已建的积木与教学体系。**等于把"编译服务器"的复杂度，推迟到真正需要它那天**，而不是让 100% 的学生从第一天就忍受编译卡顿。缺驱动时让 LLM 照 C++/数据手册转 MicroPython，也接上教程那条 AI 未来线。

## 4.2 决策深探：Blockly 版本与"用更新技术"

**事实（已核实）：** aily 装的是 **Blockly 11.2.2**；npm 最新是 **13.0.0**。

**为什么挑 13 几乎免费：** 本项目是**全新挂载自己的 Blockly**（见 §5"收割资产，不移植 Angular"），运行时由我们自己装，版本随便选——**不存在"11 升 13"的迁移，是从头装 13**。继承 11 无任何好处。

**适配成本落在收割资产，且分层（轻→重）：**
- **块定义(JSON)**：跨版本基本稳定，≈零改。
- **生成器**：现代 Blockly 用 `forBlock` 注册；ESP32Blockly 已在用 `Blockly.Python.forBlock[type]`，aily(11) 同此——**已是前向兼容写法，风险低**。
- **自定义字段 / 自定义渲染器**（aily 的 LED 点阵、u8g2 动画等）：跨大版本**最易炸**的部分。**v1 不拿它们卡进度，用普通字段先上，炫字段列 P3+ 选配**。

**"13 更适合平板"——别把版本号当银弹：** 新版触控/渲染/无障碍确在持续改进，greenfield 没理由停在 11、该用最新；但**平板手感的大头来自你的集成层**：触控目标尺寸、工具箱形态(连续 toolbox/抽屉)、缩放控件、窄屏 flyout 行为。版本选最新是"不留技术债"，真正好用得靠调布局。

## 5. 关键洞察：不要"移植 Angular"，而是"收割 Blockly 资产"

Web 优先最容易被高估工作量的点，是以为要把 aily 的 **Angular** 编辑器整体移植——那很重。**不需要。**

aily 的核心价值物（块定义、MicroPython 生成器、自定义字段、插件）都是**框架无关的 Blockly JS/TS**。而你的 **ESP32Blockly 本来就是"原生 Blockly + 自定义块/生成器"的架构**（`public/js/blocks/esp32.js` + `generators/micropython.js` + `blockly-setup.js`）。

**实测修正（2026-06-23）：aily-blockly 仓库里并没有 ESP32 的 MicroPython 块——它们在外部 npm 包（boards/libraries），以 Arduino C++ 为主，本地也未安装。** 所以本项目的真实底座**不是"收割 aily"，而是 ESP32Blockly 自带、已 headless 测过的 MicroPython 块/生成器**（`blocks/esp32.js` + `generators/micropython.js`）。aily 退为**参考与零件**：核心生成器的 import 注入机制可借鉴，个别可视化字段可选摘。这反而**更省事、更低风险**——少了对 GPL 重代码的耦合。**v1 = 在自己已跑通的工具上「扩块 + 升级 Blockly 13」，而非从外部抽代码。**

## 7. v1 功能范围（MVP）

**做：**
- 一个 Web 图形化编辑器：ESP32/S3 工具箱（GPIO 输入/输出、PWM、模拟读、串口 print、延时、循环/条件/变量、I2C OLED、常用传感器）。
- 生成 MicroPython（复用 aily 生成器 + ESP32Blockly 已有块）。
- 桌面：Web Serial 烧录 + 串口回显（复用 `esp32-serial.ts`）。
- 平板：接 ESP32Blockly 无线管线烧录 + 回显。
- 育才蓝主题；本地草稿（localStorage）。

**不做（v1 明确排除）：**
- AI / 自然语言助手、应用商店、模型市场、云同步、OAuth 登录。
- Arduino C++ 生成与编译服务器。
- 多开发板（只 ESP32 / ESP32-S3）。
- 给学生开放 WiFi 连接/断开积木（沿用 ESP32Blockly 约束，避免切断控制通道）。

## 10. 风险与待验证项

- **BLE 直连下发为新增、未验证路径**：课堂主管线（WS 无线下发）已可跑通；但 **BLE 直连下发**（单机/在家测试用）是新路径，需 ESP32 端写"收码→运行→回显"的 BLE 固件并单台验证后再用。属次要路径，不阻塞课堂。
- **块收割兼容性**：aily 生成器可能依赖其运行时上下文（import 注入机制、`.abi` 格式）。P0 spike 要先验证能脱离 aily 框架独立产出代码。
- **Blockly 自定义字段/渲染器跨版本风险**：aily 的 LED 点阵 / u8g2 等自定义 field/renderer 在 11→13 最易破。v1 用普通字段，炫字段 P3+ 选配（见 §4.2）。
- **MicroPython 长尾/前沿短板**：性能时序、摄像头/重 GUI/端侧 AI、冷门新芯片处会咬人（见 §4.1）。退路是按需给那一类项目单独接 Arduino C++ 生成 + 编译服务器，可逆增量。
- **平板有线烧录**：v1 平板**不做**有线（Web Serial 不支持）。若未来必须，再评估 WebUSB 或安卓原生壳，属独立工程。
- **GPL 许可**：aily-blockly 为 GPL，收割其代码后本项目需遵守 GPL 与其附加权利说明（禁未授权销售/移除权利人信息）。教学自用无碍，公开发布需注意。

## 12. aily-blockly 可借鉴清单（2026-06-23 复核修正）

§2/§4.1 说 aily「可取的很有限」——那只对 **ESP32 块/生成器**成立（不在仓库、且 Arduino 向）。其 UX 与架构仍有真东西可借鉴，分级如下：

**🟢 可直接装（标准 Blockly 插件，MIT，兼容 Blockly 13）**
- `@blockly/continuous-toolbox`（连续滚动工具箱）、`@blockly/plugin-toolbox-search`（块搜索框）、`@blockly/plugin-workspace-multiselect`（多选）、`block-plus-minus`（块上动态加减输入）。aily 正用这几个；工具箱变大后平板体验提升明显。**建议 P1.5 引入。**

**🟡 借交互思路、为我们的块重写（aily 字段是 Arduino 向 + 跨版本脆，只抄 UX）**
- 可视化字段：舵机角度转盘（field-angle）、PWM/亮度滑条（field-slider）、蜂鸣器音符选择（field-tone）、点阵/图案绘制（field-led-matrix/bitmap）。正好配 servo/PWM/buzzer/RGB 块——平板上转盘/滑条比敲数字好太多。
- app 内**引脚图面板**（教程已有 `esp32-pinout.png`），学生接线时查 GPIO 用途。

**🔵 v2 / 长尾参考架构（现在不做）**
- aily-chat agentic 内核（turn-manager / tool-registry / 工具审批）→ 对接教程「自然语言→硬件代码」未来线。
- AI 转库（C/C++ → Blockly）→ 缓解 §4.1 的 MicroPython 长尾短板（缺驱动时让 AI 照数据手册生成 MicroPython 块）。
- 序列化版本兼容对话框（块定义迭代多了会需要）。

**🔴 明确不借（"重"，见下附录）**：OAuth、应用/模型商店、云空间、自动更新、MCP 托管、node-pty 终端、probe-rs、Electron/Angular 壳、Arduino/PlatformIO 编译链。

## 13. Mixly 借鉴清单（2026-06-24）

**许可（已查证）**：Mixly（北师大）核心仓库 `mixly/Mixly_Arduino`、`mixly/mixly_lite` 在 GitHub 公开，但用**自定义许可**（GitHub 标 `NOASSERTION`/"Other"，非标准开源）。实际条款：允许使用/修改，但**修改后须保留「Mixly」名 + 作者信息**（可改名 `Mixly4XXX`），并遵守其捆绑组件各自许可。
→ **结论**：法律上可改用（带署名/改名义务），但其代码是 **Arduino C++ + 自家框架**，复用不干净；「Mixly4XXX」命名对「育才」品牌不合适。**维持：借思路、不抄码。** Web 2.0/3.0 + MixIO + 仿真器很可能不在这两个开源仓库（MixIO 单独仓库、无许可）。
