## 3. 教师作为资源开发者的脉络梳理（"教师即开发者"角色演变）

```
阶段一(1990s-2000s)：教师作为课件制作者(courseware maker)
  └─ 工具：PowerPoint/Authorware/Flash；能力模型偏"操作技能"
  └─ 英文学理：Hu et al.(L21)已提出"Teacher as Developer"，MERLIN(L20)强调"电子格式"开发
  └─ 中文语境：电教馆体系、课件评比驱动；教师=资源的"使用者优先、制作者其次"

阶段二(2010s)：教师作为资源共建共享者(resource co-creator & sharer)
  └─ 政策：信息技术应用能力提升工程、国家教育资源公共服务平台、一师一优课
  └─ 论据：L11、L18(师徒制/共建共享机制)、C7检索结果(区域联盟、教师工作坊)
  └─ 范式：从"个人制作"→"区域共建共享"；教师角色仍在"资源"层，未触及"平台/系统"

阶段三(2020-2022)：教师作为数字课程开发者(digital curriculum developer)
  └─ 工具：H5微课(PP匠/兔展/希沃白板5)、Camtasia录屏、Articulate Storyline(C8)
  └─ 范式：教师能产出"可交互的教学产品"，但仍受限于模板与代码门槛
  └─ 瓶颈：网页/H5级开发仍需第三方平台或编程，零基础教师难以独立建站

阶段四(2023-至今)：AI 赋能下"教师即校本资源开发者"(teacher as school-based AI-augmented developer) ★本文位置
  └─ 触发：ChatGPT(2022.11)→国产GLM/文心/通义(2023)→GLM-4(2024)→GLM-5.2+ZCode3.0(2026.6)
  └─ 论据：L3/L4/L5(GAI生成个性化资源、突破知能局限)、L9(五大场景嵌入)
  └─ 关键跃迁：教师从"用工具做资源"→"与AI工程化协作产出完整教学门户(网站级系统)"
  └─ 本文增量：把"教师即开发者"从"资源粒度"推到"系统/门户粒度"，这是文献中最薄弱的一环
```

**脉络结论**：现有文献对"教师即开发者"的讨论，绝大多数停留在**单个课件/资源/微课**粒度（阶段一-三），极少触及**网站/系统级**的独立开发。本文是阶段四"系统粒度"的早期实证，撞车风险低（见第6部分）。

## 4. 纵向脉络：AI 赋能教师开发教学资源主题的演变

| 时段 | 代表性事件/文献 | "AI赋能教师开发资源"的具体形态 |
|---|---|---|
| 2017-2021 | 智能教育/AI辅助备课(非生成式) | 规则型/检索型辅助，教师仍是资源主导者；TPACK经典框架(L6前半段) |
| 2022.11-2023 | ChatGPT问世；Kasneci等(L23)首篇综述 | "AI能写教案吗"的可行性验证；态度调查为主 |
| 2023-2024 | UNESCO指南(L12)；教育部AI+高教案例(L17)；ChatGLM技术报告(L14/L15) | 从"能否用"转向"如何用"；GAI进入教学设计(L5)、资源生成(L3/L4)；提示词工程进入教师话语(L24/L25/L26) |
| 2024-2025 | TPACK→AI-TPACK→GHEX-IPACK框架演进(L6/L7/L8)；教育部《数字化赋能教师发展行动》(L10)；《中国教师生成式AI应用报告2026》(L9) | 框架化、标准化、培训课程化；但实证多停留在"教师用AI写教案/出题"粒度 |
| 2025-2026 ★ | harness engineering成为AI编程显学(L30)；GLM-5.2+ZCode3.0(2026.6)发布 | "AI辅助开发"开始具备工程化协作形态；**但教育界尚未把harness engineering引入教师PD** |

## 6. 与本文的关系：文献地形图中的定位

### 6.1 本文的位置（一句话）
本文位于"**F(国产AI工具)×G(harness engineering)×H(教师系统级开发)**"三重交叉的空白区，是把 Martin Fowler/Addy Osmani 式的 harness engineering 论述**首次降维迁移到零基础教师校本资源开发**的实证研究。

### 6.2 可深挖的切口（本文独有的学术贡献点）

1. **"从单次提示词到工程化协作"的阶梯**：现有提示词框架(L24 RPE、L25)只到"单轮/多轮提示词策略"，本文把**规则文件、Skill技能文档、需求模板、验收清单、版本管理**作为一个完整工程体系引入教师PD——这一阶梯在检索文献中无人建构，**原创性强**。

2. **harness engineering 的教育学转译**：L30 全是产业论述(OpenAI/Martin Fowler/Augment)，无一篇进入教育话语。本文可提出"**教学 harness**"或"**校本资源开发 harness**"概念，把"提示词/工具/上下文/反馈环/沙箱"映射为"教学需求/资源类型/学情上下文/验收清单/试错环境"——**概念性贡献**。

3. **"教师即校本资源开发者"的角色升级到"系统粒度"**：L18-L22 的"教师开发者"停在资源粒度；本文用建站实证把角色推到门户/系统粒度，**角色理论升级**。

4. **国产工具(GLM-5.2/ZCode3.0)的早期教育实证**：检索显示 GLM 教育应用"多为产品页/政策案例，独立学术实证稀少"(C5/C6)，本文是国内较早的 GLM+ZCode 教育实证，**填补 F 阵营空白**。

5. **零基础教师群体的特殊性**：L28/L29 的 Copilot 实证对象是 CS 学生(有编程基础)，本文对象是**零基础学科教师**，人群互补，可形成对照讨论。
