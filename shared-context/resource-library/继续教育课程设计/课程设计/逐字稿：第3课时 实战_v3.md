## 一、开场：为什么选这个课题（00:00–02:00）

> **【画面：PPT第1页（第三课时封面），切第2页（驻波的三个教学痛点）。】**

　　各位老师，这一课时是全课核心：全程不间断，从教学设计到完整教学网页。

　　演示课题我选了《波的叠加与驻波》。选它是因为教这个内容的时候，痛点特别集中。实物实验几乎没法教——叠加过程看不清、静态挂图讲不动。学生误区也集中：很多学生认为波节那个点不动，是因为"没有波经过那里"；还有学生以为驻波的图样在向前跑。而且这个课题能往后长——扩展到波的干涉，一维是驻波，二维是水波加强减弱区图样，同一套框架可以一直深化。

> **【画面：切PPT第3页（开发五步法：设计→PRD→开发→修复→验收）。】**

　　整个过程分五步：教学设计、需求文档、分步开发、出错修复、质量验收。其中出错修复这一步，我特意保留了AI出错的真实过程，没有剪掉。因为那才是日后每天面对的真实状态。

## 二、第1节 教学设计先行＋需求文档（02:00–10:00）

> **【画面：PPT第4页（从难点到功能的对照表）。】**

　　可能有老师看到上节课的演示，觉得直接把需求告诉AI就行了。我一开始也是这么做的，结果改了十几轮。后来想明白了：动手之前先理清楚这个页面要解决什么教学问题，比急着让AI写代码重要得多。

　　我的做法是把难点和功能做一张对照表。叠加原理看不见——页面要把分波和合成波同时画出来，能暂停、能逐帧走，让学生亲眼看到合位移等于两个分位移相加。驻波形成过程抽象——两列相向波实时叠加，波节波腹自动标注。误区"波节处没有波"——在习题里专门设计辨析题。于是页面四个板块：原理讲解区、交互模拟区、读图练习区、配套习题区。

　　每个功能都对应一个具体的教学问题。

> **【画面：切PPT第5页（先要PRD，再要代码）。】**

　　对照表理清之后，下一步不是直接让AI写代码，而是让它先当"产品经理"，输出一份需求文档。我确认了才动工。

　　把验收前置，是我踩了很多坑之后学到的。这里也用上第二课时下发的脚手架——我直接拿"PRD需求文档模板"来填，省事；而且项目里已经放了规则文件AGENTS.md，配色、单文件、不依赖外网、平板适配这些约定AI会自动遵守，所以下面这条提示词里我就不再重复交代了。

> **【操作：在ZCode中打开"教学网页脚手架"项目，AI对话区粘贴以下提示词并发送。】**

#### ▶ 提示词①：需求文档（PRD）

```
我是高中物理教师，准备开发《波的叠加与驻波》教学网页，面向高二学生，
在平板浏览器上使用。请先不要写代码，以产品经理身份输出一份需求文档，
内容包括：

1. 页面结构（原理讲解区、交互模拟区、读图练习区、配套习题区）；
2. 交互模拟的可调参数与显示要素：两列相向传播的等幅同频波，
   两列分波与合成波可分别显示或隐藏，支持暂停与逐帧播放，
   波节与波腹位置自动标注，频率与振幅滑块可调；
3. 读图练习区：给出一幅驻波图样，让学生读出波长和相邻波节间距；
4. 习题类型与数量：4–6道分层习题，必须包含针对"波节处没有波通过"
   这一误区的辨析题；
5. 平板适配要点。

请用表格呈现需求文档，等我确认后再进入开发。
```

> **【操作：等待AI输出PRD表格（可快进），滚动展示，鼠标停在"显示要素"一行，现场口头确认或修改一处，然后回复。】**

#### ◆ 预期输出与备用话术

> **预期**：AI输出包含页面结构、参数、习题规划的表格。
>
> **台词**："大家看这份需求文档，我只花了一条提示词，它把我的教学需求全部结构化了。核对一遍……这里我补充一点：合成波要用粗实线、分波用细虚线，颜色区分。"
>
> **回复AI**："确认需求，补充一点：合成波用粗实线，两列分波用不同颜色的细虚线。请开始开发，先输出页面骨架和原理讲解区。"

　　从教学设计到需求文档，整个过程用的全是学科判断力，和写代码没有关系。这就是上节课说的——提需求的能力。

## 三、第2节 开发实录（10:00–32:00）

### （一）页面骨架与原理区（10:00–17:00）

> **【操作：AI生成HTML文件（快进），在ZCode中保存为 standing-wave.html，右侧内置浏览器自动预览。滚动展示骨架与原理区。】**

　　第一版骨架出来了，四个板块框架都在，原理区有了文字。但两个排版问题：公式下标没效果，段落挤在一起。用第二课时学的"给证据"方法——截图，圈出问题，发给它。

#### ▶ 提示词②：排版修正（配截图）

```
见截图。两个问题：
1. 原理区公式中的下标（如波长λ、周期T的下标形式v₁、v₂）
   没有正确显示为下标格式，请用HTML的sub标签处理；
2. 原理区段落间距太小，平板上阅读吃力，
   请将段落行距调整为1.8倍，段间增加适当留白。
其他部分不要改动。
```

> **【操作：内置浏览器自动刷新，对比前后。然后用ZCode的Git一键提交保存版本（呼应第二课时）。】**

　　改好了，用ZCode的Git一键存一个版本。接下来啃硬骨头：交互模拟。

### （二）交互模拟开发（17:00–26:00）

> **【操作：发送以下提示词。】**

#### ▶ 提示词③：交互模拟区

```
现在开发交互模拟区。要求：

1. 用canvas绘制：上方并排显示两列相向传播的等幅同频简谐波
  （红色细虚线向右传播、蓝色细虚线向左传播），
   下方显示它们的合成波（深色粗实线）；
2. 提供"显示/隐藏分波""显示/隐藏合成波"开关；
3. 提供"播放/暂停"按钮和"逐帧前进"按钮，逐帧步长为周期的1/16；
4. 合成波上自动标注波节（▽符号）和波腹（△符号）位置，
   随参数变化自动更新；
5. 频率与振幅滑块可调，调节时波形实时更新；
6. 按钮和滑块尺寸适合平板触屏操作。

请基于现有文件继续开发，不要改动原理区。
```

> **【操作：生成（快进），刷新预览。预期此处出现真实问题：点击"逐帧前进"后合成波与分波位置对不上（或动画不动等实际遇到的问题，按真实情况调整台词）。放大问题画面。】**

　　来了——动画能播放，但逐帧前进时合成波和分波位置对不上了。物理上不可能：合成波每一点的位移必须等于两列分波位移之和。

　　这种时候新手最容易说一句"不对，重做"。

　　千万别。我们按"给证据"的方法来：截图，打开浏览器的控制台把报错原文复制下来——按F12就能打开，红色的就是报错——一起发给它。

#### ▶ 提示词④：报错反馈（配截图＋报错原文）

```
切换到"逐帧前进"后，合成波曲线与两列分波的位置对不上（见截图）。
浏览器控制台报错如下：（粘贴报错原文）。
请定位原因，给出修改后的完整代码段，
并用通俗语言解释这个错误的成因，让我以后能自己排查类似问题。
```

> **【操作：AI返回修复代码与解释（快进应用），刷新预览，逐帧演示恢复正常；将AI的"错误成因解释"段落放大展示3秒。】**

#### ◆ 预期输出与备用话术

> **预期**：AI定位到逐帧模式下时间变量未同步（或等价原因），给出修复代码并附通俗解释。
>
> **台词**："修好了。注意我还让它解释了原因——它说逐帧模式下两套图形用了两个不同步的时间变量。我听懂了，下次再遇到类似现象，自己就能判断个八九不离十。每修一个错，经验就厚一层。"
>
> **若AI一次未修复**：追加台词"一次没修好也正常，我把新的现象再喂给它——证据给得越具体，修得越快。"（重复给证据流程）

> **【操作：验证物理正确性的快速演示：暂停在某一帧，鼠标指着波节位置，口算/旁白核对两分波位移相加为零。】**

　　修完我有个习惯：暂停任意一帧，取特殊点核对。波节位置——红色分波在波峰，蓝色在波谷，相加为零。对了。

　　这种物理直觉上的验证，AI做不了。它能写代码，但判断"这个物理过程对不对"，靠的是教师的学科功底。

　　大家注意刚才这一整段的节奏——提需求、它改、我看效果、发现问题、给证据让它修、再验证。这转的就是上节课说的那个"循环"：计划→修改→验证→修复。实战里你会一圈一圈地转，每修好一处，顺手用Git提交一次，稳扎稳打。

### （三）习题区生成与把关（26:00–31:00）

> **【操作：发送以下提示词，生成习题区（快进），逐题滚动展示。】**

#### ▶ 提示词⑤：配套习题区

```
最后开发配套习题区。要求：

1. 共5道题，按"基础–中等–挑战"分层标注：
   2道单选、1道多选、1道读图填空
  （由驻波图读出波长与相邻波节间距）、1道辨析题；
2. 辨析题必须针对"波节处质点不振动，是因为没有波传到那里"
   这一错误说法，要求学生判断并说明理由；
3. 每题提供"提交"即时判对错、"查看详解"折叠展开、"重做"功能；
4. 答案和详解由你生成，但请在详解中明确写出物理依据。

请基于现有文件继续开发，不要改动已完成的区域。
```

> **【操作：在预览中现场逐题审题——重点停在辨析题和读图题，发现任一科学性问题则现场让AI修正（保留真实过程）；若全对，则口头确认每题答案。】**

　　习题出来了，接下来是最重要的一步：逐题审核。AI出题又快又像样，但科学性它不负责。

　　负责的人是我们。

　　看这道辨析题——表述准确：波节处两列波始终存在，只是位移叠加恒为零，"没有波经过"是错的，详解也讲清楚了物理依据。再看读图题，图上波长四米，相邻波节间距应该是二米——答案正确。五道题逐一过完，确认无误。

　　到这里，从教学设计到功能开发到出题，核心工作完成了。在进验收之前，我插一段很多新手老师最容易忽略、但一旦吃过亏就忘不了的东西——开发规范，特别是git。

> **【画面：切PPT第6页之后插页（开发规范：反·正对比）。先演示"反面"，再演示"正面"。】**

　　我先演个"反面教材"，故意不守规范。这一路我一直让AI大改、一次都没提交。现在我说一句"把配色全换成暗色风格"——它一通改。结果呢，暗色是上了，可刚才好好的波节标注不见了、习题折叠也坏了。我想退回到上一个好版本？退不回去，因为我根本没存过；我想搞清它到底改了哪些地方？也说不清。这就是新手最常见的崩溃现场——**改坏了找不回、版本一团乱、说不清动过什么。**

> **【操作：用ZCode可视化Git展示提交历史，演示小步提交与一键回退。】**

　　再看"正面"。如果我一路是这么干的：每做好一块就用ZCode的Git提交一次，提交时写一句话说明改了啥——"完成交互模拟""加好分层习题"。现在历史清清楚楚，每一步都在。哪怕这次暗色改砸了，一键回退，立刻回到上一个好版本，前面的成果一点不丢。

　　大家感受一下这两种状态的差别。同样用AI，**守不守规范，决定你是越做越稳，还是越做越慌。**git不难，对我们就两个动作：满意了就提交、写句话；改坏了就回退。这就是这门课希望大家带走的开发习惯——它对应作业三里"过程记录"这一项的分值。

　　好，规范铺垫完，下一步真正进验收。

## 四、第3节 质量验收（33:00–38:30）

> **【画面：切PPT第7页（三查验收清单：科学性、交互、适配），随后切回浏览器逐项执行。】**

　　开发完不等于完工。我自己的习惯是做三轮检查——这里就照着脚手架里那份"验收清单"逐条过，科学性、交互、适配三查。

　　一查科学性：波节位移和习题刚才核过了，再补一个——波长调到四米，标注间距两米，对；波腹振幅是单列波的两倍，看数值，对。

> **【操作：用浏览器开发者工具切换到平板模拟视图（或直接用真实平板演示），触屏操作滑块和按钮；再换一个浏览器打开一次。】**

　　二查交互与适配：切到平板视图，滑块好拖吗？按钮够大吗？横屏竖屏正常吗？换个浏览器——没问题。三查学生视角：假设我是第一次打开这个页面的学生，我知道先干什么吗？页面顶部有没有一句话引导？这里我让AI加了一行"先看原理，再玩模拟，最后做题"。小细节，但对学生的使用体验影响很大。

> **【画面：切PPT第8页（成品页面全景截图）。】**

　　到这里，从教学设计到一个可以进课堂的教学网页，全程大约一小时。设计、需求文档、开发、修复、验收——没有一步需要写代码，但每一步都离不开教学判断。

　　这条路我自己还在走，每做一个新页面都会有新的问题要解决。但方向是确认了的：教师提需求、做验收，AI负责实现。

## 五、小结与作业三（38:30–40:00）

> **【画面：切PPT第9页（小结），再切第10页（作业三：结业核心作业）。】**

　　作业三是结业核心作业：自选课题，做一个包含原理讲解、交互演示、配套习题的教学网页。提交四样东西：HTML文件；关键提示词记录，特别是PRD那一轮；一分钟使用录屏；一小段话说明课堂和课后怎么用。鼓励大家把开发过程也守一守规范——做一块、Git提交一句，最后顺手截一张提交历史图，这正对应"人机协作过程"这一项的加分。

　　评价看五个维度：教学设计性、科学正确性、交互有效性、人机协作过程（含版本管理）、可用性。

　　选题方面，我的建议是选自己教学中最痛的那个点——哪个知识点讲了很多遍学生还是不懂，哪个实验条件不允许做但又特别想让学生看到。痛点越真实，做出来的东西越有用。

　　下一课时，发布上线，形成闭环。
