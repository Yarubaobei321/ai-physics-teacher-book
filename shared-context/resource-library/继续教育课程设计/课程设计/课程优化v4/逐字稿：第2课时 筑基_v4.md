### （四）认清界面：不是 IDE，是对话工作台 ADE（06:00–09:30）

> **【画面：切PPT第6页（ZCode 是 ADE：对话驱动的 Agent 工作台）。】**

　　这一段很重要，得帮大家把 ZCode 的界面看对。很多老师印象里的"编程软件"，是 **IDE**（集成开发环境）那种——左边文件树、中间一大块代码编辑器、右边一个聊天小窗，核心动作是"你坐在那敲代码"。**ZCode 不是这种**。

　　它的官方定位叫 **ADE——Agent 开发工作台**。结构更像 ChatGPT、Codex 那种"以对话为核心"的形态，只是多了项目文件和执行能力。我用一张图帮大家记，PPT 第6页：

> **【操作】鼠标依次指向界面区域，每处停顿2秒，配合PPT第6页示意图逐区讲解。】**

> **【画面：对照PPT第6页 ADE 布局示意图。注意：输入框在中间工作区底部，这是 ZCode 区别于传统 IDE 的关键特征。】**

　　**左边**是一条窄窄的**导航栏**，从上到下：新建任务、搜索、技能、仓库，最下面是设置和账号连接。点"技能"能看已装的技能，点"仓库"进版本管理。下面还有**任务视图**，按"分组/工作区/时间线"三种方式组织你做过的任务，还有**工作区文件树**——这两块是 ZCode 在导航栏里塞进的项目管理能力。简单说，左边是"入口列表"，不是 IDE 那种占一大块地方的文件树。

　　**中间最大的区域**，是整个软件的**核心**——**对话工作区**。这是你和 AI 交互的地方：上面显示你们的对话历史、AI 的每一步操作、生成的代码和文件；**最关键的是这个输入框，就在中间工作区的底部**。你以后所有的需求，都是从这个输入框发出去的。

　　**右侧**会按需弹出**面板**——比如 AI 生成的代码、内置预览、模型选择、执行模式控件。注意它是"按需弹出"的，不是固定占着右半屏，这让中间的对话区始终保持最大。

　　**底部**偶尔弹出的黑色窗口叫**终端**，是机器执行命令时的工作日志，现在不用管它。

　　一句话总结这个布局：**传统 IDE 的中心是代码编辑器，你得自己写；ZCode 的中心是对话工作区，你发需求、AI 干活、你验收。** 这是用 ZCode 最重要的一个认知转变，先记住它。

> **⚠ 以界面为准**：ZCode 版本更新较快，左右面板的具体入口和图标可能调整，但"中间对话工作区为核心、输入框在底部、右侧按需弹面板"这个 ADE 骨架是稳定的。

#### ① 输入框的符号系统（核心交互）

　　ZCode 的输入框有一套**符号系统**，是你高效交代任务的关键，四个符号：

> **【画面：切PPT第7页（输入框符号系统：@文件 /命令 $技能 #会话）。】**

| 符号                                                                        | 作用                    | 怎么用                                      |
| --------------------------------------------------------------------------- | ----------------------- | ------------------------------------------- |
| **`@` 文件**                                                        | 把项目里某个文件喂给 AI | 输入`@` 弹出文件列表，选文件，AI 就会读它 |
| **`#` 会话**                                                        | 引用之前的某段对话      | 输入`#` 选择历史消息，避免重复粘贴        |
| **`/` 命令**                                                        | 执行内置命令            | 输入`/` 看到斜杠命令菜单                  |
| **`$` 技能** | 直接调用某个技能 | 输入 `$` 选择已装技能，精准触发 |                         |                                             |

　　这四个符号不用全记，最常用的是 `@`——下一课时做驻波页，我会用 `@standing-wave.html` 把文件喂给 AI 让它改。`$` 调技能也很有用，想精准触发某个技能时用它。先有个印象。

#### ② 命令中心与推理强度（两个效率快捷键）

　　两个快捷键提一下：**`Ctrl+K`**（Mac 是 `Command+K`）打开**命令中心**，几乎所有操作都能从这里搜着执行，相当于"什么都找它"；它还能保存常用提示词，下次一键调出。**`Ctrl+T`**（Mac 也是 `Ctrl+T`）切换**推理强度**（官方叫 Thought Level），难一点的问题开"高推理"，简单任务关掉省 Token。零基础阶段知道有这两个就行。

## 三、第二层·学会说话：从生成到改好，一个完整闭环（15:30–31:00）

> 本层围绕**一个真实网页（单摆周期演示页）**展开，顺序就是真实工作流：**把需求说清楚 → 做出来 → 在内置浏览器看效果 → 定目标让 AI 自验 → 精确改 → 同题对比看工具差距 → 迭代三习惯**。每一步都接着上一步的产物，不再引用尚未生成的东西。

### （一）为什么提示词需要"方法"（15:30–17:00）

> **【画面：切PPT第13页（提示词四要素：让 AI 稳定出活的最小套路）。】**

　　可能有老师觉得，跟AI对话不就是打字聊天吗，有什么方法？我用了一段时间发现，同样一个需求，提示词写法不同，出来的东西质量差距非常大。

　　这里要先讲一个对新手很重要的认知——**你可能会发现，ZCode 里的 AI 不是你发一句话它就直接干活，它会先反问你**。比如你让它做个教学网页，它可能问你："面向哪个年级？要在什么设备上用？要不要带练习题？"

　　**这不是 AI 笨，恰恰相反——它在帮你把需求说清楚。** 它的每一个反问，背后都对应着一条必须明确的信息。我踩了不少坑之后，把这些信息总结成一条合格提示词的**四个要素**，你把这四样主动写清楚，AI 就不啰嗦了，出来的东西也准：

　　**第一，角色与背景**——告诉AI它是谁、我是谁、东西给谁用。比如"你是一名熟悉高中物理教学的前端工程师，我是高中物理教师，页面给高一学生在平板上用"。

　　**第二，任务目标**——做什么，越具体越好。

　　**第三，约束条件**——学段、设备、所有代码放一个文件、不依赖外网。这几条是教学场景的标配，值得记下来。**这条特别重要**：稍后我们会用一道"漏沙"题做对比，到时候你会看到，约束给得不到位，AI 就会按自己的想象乱发挥——比如把"运动的罐子"画成在地上滚的。

　　**第四，输出形式**——结尾加一句"请先用列表复述你理解的需求，待我确认后再输出代码"。这最后一句，我的经验是一定要加，它能避免大量返工。

### （五）为什么用 ZCode：一道物理题见分晓（24:00–27:30）

　　这题是高中物理一道经典题——**运动的罐子漏沙**。一个罐子**悬空**在水平方向移动（可匀速、可匀加速），底部小孔不断漏出沙粒，沙粒离开后只受重力。问：任一时刻，**空中的沙粒排成什么形状？** 正确答案是：**罐子匀速时排成一条竖直线，匀加速时排成一条斜直线**——因为沙粒离开瞬间的水平速度被保留，匀速时所有沙粒水平速度相等所以对齐成竖线；匀加速时罐子越走越快、越晚离开的沙粒水平飞得越远，但每一颗都做一样的平抛，所以在任一时刻它们排成一条斜直线（斜率与加速度、重力有关）。⚠ 注意区分：**单颗沙子的运动轨迹**才是抛物线，而"某一时刻空中所有沙粒排成的形状"是斜直线——这是高考最常见的易错点，稍后你会看到，能不能把这个区别做对，正好拉开 AI 的差距。

　　这题考的是**运动学建模**，区分度很高。咱们用同一句话让三家去做：

## 四、第三层·工程化协作（31:00–39:00）

### （一）进阶主线：提示词 → 工装 → 循环 → 钩子（31:00–32:00）

> **【画面：切PPT第20页（进阶主线：提示词→工装→循环→钩子）。】**

　　最后一层，给大家一张"地图"，看完就知道自己在哪、往哪走。

　　这两年AI编程圈形成了一条很清晰的能力进阶线，四级：**提示词、工装、循环、钩子**。第一级提示词，就是把需求说清楚，咱们刚练的就是它。但只靠提示词有个问题——说一次做一次，换个课题又要从头说。于是有了第二级，工装。

### （二）工装：脚手架五件套（32:00–34:00）

> **【画面：切PPT第21页（harness：给AI搭工装·五件套）。】**

　　第二级叫harness engineering，直译"驾驭工程"。意思是：和AI协作的质量，不取决于某一条提示词多精巧，而取决于你给AI搭的整套工作环境——规则、技能、模板、验收、版本管理，五件套。我已经做成一个现成文件夹，随课下发（**学员请先从课程资料下载并解压"教学网页脚手架"文件夹到电脑上**）。

> **【操作】在ZCode中"打开文件夹"，选中已解压的"教学网页脚手架"。⚠ 具体菜单路径以界面为准（命令中心 Ctrl+K 搜"打开文件夹"，或欢迎页"打开文件夹"按钮）。**

> **【操作】文件树展示：AGENTS.md、PRD模板、验收清单、index.html、skills文件夹、参考文件夹。】**

　　**规则文件AGENTS.md**，就像给班级立班规：学校名称、配色、三段式结构、平板适配，一次写进去，ZCode打开项目自动读，以后每次对话AI都遵守，不用重复交代。**需求模板PRD**把验收提前到开工前；**验收清单**做完逐条三查；**版本管理**待会单说。这几件先记个印象，下一课时实战会反复用到。

### （三）技能 Skill：从提示词到"标准作业流程"的跳级（34:00–36:30）

> **【画面：切PPT第22页（提示词 vs 技能 + 宝玉《图解 Skill》）。】**

　　五件套里，我要单拎出"技能"重点讲，因为它是一次真正的升级。这一段请大家务必收藏——我会给你一个**特别适合新手的学习资源**。

　　打个比方。**提示词，像你临时口头交代一个代课老师怎么上这节课**——说得再细，也是一次性的，他下次来还得重新交代，讲得好不好全看你这次说得清不清楚。**技能呢，是你把"这类课怎么上才算上好"写成一份标准教案，谁拿到都照着同一套高标准来。**这就是从"碰运气"到"工程化"的分水岭：**提示词决定这一次，技能决定每一次。**

> **【画面：PPT第22页下半部分（技能是什么·三点核心 + 宝玉资源）。】**

　　技能到底是什么，我只讲三点最关键的：

　　**第一，它是一个模块化的能力包**——说白了是个文件夹，里面一份说明书（SKILL.md），外加可选的脚本、参考、模板；一个技能只做一件事，AI需要时自动加载。

　　**第二，装多了也不拖慢。** 它有个聪明设计叫"渐进式披露"：平时只加载每个技能的"名字+用途"，就百来字的量；真匹配到任务，才加载完整说明；用到脚本或参考，才去读。所以哪怕你备了几十个技能，平时也几乎不占地方。

　　**第三，也是最关键的一句**——做技能，你不必会写代码。技能值钱的地方是它"封装了什么"：你备课、出题、做页面的那套固定套路，这是你的专业积累；至于把它写成SKILL.md这件格式活，交给AI就行，你说一句"帮我建一个技能，用来做……"，它就生成了。记住八个字：**知识来源于你，格式交给AI。**

#### ★ 推荐学习资源：宝玉《图解 Skill —— AI 提效实战指南》

> **【画面：PPT第22页右下/底部，展示书名 + GitHub 二维码/链接 + 微信读书入口。】**

　　说到技能，我必须推荐一本**专门讲这个、而且特别适合新手**的书——宝玉写的《图解 Skill —— AI 提效实战指南》。这本书用大量图解，把"什么是技能、怎么写技能、怎么用它和 AI 协作"讲得明明白白，是我见过对老师最友好的入门材料。

　　两个获取方式，PPT 上都有：**第一，微信读书已经上架**，搜书名就能看；**第二，配套代码和示例在 GitHub 上完全开源**，地址是 `github.com/JimLiu/baoyu-skills`（这个仓库在 GitHub 上有两万多人收藏，是中文圈最火的技能集合之一）。你甚至可以直接在 ZCode 里用一句命令 `/plugin marketplace add JimLiu/baoyu-skills` 把它整套装进来用。

　　为什么要重点讲技能这个概念？因为**所谓技能，本质就是"固化的工作流"——它是一种人和 AI Agent 协作的组织方式**。这种组织方式是**通用的**：不管模型怎么升级、怎么换代，你沉淀下来的技能、你跟 AI 协作的那套套路，都还能用。换句话说，**学技能，学的是一种不会被模型迭代淘汰的能力**。对咱们老师来说，这是最值得花时间投入的事。

### （四）有技能 vs 没技能：肉眼可见的差距（36:30–37:30）

> **【画面：切PPT第23页（漏沙问题·无技能 vs 有技能对比，左右并排两版成品截图）。】**

　　还记得前面那道漏沙题吗？我们已经攒了两版结果：**ZCode 不挂任何技能**做出来的，和**挂上 `frontend-design` 技能**之后做出来的。现在并排看一眼——左边是清爽但朴素的教学版，右边是带模块化分栏、实时数据面板、深蓝科技网格背景的专业版。**同一个 GLM-5.2 模型、同一句话、同一道题，物理都对，但右边的版式、配色、质感明显上了一档，更像能直接拿出去的成品。**

> **【画面：PPT第23页停留。左：无技能版（compare-zcode-noskill.png） 右：挂 frontend-design 版（compare-zcode-withskill.png）。】**
>
> **台词**："一句话没变，模型没变，变的是它背后遵循的'标准'。**提示词决定这一次，技能决定每一次。**"

> **⚠ 说明**：`frontend-design` 这个前端技能**已经随咱们下发的"教学网页脚手架"自带了**（在 `skills/frontend-design/` 目录里），打开脚手架就能用，不必另装。它是开源社区技能（Apache 2.0 许可），不是 Anthropic 官方。

　　咱们脚手架里那个《物理交互模拟》技能也是同一个道理——是我把"数智育才"网站那些动量模拟实验的成功套路提炼成的标准流程。下一课时你会看到，挂上它，AI做出来的模拟页，专业度完全不一样。

　　**所以我给大家的建议是：MCP（Model Context Protocol，模型上下文协议——简单说就是给 AI 接外部工具的接口，比如模拟器、数据库）一个不用装，但技能值得用心攒。**先用下发的这几个和宝玉开源的那套，以后把你自己反复做的活儿，一个一个沉淀成技能。

### （五）循环与钩子（37:30–38:00）

> **【画面：切PPT第24页（循环loop与钩子hooks + 三Agent循环案例）。】**

　　地图的后两级，我带大家认认门，零基础阶段了解即可，不要求现在上手。

　　**第三级，循环（loop）。**现代AI开发不是"一次生成完事"，而是"计划→修改→验证→修复"转圈跑。其实你们已经在用了——先复述需求、小步改、用截图报错喂回去修、三查验收，这就是一个循环。再往前一步，是让AI自己把这个圈跑起来、自动推进，你只负责设计这个圈。记住一句话：**你设计循环，AI自动跑。**

> **【画面：PPT第24页下半部分，三Agent循环示意图。停留让学员看清。】**

　　这个"循环"不是我杜撰的词，我给大家讲一个真实的例子。2026年6月，开发Claude的Anthropic公司工程师公开演示了怎么用AI从零做一个完整App——他们用了**三个角色循环**：一个"规划者"把模糊想法翻译成规格书，一个"构建者"写代码，一个"评判者"像真人一样打开浏览器点界面、测功能、打分，不通过就退回让构建者改，循环直到真正能用。

　　结果很有意思：同样的模型，一个agent自己跑20分钟，做出来的是半成品；三个角色循环跑6小时，做出来的是能玩、能测的完整成品。所以那场演示有句话被反复引用——"赢家不会拥有最聪明的模型，会拥有最好的循环。"

　　这正是我们这条"提示词→工装→循环→钩子"主线的方向：不是某一句提示词多聪明，而是你给AI搭的整套工作环境让智能体稳定地转起来。咱们今天学的"先复述需求、小步迭代、给证据修复、三查验收"，就是这个循环的最简版本。讲到这里，大家应该能感觉到，我们走的路，和顶尖工程师是同一个方向。

　　**第四级，钩子（hooks）。**它像生产线上的自动质检员——在"保存""提交"这些节点，自动触发检查，把规范变成自动执行，不靠你记。

> **【操作】演示一个最简单的现成钩子效果：保存文件即自动在内置浏览器刷新预览（或：提交前自动弹出"过一遍验收清单"的提醒）。只演示效果，不展开配置。】**

　　比如这个——我一保存，预览自动刷新；再比如，设一个"提交前自动提醒我过验收清单"的钩子。好处是：规范不再靠自觉，工具帮你守住。配置怎么写，零基础阶段不碰，知道有这么个东西、将来用得上，就够了。

### （六）版本管理：开发规范的安全网（38:00–39:00）

> **【画面：切PPT第25页（git：开发规范的安全网）。】**

> **【操作】用ZCode可视化Git一键提交保存当前版本（含刚才改好的单摆页）。⚠ 具体按钮位置以界面为准（左侧"仓库/源代码管理"区）。**

> **【操作】然后故意让AI"改坏"（发一句"把配色全换成暗色风格"），预览出问题。**

> **【操作】用Git一键回退，恢复如初。】**

　　最后说五件套里的版本管理，也就是git。很多老师担心"让AI一改，把原来好的也改坏了怎么办"——这正是它要解决的。我每到一个满意阶段就一键提交，相当于给教案打备份。现在我故意让它改坏——页面乱了。不慌，一键回退，恢复如初。

　　这里我先埋个伏笔：下一课时实战，我会专门演一遍"不守规范"和"守规范"的差别，让大家亲眼看到不小步提交会有多被动。现在你只要记住：**有这个安全网，就敢放手让AI去试。**

　　提示词、工装、循环、钩子——这张地图你不必一步到位。把下发的脚手架用起来、把技能攒起来、养成提交回退的习惯，你就已经站在了大多数人前面。

## 五、小结与作业二（39:00–40:00）

> **【画面：切PPT第26页（本课时小结），再切第27页（作业二）。】**

　　回顾一下这节课。**第一层，拿到工具**：装好了ZCode，认清了它的 **ADE 对话工作台布局**（中间对话工作区为核心、输入框在底部、符号系统 `@#/$`）、辅助工具（终端、可视化Git、仓库Wiki、状态看板、三种任务视图、编辑历史、命令中心）。**第二层，学会说话**：围绕单摆页走通了一个完整闭环——四要素把需求说清 → 内置浏览器点开看 → 目标模式自验 → 精确点击改 → 迭代三习惯；并用一道漏沙题看清了不同工具和技能的差距。**第三层，工程化协作**：最重要的一张地图是提示词→工装→循环→钩子，其中技能是关键升级——**提示词决定这一次，技能决定每一次。** 学技能这件事，推荐从宝玉的《图解 Skill》起步。

　　作业二：装好ZCode、配置GLM-5.2，用四要素写一条提示词，让AI生成刚才演示的"单摆周期"网页——也可以换成自己学科的小主题；再体验一次版本管理——做好后用Git提交一次，故意改坏、一键回退，感受一下"有规范"的踏实。

　　提交四样：①完整提示词文本；②网页运行截图；③一句话说明你选用的工具与模型；④一句话写下版本管理（回退）带给你的感受。评价看点：四要素是否齐全、有没有让AI先复述需求、有没有完成一次提交与回退。

　　下一课时动真格——完整做一个《波的叠加与驻波》教学网页，从需求文档到最终验收，全程实战，咱们就用今天这套脚手架。
