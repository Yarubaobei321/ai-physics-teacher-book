## 一、开场：为什么选这个课题（00:00–02:00）

> **【画面：PPT第1页（封面），切第2页（驻波痛点），切第3页（开发五步法）。】**

　　上一课时我们装好了 ZCode、学会了提示词方法、认识了内置浏览器和技能。这一课时，动真格——我们从零开始，完整做一个《波的叠加与驻波》教学网页，从需求文档一路做到上线验收。

　　为什么选这个课题？四个原因：第一，实物实验看不清——驻波是两列波叠加，真在水槽、绳子上演示，学生根本分不清哪是分波、哪是合成波；第二，静态图讲不动——课本上的驻波图是死的，学生看不出"波节处为什么位移始终为零"；第三，学生误区集中——"波节处没有波经过""驻波图样会向前跑"，这些错念反复出现；第四，它能扩展——驻波是一维干涉，做好了自然能延伸到二维水波双源干涉。

　　这节课的开发五步法，记一下：**设计 → PRD → 开发 → 修复 → 验收**。其中"修复"段我会真实保留 AI 出错的过程，不剪——因为这是大家自己用的时候一定会遇到的。**带上你的电脑，咱们边看边做。**

## 二、第1节 教学设计先行 + PRD（02:00–10:00）

### （一）先做"难点↔功能"对照表（02:00–05:00）

> **【画面：切PPT第4页（难点↔功能对照表）。】**

　　动手写代码之前，先做一件事——理清"这个页面到底要解决什么教学问题"。我习惯先列一张"难点↔功能"对照表：

| 学生的难点 | 对应功能 |
|---|---|
| 分不清分波和合成波 | 两列分波、合成波分别可显示/隐藏 |
| 不懂波节处为什么位移为零 | 逐帧前进，取波节那一帧看两分波相加 |
| 把驻波图样当成在跑 | 暂停对比相邻时刻 |
| 读不懂驻波图 | 配读图练习题 |

　　**动手之前先理清楚这个页面要解决什么教学问题，比急着让 AI 写代码重要得多。** 这是教师做资源的真正优势——你比任何 AI 都懂学生的卡点在哪。

### （二）先要 PRD，再要代码（05:00–10:00）

> **【画面：切PPT第5页（先要PRD·把验收前置）。】**

　　理清难点后，我不直接让 AI 写代码，而是先要一份**需求文档（PRD）**。为什么？因为把"验收标准"前置到开工前，能避免大量返工。这是我踩了很多坑之后学到的。

> **【操作】在 ZCode 打开"教学网页脚手架"项目（⚠ 学员请先从课程资料下载并解压脚手架文件夹；打开方法：命令中心 Ctrl+K 搜"打开文件夹"，或欢迎页"打开文件夹"按钮）。脚手架里的 AGENTS.md 已写好配色、单文件、不依赖外网、平板适配等约定，ZCode 打开项目会自动遵守——所以下面这条提示词里**就不重复交代这些了**。在中间工作区底部输入框粘贴下面这条提示词，回车。】**

#### ▶ 提示词①：需求文档（PRD）

```
我是高中物理教师，准备开发《波的叠加与驻波》教学网页，面向高二学生，
在平板浏览器上使用。请先不要写代码，以产品经理身份输出一份需求文档，
内容包括：

1. 页面结构（原理讲解区、交互模拟区、读图练习区、配套习题区）；
2. 交互模拟的可调参数与显示要素：两列相向传播的等幅同频波，
   两列分波与合成波可分别显示或隐藏，支持暂停与逐帧播放，
   波节与波腹位置自动标注，频率与振幅滑块可调；
3. 读图练习区：给出一幅驻波图样，让学生读出波长和相邻波节间距；
4. 习题类型与数量：4–6道分层习题，必须包含针对"波节处没有波通过"
   这一误区的辨析题；
5. 平板适配要点。

请用表格呈现需求文档，等我确认后再进入开发。
```

> **【操作】等待 AI 输出 PRD 表格（可快进）。滚动展示，鼠标停在"显示要素"那一行。现场口头补充一点，然后回复确认。】**

#### ◆ 回复 AI（确认 + 补充）

> **确认需求，补充一点：合成波用粗实线，两列分波用不同颜色的细虚线。请开始开发，先输出页面骨架和原理讲解区。**

> **◆ 预期**：AI 输出含页面结构、参数、习题规划的表格 → 你确认后它才开始写代码。台词："看，它先给方案、我们点头它才动手。这就叫把验收前置。"

## 三、第2节 开发实录（10:00–33:00）

> **【画面：切PPT第6页（开发实录·四个阶段总览）。】**

　　这一节是全程实录，分四段：页面骨架、交互模拟（含报错修复）、习题区、开发规范的反正对比。**报错那段我会真实保留，不剪。**

### （一）页面骨架与原理区（10:00–13:00）

> **【操作】AI 生成 HTML 骨架（可快进）。保存为 standing-wave.html。右侧预览窗口自动刷新。滚动展示骨架与原理讲解区。】**

> **【操作】发现两个问题：原理区公式的下标（如 v₁、v₂）没显示成下标格式；段落间距太小，平板上阅读吃力。截图圈出这两个问题。】**

　　第一版出来了。但有两个小问题——公式的下标没效果、段落挤在一起。这种情况**千万别**直接说"重做"，我们按"给证据"的方法来。

> **【操作】在输入框粘贴下面这条提示词（连同截图一起发给 AI），回车。预览自动刷新，对比修改前后。】**

#### ▶ 提示词②：排版修正（配截图）

```
见截图。两个问题：
1. 原理区公式中的下标（如波长λ、周期T的下标形式v₁、v₂）
   没有正确显示为下标格式，请用HTML的sub标签处理；
2. 原理区段落间距太小，平板上阅读吃力，
   请将段落行距调整为1.8倍，段间增加适当留白。
其他部分不要改动。
```

> **【操作】改好后，用 ZCode 可视化 Git 一键提交保存版本（左侧"仓库/源代码管理"区，⚠ 按钮以界面为准）。让 AI 自动写提交说明。】**

> **◆ 台词**："改好了。每到一个满意阶段就提交一次，相当于给教案打备份——这就是第二课时讲的版本管理。"

### （二）交互模拟区开发（含真实报错 + 给证据找根因）（13:00–21:00）

> **【画面：切PPT第7页（交互模拟区·要求）。】**

> **【操作】在输入框粘贴下面这条提示词，回车。AI 生成（可快进），预览刷新。】**

#### ▶ 提示词③：交互模拟区

```
现在开发交互模拟区。要求：

1. 用canvas绘制：上方并排显示两列相向传播的等幅同频简谐波
  （红色细虚线向右传播、蓝色细虚线向左传播），
   下方显示它们的合成波（深色粗实线）；
2. 提供"显示/隐藏分波""显示/隐藏合成波"开关；
3. 提供"播放/暂停"按钮和"逐帧前进"按钮，逐帧步长为周期的1/16；
4. 合成波上自动标注波节（▽符号）和波腹（△符号）位置，
   随参数变化自动更新；
5. 频率与振幅滑块可调，调节时波形实时更新；
6. 按钮和滑块尺寸适合平板触屏操作。

请基于现有文件继续开发，不要改动原理区。
```

> **【操作】演示时，点"逐帧前进"——预期会出现真实问题：合成波曲线与两列分波的位置对不上（物理上不可能）。放大这个问题的画面。】**

> **⚠ 以实际为准**：现场若 AI 没出错，请用预录的真实报错素材，画面角注"真实案例回放"，**切勿摆拍假错误**。

> **【画面：切PPT第8页（报错了！给证据，找根因）。这是本课时高光页之一。】**

　　报错了——这种时候最容易犯的错，是直接说"不对，重做"。但这样 AI 只会换个写法再试一次，治标不治本。这里有一个特别管用的措辞——在提示词里加一句"**从第一性原理出发**"。就这七个字，能逼 AI 回到根本重新推导，而不是东修西补。

> **【操作】按 F12 打开浏览器开发者工具 → 控制台（Console）→ 复制红色报错原文（**⚠ 注意：本例的"逐帧模式时间变量不同步"通常是纯视觉错位，控制台很可能没有红色报错。若有报错，复制原文；若无报错，把提示词里那句改成"浏览器控制台无报错，但视觉上合成波与分波位置对不上"**）。截图问题画面。在输入框粘贴下面这条提示词（连同截图和报错原文/或无报错说明），回车。】**

#### ▶ 提示词④：报错反馈（配截图 + 控制台报错原文 + 给证据找根因）

```
切换到"逐帧前进"后，合成波曲线与两列分波的位置对不上（见截图）。
浏览器控制台报错如下：（粘贴报错原文）。

请从第一性原理出发，定位这个问题的根本原因——不要只修补表面现象，
要找到两套渲染逻辑（连续播放 vs 逐帧）在时间变量上不一致的根源。
给出修改后的完整代码段，并用通俗语言解释这个错误的成因，
让我以后能自己排查类似问题。
```

> **【操作】AI 返回修复代码 + 通俗解释（可快进应用）。把"错误成因"那一段放大展示 3 秒。预览刷新，逐帧演示恢复正常。】**

> **◆ 预期**：AI 定位到"逐帧模式下时间变量没有同步累加，导致分波和合成波用了不同的时间基准"，给出修复 + 解释。
>
> **◆ 台词**："修好了。注意我加了一句'从第一性原理出发'——它没有去试别的写法，而是回到时间变量这个根本，一次就挖到了根。**治本，不治表**——这就是给证据、找根因的力量。还有，我让它解释了原因——下次再遇到类似现象，自己就能判断个八九不离十。"
>
> **◆ 若一次没修好**："一次没修好也正常。把新的现象再喂给它，证据给得越具体，修得越快。"

### （三）物理验证（21:00–23:00）

> **【操作】暂停在某一帧 → 鼠标指波节位置 → 口算核对：这一帧红分波在波峰、蓝分波在波谷，相加为零，所以合成波在波节处位移为零。】**

> **【操作】顺手用 Git 提交一次（呼应"每修好一处提交一次"）。】**

### （四）习题区生成与教师把关（23:00–28:00）

> **【画面：切PPT第10页（习题区·AI出题快但科学性要教师把关）。】**

> **【操作】在输入框粘贴下面这条提示词，回车。AI 生成（可快进），预览里逐题滚动展示。】**

#### ▶ 提示词⑤：配套习题区

```
最后开发配套习题区。要求：

1. 共5道题，按"基础–中等–挑战"分层标注：
   2道单选、1道多选、1道读图填空
  （由驻波图读出波长与相邻波节间距）、1道辨析题；
2. 辨析题必须针对"波节处质点不振动，是因为没有波传到那里"
   这一错误说法，要求学生判断并说明理由；
3. 每题提供"提交"即时判对错、"查看详解"折叠展开、"重做"功能；
4. 答案和详解由你生成，但请在详解中明确写出物理依据。

请基于现有文件继续开发，不要改动已完成的区域。
```

> **【操作】在预览中现场逐题审题——重点停在辨析题和读图题。】**

> **◆ 验收锚点（必须念准）**：
> - 辨析题：波节处**两列波始终存在**，只是位移叠加恒为零，"没有波经过"是错的。
> - 读图题：图上波长 4 米 → 相邻波节间距应为 2 米。
>
> **◆ 台词**："AI 出题又快又像样，但科学性它不负责。负责的人是我们——这就是角色转变里的'做验收'。"

> **【操作】若发现科学性问题，现场让 AI 修正，保留真实过程；若全对，口头确认每题答案。】**

### （五）开发规范·反正对比（28:00–33:00）

> **【画面：切PPT第11页（反面：不守规范的崩溃现场）+ 第12页（正面：守规范的安全网）。】**

　　这一段是本课时最有"教训感"的，我用正反两个对比告诉大家——**同样用 AI，守不守开发规范，结果天差地别**。

#### 反面：不守规范

> **【操作】演示反面（可用预录素材）：连续大改、一次都不提交 → 发一句"把配色全换成暗色风格" → 展示暗色上了，但波节标注没了、习题折叠坏了 → 演示"退不回去、说不清改了啥"。】**

> **◆ 台词**："改坏了找不回、版本一团乱、说不清动过什么——这是新手最常见的崩溃现场。"

#### 正面：守规范

> **【操作】用 ZCode 可视化 Git 展示提交历史 → 演示小步提交（每步一句话："完成交互模拟""加好分层习题"）→ 演示一键回退，恢复如初。】**

> **◆ 台词**："同样用 AI，守不守规范，决定你是越做越稳，还是越做越慌。git 不难，对我们就两个动作：满意了就提交、写句话；改坏了就回退。**每修一个错，经验就厚一层。**"

> **🎬 录制提醒**：两种状态要让学员有直观冲击，正面演示时强调"安全网"的感觉。

## 四、第3节 质量验收（含对抗性审查）（33:00–38:30）

> **【画面：切PPT第13页（验收三查）。】**

　　网页做完了，但别急着上线。我们用脚手架里的"验收清单"逐条过——科学性、交互与适配、学生视角，三查。

### （一）验收三查

> **【操作】按验收清单逐条演示。】**

　　**一查科学性**：波长调到 4 米 → 看标注的相邻波节间距是不是 2 米（✓）；波腹处振幅是不是单列波的 2 倍（✓）。

　　**二查交互与适配**：打开浏览器开发者工具，切到**平板模拟视图**（或用真机）→ 触屏操作滑块和按钮 → 横竖屏都试 → 再换个浏览器开一次，看兼容性。

　　**三查学生视角**：页面顶部有没有一句引导语？比如"先看原理，再玩模拟，最后做题"。如果没有，让 AI 加一行。

> **【操作】切成品页的全景截图，停留。】**

### （二）上线前最后一道：对抗性审查（高光）

> **【画面：切PPT第14页（对抗性审查·上线前的最后一道验收）。】**

　　三查通过后，还有最后一道——**对抗性审查**。做法是：让 AI 站在"我要搞垮你的页面"的角度，专找你自己想不到的边界漏洞。这是上线前最值得做的一件事。

> **【操作】在输入框粘贴下面这条提示词，回车。等 AI 返回风险清单，挑 2-3 条现场修复。】**

#### ▶ 对抗性审查 Prompt（上线前最后一道）

