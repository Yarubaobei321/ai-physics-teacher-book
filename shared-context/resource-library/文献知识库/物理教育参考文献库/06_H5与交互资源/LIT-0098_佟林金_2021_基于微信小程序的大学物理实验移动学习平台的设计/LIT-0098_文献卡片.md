# 基于微信小程序的大学物理实验移动学习平台的设计

> 作者：佟林金、陈曲扬、陈雅薇、王晓萌（中国石油大学（华东）理学院）
> 核验状态：**已核验**（以 YAML 题录字段和“引用信息”为准；核验来源与日期见 `metadata_source`、`verified_at`）。

## 一句话贡献

设计学生端与教师后台相连的微信小程序，把实验微视频、自测、学情统计、仪器故障反馈和成果展示整合为移动学习平台。

## 研究方法

- 平台设计 + 开发实现：提出总体框架（学生端+教师后台），分三功能模块设计，再给小程序技术路线（前端iview组件+HTML/CSS/JS，后台云开发）。
- 含数据库设计（video/user_comment/test/question/ppt_info五表）与核心功能代码实现说明，并在实际教学初步应用。

## 可借鉴点（对我有用）

1. "师生共建型"平台理念与三模块划分（教学资源/实验教学管理/成果展示），可为本人数智育才网站功能架构提供参照。
2. "课前预习传递→课上内化→课后巩固扩展"的线上线下闭环思路，与本人"课堂到课后闭环"主张高度契合，可作同理念佐证。
3. 微视频"扫码即看、10分钟内、聚焦仪器规范使用与操作演示"的设计，与本人"扫码即学"要素可对话。

- 数智育才网站 · 机械能守恒在线实验室（移动学习平台架构 + 课堂课后闭环要素相关）

## 精读笔记

- 背景：教育信息化2.0，移动智慧终端学习受青睐；小程序无须安装、即用即走、交互性好，避免同类APP束缚。
- 大学物理实验现状问题：学生多专业杂学时少；预习停留在原理、对仪器操作缺乏理解；课后复习无条件；PC端资源多、移动端匮乏。
- 三模块：①教学资源（实验项目分布/教学微视频/实验讲义/习题测试，单选多选判断）②实验教学管理（学情统计分析+仪器问题反馈）③成果展示（学生论文/大赛作品/创新训练作品）。
- 技术路线：前端iview组件库+HTML/CSS/JS，后台小程序云开发；每页四文件（js/json/wxml/wxss）；视频功能含播放记录/点赞/收藏/转发/评论。
- 五张数据表：video、user_comment、test、question、ppt_info，tid为主键。
- 结语：加大数字化资源建设、提升兴趣效果，待完善题库与私信功能。

## 研究问题

面对实验课学生多、学时少、预习和复习受仪器场地限制的问题，微信小程序如何支持课前、课中、课后并形成师生共建平台。

## 研究方法与样本

先对部分已修课学生做需求调研，再以小程序前端、云开发数据库和教师后台实现教学、实验管理、成果展示三模块；文章只称在教学中初步应用，未报样本数。

## 核心证据与结论

系统提供几十个10分钟以内实验视频、选择判断自测、观看点赞评论记录、设备故障反馈和五张数据表；功能页面与核心代码路径可见，但未给使用量或学习成效统计。

## 局限

需求调研人数和问卷结果未报告，初步应用缺少日志、故障率、成绩、满意度与对照；观看量和点赞只被设计为指标，未证明能有效表征学习。

## 对应我的项目与论文

服务C1和数智育才网站，可作为移动端资源门户、二维码入场、练习自测和教师管理的系统对标案例。

## 精读摘要

文章针对大学物理实验学生多、专业杂、学时少，以及预习复习受场地和仪器限制的问题，开发微信小程序移动平台。系统分学生端和教师后台，包含教学资源、实验管理与成果展示三模块：几十个10分钟以内的仪器与操作微视频，单选、多选和判断自测，观看、点赞、收藏、评论记录，学情统计，仪器故障反馈，以及学生竞赛和创新成果展示。前端采用小程序组件、HTML/CSS/JavaScript，后台使用云开发和五张数据表。文章声称进行了初步应用，但没有给需求调研人数、平台用户量、测试成绩、故障率或对照数据，点击和点赞也只是预设指标。因此它可作为移动实验平台功能架构和数据结构案例，不能据此判断平台已提高兴趣和教学效果，证据仍属开发案例。
