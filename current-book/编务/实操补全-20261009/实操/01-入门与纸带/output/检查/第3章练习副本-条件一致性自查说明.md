# 第 3 章练习副本 · 条件一致性自查说明

**对象**：`input/含条件不一致的练习副本.html`（**只读**，未修改；文件 mtime 2026-10-09 22:38）
**性质**：本副本是人为设置的教学练习，其"条件不一致"是**设定**，不是原页面自然发生的错误；我按练习对待，不作缺陷修复。

---

## 一、静态推断（只读源码得到的判断）

- **顶部条件**：原纸带相邻计数点之间**还有 4 个计时点**；电源 50 Hz。
- **副本预填输入**：f = 50，**n = 4**，位置 0 / 3.75 / 9.00 / 15.75 / 24.00 / 33.75 / 45.00（cm）。
- **推断**：两个相邻计数点之间还有 4 个计时点 ⇒ 这一段被分成 **5 个打点周期** ⇒ 应取 **n = 5**，T = 5 ÷ 50 = **0.100 s**。而输入写的是 n = 4（对应 T = 0.080 s）。
  → **不一致点落在 n 上**；f 与条件一致；位置读数本身不违背条件。
- **口径说明（重要）**：若把条件读成"相邻计数点的间隔是 4 个打点周期"，那 n = 4 才是对的，不一致就落在**条件表述**上。按副本原句"还有 4 个计时点"的字面读法，n 应取 5。建议练习里把口径钉死（"还有 4 个计时点"与"间隔为 4 个打点周期"二选一），否则学生会有两解。
- **附带发现（与本题无关）**：副本快照早于我后续的三处修订——T 行显示用编辑原值、刻度标签小数位、打印记录表。属于"拿了旧版本做副本"，不影响本次条件不一致的判定。

## 二、程序计算（用我自己的计算核心独立算，不依赖副本的代码）

同一组位置，只改 n：

| 输入 | T /s | 五个时刻 /s | 五点速度 /(m·s⁻¹) | 拟合 k /(m·s⁻²) | 拟合 b /(m·s⁻¹) | 逐差法 a /(m·s⁻²) |
|---|---|---|---|---|---|---|
| n = 5（条件应有的取值） | 0.100 | 0.10 / 0.20 / 0.30 / 0.40 / 0.50 | 0.4500 / 0.6000 / 0.7500 / 0.9000 / 1.0500 | 1.5000 | 0.3000 | 1.5000 |
| n = 4（副本实际输入） | 0.080 | 0.08 / 0.16 / 0.24 / 0.32 / 0.40 | 0.5625 / 0.7500 / 0.9375 / 1.1250 / 1.3125 | 2.3437 | 0.3750 | 2.3437 |

**影响**：速度全部 **×1.25（+25%）**；加速度全部 **×1.5625（+56.25%）**；时刻全部 **×0.8（−20%）**。
值得注意：**数值错了，图像却照样"漂亮"**——v-t 仍是一条直线，各段位移之差仍相等。所以光看图看不出错，必须回到原始条件核对 T。这正是这个练习最该抓的点。

## 三、浏览器运行（把副本原样打开、点击「计算」）

页面实际显示：`T = n / f = 4 / 50.000000 = 0.080 s`；斜率 k = **2.344 m/s²**；截距 b = **0.375 m/s**；逐差法 a = **2.344 m/s²**；v-t 图正常生成；无 JS 报错。

与第二节的独立计算**逐项吻合**（2.3437 显示为 2.344），说明差异**只来自 n 这一个输入**，副本的算法本身没有问题。另外，页面不会（也不应该）替学生判断纸带条件——它只认 f、n、位置，"条件与输入是否一致"只能由人核对，这正是练习的考查点。

## 四、结论

**就一处不一致**：n 应为 5，副本写成 4。不改这一处，加速度会从 1.50 m/s² 记成 2.34 m/s²（偏高 56.25%），五个速度全部偏高 25%，时刻全部偏小 20%。
