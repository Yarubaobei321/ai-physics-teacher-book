## 二、第12章 真实数值（有限模型）

几何：内腔 294×294 mm，原点槽中心；上下水平钢条长 250、俯视厚 3、高 10 mm，中心线 **y = ±90 mm**；水深 5 mm 均匀；正端上板 φ=U、负端下板 φ=0；四壁绝缘 ∂φ/∂n=0。**二维拉普拉斯数值求解**，非理想平行板直线填充。

| 项 | 值 |

| 主网格 | 0.5 mm，n = 589 × 589 |
| 迭代 / 松弛因子 ω | 1900 次 / 1.989389 |
| 缺陷 max\|h²∇²φ\| | **9.06 × 10⁻⁹** V（U=1 归一） |
| 中心 φ/U | **0.4999997**（h=1 mm 时 0.4999999） |
| 上下反射 φ(x,y)+φ(x,−y) | 最大偏差 **8.8 × 10⁻⁷** |
| 左右对称 φ(−x,y)−φ(x,y) | 最大差 **5.8 × 10⁻¹⁵**（机器精度） |

细化时迭代数单调增加（400→1900），说明几何确实被表示、真在求解。

**被拒绝的网格**：h = 7.35 mm 与 h = 3.675 mm —— 两端的固定节点数都是 **0**。原因：节点落在 h 的整数倍上，`|y∓90| ≤ 1.5 mm` 内没有任何节点，**3 mm 钢条被整个漏掉**；此时 `fixed` 为空，初值全零恰好"满足"拉普拉斯方程，于是**迭代 1 次、缺陷 0、φ≡0**——看着像收敛，其实是空解，**不能当作收敛检验**。现在 `solve(..., require_electrodes=True)`（默认开）对这种网格直接抛错。

**两种模型对照（x=0）**：y=57 mm 处数值解 **0.8218**，理想无限大平行板 (57+90)/180 = **0.8167**；两者接近说明中央区近似匀强，但板端与板外显著偏离。

**A 布局（仅拓展，二维轴对称简化）**：r = R·(a/R)^(φ/U)，a=3 mm（底帽半径）、R=124 mm
→ 3U/4 : **7.607 mm**　U/2 : **19.287 mm**　U/4 : **48.904 mm**（与任务给定 7.606/19.287/48.904 一致）。
声明：原实物柱杆半径 1.5 mm、底帽高 1.1 mm，**不能说整个水深截面都是半径 3 mm**。

## 八、复核修正记录（2026-10-09 晚）

独立复核对第12章提出两处问题，逐条复核后的处理如下。**修改前的原件保留在 `output/第12章/_修改前备份-20261009/`**（solve_tank.py、generate_ch12.py、tank-prediction.svg/.html）。第12章主网格（1 mm / 0.5 mm）的求解数据不受影响，数值与修正前一致。

### 问题 1a：电力线箭头漏画 —— **属实，已修**

- 现象：13 条电力线只画了 **8 个**箭头（应 26 个），中央区域的线一个箭头都没有。
- 原因：原实现按折线**点数**的 30% / 70% 取**整数下标**放箭头（`i = int(len(p)*frac)`，且要求 `1 <= i < len(p)-1`）。
  中央区域的线近似直线，被 RDP 简化成 **2 个点**，下标越界 → 判据不成立 → 静默跳过。
- 修法：改为 `place_arrows()` 沿折线**弧长**插值取点放箭头，并 `assert arr` 保证每条线至少 1 个箭头；
  线过短（< 30 mm）时退化为在 50% 处放 1 个，仍然不留空。
- 结果：**26 个箭头 / 13 条线，每条 2 个**，覆盖率 100%。

### 问题 1b：箭头方向"被翻转两次" —— **在早期写法中属实，对当前产物未复现**

- 复核指出的双翻转确实存在于**早期版本**：先用 `atan2(−Δy, Δx)` 把模型方向转成屏幕角度，输出时又写 `rotate(−ang)`，y 方向被翻了两次。
- 但该写法在本轮工作早期已被替换为"**只做一次模型坐标 → 屏幕坐标转换**"的绝对坐标箭头（`arrow_svg` 内只有 `sx()/sy()` 一次映射，无 `atan2`、无 `transform`）。
- 对**当前** `tank-prediction.svg` 做数值复核：8 个（当时）箭头在模型坐标下，尖端相对两翼中点的位移 **dy = −3.146**（指向 −y）；与 `tank-field-0.5mm.npz` 中 **E_y = −0.005641**（指向负端）一致 → **方向本来就是对的**。
- 为防回归：箭头改为**填充三角**（尖端无歧义），并把"箭头方向与 −∇φ 的夹角余弦"写进自检——
  实测最小余弦 **0.99994**，代码内含 `assert min(ARROW_COS) > 0.9`。

### 问题 2：坏网格被当成"收敛" —— **属实，已修**

- 现象：自测里的 h = 7.35 mm 与 h = 3.675 mm 两个网格，两条钢条的固定节点数都是 **0**，
  却报"迭代 1 次、残差 0"，全场 φ ≡ 0。
- 原因：网格节点落在 h 的整数倍上；`|y∓90| ≤ 1.5 mm` 内没有任何节点 → 3 mm 钢条被整个漏掉 →
  `fixed` 为空 → 初值全零恰好满足 ∇²φ = 0 → 迭代 1 次即"收敛"。**缺陷为 0 恰好是空解的指纹**，而代码没有识别它。
- 修法：
  1. `solve(..., require_electrodes=True)`（**默认开启**）在求解前显式检查两条电极是否都有固定节点，为 0 直接抛错并说明原因；
  2. 新增 `check_grid()` / `valid_steps()` / `electrode_nodes()` 供调用方先筛选网格；
  3. 自测改用**能表示几何**的阶梯 h = 3 / 1.5 / 1 / 0.75 / 0.5 mm，逐行报告**电极节点数、迭代数、残差、中心值、对称性**，
     并加硬断言：`n_hi>0 and n_lo>0`、`iters>1`、`|φ_max − U| < 1e-9`、`|φ_center − 0.5| < 1e-6`；
  4. 把复核对指出的两个坏网格**保留在候选列表**里，由程序显式打印拒绝原因（不删证据）。
- 结果：坏网格被明确拒绝；有效阶梯上中心 φ 全为 0.5、上下反射和全为 1、左右差 ~1e-15、
  缺陷 ~1e-9，迭代数随网格细化 400→1900 单调增加。
- 第12章页面新增一节「二、网格必须能表示几何（否则是假解）」，把该阶梯与拒绝原因直接展示出来。
