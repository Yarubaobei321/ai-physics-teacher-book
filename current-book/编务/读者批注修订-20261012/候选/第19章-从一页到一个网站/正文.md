# 第 17 章　从网页到网站：组织、发布与维护

前面已经做了若干教学网页：一张纸带记录页，一个圆弧轨道模型，一个测速页面，一组电场模型。它们先在教师自己的电脑上使用。可是要让学生在家里打开，要让同事拿去用，要在下学期接着改，就要回答另外几个问题：放到哪里，别人怎样打开；改了以后，别人看到的是不是新版；改坏了，能不能退回去；哪些东西不该放上去。

这一章把网页文件、本机预览、公开链接和修改记录连起来，介绍怎样组织、发布与维护教学资源。

## 一、问题：网页做好了，然后呢

第 5 章的超声波测速网页，需要连同可继续修改的文件夹和发布方法一起交给使用者。这样，下次需要增加一张图或调整说明时，教师就可以从现有项目继续修改。

一个教师在这里常见的困惑有：

1. **本机地址和公开链接分不清。** AI 打开网页后给出 `http://127.0.0.1:8090/`，教师把它发给同事，同事打不开。`127.0.0.1` 指的就是“这台电脑”。
2. **改了，但别人看不到。** 本机的文件改了，网上的版本不会自动跟着变。
3. **网页和开发板混在一起。** 改网页上的一张图，要不要重新烧录开发板？不用。改采样方式，网页更新也没用，要烧录。
4. **什么能公开。** 学生作品、学生姓名、私人笔记，一不小心就跟着网页一起发布了。
5. **改坏了怎么办。** 没有保留旧版本，就只能凭记忆往回改。

> **本章在框架中的位置**
>
> **载体**：所有网页类资源的组织与发布。
>
> **看不见的东西**：文件、本机预览、公开链接之间的关系；版本之间的差别。
>
> **科学思维**：这一章主要是工程和管理，对应的是“科学态度与责任”：哪些内容可以公开，怎样对使用者负责。
>
> **教师的关键判断**：发布什么、不发布什么；更新以后怎样确认别人看到的是新版；出了问题怎样退回。

## 三、跟着做：打开、更新，再从副本恢复

以下示范使用 WorkBuddy 5.6.2 和 **Deepseek-V4.1-Flash**。配套起步包中的第一版尚未加入速度—距离图，便于观察修改前后。已经做完第 2 章的读者，也可以换成自己的纸带记录页，按相同步骤修改和发布。

### 1. 解压副本，让AI解释文件夹

从[本章操作材料](配套/练习材料.md)找到起步包，解压到新的“我的测速实践”文件夹。新建 WorkBuddy 任务，工作空间选这个文件夹，模型选择 Deepseek-V4.1-Flash。作者实际发送的第一句话是：

```text
帮我解释当前项目内容，帮我在本机打开网页
```

先认出三个文件夹：“网页站点”放网页；“固件源码”是开发板上运行的程序；“练习数据”是以前保存的记录。暂时只处理网页。回复中的本机地址通常含 `127.0.0.1` 和一个端口号；端口号是本机预览服务的入口，跟着实际回复打开，不必照抄书里的 8090。

进入第二版，点击“载入已有50点试次”，看看保存的数据和曲线。顶部的“未连接”仍然合理，因为此时没有进行新的测量。第一版没有这个载入入口；它的图为空时，先查数据入口，不要立即判断网页坏了。

### 2. 改之前保留一份可恢复副本

在文件管理器中复制整个“我的测速实践”文件夹，命名为“我的测速实践-修改前”。副本放在工作区旁边，不放进准备发布的网页目录。也可以让 WorkBuddy 帮忙复制，但要在文件管理器里确认副本存在，能打开其中的网页。

然后在本机做一个小修改。测速页的例子是给第一版增加第二版已有的图；纸带记录页可以只增加一行数据来源说明。下面是依据实际需求整理的简略指令，拆开修改和发布，便于先看效果：

```text
请给第一版也增加第二版已有的速度—距离图，原来的图和功能保留。先只改本机文件，打开让我看看，不更新线上。
```

如果只得到“已修改”的回复，追问具体改了哪些文件、用什么地址查看。第一版没有旧试次入口时，先检查新图标题、轴名、说明与已有图是否保留；再接入有来源的数据，检验曲线。

### 3. 需要公开时，先确认发布范围

向 AI 说明准备公开的文件夹，并让它列出清单。学生原件、私人笔记、账号信息和与网页无关的资料不应进入发布目录。作者那次实际发送的是：

```text
请把这套测速网页发布成独立的网页应用，给我公开访问链接，先保留现有功能。
```

这句话由 AI 提供候选，作者选择后实际发送。独立网页应用是当时为连接开发板采用的路径；作者此前遇到的特定轻量发布方式限制了设备连接。换平台或浏览器时，要确认它支持所需的 USB 或蓝牙接口，并实际连接开发板。

发布完成后，打开实际返回的公开链接，检查首页、两个测量页，以及第二版的旧试次入口。再换一台设备访问，确认它不依赖你电脑里的本机服务。作者当时得到的应用管理提示是“设置—数据管理—应用”；如果当前界面已经调整，可以请 WorkBuddy 给出这个应用当前的管理入口，核对应用名称和网址后再操作。

只做本机练习时，可以停在上一步，网页仍可使用。需要交给学生或同事访问时，再进行公开发布。

### 4. 更新原应用，回原链接核对

作者那次把第一版的网址贴进消息，并实际发送：

```text
https://esp32-motion-speed-lab.app.workbuddy.host/online-lab/motion-compare/，我希望给一版，也增加速度vs距离的图像。你帮我完成后，更新到应用。
```

“一版”是当时输入的简称，指第一版。自己操作时换成自己的应用地址，明确说“更新已有应用，保留原链接”。发送前核对自己的应用名称和地址。

回复“已更新”以后，从原链接重新打开，核对新增图标题和原有两张图；如果看见旧版，先刷新，再请 AI 核对当前线上文件是否与本机准备的版本相同。随后按第四节检查物理含义：速度—距离图的点应按采集先后连接，往返经过同一位置的点不能按距离重新排序。

新增图完成后，用一段往返运动的数据检查连线顺序。需要现场采集时，再连接开发板，确认新读数能进入图像。

### 5. 练习从副本恢复

恢复方法可以先在本机练，不影响公开资源。另取一份“修改前”副本，在页上加一行临时说明，打开确认看得见；然后用保存的副本恢复，再打开确认这行消失且原有功能仍在。需要 AI 协助时可说：

```text
请把这份本机练习恢复到“我的测速实践-修改前”的网页版本。先列出准备恢复的文件；保留现在这一版到旁边的“恢复前”文件夹，再恢复并在本机打开。不要发布。
```

确认恢复对象是本次网页，避免拿一个过旧的整个项目覆盖后来新增的数据。真正需要线上退回时，先完成相同的本机检查，再明确要求把恢复后的网页更新到同一个应用，回原链接核对。这条方法靠自己保存的文件副本，不依赖平台是否提供历史版本按钮。恢复后重新打开关键页面，并重复一次原有操作。

## 四、审核：发布前后要查什么

### 1. 发布前：发的是什么

请 AI 发布之前，先问它“你准备发布哪些文件”。本例把“网页站点”作为发布目录，说明文档和练习数据另存。需要逐项检查的是：

| 不该公开的 | 为什么 |
| --- | --- |
| 学生姓名、学号、照片、作品原件 | 隐私；没有授权 |
| 课堂录像、学生的对话记录 | 同上 |
| 私人笔记、备课草稿 | 不必公开，也可能有错 |
| 整个资料包（含固件源码、旧数据） | 体积大，部分内容不适合公开 |
| 密码、密钥和登录凭据 | 防止他人取得账号或服务权限 |

公开链接可以被转发，“只发给一个人”不等于只有一个人能看到。

### 2. 发布后：别人看到的是什么

- **换一台设备打开。** 不要只看 AI 回复里的“已上线”。用手机、用另一台电脑、用另一个浏览器各打开一次。
- **断网试一次。** 课堂上网络不稳，最好确认网页在弱网下能否打开，或者准备一份本机文件作为备用。
- **硬件功能分开验证。** 页面能打开，不等于能连开发板。要在电脑的 Chrome 或 Edge 上实际点“连接”、看到新读数，才算连上。微信里打开、iPad 的 Safari 打开，都可能不支持 USB 和蓝牙。

### 3. 更新后：新版对不对

更新以后，回原链接刷新，再按第 3 章的方法检查改动。速度—距离图有一个关键点：物体往返时会两次经过同一个位置，速度方向相反，所以点要按采集先后连线，不能按距离重新排序。核对数据表中的记录顺序，再沿图线看一遍，确认两者一致。

### 4. 版本：改坏了能不能退回

每次修改前复制一份文件夹，并在名字里注明日期和用途。也可以请 AI 使用 Git 保存一次版本；Git 是记录文件改动的工具，可以查看前后差异并恢复旧版本。发布时保留上一版文件和对应网址，更新后核对线上内容。

### 5. 内容的生命周期

每学期检查一次网站：哪些页面仍在使用，内容和功能是否正确，公开范围是否合适。过时说明及时更新，含个人信息的展示材料按授权和用途重新核对。

## 五、带进课堂：让学生打开你的网页

### 课前

- 把链接做成二维码，印在学案上。
- 在教室的电脑和学生会用的设备（平板、手机）上各打开一次。
- 准备离线备份：单文件网页拷在 U 盘里；要用到的截图放进课件。

### 课上

- 需要连接硬件的页面，由教师的电脑操作、投屏；学生的设备用于观察、比较和记录。
- 网页打不开时，直接切到课件里的截图，不要在课上排查网络。

### 课后

- 学生可以用链接复习、整理实验数据和比较模型结果，例如第 7 章的机械能守恒网页。
- 收集反馈：哪个按钮看不懂，哪里显示不全。下一轮修改从这些反馈开始。

## 六、变式与迁移

### 一份发布检查清单

每次发布前，可以按这份清单逐项检查：

| 时机 | 检查 |
| --- | --- |
| 发布前 | AI 准备发布哪些文件？里面有没有学生信息、私人笔记、资料包？ |
| 发布前 | 这个网页要不要连 USB 或蓝牙？要的话，选能支持的发布方式 |
| 发布前 | 当前版本保存了吗？ |
| 发布后 | 换一台设备打开；手机、电脑各一次 |
| 发布后 | 硬件功能在电脑的 Chrome/Edge 上实际连接一次 |
| 更新后 | 回原链接刷新，确认是新版；改动的部分按第 3 章的方法审核 |
| 每学期 | 哪些页面过时了、出错了、不适合公开了？ |

### 同样的方法还能用在哪里

- **把网页交给同事**：不只交一个链接，连同能继续修改的文件夹和这一章的方法一起交。第 5 章的测速网页已经按这个目的整理为可继续修改的资料包。
- **学生作品的展示**（第 18 章）：学生用 AI 做的网页，展示之前同样要过一遍发布前的检查，尤其是隐私。
- **课件和学案**：同样有版本、更新和过时的问题，同样适用“改之前保存一份”。
